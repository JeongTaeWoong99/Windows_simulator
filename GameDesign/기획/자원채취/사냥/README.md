## 1. 산업 정체성 (제안)

> ⚠️ 제안이다.

| 항목 | 값 |
| --- | --- |
| 한 줄 | **드물게 나오지만, 나오면 크다** |
| 리듬 | 장주기 · 저빈도 · 고가치 |
| 변동성 | 높음 (낚시와 다른 방향) |
| 역할 | **고가 거래 재화** 공급 — 거래소 상위 물량 |
| 플레이어 개입 | 사냥감 선택 (난이도 ↔ 보상) |

낚시와 사냥은 둘 다 변동성이 높지만 방향이 다르다.

| | 낚시 | 사냥 |
| --- | --- | --- |
| 빈도 | 자주 굴린다 | 드물게 굴린다 |
| 1회 가치 | 낮음 | **높음** |
| 체감 | 잔재미 · 도파민 | 기대 · 한 방 |
| 실패 | 허탕 (손실 없음) | 실패 (손실 있음) |

## 2. 채취 특성 (제안)

| 파라미터 | 상대값 | 비고 |
| --- | --- | --- |
| 채취주기 | 김 | 판정 횟수가 적다 |
| 회당 산출 | **가장 많음/가치 높음** | 성공 시 |
| 희귀도 편차 | 높음 | 하위 등급이 적다 |
| 실패 | **있음 (손실 동반)** | 5개 산업 중 유일 |

### 성공/실패 (제안)

- 사냥감마다 **성공률**이 다르다.
- 실패 시 산출이 없고, 소모품(미끼·화살 등)을 잃는다.
- 특성으로 성공률을 올릴 수 있다 → [특성](../../특성/README.md)와 가장 강하게 연결되는 산업.

> **주의:** "손실"은 방치형에서 매우 조심해야 하는 요소다.
> 자는 동안 자동으로 실패해 재화를 잃으면 P1·P2를 동시에 위반한다.
> 손실은 **소모품 한정**으로 두고, 보유한 자원·성장은 절대 잃지 않게 한다.
> 소모품이 떨어지면 사냥이 멈추는 정도가 안전선이다.

## 6. ⚠️ 선행 작업 — `ItemType.Hunting` 추가

현재 `ItemType` enum에 사냥이 없다.

```
None=0, Farming=1, Fishing=2, Mining=3, Logging=4, Misc=5, Special=6, Max
```

**조치:**

1. `GameDesign/Excel/Enum.xlsx`의 `ItemType` 시트에 `Hunting`을 추가한다.
2. **값은 `7`로 뒤에 붙인다.** 중간(예: 5)에 끼워 넣으면 `Misc`·`Special`의 값이
   밀려 기존 `.bytes`·DB에 저장된 값이 전부 어긋난다.
3. `Server/generate-tables.ps1`을 실행해 생성물을 갱신한다.
4. 엑셀 + 생성물(`Server/GameData`, `Server/Shared/Data`, `GameDesign/DataLog`, Unity 미러)을
   **같은 커밋**에 담는다.

> 생성물은 직접 수정하지 않는다. 반드시 엑셀 → 재생성 경로로 처리한다.
> 이 작업은 아직 수행되지 않았다.
