# 01. 자원 채취 (Gathering)

> 상위 문서: [`게임기획코어.md`](../게임기획코어.md)
> 최종 업데이트: 2026-07-27 · 상태: **산업 5종 확정 · 수치 미정**

코어 루프의 시작점이자, 게임에서 **유일하게 재화가 새로 생성되는 지점**(faucet)이다.
여기서 나오는 총량이 경제 전체의 상한을 정하므로, 이 문서의 수치는 [거래](../거래/README.md)와 반드시 함께 결정한다.

---

## 1. 확정 사항

- 요일별로 채취 가능한 **1차 산업**이 정해진다.
- 1차 산업은 **5종**이다: **농사 · 벌목 · 낚시 · 채굴 · 사냥**.
- 주말: 평일 산업 중 **택 1** + **효율 ×2**.
- 진행은 **방치형**. 플레이어의 조작 없이 자동으로 흐른다.
- 산출물은 자원·아이템이며, 낮은 확률로 희귀 보상이 섞인다.

---

## 1-1. 1차 산업 5종

각 산업은 **서로 다른 리듬**을 갖는다. 같은 채취를 스킨만 바꾼 것이 되지 않도록,
산업마다 하나씩 고유한 축을 배정했다.

| 산업 | enum | 한 줄 정체성 | 고유 축 | 상세 |
| --- | --- | --- | --- | --- |
| **농사** | `Farming` ✅ | 가장 느리고, 가장 많이 나온다 | 파종 선택 (장주기 ↔ 단주기) | [농사](농사/README.md) |
| **벌목** | `Logging` ✅ | 베면 줄고, 시간이 지나면 돌아온다 | 자원 고갈·재생 | [벌목](벌목/README.md) |
| **낚시** | `Fishing` ✅ | 무엇이 잡힐지 모른다 | 높은 변동성 · 잦은 판정 | [낚시](낚시/README.md) |
| **채굴** | `Mining` ✅ | 깊이 갈수록 좋아진다 | 누적 진행도 (깊이) | [채굴](채굴/README.md) |
| **사냥** | `Hunting` ❌ | 드물게 나오지만, 나오면 크다 | 성공/실패 · 고가치 | [사냥](사냥/README.md) |

> ⚠️ **`ItemType.Hunting`이 아직 enum에 없다.** `Enum.xlsx`에 값 `7`로 추가하고
> `Server/generate-tables.ps1` 재실행이 필요하다. 절차는 [사냥](사냥/README.md) 6장 참조.

### 산업 간 역할 분담 (제안)

| 축 | 담당 산업 |
| --- | --- |
| 기반 물량 | 농사 |
| 총량 제어 | 벌목 |
| 잔재미·티켓 | 낚시 |
| 장기 성장 재료 | 채굴 |
| 고가 거래 재화 | 사냥 |

이 분담이 유지되면 5개 산업이 서로를 대체하지 않는다.
새 산업을 추가할 때도 **비어 있는 축**을 찾아 배정한다.

## 2. 채취 모델 (제안)

> ⚠️ 아래는 확정 골격에서 도출한 **제안**이다. 확정 시 ⚠️를 제거한다.

### 2.1 기본 공식

```
채취 산출량 = floor(경과시간 / 채취주기) × 회당산출 × 효율배수
효율배수    = 요일배수 × 특성패시브 × 액티브부스트
```

| 항목 | 출처 | 비고 |
| --- | --- | --- |
| 채취주기 | 산업별 테이블 | 산업마다 다른 리듬 (예: 농업 느리게·다량 / 채광 빠르게·소량) |
| 회당산출 | 산업별 테이블 | |
| 요일배수 | 요일 로테이션 | 평일 1.0 / 주말 선택 산업 2.0 |
| 특성패시브 | [특성](../특성/README.md) | 상시 적용 |
| 액티브부스트 | [특성](../특성/README.md) | 지속시간 동안만 |

### 2.2 오프라인 진행 (P2 "꺼져 있어도 자란다")

방치형의 핵심이므로 **가장 먼저 확정해야 할 규칙**이다.

| 논점 | 선택지 | 권장 |
| --- | --- | --- |
| 오프라인 누적 상한 | 무제한 / N시간 / 등급별 확장 | **상한 있음** — 무제한이면 접속 동기가 사라짐 |
| 오프라인 효율 | 온라인과 동일 / 감쇠 | **동일** — P1·P2와 충돌 없음 |
| 정산 시점 | 접속 시 일괄 / 서버 틱 | **접속 시 일괄** — 서버 부하 최소 |
| 요일이 바뀌며 오프라인이 걸친 경우 | 시작 요일 기준 / 구간 분할 | **구간 분할** — P3 유지 |

> 오프라인 상한은 "하루 한 번 접속하면 손해 없음"을 기준선으로 잡기를 권장한다.
> 상한이 8시간이면 근무 중 손실이 발생해 P1(주의를 뺏지 않는다)을 스스로 위반한다.

### 2.3 요일 로테이션

**산업이 5종으로 확정되면서 평일 5일과 1:1로 맞아떨어진다.**
아래 배정을 기본안으로 제안한다.

| 요일 | 활성 산업 | 배수 |
| --- | --- | --- |
| 월 | 농사 | ×1.0 |
| 화 | 벌목 | ×1.0 |
| 수 | 낚시 | ×1.0 |
| 목 | 채굴 | ×1.0 |
| 금 | 사냥 | ×1.0 |
| 토·일 | 평일 5종 중 **택 1** | ×2.0 |

> ⚠️ 배정 순서는 제안이다. 다만 **1일 1산업 · 5일 1주기**라는 구조는
> 산업 수와 평일 수가 일치하므로 자연스럽다.

**이 구조의 부작용 — 반드시 함께 결정할 것:**

- 각 산업이 **주 1회(주말 포함 최대 2회)** 만 열린다. 산업별 진행이 매우 느려진다.
  - 특히 [채굴](채굴/README.md)의 깊이 누적이 주 1회씩만 진행된다.
  - 대책: 회당 산출을 크게 잡거나, 비활성 산업도 저효율로 돌아가게 한다.
- 특정 산업 재료가 막히면 **[특성](../특성/README.md) 성장이 일주일 단위로 대기**한다.
- 금요일에 사냥이 걸리면 주말 택1이 사냥에 쏠릴 수 있다 (연속 2일).

| 논점 | 선택지 | 권장 |
| --- | --- | --- |
| 비활성 산업 | 완전 정지 / 저효율 가동 | **저효율 가동** — 주 1회는 너무 성기다 |
| 하루 산업 수 | 1개 / 2개 | 1개 (P3 선명함) |
| 주말 택1 시점 | 토요일 1회 선택 → 일요일까지 고정 | 고정 (변경 남용 방지) |

여전히 미결: 요일 경계 기준 시각 (예: KST 05:00). [퀘스트](../퀘스트/README.md) 리셋과 **같아야 한다.**

### 2.4 희귀 보상

- 매 채취 판정마다 희귀도 롤을 굴린다.
- 희귀도는 `ItemRarity` 6단계(`Common`~`Mythic`)를 그대로 쓴다.
- 확률 테이블 **미정**. 산업별로 다르게 할지, 전 산업 공통으로 할지도 미정.
- 특성이 희귀도 확률에 개입하는지 여부 미정 → [특성](../특성/README.md)와 함께 결정.

## 3. 데이터 설계 (제안)

밸런스 수치는 코드가 아니라 **엑셀 테이블**로 간다 (게임기획코어 6장 규칙).

| 신규 테이블(제안) | 용도 | 주요 컬럼 |
| --- | --- | --- |
| `GatheringTable` | 산업별 채취 파라미터 | `IndustryType`(=`ItemType`), `CyclSec`, `YieldPerCycle`, `UnlockCondition` |
| `WeekdayRotationTable` | 요일↔산업 배정 | `DayOfWeek`, `IndustryType`, `Multiplier` |
| `DropTable` | 산업별 산출 아이템·확률 | `IndustryType`, `ItemTID`, `Weight`, `Rarity` |

기존 `ItemTable`(`ItemTID`/`Name`/`ItemType`/`ItemRarity`/`MaxStack`/`Desciption`)을 그대로 참조한다.

> `ItemType`을 "아이템 분류"와 "산업 종류" 양쪽으로 쓰는 중이다.
> 의미가 갈리기 시작하면 `IndustryType` enum을 분리한다. 자세한 우려는
> [`기획평가.md`](../기획평가.md) 참조.

7. 채취에 재료·도구 소모가 있는가? (사냥은 소모품 전제 — [사냥](사냥/README.md))

> "+β"(주말 추가 요소)는 여전히 미정 — 필요 없으면 삭제를 권장한다.
