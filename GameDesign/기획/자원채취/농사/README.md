## 1. 산업 정체성 (제안)

> ⚠️ 제안이다. 5개 산업이 서로 다른 리듬을 갖게 하기 위한 차별화 축.

| 항목 | 값 |
| --- | --- |
| 한 줄 | **가장 느리고, 가장 많이 나온다** |
| 리듬 | 장주기 · 대량 산출 |
| 변동성 | 낮음 (예측 가능) |
| 역할 | 경제의 **기반 물량** 공급 |
| 플레이어 개입 | 파종 시 작물 **선택** 1회 |

농사는 5개 산업 중 **유일하게 "미리 정하고 기다리는"** 구조다.
심는 순간의 선택이 수확까지 고정되므로, 방치형에 가장 잘 맞는다.

---

## 2. 채취 특성 (제안)

```
파종(작물 선택) → 성장 대기 → 수확
```

| 파라미터 | 상대값 | 비고 |
| --- | --- | --- |
| 채취주기 | **가장 김** | 다른 산업의 기준점 |
| 회당 산출 | **가장 많음** | 주기가 긴 만큼 보상 |
| 희귀도 편차 | 낮음 | 대부분 `Common`~`Uncommon` |
| 실패 | 없음 | 심으면 반드시 수확 |

### 작물 선택

- 작물마다 `성장시간 × 산출량 × 산출 아이템`이 다르다.
- 짧은 작물(자주 접속) ↔ 긴 작물(하루 1회)의 **트레이드오프**를 만든다.
- 총 효율은 비슷하게 두어, 접속 빈도가 낮은 유저가 손해 보지 않게 한다 (P1·P2).

> 이 "짧게 여러 번 vs 길게 한 번"이 농사의 유일한 의사결정이다.
> 여기서 긴 쪽이 명백히 손해가 되면 P1을 위반한다.

## 3. 산출물

| 구분 | 내용 |
| --- | --- |
| 기본 자원 | 작물류 (곡물·채소 등) |
| 희귀 산출 | 변종 작물 |
| 용도 | 특성 재료 · 거래소 대량 유통 |

`ItemTable.ItemType = Farming`. 현재 더미 데이터(`A`/`B`/`C`)가 이 타입으로 들어가 있다.

## 4. 데이터 설계 (제안)

| 테이블 | 컬럼 |
| --- | --- |
| `CropTable` | `CropTID`, `Name`, `GrowSec`, `YieldItemTID`, `YieldCount`, `UnlockCondition` |

`GatheringTable`의 `Farming` 행이 산업 공통 파라미터를, `CropTable`이 작물별 값을 갖는다.
