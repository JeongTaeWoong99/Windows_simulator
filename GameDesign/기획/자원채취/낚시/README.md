# 1차 산업 — 낚시 (Fishing)

> 상위: [`자원채취`](../README.md) · [`게임기획코어.md`](../../게임기획코어.md)
> 최종 업데이트: 2026-07-27 · 상태: **정체성 제안 · 수치 미정**
> enum: `ItemType.Fishing = 2` ✅ 존재

---

## 1. 산업 정체성 (제안)

> ⚠️ 제안이다.

| 항목 | 값 |
| --- | --- |
| 한 줄 | **무엇이 잡힐지 모른다** |
| 리듬 | 단주기 · 소량 산출 |
| 변동성 | **가장 높음** |
| 역할 | 게임의 **도파민 담당** — 희귀 보상의 주 출처 |
| 플레이어 개입 | 낚시터 선택 (기대값 ↔ 변동성) |

낚시는 5개 산업 중 **유일하게 결과가 매번 다른** 구조다.
"오늘 뭐 잡혔나 볼까"가 접속 동기가 되는 산업이다.

> 방치형에서 접속 동기를 만드는 가장 자연스러운 방법은 **불확실성**이다.
> 농사처럼 결과가 정해진 산업은 접속해도 놀라움이 없다. 낚시가 그 역할을 맡는다.

---

## 2. 채취 특성 (제안)

| 파라미터 | 상대값 | 비고 |
| --- | --- | --- |
| 채취주기 | **가장 짧음** | 판정 횟수가 많다 |
| 회당 산출 | 적음 (1~2개) | |
| 희귀도 편차 | **가장 큼** | `Common`~`Mythic` 전 구간 |
| 실패 | 있음 (허탕) | 변동성의 일부 |

### 낚시터 (제안)

| 낚시터 | 기대값 | 변동성 |
| --- | --- | --- |
| 저수지 | 안정 | 낮음 — 잡템 위주 |
| 강 | 중간 | 중간 |
| 바다 | 낮음 | **높음** — 허탕 많지만 대박 가능 |

기대값 총합은 비슷하게 두고, **성향 선택**으로 만든다.
"바다가 무조건 좋다"가 되면 선택이 사라진다.

## 3. 산출물

| 구분 | 내용 |
| --- | --- |
| 기본 자원 | 어류 (크기·등급 편차) |
| 희귀 산출 | 대물 · 고유 아이템 · **가챠 티켓 주 출처** |
| 잡템 | 낡은 장화 등 (저가 판매용) |
| 용도 | 특성 재료 · 거래소 고가 거래 |

> [아이템](../../아이템/README.md)의 "낮은 확률로 티켓·고유 아이템"은
> 낚시에 몰아주는 편이 산업 차별화에 유리하다.

---

## 4. 데이터 설계 (제안)

| 테이블 | 컬럼 |
| --- | --- |
| `FishingSpotTable` | `SpotTID`, `Name`, `CycleSec`, `FailRate`, `UnlockCondition` |
| `FishTable` | `FishTID`, `SpotTID`, `ItemTID`, `Weight`, `Rarity` |

`FishTable`의 `Weight`가 실질적인 **가중치 드랍 테이블**이다.
`DropTable`(산업 공통)로 통합할지, 낚시 전용으로 둘지 결정 필요.

---

## 5. 결정 필요

1. 허탕(실패)을 넣는가? 방치형에서 실패는 체감이 나쁠 수 있다
2. 낚시터를 여러 개 두는가? 해금 조건은?
3. 티켓·고유 아이템을 낚시에 집중시키는가, 전 산업 공통으로 두는가?
4. 잡은 물고기의 "크기" 같은 개체 변량을 두는가? (거래소 가치 편차 발생)
5. 드랍 테이블을 산업 공통(`DropTable`)으로 통합하는가?
