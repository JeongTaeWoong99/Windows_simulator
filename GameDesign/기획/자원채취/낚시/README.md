## 2. 낚시 루프

### 2.1 판정 루프 (30초) — 실패 없음

```
30초 경과 ── 반드시 보상
  │
  ├─ ① 기본 / 특별 분기 (9 : 1 ⚠️ 재검토 대상)
  │     │
  │     ├─ 90%  기본보상
  │     │        ├─ 희귀도 롤  ← RarityWeightTable (전 산업 공통) ✅
  │     │        └─ 그 희귀도의 낚시 아이템 ← FishingBasicTable
  │     │             예) Common → 붕어 / Rare → 월척 붕어
  │     │
  │     └─ 10%  특별보상
  │              └─ FishingSpecialTable 롤 → 대물
  │
  └─ ② CommonRewardTable 롤 (①과 별개, 매 판정)
          └─ 티켓 · 고유 아이템
```

산출량에는 `회당산출 × 요일배수 × 특성패시브 × 액티브부스트`가 곱해진다.
서버가 굴리는 롤은 **판정당 3회**(기본/특별 분기 → 희귀도 or 특별 → 공통보상).

### 2.2 체감 루프

**온라인 (위젯 상주)**
30초마다 찌 → **반드시** 무언가 올라온다. 헛치는 일이 없다.
낚시를 선택한 동안 위젯에는 **낚시만** 표시되므로 화면이 단순하다.

> 실패가 없다는 것이 **"확실한 도파민"의 핵심 근거**다.
> 위젯을 볼 때마다 뭔가 잡혀 있고, 기다림에 배신이 없다.

**오프라인 (접속 시 일괄 정산)**
```
경과시간
  ├─ 0~24h 구간   → 판정수 × 1.0
  └─ 24h 이후      → 판정수 × 0.5
  ↓ 요일 경계 걸치면 구간 분할 (배수만 변경)
  ↓ 판정 횟수만큼 ①~③ 반복
Dictionary<ItemTID, count> 집계 → 한 번에 지급
```

### 2.3 하루 기준 실측 (24시간 · 실패 없음)

| 구분 | 9 : 1 (현행) | 8 : 2 (도파민 강화안) |
| --- | --- | --- |
| 총 판정 | 2,880 | 2,880 |
| 기본보상 | 2,592 | 2,304 |
| **특별보상** | **288** | **576** |

> ⚠️ **특별보상이 하루 288회다.** "특별"이라 부르기엔 많다.
> 특별보상 안에 등급을 두거나(대물 등급 분화) 비율을 재검토해야 한다. → 7장

## 3. 산업 정체성

| 항목 | 값 |
| --- | --- |
| **심리 정의** | **확실한 도파민** |
| 투자 비유 | 소액 잦은 당첨 |
| 한 줄 | **기다리면 반드시, 자주 나온다** |
| 회당 산출 | 적음 (소액을 자주) |
| 실패율 | **없음** |
| 특별보상 | **대물** |
| 역할 | 접속 동기 담당 — "오늘 뭐 잡혔나 볼까" |
| 플레이어 개입 | **없음** (낚시터 1개인 동안) |

### 도파민 정의가 요구하는 것

"확실한 도파민"이 되려면 **자주 · 즉각 · 배신 없이** 보상이 와야 한다.

| 조건 | 현재 상태 |
| --- | --- |
| 배신 없음 | ✅ 실패 폐기로 충족 |
| 자주 | ✅ 30초 주기 |
| 즉각 | ✅ 위젯에서 바로 보임 |
| **특별한 게 자주** | ⚠️ 특별보상 10%는 다른 산업과 같다 |

> **낚시의 특별보상 비율을 다른 산업보다 높게 두는 것을 제안한다** (예: 20%).
> "특별한 게 흔한 산업"이 곧 도파민 담당이다.
> 대신 특별보상 내부에 등급을 둬 대물 안에서도 편차를 만든다.
> → [자원채취](../README.md) 5장 결정 필요 3번

### ⚠️ 낚시에는 고유 메커니즘이 없다

주기·희귀도 분포·실패가 모두 전 산업 공통이 되면서, 낚시를 다른 산업과 구분하는 것은
**회당 산출(적음)과 특별보상 내용(대물)** 둘뿐이다.

| 산업 | 개입 지점 | 고유 메커니즘 |
| --- | --- | --- |
| 농사 | 파종 작물 선택 | 있음 |
| 벌목 | 벌목 강도 조절 | 자원 고갈·재생 |
| 채굴 | 하강 ↔ 채굴 배분 | 깊이 누적 |
| 사냥 | **사냥터 선택** | 사냥터 분리 + **보스** |
| **낚시** | **없음** | **없음** |

낚시는 **5종 중 유일하게 "고르고 지켜보기만 하는" 산업**이다.

**심리 정의상 이게 맞을 수도 있다.** "확실한 도파민"은 조작을 요구하지 않는 게 자연스럽고,
P1(주의를 뺏지 않는다)과도 가장 잘 맞는 산업이 된다.
다만 그렇다면 **체감을 특별보상 빈도로 만들어야** 한다 — 지금 비율(10%)로는
다른 산업과 구분되지 않는다.

> **낚시터 확장은 단순 콘텐츠 추가가 아니라 낚시에 의사결정을 만드는 작업이다.**
> 사냥이 사냥터로 갈리는 것과 대비되므로, 낚시터를 계속 1개로 둘지
> "조작 없는 산업"으로 확정할지를 정해야 한다.

## 4. 산출물

### 기본보상 (90%) — 희귀도별 어종

| 희귀도 | 예시 | 비고 |
| --- | --- | --- |
| `Common` | 붕어 · 낡은 장화 | 잡템도 여기 |
| `Uncommon` | 잉어 | |
| `Rare` | 월척 붕어 | 같은 어종의 상위 등급 = **별도 `ItemTID`** |
| `Epic` | 향어 | |
| `Legendary` | 대물 잉어 | |
| `Mythic` | 전설의 잉어 | |

**희귀도가 나올 확률은 채굴·농사와 완전히 동일하다.** 아이템 이름만 다르다.

### 특별보상 (10%) — 대물

낚시 전용 산출물. 기본보상의 최상위와는 별개 축이다.

### 공통 보상 (별도 롤)

티켓 · 고유 아이템. 전 산업 동일 확률.

## 5. 데이터 설계 (제안)

| 테이블 | 컬럼 | 범위 |
| --- | --- | --- |
| `FishingSpotTable` | `SpotTID`, `Name`, `UnlockCondition` | 낚시터. **지금은 행 1개** |
| `FishingBasicTable` | `Rarity`, `ItemTID` | 희귀도 → 어종 **매핑만**. 6행 |
| `FishingSpecialTable` | `SpotTID`, `ItemTID`, `Weight` | 대물 |

**낚시 테이블에 두지 않는 것:**

| 항목 | 어디에 있나 |
| --- | --- |
| `CycleSec` (30초) | 전역 상수 |
| 희귀도 분포 확률 | `RarityWeightTable` (전 산업 공통) |
| 기본/특별 비율 (9:1) | 전역 상수 또는 `GatheringTable` |
| 티켓·고유 아이템 | `CommonRewardTable` |
| `Rarity` 중복 컬럼 | `ItemTable.ItemRarity`가 원본 |

> 낚시터를 늘릴 때 `SpotTID` 행만 추가하면 되도록 **처음부터 `SpotTID`를 키에 넣어 둔다.**
> 밸런스 수치는 `GameDesign/Excel/*.xlsx`가 원본. 수정 후 `Server/generate-tables.ps1` 실행.

## 6. 서버 / 클라이언트 책임

| 책임 | 주체 | 이유 |
| --- | --- | --- |
| 판정 횟수 산정 (경과시간 / 30초) | **서버** | 클라 시계 조작 방지 |
| 24h 감쇠 구간 분할 | **서버** | 시간 기준이 서버 시각 |
| 기본/특별 분기 · 희귀도 롤 | **서버** | 재화 생성 지점 (P4) |
| 산업 선택 변경 기록 | **서버** | 변경 시점 이전 구간을 낚시로 정산해야 함 |
| 낚시 연출 · 물고기 표시 | 클라이언트 | 서버 값의 시각화 |

> 판정당 서버 롤은 **3회**(기본/특별 분기 → 희귀도 or 특별 → 공통보상).
> 실패 롤이 없어지고 개체 변량도 없어 이 이상 늘지 않는다.
