## 1. 산업 정체성 (제안)

> ⚠️ 제안이다.

| 항목 | 값 |
| --- | --- |
| **심리 정의** | **확실한 스노우볼** |
| 투자 비유 | 복리 장기투자 — 오늘은 어제보다 낫다 |
| 한 줄 | **깊이 갈수록 좋아진다** |
| 회당 산출 | 중간 — 깊이에 비례 |
| 실패율 | 낮음 |
| 특별보상(10%) | 보석류 — **깊이에 연동** |
| 역할 | **장기 투자** 축 — 유일하게 진행도가 누적된다 |
| 플레이어 개입 | 하강 ↔ 채굴 중 배분 |

채굴은 5개 산업 중 **유일하게 "어제의 진행이 오늘에 남는"** 구조다.
다른 산업이 매일 리셋되는 반복이라면, 채굴은 계속 깊어진다.
산업 택1(자유 변경)에서도 **깊이는 유지된다** — 다른 산업을 하다 돌아와도 그대로다.

### ⚠️ "깊이가 희귀도를 올린다"는 이제 성립하지 않는다 — 대안

기존 기획은 **깊이가 희귀도 구간을 통째로 올리는** 구조였다.
**기본보상의 희귀도 분포가 전 산업 동일로 확정되면서 이 방식은 쓸 수 없다.**
깊이로 분포를 올리면 채굴만 다른 분포를 갖게 되어 확정 사항과 충돌한다.

**대안 — 확률이 아니라 매핑을 깊이별로 바꾼다.**

| 등급 (확률 동일) | 깊이 1 | 깊이 10 | 깊이 30 |
| --- | --- | --- | --- |
| `Common` | 돌덩어리 | 철광석 | 티타늄 원석 |
| `Rare` | 은광석 | 백금광석 | 미스릴 |
| `Legendary` | … | … | … |

- **등급이 나올 확률은 늘 같다.** 깊이가 바뀌면 **그 등급에서 나오는 아이템**이 바뀐다.
- 깊이의 보상이 "희귀한 게 더 자주"가 아니라 **"같은 등급이라도 더 값진 것"** 이 된다.
- 확정 사항(분포 공통)을 지키면서 깊이 누적의 의미가 그대로 산다.
- `MiningBasicTable`에 `DepthLevel` 컬럼을 두면 그대로 구현된다.

> 이 방식이 밸런싱도 쉽다. 깊이가 확률을 건드리면 깊은 유저와 얕은 유저의
> 기대값 격차가 지수적으로 벌어지지만, 매핑만 바꾸면 **아이템 가치 차이**로 선형 통제된다.

## 2. 채취 특성 (제안)

```
깊이 0 ─하강→ 깊이 N ─채굴→ 광석 (깊을수록 등급↑)
```

| 파라미터 | 값 | 비고 |
| --- | --- | --- |
| 채취주기 | **30초** ✅ | 전 산업 공통 → [자원채취](../README.md) 2.1 |
| 회당 산출 | 중간 ⚠️ | 깊이에 비례. 수치 미정 |
| 실패율 | 낮음 ⚠️ | 수치 미정 |
| 희귀도 분포 | **전 산업 동일** ✅ | 깊이는 확률이 아니라 **아이템 매핑**을 바꾼다 (1장) |
| 특별보상(10%) | 보석류 ✅ | 깊이 연동 |
| 특이 규칙 | 깊이 누적 | 리셋되지 않음 |

> ⚠️ **하강 속도를 30초 판정 기준으로 잡는다.** 하루 2,880회이므로
> 판정당 깊이 증가를 크게 잡으면 며칠 만에 최대 깊이에 도달해 장기 목표가 소진된다.

### 깊이 (제안)

- 깊이는 **유저별로 누적**되며 리셋되지 않는다.
- 깊이 구간마다 산출 광석과 희귀도 분포가 달라진다.
- 더 깊이 가려면 시간(또는 재료)이 든다.

| 논점 | 권장 |
| --- | --- |
| 하강과 채굴을 동시에? | **택1** — 선택이 생긴다 (지금 캘까, 더 갈까) |
| 깊이 상한 | 있음 — 없으면 무한 스케일링 |
| 오프라인 중 진행 | 자동 채굴 (현재 깊이에서) |

> 이 "지금 캘까 / 더 내려갈까"가 채굴의 유일한 의사결정이다.
>
> ✅ **해소 (2026-07-27):** 요일 로테이션이 "전 산업 상시 가동 + 요일 효율 보너스"로
> 확정되면서 **채굴도 매일 진행된다.** 주 1회만 열려 깊이 누적이 정체되던 문제는 사라졌다.
> 배정 요일(목요일 제안)에는 보너스 배수가 붙는다. → [자원채취](../README.md) 2.3

## 3. 산출물

| 구분 | 내용 |
| --- | --- |
| 기본 자원 | 광석 (깊이별 등급) |
| 희귀 산출 | 보석류 |
| 용도 | 특성 재료 (고레벨 재료의 주 출처) |

> 광석을 **고레벨 특성 재료**로 묶으면, 깊이 진행 = 성장 진행이 되어
> [특성](../../특성/README.md)와 자연스럽게 연결된다.

## 4. 데이터 설계 (제안)

| 테이블 | 컬럼 |
| --- | --- |
| `MineDepthTable` | `DepthLevel`, `DescendCycles`, `YieldCount`, `UnlockCondition` |
| `MiningBasicTable` | `DepthLevel`, `Rarity`, `ItemTID` — **깊이별 희귀도 → 광석 매핑** |
| `MiningSpecialTable` | `DepthLevel`, `ItemTID`, `Weight` — 보석류 |

현재 깊이는 **유저 DB**에 저장한다.

- `DescendCycles`는 초가 아니라 **판정 횟수**로 둔다 (30초 고정이므로 초를 쓸 이유가 없다).
- `MinRarity`/`MaxRarity` 컬럼은 **두지 않는다.** 희귀도 확률은 전 산업 공통
  `RarityWeightTable`이 정하고, 채굴은 `(DepthLevel, Rarity) → ItemTID` 매핑만 갖는다.
  → [자원채취](../README.md) 2.4
- `MiningBasicTable` 행 수 = `깊이 단계 × 6`. 깊이를 30단계로 두면 180행이 된다.
  깊이마다 전 등급을 채우지 말고 **구간 단위**(1~5, 6~10 …)로 묶는 편이 관리하기 쉽다.

## 5. 결정 필요

1. 깊이 개념을 넣는가? (넣지 않으면 농사·벌목과 차별점이 약하다)
2. **깊이 1단계 하강에 필요한 판정 횟수는?** (하루 2,880회 기준으로 역산)
3. 깊이 상한은?
4. 하강에 재료(곡괭이·연료)가 소모되는가?
5. 깊이가 리셋되는 상황이 있는가? (붕괴 이벤트 등 — P1 관점에서 비권장)
6. `ItemType.Mining` 주석이 "채광"인데 기획 용어는 "채굴"이다. 용어를 통일할 것

> 해소됨: 채취주기 30초 ✅ / 주 1회 문제(요일 구조 전환) ✅
