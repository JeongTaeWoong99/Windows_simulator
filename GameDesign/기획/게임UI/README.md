# 07. 게임 UI

> 상위 문서: [`게임기획코어.md`](../게임기획코어.md)
> 최종 업데이트: 2026-07-31 · 상태: **방향만 정해짐 + 목업 2종**

이 게임이 다른 방치형과 구분되는 **유일한 차별점**이다.
"바탕화면 위에서 상시 동작"은 컨셉 문구가 아니라 **가장 강한 제약**이다.

---

## 1. 확정 사항

- Windows 바탕화면 위 **투명 창**으로 상시 동작한다.
- 기본은 **방치형** — 조작이 필요 없다.
- **위젯 클릭 → 팝업 UI**로 퀘스트·특성·아이템·거래를 조작한다.
- 아트: Pixel + Stylized (AI). UI/UX도 동일 방향.

---

브라우저로 열면 **동작한다.** 카운트다운은 실제 계산식

클라 구현 시 계산 부분을 옮겨 쓸 수 있다.

| [게임UI목업.html](게임UI목업.html) | **전체 경영 패널** — 좌: 캐릭터 수치·장비 / 중: 작업장·인벤토리 / 우: **거래소·상점** | T-006 · T-007 · T-010 · T-002 |

> 톤: 다크 판타지 픽셀 + **관리자 패널**. "캐릭터를 배치해 얻은 아이템으로 부를 쌓는다"가
> 화면의 주제이므로, 상단에 **경영 지표**(가동 슬롯 · 시간당 산출 · 누적 수확 · 거래소 등록)를 둔다.

> 특히 **상점은 게임기획코어에 항목 자체가 없다**(수익화 미정). 6장 결정 필요 참조.

## 2. 화면 구조 (제안)

> ⚠️ 제안이다.

| 레이어 | 역할 | 상주 여부 |
| --- | --- | --- |
| **위젯** | 바탕화면 상주. 현재 산업·진행 상황을 시각화 | 항상 |
| **팝업** | 인벤토리·특성·퀘스트·거래소 조작 | 클릭 시 |
| **토스트** | 희귀 획득 등 최소 알림 | 조건부 |

### 2.1 위젯 (상주 레이어)

이 게임의 얼굴이자, P1을 지키거나 어기는 지점이다.

| 원칙 | 내용 |
| --- | --- |
| 작을 것 | 화면 구석 소형. 작업 창을 가리지 않음 |
| 조용할 것 | 급격한 애니메이션·번쩍임 금지 |
| 클릭 통과 | 위젯 바깥은 마우스 입력을 데스크톱으로 통과시킨다 |
| 항상 위 여부 | **선택 가능해야 함** — 강제 최상위는 업무 방해 |
| 상태 한눈에 | 오늘의 산업 / 진행도 / 수확 대기 여부 |

### 2.2 팝업 (조작 레이어)

| 항목 | 내용 |
| --- | --- |
| 진입 | 위젯 클릭 |
| 탭 구성 | 인벤토리 · 특성 · 퀘스트 · 거래소 |
| 크기 | 일반 창 수준. 이동·닫기 자유 |
| 종료 | 팝업을 닫아도 게임 진행은 계속된다 |

### 2.3 알림 정책 (P1 직결)

| 상황 | 알림 | 근거 |
| --- | --- | --- |
| 일반 채취 완료 | **없음** | 상시 발생 → 알리면 방해 |
| 희귀 이상 획득 | 위젯 내 조용한 표시 | 놓쳐도 손해 없음 |
| 인벤토리 가득 | 위젯 표시 | 진행이 멈추므로 필요 |
| 거래 체결 | 접속 시 요약 | 실시간 알림 불필요 |
| 소리 | **기본 꺼짐** | 업무 중 사용 전제 |

> 원칙: **어떤 알림도 "지금 클릭하지 않으면 손해"를 만들지 않는다.**

### 2.4 중앙 패널 최하단 탭 — 특별 이벤트 자리 (2026-07-31)

경영 패널의 **중앙 열은 작업슬롯 전용**이다. 그 **최하단에 탭 한 줄을 비워 둔다.**
지금은 비어 있지만, 나중에 **채취 루프 바깥의 콘텐츠**가 여기로 들어온다.

| 들어올 후보 | 근거 |
| --- | --- |
| **보스** | 사냥에서 티켓을 모아 도전. 채취 루프 밖으로 나가는 **유일한 통로** → [사냥](../자원채취/사냥/README.md) 4장 |
| **대형 작업물 채취** | 여러 슬롯·시간을 들여 하나를 캐는 형태 (미기획) |
| 기타 특별 이벤트 | 미기획 |

**지금 필요한 것은 자리를 비워 두는 것이지 콘텐츠를 만드는 것이 아니다.**

- 탭이 늘어나도 **작업슬롯 영역이 밀리거나 줄지 않게** 레이아웃을 잡는다
- **비어 있을 때는 탭 줄 자체를 숨긴다.** 잠긴 탭을 보여 주면
  "지금 못 하는 것"이 상시로 눈에 남는다
- 이 층은 **큰 창에서만** 열린다. 상시 위젯에는 올라오지 않는다

> ⚠️ **여기 들어오는 것은 무엇이든 [사냥](../자원채취/사냥/README.md) 4.2의 보스 4원칙을 지킨다** —
> 도전 시점 자유 · 실시간 조작 없음 · 실패해도 티켓만 손실 · **기간 한정 없음**.
>
> **탭에 배지·타이머·"오늘까지" 표시를 붙이지 않는다.**
> 붙이는 순간 바탕화면 상주 위젯이 **재촉하는 물건**이 되고, 2.3의 알림 원칙과
> P1(주의를 뺏지 않는다)을 동시에 어긴다.

> 왜 중앙인가 — 왼쪽은 배치에 쓰는 재료(캐릭터·장비), 오른쪽은 결과물의 출구·입구(거래소·상점)다.
> **"모은 것을 쓰는" 콘텐츠는 슬롯과 같은 열에 있어야** 동선이 한 방향으로 유지된다.
> 3열 배치는 [방향 제안](../방향제안/2026-07-30-종합제안정리.md) 2장 참조.

**구현: 일감 [T-015](../../../일감/T-015-산업아이템클라적용.md)**

## 3. 데스크톱 환경 제약

바탕화면 상주 앱 특유의 문제들. 기획 단계에서 답이 있어야 한다.

| 제약 | 논점 |
| --- | --- |
| 멀티 모니터 | 어느 모니터에 뜨는가? 이동 가능한가? |
| 해상도·DPI 변경 | 위치·크기 보존 |
| 전체화면 앱 | 게임·영상 실행 중 자동 숨김? |
| 절전·최대 절전 | 복귀 시 경과 시간 정산 → [자원채취](../자원채취/README.md) 2.2 |
| 시작 프로그램 | 부팅 시 자동 실행 옵션 |
| 트레이 | 위젯 숨김 시 트레이 상주 |
| 리소스 사용량 | 상시 실행이므로 CPU·메모리 최소화가 필수 요건 |

> 상시 실행 앱에서 리소스 사용량은 **기능이 아니라 생존 조건**이다.
> "게임 때문에 노트북이 느려진다"는 즉시 삭제 사유다.

## 6. 결정 필요 (Open Questions)

1. 위젯의 크기·형태·배치 기본값은?
2. 항상 위(Always on top) 기본값은 켜짐인가 꺼짐인가?
3. 전체화면 앱 감지 시 자동 숨김을 넣는가?
4. 트레이 상주를 지원하는가?
5. 사운드를 넣는가? 넣으면 기본 꺼짐인가?
6. 목표 리소스 사용량 상한은? (CPU %, 메모리 MB)
7. **상시 스트립의 방향은?** 탑뷰 / 가로 / 세로 — 슬롯이 8개까지 늘어나므로
   세로안만 폭이 늘지 않는다. → [작업슬롯UI목업.html](작업슬롯UI목업.html)
8. **3열 패널을 동시에 띄우는가?** 레퍼런스는 동시 표시인데, 바탕화면 위젯에서
   그만한 창을 상주시키는 것은 P1(주의를 뺏지 않는다)과 부딪힌다.
   "필요할 때만 여는 큰 창"으로 둘지 정해야 한다.
   → [방향 제안](../방향제안/2026-07-30-종합제안정리.md) 2.3이 **"필요할 때 여는 큰 창"** 으로
   답을 냈다. 상주하는 것은 위젯뿐이다. 2.4가 이 전제 위에 서 있다.
9. **상점은 골드 상점인가 현금 상점인가?** 수익화가 미정이라
   슬롯 확장권을 무엇으로 파는지부터 비어 있다. 슬롯은 곧 재화 생성량의 배수이므로
   T-012(슬롯 곡선)·[거래](../거래/README.md) 경제와 함께 정해야 한다.
