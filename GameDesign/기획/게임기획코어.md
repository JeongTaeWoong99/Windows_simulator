# 게임기획코어 — Window Simulator

> 최종 업데이트: 2026-07-27
>
> **이 문서는 게임 기획의 최상위 문서이자 단일 진입점이다.**
> 게임 시스템·콘텐츠를 개발하는 모든 작업은 착수 전에 이 문서를 먼저 읽고,
> 해당 영역의 **상세 기획안**을 이어서 읽는다.
> 상세 수치·예외는 여기 쓰지 않는다. 여긴 **"무엇을 왜 만드는가"**만 담는다.

---

## 1. 정체성

| 항목 | 내용 |
| --- | --- |
| 한 줄 요약 | 바탕화면 위에서 자라는, 매일 바뀌는 1차 산업 방치 게임 |
| 장르 | 방치형 · 경영/수집 |
| 플랫폼 | Windows 데스크톱 (투명 창 위젯, 상시 동작) |
| 아트 | Pixel + Stylized (AI) |
| 승패 조건 | **없음.** 장기 목표는 자원 축적과 거래 경쟁 |
| 세션 형태 | 몰입형 세션이 아님. 업무·일상 중 바탕화면 한켠에서 진행 |

### 설계 원칙 (Design Pillars)

개발 중 판단이 갈릴 때 **이 4개를 기준으로 결정한다.**

| # | 원칙 | 의미 | 위반 예시 |
| --- | --- | --- | --- |
| P1 | **주의를 뺏지 않는다** | 플레이어의 주 작업은 게임이 아니다. 알림·모달·소리는 최소 | 필수 클릭 타이머, 화면 중앙 팝업 |
| P2 | **꺼져 있어도 자란다** | 오프라인 진행이 기본. 접속은 수확·정산을 위한 행위 | 접속 중에만 자원이 쌓임 |
| P3 | **하루 단위로 달라진다** | 요일 로테이션이 반복을 끊는 리듬 장치 | 아무 요일에나 모든 산업 채취 가능 |
| P4 | **모든 재화는 흐른다** | 획득물은 거래소를 통해 유저 간 순환. 계정에 고이지 않음 | 거래 불가 귀속 아이템의 남발 |

> ⚠️ P1~P4는 초기 컨셉에서 **도출한 제안**이다. 기획자 확정 전이며,
> 확정 시 이 표에서 ⚠️ 표기를 제거한다.

## 2. 코어 루프

```
자원 채취 → 보상 → 특성 + 아이템 → 재채취 → 거래
 (방치)     (희귀)    (성장)        (가속)   (축적·경쟁)
```

| 단계 | 하는 일 | 담당 시스템 |
| --- | --- | --- |
| 자원 채취 | 요일별 산업이 자동 진행되며 자원 획득 | [자원채취](자원채취/README.md) |
| 보상 | 자원·아이템 지급, 낮은 확률로 희귀 보상 | [자원채취](자원채취/README.md) · [아이템](아이템/README.md) |
| 성장 | 자원으로 특성·스킬 해금, 채취 효율 상승 | [특성](특성/README.md) · [아이템](아이템/README.md) |
| 재채취 | 강화된 상태로 루프 반복(가속) | [자원채취](자원채취/README.md) |
| 거래 | 잉여 자원을 화폐로 전환, 유저 간 경쟁 | [거래](거래/README.md) |

루프에 목표를 부여하는 **[퀘스트](퀘스트/README.md)** 와, 루프 전체의 속도를 규정하는
**[진행 및 성장](진행%20및%20성장/README.md)** 이 위 5단계를 가로지른다.

## 4. 콘텐츠 지도

### 1차 산업 5종 (확정)

게임의 채취 콘텐츠는 **농사 · 벌목 · 낚시 · 채굴 · 사냥** 5종이다.
각 산업은 서로 다른 고유 축을 하나씩 갖는다 — 스킨만 다른 반복이 되지 않게 하기 위함이다.

| 산업 | enum | 정체성 | 고유 축 | 상세 |
| --- | --- | --- | --- | --- |
| **농사** | `Farming` ✅ | 가장 느리고, 가장 많이 나온다 | 파종 선택 | [농사](자원채취/농사/README.md) |
| **벌목** | `Logging` ✅ | 베면 줄고, 시간이 지나면 돌아온다 | 자원 고갈·재생 | [벌목](자원채취/벌목/README.md) |
| **낚시** | `Fishing` ✅ | 무엇이 잡힐지 모른다 | 높은 변동성 | [낚시](자원채취/낚시/README.md) |
| **채굴** | `Mining` ✅ | 깊이 갈수록 좋아진다 | 누적 진행도 | [채굴](자원채취/채굴/README.md) |
| **사냥** | `Hunting` ❌ | 드물게 나오지만, 나오면 크다 | 성공/실패·고가치 | [사냥](자원채취/사냥/README.md) |

### 요일 로테이션

산업 5종 = 평일 5일. **1일 1산업 · 5일 1주기**가 기본 구조다.

| 구분 | 내용 |
| --- | --- |
| 평일 | 월~금에 5개 산업을 하나씩 배정 |
| 주말 | 평일 산업 중 **택 1** + **효율 ×2** |

> 배정 순서와 "비활성 산업을 정지시킬지 저효율로 돌릴지"는 미확정.
> → [자원채취](자원채취/README.md) 2.3

### 산업 = 아이템 분류 (코드값)

`GameData.ItemType` — 엑셀 `Enum.xlsx`가 원본. **코드에서 임의 추가 금지.**

| 값 | 의미 | 상태 |
| --- | --- | --- |
| `Farming = 1` | 농사 | ✅ |
| `Fishing = 2` | 낚시 | ✅ |
| `Mining = 3` | 채굴 (주석은 "채광" — 용어 통일 필요) | ✅ |
| `Logging = 4` | 벌목 | ✅ |
| `Misc = 5` | 기타 | ✅ |
| `Special = 6` | 특수 | ✅ |
| `Hunting = 7` | 사냥 | ❌ **미추가** |

> ⚠️ **`Hunting`은 아직 enum에 없다.** `Enum.xlsx`에 **값 7로 뒤에 붙여** 추가하고
> `Server/generate-tables.ps1`을 실행해야 한다. 중간에 끼워 넣으면 기존 `.bytes`·DB 값이 어긋난다.
> 절차: [사냥](자원채취/사냥/README.md) 6장

### 희귀도 (코드 확정값)

`GameData.ItemRarity` — `Common` → `Uncommon` → `Rare` → `Epic` → `Legendary` → `Mythic` 6단계.
등급별 색상까지 `Enum.xlsx`에 정의되어 있다. **드랍 확률은 미정.**

## 5. 확정 / 미확정 현황

**Agent는 "미확정" 항목을 임의로 결정하지 않는다.** 구현이 필요하면 사용자에게 확인한다.

| 영역 | 상태 | 비고 |
| --- | --- | --- |
| 코어 루프 5단계 | ✅ 확정 | |
| **1차 산업 5종 (농사·벌목·낚시·채굴·사냥)** | ✅ 확정 | `Hunting` enum 추가 필요 |
| 요일 로테이션 규칙(평일/주말 택1·×2) | ✅ 확정 | 배정 순서는 제안 단계 |
| `ItemType` / `ItemRarity` enum | ✅ 확정 | 엑셀이 원본. `Hunting`만 미반영 |
| 승패 조건 없음 · 방치 기반 | ✅ 확정 | |
| 산업별 고유 축(정체성) | ⚠️ 제안 | 산업 문서 5종에 기술 |
| 비활성 산업 처리(정지/저효율) | ❌ 미작성 | 주 1회 문제 — 우선 결정 필요 |
| 핵심 재미 (왜 계속 하는가) | ❌ 미작성 | **최우선** — 나머지 수치의 전제 |
| 진행·난이도 곡선 | ❌ 미작성 | 온보딩/페이스/후반 전부 |
| 퀘스트 상세 | ❌ 미작성 | 종류·주기·보상 |
| 채취 수치(속도·산출량·오프라인 상한) | ❌ 미작성 | |
| 드랍 확률 테이블 | ❌ 미작성 | |
| 거래소 경제(수수료·인플레·봇 방지) | ❌ 미작성 | BM 자체가 미정 |
| 수익화 모델 | ❌ 미정 | 아직 고려하지 않음 |
| 스토리 · 세계관 · 사운드 | ❌ 미작성 | |

## 6. 개발 시 지켜야 할 접점

기획을 코드로 옮길 때의 **고정 규칙**이다. 상세는 [`CLAUDE.md`](../../CLAUDE.md) 참조.

| 규칙 | 내용 |
| --- | --- |
| 데이터 원본 | 밸런스 수치·테이블은 코드 상수가 아니라 `GameDesign/Excel/*.xlsx`에 넣는다 |
| 생성물 금지 | `Server/GameData`, `Server/Shared/Data`, `GameDesign/DataLog`, Unity 미러는 직접 수정 금지 |
| 갱신 절차 | 엑셀 수정 후 `Server/generate-tables.ps1` 실행, 엑셀+생성물을 같은 커밋에 |
| 권위 | 자원·재화·거래는 **서버 권위**. 클라 계산 결과를 신뢰하지 않는다 (P4·거래 경쟁 때문) |
| 오프라인 진행 | 시간 경과 보상은 서버 시각 기준으로 정산한다 (P2) |
| 문서 이름 | 새 기획 문서·폴더는 **항상 한글**로 만든다. `Excel`·`DataLog`는 코드가 경로를 참조하므로 예외 |

## 7. 문서 지도

모든 기획 문서는 `GameDesign/기획/` 아래에 있다.

```
GameDesign/
├─ 기획/
│  ├─ 게임기획코어.md         ← 이 문서 (최상위 · 단일 진입점)
│  ├─ 기획평가.md             ← 설계 평가·리스크
│  ├─ 자원채취/README.md      ← 시스템별 상세 기획안
│  │  ├─ 농사/README.md       ← 1차 산업 5종
│  │  ├─ 벌목/README.md
│  │  ├─ 낚시/README.md
│  │  ├─ 채굴/README.md
│  │  └─ 사냥/README.md
│  ├─ 퀘스트/README.md
│  ├─ 특성/README.md
│  ├─ 아이템/README.md
│  ├─ 거래/README.md
│  ├─ 진행 및 성장/README.md
│  └─ 게임UI/README.md
├─ Excel/                    ← 게임 데이터 원본 (.xlsx)
└─ DataLog/                  ← 생성된 .bytes의 JSON 덤프 (리뷰용)
```

> `Excel`·`DataLog`는 `Server/ExcelGenerator/Program.cs`가 경로를 직접 참조하므로
> **이름을 바꾸지 않는다.** 기획 문서 폴더만 한글을 쓴다.

| 문서 | 역할 |
| --- | --- |
| **게임기획코어.md** (이 문서) | 최상위 진입점 — 정체성·루프·시스템 지도·확정 현황 |
| [`기획평가.md`](기획평가.md) | 기획 전체에 대한 평가·리스크 정리 |
| `<시스템>/README.md` | 시스템별 상세 기획안 |
| `자원채취/<산업>/README.md` | 1차 산업 5종별 기본 기획안 |
| [`../DataLog/*.json`](../DataLog/) | 생성된 `.bytes`의 JSON 덤프 (데이터 diff 리뷰용) |
