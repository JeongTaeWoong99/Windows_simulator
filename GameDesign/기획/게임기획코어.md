# 게임기획코어 — Window Simulator

> 최종 업데이트: 2026-07-29
>
> **이 문서는 게임 기획의 최상위 문서이자 단일 진입점이다.**
> 게임 시스템·콘텐츠를 개발하는 모든 작업은 착수 전에 이 문서를 먼저 읽고,
> 해당 영역의 **상세 기획안**을 이어서 읽는다.
> 상세 수치·예외는 여기 쓰지 않는다. 여긴 **"무엇을 왜 만드는가"**만 담는다.

## 1. 정체성

| 항목 | 내용 |
| --- | --- |
| 한 줄 요약 | 바탕화면 위에서 자라는, **캐릭터를 배치해 굴리는** 1차 산업 방치 게임 |
| 장르 | 방치형 · 경영/수집 |
| 플랫폼 | Windows 데스크톱 (투명 창 위젯, 상시 동작) |
| 아트 | Pixel + Stylized (AI) |
| 승패 조건 | **없음.** 장기 목표는 자원 축적과 거래 경쟁 |
| 세션 형태 | 몰입형 세션이 아님. 업무·일상 중 바탕화면 한켠에서 진행 |

### 설계 원칙 (Design Pillars)

개발 중 판단이 갈릴 때 **이 4개를 기준으로 결정한다.**

| # | 원칙 | 의미 | 위반 예시 |
| --- | --- | --- | --- |
| P1 | **주의를 뺏지 않는다** | 플레이어의 주 작업은 게임이 아니다. 알림·모달·소리는 최소 | 필수 클릭 타이머, 화면 중앙 팝업 |
| P2 | **꺼져 있어도 자란다** | 오프라인 진행이 기본. 접속은 수확·정산을 위한 행위 | 접속 중에만 자원이 쌓임 |
| P3 | ~~**하루 단위로 달라진다**~~ ❌ | **근거 폐기 — 재정의 필요** (아래) | — |
| P4 | **모든 재화는 흐른다** | 획득물은 거래소를 통해 유저 간 순환. 계정에 고이지 않음 | 거래 불가 귀속 아이템의 남발 |

> ⚠️ P1~P4는 초기 컨셉에서 **도출한 제안**이다. 기획자 확정 전이며,
> 확정 시 이 표에서 ⚠️ 표기를 제거한다.

#### ⚠️ P3가 근거를 잃었다 (2026-07-29)

P3는 **요일 로테이션**을 근거로 삼고 있었는데, 요일 시스템이 **폐지**됐다.
현재 게임에는 "하루 단위로 달라지는" 장치가 하나도 없다.

| 후보 | 성격 |
| --- | --- |
| 슬롯 재배치 | 플레이어가 원할 때 바꾼다 — **하루 주기가 아니다** |
| 캐릭터 육성 | 누적 성장 — 주기성 없음 |
| 일일 퀘스트 | 미작성 시스템. 여기에 리듬을 맡길 수는 있다 |

**P3를 되살릴지(다른 장치로), 아예 4개 원칙에서 뺄지 결정이 필요하다.**
그때까지 P3를 근거로 한 판단은 하지 않는다. → 5장 미확정

## 2. 코어 루프

```
캐릭터 배치 → 자원 채취 → 보상 → 캐릭터 + 특성 + 아이템 → 재배치 → 거래
  (슬롯)       (방치)      (희귀)        (성장)            (가속)   (축적·경쟁)
```

| 단계 | 하는 일 | 담당 시스템 |
| --- | --- | --- |
| **캐릭터 배치** | **작업슬롯에 산업을 지정하고 캐릭터를 배치** | [작업슬롯](작업슬롯/README.md) |
| 자원 채취 | **배치된 슬롯마다** 자동 진행되며 자원 획득 | [자원채취](자원채취/README.md) |
| 보상 | 자원·아이템 지급, 낮은 확률로 희귀 보상 | [자원채취](자원채취/README.md) · [아이템](아이템/README.md) |
| 성장 | 자원으로 특성·스킬 해금, 채취 효율 상승 | [특성](특성/README.md) · [아이템](아이템/README.md) |
| 재채취 | 강화된 상태로 루프 반복(가속) | [자원채취](자원채취/README.md) |
| 거래 | 잉여 자원을 화폐로 전환, 유저 간 경쟁 | [거래](거래/README.md) |

루프에 목표를 부여하는 **[퀘스트](퀘스트/README.md)** 와, 루프 전체의 속도를 규정하는
**[진행 및 성장](진행%20및%20성장/README.md)** 이 위 5단계를 가로지른다.

## 4. 콘텐츠 지도

### 1차 산업 5종 (확정)

게임의 채취 콘텐츠는 **농사 · 벌목 · 낚시 · 채굴 · 사냥** 5종이다.
각 산업은 서로 다른 고유 축을 하나씩 갖는다 — 스킨만 다른 반복이 되지 않게 하기 위함이다.

**플레이어는 작업슬롯마다 산업을 하나씩 지정한다.** 슬롯이 여러 개면 여러 산업이 동시에 돈다.
산업은 수치가 아니라 **플레이어가 느끼는 심리**로 구분한다 —
"무엇이 나오는가"가 아니라 **"왜 이걸 고르는가"** 가 산업의 정의다.

| 산업 | enum | **심리 정의** | 투자 비유 | 고유 메커니즘 | 상세 |
| --- | --- | --- | --- | --- | --- |
| **낚시** | `Fishing` ✅ | **확실한 도파민** | 소액 잦은 당첨 | 없음 ⚠️ | [낚시](자원채취/낚시/README.md) |
| **농사** | `Farming` ✅ | **안정적인 수익** | 적금 | 파종 선택 | [농사](자원채취/농사/README.md) |
| **채굴** | `Mining` ✅ | **확실한 스노우볼** | 복리 장기투자 | 깊이 누적 | [채굴](자원채취/채굴/README.md) |
| **벌목** | `Logging` ✅ | **절제하면 지속되는 수익** | 배당주 | 자원 고갈·재생 | [벌목](자원채취/벌목/README.md) |
| **사냥** | `Hunting` ❌ | **도전 · 목표 지향** ⚠️ | 적립식 목표 투자 | 사냥터 + **보스** | [사냥](자원채취/사냥/README.md) |

5개 산업이 **투자 성향 스펙트럼**을 이룬다. 슬롯이 늘어날수록
**"어떤 조합으로 채울까"** 가 이 게임의 질문이 된다.

> ⚠️ 주기·희귀도 분포·실패가 모두 전 산업 공통이 되면서,
> **수치로 남은 차별화 수단은 회당 산출 하나뿐**이다.
> 산업의 정체성은 이제 **고유 메커니즘**이 담당한다.
> → [자원채취](자원채취/README.md) 1-1

### 작업슬롯 — 배치로 굴린다 (2026-07-29 확정)

**플레이어는 작업슬롯(`WorkStationSlot`)을 여러 개 갖는다.**
슬롯마다 **산업 1개를 지정**하고 **캐릭터 1명을 배치**하면 그 슬롯이 독립적으로 돌아간다.

| 항목 | 내용 |
| --- | --- |
| 슬롯당 캐릭터 | **1명** (확정) |
| 슬롯당 산업 | 1개 (5종 중 선택) |
| 최대 슬롯 수 | **레벨 등으로 증가** — 증가 곡선 미정 |
| 동시 가동 | **슬롯 수만큼** |

> 이 결정으로 **"산업 택 1"과 "요일 로테이션"이 폐지**됐다.
> 슬롯이 늘어나면 결국 5종을 다 돌리게 되므로, 요일 보너스는 선택을 유도할 대상이 없어진다.
> → [작업슬롯](작업슬롯/README.md)

> ⚠️ **오프라인 정산 부담이 슬롯 수에 비례한다.** 이전 구조(산업 택 1)에서는
> 접속 한 번에 산업 하나만 계산하면 됐다. 이제 슬롯마다 계산한다.

### ~~요일 로테이션~~ — **폐지 (2026-07-29)**

요일별 보너스 산업 · 주말 택1 ×2를 **전부 없앤다.**
슬롯 구조에서는 플레이어가 여러 산업을 동시에 돌리므로 "오늘 무엇을 고를까"라는 질문이 성립하지 않는다.

**영향:** 설계 원칙 **P3가 근거를 잃었다**(1장 참조). 효율배수에서 요일 항이 빠진다.

### 오프라인 누적 — 감쇠 없음 (2026-07-29 변경)

**경과 시간 전체가 100%로 쌓인다.** 상한도 감쇠도 없다.

| 경과 | 효율 |
| --- | --- |
| 전 구간 | **100%** |

> ~~24시간 이후 -50%~~ **폐지.** 접속 시점과 무관하게 같은 규칙이 적용되므로
> "언제 접속해야 이득인가"를 계산할 필요가 없다 — P1·P2에 가장 단순하게 부합한다.
>
> ⚠️ **대신 무한 누적된다.** 한 달을 비워도 그대로 쌓이므로,
> 장기 미접속자가 복귀할 때 대량 재화가 한 번에 유입된다.
> 슬롯 수까지 곱해지므로 **[거래](거래/README.md) 경제 설계에서 반드시 다시 볼 것.**
> → [자원채취](자원채취/README.md) 2.2

### 보상 구조 — 기본 9 : 특별 1

**실패(허탕)는 없다.** 30초마다 반드시 무언가 나온다.

| 층 | 비율 | 산업 간 차이 |
| --- | --- | --- |
| **기본보상** | 90% | 희귀도 **분포는 전 산업 동일**. 나오는 **아이템만** 다르다 |
| **특별보상** | 10% | 산업마다 **완전히 다른** 산출물 (대물·보석·변종 작물 …) |
| **공통 보상** | 별도 롤 | 티켓·고유 아이템. 전 산업 동일 확률 |

> 기본보상 구조가 공통이므로 **산업의 개성은 특별보상 10%에 몰려 있다.**
> → [자원채취](자원채취/README.md) 2.4

### 보스 (신규 · 상세 미정)

**사냥의 특별보상에서만 보스 티켓이 나온다.** 모아서 플레이어가 원할 때 도전한다.

- **채취 루프 바깥으로 나가는 유일한 통로**이며, R3(후반 목표 부재)에 대한 첫 답이다.
- 도전 시점은 플레이어가 정하고, 실시간 조작을 요구하지 않는다 (P1).
- 상세는 미정. 구체화되면 별도 시스템 문서로 분리한다. → [사냥](자원채취/사냥/README.md) 4장

### 산업 = 아이템 분류 (코드값)

`GameData.ItemType` — 엑셀 `Enum.xlsx`가 원본. **코드에서 임의 추가 금지.**

| 값 | 의미 | 상태 |
| --- | --- | --- |
| `Farming = 1` | 농사 | ✅ |
| `Fishing = 2` | 낚시 | ✅ |
| `Mining = 3` | 채굴 (주석은 "채광" — 용어 통일 필요) | ✅ |
| `Logging = 4` | 벌목 | ✅ |
| `Hunting = 5` | 사냥 | ✅ **추가됨 (2026-07-28)** |
| `Misc = 6` | 기타 | ✅ |
| `Special = 7` | 특수 | ✅ |

> `Hunting`이 **값 5로 중간에 삽입**되면서 `Misc`·`Special`이 한 칸씩 밀렸다.
> 1차 산업 5종이 1~5로 연속돼 읽기는 좋아졌고, 당시 `ItemType` 정수를 저장한 DB 컬럼이
> 없어 실제 피해는 없었다.
> ⚠️ **다만 앞으로는 뒤에 붙인다.** 운영 데이터가 쌓인 뒤 중간 삽입하면
> 기존 `.bytes`·DB 값이 조용히 어긋난다. `DataLog`의 JSON은 enum을 **이름**으로 덤프하므로
> 이 종류의 변경을 diff로 잡아내지 못한다.

### 희귀도 (코드 확정값)

`GameData.ItemRarity` — `Common` → `Uncommon` → `Rare` → `Epic` → `Legendary` → `Mythic` 6단계.
등급별 색상까지 `Enum.xlsx`에 정의되어 있다. **드랍 확률은 미정.**

**희귀도가 아이템 분류의 유일한 등급 축이다.** 개체 변량(크기 등 개체별 수치 롤)은 두지 않는다.
"더 큰 것 / 더 좋은 것"은 희귀도가 높은 **별도 `ItemTID`** 로 만든다.
예: `붕어(Common)` / `월척 붕어(Rare)` / `대물 붕어(Epic)`.

> 이 결정으로 모든 아이템이 정상 스택되고, 오프라인 정산이 단순 집계로 끝난다.
> **기본보상의 희귀도 분포는 전 산업 동일**하며 `RarityWeightTable` 한 곳에서 관리한다.
> → [자원채취](자원채취/README.md) 2.4

## 6. 개발 시 지켜야 할 접점

기획을 코드로 옮길 때의 **고정 규칙**이다. 상세는 [`CLAUDE.md`](../../CLAUDE.md) 참조.

| 규칙 | 내용 |
| --- | --- |
| 데이터 원본 | 밸런스 수치·테이블은 코드 상수가 아니라 `GameDesign/Excel/*.xlsx`에 넣는다 |
| 생성물 금지 | `Server/GameData`, `Server/Shared/Data`, `GameDesign/DataLog`, Unity 미러는 직접 수정 금지 |
| 갱신 절차 | 엑셀 수정 후 `GameDesign/generate-tables.ps1` 실행, 엑셀+생성물을 같은 커밋에 |
| 권위 | 자원·재화·거래는 **서버 권위**. 클라 계산 결과를 신뢰하지 않는다 (P4·거래 경쟁 때문) |
| 오프라인 진행 | 시간 경과 보상은 서버 시각 기준으로 정산한다 (P2) |
| 문서 이름 | 새 기획 문서·폴더는 **항상 한글**로 만든다. `Excel`·`DataLog`는 코드가 경로를 참조하므로 예외 |

## 7. 문서 지도

모든 기획 문서는 `GameDesign/기획/` 아래에 있다.

```
GameDesign/
├─ 기획/
│  ├─ 게임기획코어.md         ← 이 문서 (최상위 · 단일 진입점)
│  ├─ 기획평가.md             ← 설계 평가·리스크
│  ├─ 작업슬롯/README.md      ← 배치 구조 (채취의 전제)
│  ├─ 자원채취/README.md      ← 시스템별 상세 기획안
│  │  ├─ 농사/README.md       ← 1차 산업 5종
│  │  ├─ 벌목/README.md
│  │  ├─ 낚시/README.md
│  │  ├─ 채굴/README.md
│  │  └─ 사냥/README.md
│  ├─ 퀘스트/README.md
│  ├─ 특성/README.md
│  ├─ 아이템/README.md
│  ├─ 거래/README.md
│  ├─ 진행 및 성장/README.md
│  └─ 게임UI/README.md
├─ Excel/                    ← 게임 데이터 원본 (.xlsx)
└─ DataLog/                  ← 생성된 .bytes의 JSON 덤프 (리뷰용)
```

> `Excel`·`DataLog`는 `Server/ExcelGenerator/Program.cs`가 경로를 직접 참조하므로
> **이름을 바꾸지 않는다.** 기획 문서 폴더만 한글을 쓴다.

| 문서 | 역할 |
| --- | --- |
| **게임기획코어.md** (이 문서) | 최상위 진입점 — 정체성·루프·시스템 지도·확정 현황 |
| [`기획평가.md`](기획평가.md) | 기획 전체에 대한 평가·리스크 정리 |
| `<시스템>/README.md` | 시스템별 상세 기획안 |
| `자원채취/<산업>/README.md` | 1차 산업 5종별 기본 기획안 |
| [`../DataLog/*.json`](../DataLog/) | 생성된 `.bytes`의 JSON 덤프 (데이터 diff 리뷰용) |
