# 00. 작업슬롯 (WorkStationSlot)

> 상위 문서: [`게임기획코어.md`](../게임기획코어.md)
> 최종 업데이트: 2026-07-29 · 상태: **골격 확정 · 수치 미정**

채취가 시작되는 지점이다. **플레이어는 슬롯에 산업을 지정하고 캐릭터를 배치**하며,
배치된 슬롯 하나하나가 독립적으로 [자원채취](../자원채취/README.md) 루프를 돌린다.

이 문서는 **"무엇을 얼마나 굴릴 수 있는가"** 를 정한다.
그 슬롯이 무엇을 산출하는지는 [자원채취](../자원채취/README.md)가 담당한다.

---

## 1. 확정 사항

| # | 항목 | 확정 내용 |
| --- | --- | --- |
| 1 | **슬롯당 캐릭터** | **1명.** 여러 명을 한 슬롯에 넣지 않는다 |
| 2 | **슬롯당 산업** | **1개.** 5종 중 선택 |
| 3 | **동시 가동** | **슬롯 수만큼.** 산업 택1이 폐지됐다 |
| 4 | **최대 슬롯 수** | 레벨 등으로 **증가한다** (곡선 미정) |
| 5 | **채취 판정 주체** | **서버.** 클라이언트는 결과를 받기만 한다 |
| 6 | **접속 중 알림** | **서버가 실시간으로 밀어 준다** (푸시) |
| 7 | **요일 로테이션** | **폐지.** 효율배수에서 요일 항이 빠진다 |
| 8 | **오프라인 감쇠** | **없음.** 경과 시간 전체가 100%로 쌓인다 |

---

## 2. 구조

```
Player
 └─ WorkStationSlot[]        ← 최대 개수는 레벨 등으로 증가
      ├─ SlotIndex           슬롯 번호 (0-based)
      ├─ Industry            농사 · 벌목 · 낚시 · 채굴 · 사냥 중 1개
      ├─ Character           배치된 캐릭터 1명 (비어 있을 수 있다)
      └─ LastTickAt          마지막 정산 시각 ← 진행도의 단일 원본
```

**슬롯은 "산업 + 캐릭터 + 마지막 정산 시각"의 묶음이다.**
비어 있는(캐릭터 미배치) 슬롯은 돌지 않는다.

### 왜 `LastTickAt` 하나로 진행도를 표현하는가

방치형의 진행은 **시각의 함수**다. `누적량 = f(지금 - 마지막 정산 시각)`이면
온라인·오프라인을 구분할 필요가 없다 — **같은 계산이 양쪽을 모두 처리한다.**

진행도를 별도 카운터로 들고 있으면 온라인용/오프라인용 두 경로가 생기고,
둘이 어긋나는 순간 재화가 새거나 사라진다.

---

## 3. 채취 판정 — 서버 권위

**클라이언트는 "캤습니다"라고 신고하지 않는다.** 재화가 생성되는 지점이므로
서버가 시각을 기준으로 계산하고 결과만 내려 준다 (게임기획코어 P4).

```
정산(slot, now):
    경과      = now - slot.LastTickAt
    판정 횟수 = floor(경과 / 30초)
    산출      = 판정 횟수 × 회당산출 × 효율배수
    slot.LastTickAt += 판정 횟수 × 30초     ← 나머지 시간은 다음으로 이월
```

| 항목 | 값 |
| --- | --- |
| 채취주기 | **30초** (전 산업 공통 · 확정) |
| 효율배수 | **캐릭터 스탯** × 특성패시브 × 액티브부스트 |
| 오프라인 감쇠 | **없음** — 경과 시간 전체가 100% (2026-07-29 변경) |

> **요일배수가 빠졌다.** 이전 공식의 `요일배수` 항은 폐지됐고,
> 그 자리를 **캐릭터 스탯**이 대신한다. → 5장

### 3.1 정산 시점

같은 함수를 아래 시점마다 부른다. **온라인/오프라인 코드가 갈리지 않는다.**

| 시점 | 이유 |
| --- | --- |
| 로그인 | 비운 동안의 누적을 정산 |
| 슬롯 변경 (산업·캐릭터) | **변경 전 구간을 이전 설정으로 정산**해야 한다 |
| 상태 조회 | 플레이어가 위젯을 열었을 때 |
| 로그아웃 | 확정 저장 |
| **주기 푸시** | 접속 중 실시간 알림 (3.2) |

### 3.2 접속 중 실시간 푸시

**접속해 있으면 30초마다 "잡혔다"가 서버에서 온다.**

| 항목 | 내용 |
| --- | --- |
| 주기 | 채취주기와 같은 **30초** |
| 대상 | **접속 중이고 캐릭터가 배치된 슬롯**만 |
| 내용 | 이번에 나온 `ItemTID`와 개수 |

> ⚠️ **초당 수십 번 도는 루프(30fps 등)를 두지 않는다.**
> 판정 간격이 30초인데 초당 30번 깨우면 900틱 중 899틱이 헛돈다.
> 게다가 게임 로직 스레드가 단일이라 채취 계산이 패킷 처리를 밀어낸다.
> **연출은 클라이언트가 로컬 타이머로 만들고, 값의 진실은 서버가 정한다.**

## 4. 슬롯 확장

**최대 슬롯 수는 늘어난다.** 늘리는 수단과 곡선은 미정이다.

| 논점 | 상태 |
| --- | --- |
| 시작 슬롯 수 | ❌ 미정 |
| 증가 수단 (레벨? 재화? 퀘스트?) | ❌ 미정 — 레벨이 유력 |
| 상한 | ❌ 미정 |

> ⚠️ **슬롯 수가 곧 재화 생성량의 배수다.**
> 슬롯이 2배가 되면 경제에 유입되는 총량도 2배다. 이 곡선은
> **[거래](../거래/README.md)의 경제 설계와 반드시 함께** 정해야 한다 (P4).
> 슬롯을 먼저 풀어 놓고 경제를 나중에 맞추면 되돌릴 수 없다.

---

## 5. 캐릭터 (미작성 · 전제 시스템)

슬롯에 배치되는 주체다. **이 시스템이 정해지지 않으면 효율배수를 계산할 수 없다.**

| 논점 | 상태 |
| --- | --- |
| 스탯 구성 | ❌ 미정 |
| 스탯 → 효율 기여식 | ❌ 미정 — 채취 산출량에 직접 곱해진다 |
| 육성 방식 | ❌ 미정 |
| 획득 경로 (가챠?) | ❌ 미정 — 기존 [가챠 코드](../../../Server/WSGameServer/Gacha/)가 있다 |
| 산업 적성 유무 | ❌ 미정 — "낚시 잘하는 캐릭터"를 둘 것인가 |

> **산업 적성을 두면 배치가 퍼즐이 된다.** 슬롯 3개에 캐릭터 5명이면
> "누구를 어디에" 가 실제 선택이 된다. 적성이 없으면 스탯 높은 순으로 채우면 끝이라
> 배치에 의사결정이 없다. → 6장

---

## 6. 결정 필요 (Open Questions)

1. **캐릭터에 산업 적성이 있는가?** 없으면 배치가 "스탯 높은 순 정렬"로 끝난다
2. **시작 슬롯 수와 증가 곡선은?** (4장 — 경제 총량과 직결)
3. **빈 슬롯도 굴러가는가?** (캐릭터 없이 산업만 지정 — 현재는 "돌지 않는다"로 가정)
4. **슬롯 변경에 제약이 있는가?** 쿨타임·비용 없이 자유롭게 바꾸는가
5. **설계 원칙 P3를 무엇으로 되살리는가?** 요일이 사라져 "하루 단위 리듬"이 없다
   → [게임기획코어](../게임기획코어.md) 1장
6. 오프라인 정산이 슬롯 수에 비례해 무거워진다 — 슬롯 상한이 곧 정산 비용 상한이다

> 해소됨:
> - **슬롯당 캐릭터 수** — 1명으로 확정
> - **동시 가동** — 슬롯 수만큼. 산업 택1 폐지
> - **판정 주체** — 서버 권위 확정
> - **실시간 푸시** — 필요함으로 확정 (30초 주기)
> - **요일 로테이션** — 폐지 확정

## 7. 서버 / 클라이언트 책임

| 책임 | 주체 | 이유 |
| --- | --- | --- |
| 경과 시간 산정 · 판정 횟수 | **서버** | 클라 시계 조작 방지 |
| 드롭 추첨 | **서버** | 재화 생성 지점 (P4) |
| 슬롯 상태 저장 (`LastTickAt` 포함) | **서버** (DB) | 진행도의 단일 원본 |
| 30초 주기 푸시 | **서버** | 접속 중 알림 |
| 채취 연출 · 카운트다운 | 클라이언트 | `LastTickAt` + 주기로 로컬 계산. 값은 서버가 교정 |

> **클라이언트의 카운트다운이 서버와 어긋나도 문제되지 않는다.**
> 연출일 뿐이고, 다음 푸시·조회에서 서버 값으로 맞춰진다.
