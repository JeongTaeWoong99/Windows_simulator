# 04. 아이템 (Item)

> 상위 문서: [`게임기획코어.md`](../게임기획코어.md)
> 최종 업데이트: 2026-07-27 · 상태: **데이터 스키마 존재 · 분류 정책 미정**

**유일하게 실제 구현이 시작된 영역**이다. `ItemTable`이 엑셀→`.bytes` 파이프라인으로 이미 돌고 있다.

---

## 1. 확정 사항

### 1.1 코드에 존재하는 스키마

`Server/GameData/Tables/ItemTable.cs` (엑셀 `Item.xlsx`에서 생성):

| 컬럼 | 타입 | 비고 |
| --- | --- | --- |
| `ItemTID` | `int` | 아이템 고유 ID |
| `Name` | `string` | |
| `ItemType` | `ItemType` | 산업 분류 |
| `ItemRarity` | `ItemRarity` | 희귀도 |
| `MaxStack` | `int` | 스택 상한 |
| `Desciption` | `string` | **오타** — `Description`이 맞다 |

### 1.2 확정 enum

- `ItemType` — `Farming` / `Fishing` / `Mining` / `Logging` / `Misc` / `Special`
- `ItemRarity` — `Common` / `Uncommon` / `Rare` / `Epic` / `Legendary` / `Mythic` (색상 정의 포함)

### 1.3 기획 확정 내용

- 채취로 얻은 아이템으로 **특성·스킬을 획득·성장**시킨다.
- 모든 아이템은 거래소 등록이 가능하다.

### 1.4 채취 보상 3층 구조 (2026-07-27 확정)

채취 판정 1회가 만들어내는 아이템은 세 경로에서 나온다. → [자원채취](../자원채취/README.md) 2.4

| 층 | 비율 | 아이템 성격 | 테이블 |
| --- | --- | --- | --- |
| **기본보상** | 90% | 산업 기본 자원. **희귀도 확률은 전 산업 동일** | `RarityWeightTable` + `<산업>BasicTable` |
| **특별보상** | 10% | 산업 고유 산출물 (대물·보석·변종 작물 …) + **보스 티켓**(사냥 전용) | `<산업>SpecialTable` |
| **공통 보상** | 별도 롤 | **가챠 티켓 · 고유 아이템** | `CommonRewardTable` |

- **티켓·고유 아이템은 전 산업 공통이다.** 특정 산업에 몰아주지 않는다.
  기본/특별과 무관하게 **매 판정마다 별도로 롤**한다.
- 산업별 테이블에 중복 정의하면 확률 조정 시 5곳을 고쳐야 하고 산업 간 편차가 생긴다.

> **희귀도가 아이템 기획에 미치는 영향이 커졌다.**
> 기본보상은 `(희귀도 → 아이템)` 매핑이므로, **각 산업마다 희귀도 6단계를 전부 채울
> 아이템이 필요하다.** 최소 `5산업 × 6등급 = 30종`이 기본 자원으로 존재해야 한다.

## 2. 아이템 역할 분류 (제안)

> ⚠️ 제안이다. 현재 `ItemType`은 **산업 출처**만 나타내고 **용도**를 나타내지 않는다.

| 역할 | 설명 | 예 |
| --- | --- | --- |
| **재료** | 특성 해금·레벨업에 소모 | 산업별 기본 자원 |
| **고유 아이템** | 수집·거래 대상. 소모되지 않음 | 희귀 산출물 |
| **티켓** | 가챠·이벤트 재화 | 가챠 티켓 |
| **입장권** | 콘텐츠 도전에 소모 | **보스 티켓** (사냥 특별보상) |
| **화폐** | 거래소 결제 수단 | 돈 |

> **보스 티켓은 가챠 티켓과 다른 축이다.** 가챠는 확률 뽑기, 보스 티켓은 **콘텐츠 입장권**이다.
> `ItemUsage`를 도입한다면 이 둘을 구분해야 한다. 거래 가능 여부도 갈릴 수 있다
> (보스 티켓이 거래되면 사냥을 안 하고도 보스에 갈 수 있다 — 의도인지 확인 필요).

> 현재 스키마에는 이 축이 없다. `ItemUsage` 컬럼을 추가하거나, `Misc`/`Special`을 용도 표기로
> 전용하는 두 가지 방법이 있다. **전자를 권장** — 후자는 "출처"와 "용도"를 한 컬럼에 섞는다.

### 스택 정책

`MaxStack`이 이미 존재한다. 역할별 기준을 세운다.

| 역할 | 스택 | 이유 |
| --- | --- | --- |
| 재료 | 큰 값 (1,000~) | 방치로 대량 축적됨 |
| 고유 아이템 | 1 | 개체 식별 필요 시 |
| 티켓 | 중간 | |
| 화폐 | 스택 개념 없음 (별도 필드) | |

### ✅ 개체 변량 없음 (2026-07-27 확정)

**모든 아이템은 개체별 수치 롤을 갖지 않는다.** 같은 `ItemTID`면 완전히 동일하다.

- 한때 검토됐던 물고기 크기(개체마다 다른 수치)는 **폐기**됐다.
- 등급 차이는 **희귀도가 다른 별도 `ItemTID`** 로 표현한다.
  예: `붕어(Common)` / `월척 붕어(Rare)` / `대물 붕어(Epic)`
- 따라서 **모든 아이템이 `MaxStack`대로 정상 스택**된다. 개체 인스턴스 테이블이 필요 없다.

| 얻은 것 | 내용 |
| --- | --- |
| 인벤토리 | 스택 충돌 없음. 행 수가 아이템 종류 수로 제한됨 |
| 정산 | `Dictionary<ItemTID, count>` 집계로 끝남 |
| 거래소 | 같은 아이템은 같은 값. 개체별 시세가 없어 UI·검색이 단순 |

> 대가로 **아이템 종류 수가 늘어난다.** 어종 × 등급만큼 `Item.xlsx` 행이 생긴다.
> 같은 자원의 등급 변형을 몇 단계로 둘지는 산업 문서에서 정한다.

## 3. 인벤토리 (제안)

| 논점 | 선택지 | 권장 |
| --- | --- | --- |
| 용량 제한 | 있음 / 없음 | **없음 또는 매우 큼** — 방치 중 가득 차면 P2 위반 |
| 가득 찼을 때 | 채취 중단 / 초과분 소멸 / 자동 판매 | 용량을 두려면 **자동 판매** |
| 정렬·필터 | 산업별 / 희귀도별 | 팝업 UI에서 제공 |

> 방치형에서 "인벤토리가 차서 채취가 멈춰 있었다"는 최악의 경험이다.
> 용량 제한을 넣을 거면 반드시 넘침 처리가 함께 있어야 한다.

## 4. 가챠 · 티켓

- 티켓은 채취 중 **낮은 확률**로 획득한다.
- 가챠 결과물의 정체 **미정** — 특성? 고유 아이템? 외형?
- 확률 공개 여부 **미정**. 수익화와 연결되면 법적 고지 의무가 생길 수 있다.
  → [거래](../거래/README.md) / BM 미정 상태와 함께 결정.

## 5. 데이터 설계

기존 `Item.xlsx`를 확장한다. **컬럼 추가는 엑셀에서만** 하고 `Server/generate-tables.ps1`을 돌린다.

| 항목 | 조치 |
| --- | --- |
| `Desciption` 오타 | `Description`으로 수정 (엑셀 헤더 변경 → 재생성) |
| `ItemUsage` 컬럼 | 역할 분류 도입 시 추가 |
| 거래 가능 여부 | `Tradable` bool 컬럼 (P4 예외 관리) |
| 기준 가격 | `BasePrice` — 거래소 하한가·자동판매가 산정용 |
| 아이콘 키 | `IconKey` — 클라 리소스 매핑 |

현재 `Item.xlsx` 데이터는 `A`~`F` / `Military1` 같은 **테스트 더미**다. 실 데이터로 교체 필요.
