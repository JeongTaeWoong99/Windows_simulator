# Settings 규칙

> 최종 업데이트: 2026-08-12 · 대상: `Assets/Scripts_Client/Settings/`

**창 설정을 `PlayerPrefs`에 저장하고 되읽는 곳.** 키 상수와 읽기·쓰기 헬퍼만 둔다 —
설정을 **적용**하는 일은 [`Managers/WindowManager`](<../Managers/Managers 규칙.md>)가 한다.

---

## 1. ⚠️ 인스펙터 값의 의미가 바뀐다

**이걸 모르면 "인스펙터를 고쳤는데 반영이 안 된다"로 한참 헤맨다.**

`WindowManager`의 `setStart*` 필드는 **"저장된 값이 없을 때 쓰는 공장 초기값"** 이다.
한 번이라도 사용자가 토글·드롭다운을 만지면 그 값이 저장되고, **다음 실행부터는 저장값이 이긴다.**

```
첫 실행       → 인스펙터의 setStart* 값 사용
사용자가 조작 → PlayerPrefs에 저장
다음 실행     → 저장값 사용 (인스펙터를 고쳐도 무시된다)
```

> 인스펙터 값을 다시 시험하려면 저장을 지워야 한다 — `PlayerPrefs.DeleteAll()` 또는
> 해당 키만 삭제. 레지스트리에 남으므로 빌드를 지워도 초기화되지 않는다.

---

## 2. 왜 저장하는가

이건 **바탕화면에 상주하는 앱**이다. "항상 위"·"크기"·"위치"는 게임 옵션이 아니라
**사용자의 작업 환경**이다. 껐다 켤 때마다 되돌아가면 상주 앱으로 쓸 수 없다.

## 3. 왜 즉시 저장하는가

값이 **실제로 바뀔 때만** 그 자리에서 `PlayerPrefs.Save()`를 부른다.

Unity는 **정상 종료 시에만** 자동 저장하는데, 상주 앱은 작업 관리자로 끄거나 절전에 들어가는 일이
흔해서 그것만 믿을 수 없다.

> 대신 **같은 값은 다시 쓰지 않는다.** 시작 시 불러온 값을 그대로 다시 적용하는 경로가 있어
> (`InitializeWindow`), 거르지 않으면 실행할 때마다 불필요한 디스크 기록이 생긴다.

---

## 4. 키 규약

| 규칙 | 내용 |
|------|------|
| **접두사를 붙인다** | `Window.` — 다른 설정(사운드 등)이 생겨도 섞이지 않는다 |
| **키는 `const`로 한곳에** | 문자열을 호출부에 흩뿌리면 오타가 조용히 새 키를 만든다 |
| **`bool`은 0/1 `int`로** | `PlayerPrefs`에 `bool` 타입이 없다 (`SaveBool`/`LoadBool`이 감싼다) |

### 두 개의 위치 축을 헷갈리지 않는다

| 키 | 무엇 | 값 |
|---|---|---|
| `Window.Anchor` | **창**을 데스크톱 어디에 두는가 | 9분할 (`ScreenAnchor`) |
| `Widget.Position` | **위젯**이 창 안 어느 칸에 놓이는가 | 6칸 |

이름이 비슷하지만 다른 축이다. 그래서 `Widget.Position`만 접두사가 다르다.
