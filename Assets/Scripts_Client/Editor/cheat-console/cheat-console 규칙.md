## 왜 에디터 창인가

치트는 **개발 중 상태를 빨리 만드는 도구**라, 게임 화면에 섞지 않고 인스펙터처럼 도킹해 둔다.
에디터 전용 폴더라 빌드에는 들어가지 않는다 — exe(개발 빌드)에서 치트가 필요해지면 게임 안 패널을 따로 만든다.

- **칸은 접지 않는다.** 전부 펼쳐 두고 칸마다 색(왼쪽 띠 + 옅은 머리 바탕)으로 가른다 — 접었다 펴는 게 불편하다는 요청(2026-09-17).
- TID는 숫자 대신 **테이블 목록에서 고른다**(검색어로 거른 `이름 (TID)`). 테이블은 플레이 중 적재되므로,
  플레이 전에는 TID를 숫자로 직접 받는다.
- 경험치는 캐릭터 **종류(TID)가 아니라 보유 개체(CharacterId)** 에 준다 — 목록은 `PlayerDataModel.Characters`다.
- 결과 상태(재화·인벤·캐릭터·슬롯)는 게임 화면이 기존 동기화 패킷으로 받는다. 창의 로그는 `S_CheatResponse.Message` 한 줄뿐이다.
- ⚠️ **자원 지급은 서버 저장까지만 되고 화면은 안 바뀐다**(2026-09-17 서버 로그 확인). 서버 `GainItem`이 인벤토리를 밀어주지 않는다 — 가챠·판매·정산은 각자 응답에 변경분을 싣는데 치트 경로에는 없다. 재로그인하면 보인다. 서버 몫(T-060 · 이슈 #26).
- ⚠️ **정산 치트는 늘 `정산 슬롯 0개`다.** 쌓인 진행도만 정산하는데 서버 스케줄러가 0.1초마다 먼저 정산한다 — 판정을 앞당기지 않는다. 서버 몫(T-060).

## 도구 줄 — 이 프로젝트 전용 버튼은 여기 한 곳

**메인 툴바에 올리는 프로젝트 전용 버튼은 '치트' 하나뿐이다.** 씬 복사·서버 콘솔은 창 맨 위 도구 줄에 둔다 — 중복으로 두지 않는다.

```
                         [●][⧉ 오리지널 씬 복사] ┃ [▤ 서버 콘솔]
● 서버 › ● 클라 › ○ 로그인                  로그인 미완료
```

- **도구는 전부 오른쪽에 모은다.** 새 도구는 `DrawToolRow`에서 `DrawToolGap()` 다음에 `Draw<이름>Tool()`을 덧붙인다 — 붙은 버튼은 한 도구, 어두운 세로 구분선(`ToolDividerColor`) 너머는 다른 도구다.
- `[●]`/`[○]` — 씬 복사 **자동 알림** 켜기·끄기(`SceneCopySettings.AutoCheckEnabled`). 바로 뒤 버튼은 **복사**다. 누르는 곳이 둘이다.
- 이유: 메인 툴바에 새로 올린 요소는 기존 사용자에게 **숨겨진 채로** 들어와(→ `Editor 규칙.md`) ON/OFF를 보여 줄 수 없었고,
  IMGUI 창에서는 표시를 마음대로 그릴 수 있다. 프로젝트 전용 버튼이 툴바를 늘리지 않는 것도 함께 얻는다.
- 메모리 표시(`Common/memory-meter`)는 상시 수치를 보여야 해서 메인 툴바에 그대로 둔다.

## 안전장치

### 준비 단계 — 서버 › 클라 › 로그인

실제 작업 순서 그대로다. **클라는 Play를 누를 때 한 번만 서버에 접속하므로** 서버가 먼저 떠 있어야 한다.
모든 치트는 세 단계가 다 끝나야 보낼 수 있다.

| 단계 | 완료 판정 |
|---|---|
| 서버 | 포트 `10050`이 LISTENING (`IPGlobalProperties.GetActiveTcpListeners`) — 서버 콘솔로 켰든 터미널·IDE로 켰든 잡힌다 |
| 클라 | Play 중 + 포트 `10050`으로 맺은 TCP 연결이 Established |
| 로그인 | `PlayerDataModel.IsLoggedIn` |

- 창 맨 위 줄에 `● 서버 › ○ 클라 › ○ 로그인` · `클라 · 로그인 미완료`로 늘 보인다(0.5초마다 확인).
- **버튼은 비활성화하지 않고, 누른 순간 검사해 빠진 단계를 한 팝업으로 알린다** — "클라 · 로그인이 완료되지 않았다." + 단계별 ✓/✗.
  팝업 버튼은 가장 앞의 빠진 단계를 푼다: 서버 → `[서버 콘솔 열기]`, 클라(Play 전) → `[Play 시작]`.
  (예외: 해금 목록에서 이미 열린 줄의 [열기]만 끈다 — 이유가 줄에 `[열림]`으로 보인다.)
- ⚠️ **클라 판정은 OS 연결 목록이다.** `NetworkManager`가 연결 상태를 드러내지 않고 그 파일은 서버 담당 폴더라 손대지 않았다.
  더미 클라이언트가 같은 서버에 붙어 있으면 에디터가 끊겨도 '연결됨'으로 보인다 — 그 경우는 아래 시간 초과가 잡는다.
- `ServerRunner.IsRunning`(PID 추적)을 쓰지 않는 이유 — 서버 콘솔로 켠 서버만 알아서, 터미널에서 켠 서버를 '꺼짐'으로 본다.

### 보낸 뒤

| 조건 | 팝업 |
|---|---|
| 3초 안에 응답 없음 | `[서버 콘솔 열기]` `[닫기]` |
| `NoPermission` 응답 | admin_level 안내 |

- 대기 중인 요청이 한꺼번에 초과되면 팝업은 하나로 합친다. 에디터 일시정지 중에는 응답이 큐에 묶이므로 시계를 멈추고, 플레이를 나가면 대기 요청을 버린다.
- 그 밖의 거절(`InvalidCheatArgs` 등)은 팝업 없이 로그에 빨간 줄로만 남긴다 — 반복 테스트 중 팝업이 쌓이지 않게.

## ⚠️ 팝업은 OnGUI 밖에서 띄운다

버튼 처리(OnGUI) 안에서 `DisplayDialog`를 띄우면 레이아웃 그룹이 어긋나 오류가 난다.
창의 버튼은 전부 `Request(...)` → `EditorApplication.delayCall`로 **다음 틱에** `CheatSender.Send`를 부른다.
새 버튼도 `CheatSender.Send`를 직접 부르지 말고 `Request`를 쓴다.

## 치트 추가하기

서버가 `ECheatCommand`에 명령을 추가하면(뒤에만 붙는다):

1. `CheatWindow`에 `Draw<이름>()` 칸을 만들고 `OnGUI`의 칸 목록에 넣는다. 본문은 `BeginSection(제목, 색)` ~ `EndSection(색)`으로 감싸고, 색은 `<이름>Accent`로 하나 더 둔다(기존 색과 겹치지 않게).
2. 입력값은 `[SerializeField]`로 둔다 — 플레이 진입(도메인 리로드)에도 남게.
3. TID를 받으면 `TidPicker`를, 보유 개체를 받으면 `CheatGuard.FindLoggedInModel()`의 목록을 쓴다.
4. 버튼은 `Request(ECheatCommand.<이름>, arg1, arg2)`. 준비 단계 검사·로그·시간 초과는 자동으로 붙는다.

## 준비 — admin 계정

치트는 `t_user.admin_level ≥ 1`인 계정만 통과한다. **로그인 Id(이름)와는 무관하다** — `admin`으로 로그인해도 값이 0이면 거절된다.
계정은 처음 로그인할 때 `admin_level = 0`으로 자동 생성된다. 로컬 DB(`Server/Shared/game.sqlite3`)에서 값을 올리고 **다시 로그인**한다
(서버는 로그인 때 한 번 읽는다). 이 DB 파일은 커밋하지 않는다.

```sql
UPDATE t_user SET admin_level = 1 WHERE provider_id = '<로그인 Id>';
```

지금은 치트로 admin을 줄 수 없다 — 치트 자체가 admin이어야 통과한다. 서버에 admin 부여 명령을 요청해 두었다
([T-060](<../../../../tasks/T-060-치트어드민부여.md>) · 이슈 #26). 들어오면 이 창에 칸을 붙인다.
