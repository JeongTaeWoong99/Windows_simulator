**`#Outpost Canvas` — 마을 화면(코드 이름은 Outpost 그대로). 경매장·아티팩트와 같은 자리(3열 가운데 띠 · 화면 전체 차단)에 뜨는 지도 화면이다.**
하단 메뉴 [마을]로 열고 안쪽 [X]·판 밖 차단막으로 닫는다(Esc 없음 · 경매장과 같다). 건물 창이 떠 있으면 창 뒤 바탕·판 밖 어느 쪽을 눌러도 건물 창만 닫힌다. 경매장 · 아티팩트 · 거점은 셋 중 하나만 열린다(`UIManager`).
배치는 목업([`거점목업.html`](../../../../GameDesign/design/ui/거점목업.html))을 따른다. 규칙·수치는 [`building/README.md`](../../../../GameDesign/design/building/README.md) · [`trait/README.md`](../../../../GameDesign/design/trait/README.md).

| 파일 · 폴더 | 무엇 |
|------|------|
| `OutpostCanvasView.cs` | 캔버스 — 여닫기 · 판을 3열 가운데 띠에 맞추기(`AuctionCanvasView`와 같은 방식) |
| `OutpostHeaderPresenter/` | 머리 줄 — 제목 · 도움말 · 계정 레벨 · 보유 골드 · [X] |
| `OutpostMapPresenter/` | 지도 — 건물 5채(`OutpostBuildingView`) · 건물 메뉴 · 바닥 누르면 메뉴 닫기 |
| `OutpostBuildingPresenter/` | 건물 창 머리 줄 — 이름 · 레벨 · 분류 · 탭 · [X]. **창 전체(`window`)를 여닫는다** |
| `OutpostUpgradePresenter/` | 업그레이드 탭 — 레벨 ▶ 다음 레벨 · 비용 줄(`OutpostCostRowView`) · 얻는 것 · 이유 · 버튼 |
| `TraitPresenter/` | 특성 탭 — 트리(노드 + 선) · 오른쪽 정보 카드. 옛 인벤토리 특성 탭을 옮겼다 |

데이터는 `PlayerDataModel`(`GetBuildingLevel` · `GetBuildingPoints` · `CheckBuildingUpgrade` · `TryGetUnmetPrerequisite`)과 `GameDataLoader`(`Buildings` · `TryGetBuildingLevel` · `HasBuildingNodes`)다.

## 건물 창은 형제로 나눈다

`Building Window > Window Panel` 아래에 `Building Presenter` · `Upgrade Presenter` · `Trait Presenter`가 **형제**로 있다(Presenter 안에 Presenter를 두지 않는다).
그래서 창을 여닫는 일은 자기 오브젝트가 아니라 **`OutpostBuildingPresenter.window`** 를 켜고 끈다. 지금 탭이 아닌 페이지는 꺼져 부모 세로 배치에서 빠진다.

## 지도 위 자리

- 건물 자리는 **앵커 = 지도 %** 다(표에 자리 칼럼이 없다). 어느 건물인지도 씬이 정한다(`OutpostBuildingView.buildingTid`).
- 지금 자리(2026-11-18) — 작업장 (0.50, 0.50) 정중앙 · 관리소 (0.20, 0.70) · 상회 (0.80, 0.70) · 숙소 (0.20, 0.30) · 감정소 (0.80, 0.30).
  ⚠️ **y는 0.15~0.85 안에 둔다** — 판이 그림보다 가로로 길어 Envelope가 위아래를 자른다(사용자 창 비율에서 약 15%씩 · 1920 전체 화면은 11%씩). 옛 자리(아래 줄 0.22)는 잘림선·안내 띠에 붙어 지도가 아래로 쏠려 보였다.
- 바닥(`Ground Button`)은 `AspectRatioFitter` Envelope이고 건물·메뉴가 그 **자식**이다 — 화면 비가 바뀌어도 건물이 그림 위 같은 자리에 남는다. 넘친 부분은 `Map Presenter`의 `RectMask2D`가 자른다.
- 그림은 `Assets/Art/outpost/` — 2026-11-17 정식 도트(`_source/environment/claude-outpost/make_outpost.py`). 바닥의 길·문앞은 위 앵커에 맞춰 그렸다 — **건물 앵커를 옮기면 생성기의 `SPOTS`를 함께 고치고 다시 뽑는다.**

## 그림 단계 (2026-11-22)

레벨이 오르면 그림이 자란다 — 기준은 `OutpostMapPresenter/OutpostArtStage.cs` 한 곳(그림 규칙이지 게임 수치가 아니다).

| 무엇 | 기준 | 그림 |
|------|------|------|
| 건물 (`OutpostBuildingView.tierSprites` 6장) | 건물 레벨 — 0 · 1~19 · 20~49 · 50~89 · 90~129 · 130~ | `building_<TID>_0~5` — 빈 터 · 일하는 자리 · 작은 집 + 그 일의 물건 · 그 건물다운 집 · 정식 건물(옛 그림) + 돌 마당 · 랜드마크(아래 표) |
| 바탕 (`OutpostMapPresenter.groundStages` 5장) | 건물 레벨 합(0~750) — 0~49 · 50~199 · 200~399 · 400~599 · 600~ | `ground_1~5` — 모닥불 빈터 · 말뚝 울타리 · 돌길·분수·풍차 · **붉은 벽돌 큰길(넓힘) · 벽돌 광장(1.4배) · 생울타리 · 가로등 줄** · 돌담·성문 · **흰 석판 큰길 + 금 테 · 별 모자이크 광장 · 꽃길 · 깃발 줄** · 망루 |

- ⚠️ **지형은 다섯 장이 같다** — 풀 무늬 · 개울 · 숲 · 덤불은 단계와 상관없이 같은 자리(생성기가 나무 자리를 늘 5단계 길·소품을 피해 한 번만 고른다). 단계가 바꾸는 것은 길 · 광장 · 다리 · 울타리 · 밭 · 소품뿐이다. 4단계부터 큰길 폭 5.2 · 광장 1.4배로 넓혀도 나무는 늘 '폭 4.2 + 여유 3'을 피해 고르므로 숲이 그대로다. 가로등·깃발 줄은 나무 자리 계산(소품 목록)에 넣지 않고 맨 끝에 그린다 — 넣으면 숲이 바뀐다.
- ⚠️ **건물 단계는 모두 같은 캔버스 · 바닥선 · 문 x**에 선다 — 바닥의 문앞 길이 그 문으로 들어온다(생성기 `DOOR_X` ↔ `door_px`).
- **1~3단계는 건물마다 따로 그린다**(2026-11-22 사용자 — 팰월드 작업대 → 상급 작업대 → 공장처럼 이름에 맞게 자라게. 모두 천막에서 시작하던 첫 판은 반려).

  | 건물 | 1 | 2 | 3 |
  |---|---|---|---|
  | 관리소 | 게시판 · 장부 책상 · 파란 깃대 | 작은 사무소 + 게시판 | 종탑 달린 2층 관청 |
  | 작업장 | 원시 작업대 · 도끼 그루터기 · 장작 | 벽 하나 헛간 작업장 + 모루 · 화덕 | 굴뚝 대장간 + 바깥 작업대 · 모루 |
  | 상회 | 파라솔 손수레 · 자루 | 줄무늬 노점 + 창고 | 진열창 가게 + 차양 |
  | 숙소 | 차양 · 침낭 · 모닥불 야영지 | 통나무 오두막 + 빨랫줄 | 2층 하숙집 |
  | 감정소 | 깔개 위 점술 탁자 · 수정 구슬 | 돌 오두막 + 수정 기둥 | 작은 둥근 탑 돌집 |
- **4·5단계는 실루엣부터 바꾼다**(2026-11-22 사용자 — 4·5가 '꾸미기만 더한' 꼴이라 티가 안 났다). 3→4는 집이 커지고 **돌 마당**이 발밑에 깔린다. 5는 그 건물만의 큰 구조물이 지붕 위로 솟는다 — 캔버스를 위로 22줄(×4) 늘렸다(바닥선은 그대로).

  | 건물 | 5단계 랜드마크 |
  |---|---|
  | 관리소 | 시청 — 캔버스 꼭대기까지 오르는 종탑(종 · 큰 시계 · 금 첨탑 · 늘어뜨린 깃발) + 양끝 원뿔 탑 |
  | 작업장 | 대공방 — 성가퀴 두른 제련 탑(쇳물 아궁이 · 굴뚝 둘 · 짙은 연기) + 지붕 톱니바퀴 문장 |
  | 상회 | 대상회 — 가운데 3층 망루 + 금 돔 + 큰 금화 · 양쪽 깃대 |
  | 숙소 | 대여관 — 3층 박공 날개(발코니 · 불빛 창 줄) + 높은 굴뚝 + 큰 잔 간판 |
  | 감정소 | 마탑 — 두 배로 솟은 둥근 탑 + 떠 있는 큰 수정 · 감는 마법 고리 · 문앞 마법진 |
- ⚠️ **건물 그림은 368×384**(옛 368×296에서 위로만 늘림). 프리팹 `OutpostBuildingView` 루트 240×250.4 · 피벗 y 0.385 = 바닥에서 피벗까지 옛 거리 그대로라 바닥선·이름판·문앞 길이 제자리다. 캔버스 높이를 바꾸면 이 두 값을 함께 고친다(씬의 건물 다섯 개는 크기·피벗을 덮어쓰지 않는다 — 덮어쓰면 프리팹을 안 따른다).
- 생성기 좌표 주의 — 중심을 `45.5`처럼 .5로 두면 파이썬 반올림(짝수 쪽)이 열을 건너뛰어 원에 줄무늬가 생긴다. 원·문양의 중심은 정수로.
- **이름판은 그림 가운데 아래**에 둔다 — 단계마다 그림이 캔버스에서 치우친 정도가 달라, 생성기가 그림의 가로 가운데를 `_centers.json`으로 내고 임포트 때 **스프라이트 피벗 x**에 넣는다. `OutpostBuildingView.Bind`가 피벗을 읽어 이름판을 옮긴다. **그림을 다시 뽑으면 피벗도 다시 넣는다.** 이름판 y −26 — 바닥선 밑이라 1단계처럼 낮은 그림을 가리지 않는다.
- 바탕 다섯 장을 배열로 들고 있어 늘 메모리에 함께 올라간다(무압축 1600×896 × 5 ≈ 28MB). 무거워지면 단계 하나만 불러오는 쪽으로 바꾼다.

## 빨간 점 (2026-11-22 사용자)

지금 할 수 있는 일(건물 올리기 · 특성 찍기)이 있을 때만 켠다 — `PlayerDataModel.CheckBuildingUpgrade == Ok` · `CanLearnAnyTrait`.

| 자리 | 켜지는 때 |
|------|------|
| 하단 메뉴 [마을] (`MenuPresenter.outpostNoticeDot`) | 어느 건물이든 올리거나 찍을 수 있다(`HasVillageNotice`) |
| 지도 건물 이름판 | 그 건물을 올리거나 찍을 수 있다 |
| 지도 메뉴 [업그레이드] · [특성] | 고른 건물을 올릴 수 있다 · 찍을 수 있는 노드가 있다 |
| 건물 창 탭 [업그레이드] · [특성] | 같은 조건 — 지금 보고 있는 탭에도 띄운다 |

- 점은 버튼의 자식 `Notice Dot`(오른쪽 위 안쪽 · `ignoreLayout` · 레이캐스트 끔) — 그림 `Assets/Sprites/ui/notice_dot.png`.
- 하단 메뉴는 원래 배지를 두지 않는다(P1 — 재촉 금지). [마을] 점은 사용자가 정한 예외다 — 시간이 아니라 할 일이 있을 때만 켜진다.

## 모양 — 양피지 스타일 (2026-11-17)

거점은 `(MAIN VIEW)` 안이라 `UiSkin`이 안쪽에 액자를 자동으로 두르지 않는다 — 아래는 씬·프리팹에 직접 입혔다.

| 자리 | 모양 |
|------|------|
| 건물 이름판 (`OutpostBuildingView` 프리팹) | **한 줄 진갈 간판** — `ui_input` + 덧테 · 역할 `Border` · `이름 Lv 분류` · 글자에 맞춘 너비(ContentSizeFitter) · 건물 아래 가운데. 건물을 가리지 않게 낮고 좁게 둔다(아래 줄 건물은 지도 끝이라 밑으로 못 내린다) |
| 이름판 빨간 점 | 이름판 오른쪽 위 귀퉁이 `Notice Dot` 20px (2026-11-22 — ▲ · ● 배지를 없앴다) · 이름 글씨 26 · 레벨 23 · 분류 19(자동 축소 최소 절반) |
| 아래 안내 띠 · 메뉴 | 안내 띠는 진갈(`Border`) · 메뉴는 양피지(`PanelBg`) + 덧테, 글씨는 밝은 바탕 위라 `TextDark`·`HighlightDark` |
| 건물 창 (`Window Panel`) | 열 창과 같게 `ui_panel` + `Ui Paper` + `Ui Frame` · 여백 = 원래 + 13. 머리 줄(`Building Presenter`)은 진갈 띠(`ui_header` · `Border`) + 크림 글씨. **크기는 가운데 고정 1300×700** (2026-11-18) — 판을 거의 다 덮으면(옛 1770×827) 지도가 안 보여 '페이지'로 읽히는데 액자·[X]는 '창'이라 어중간했고, 업그레이드 내용(680 폭 한 줄)이 가로 60%·세로 160px을 비워 두었다. 창 둘레로 어두워진 지도가 보이게 줄였다 — 업그레이드 열 720(패딩 265) · 특성 트리 ≈ 860 + 정보 칸 380 |
| 업그레이드 | 필요한 것 · 얻는 것을 구획 상자(`ui_input` · `PanelSub`)로 · 비용 줄(`OutpostCostRowView`) 글씨 `TextDark` |
| 특성 | 바깥 겹상자를 뺐다(버튼 그림을 창처럼 쓰고 있었다) · 트리 칸 = 구획 상자 — 오른쪽 정보 칸과 짝. 비교 상자 값(`Lv3 고대 신전까지`)은 한 줄 + 자동 축소 12~24 — 옛 24 고정 · `…`이라 작업지 이름이 잘렸다. 이름 줄의 최대 레벨 표시(`Lv 5 / 5 · 최대`)는 `HighlightDark` — 고른 탭 노랑은 양피지에서 안 보였다 |

## 지도 표시 — 빨간 점 하나 (2026-11-22 사용자 — 레드닷으로 통일)

- 올릴 수 있다(`CheckBuildingUpgrade` — 서버 `TryUpgradeBuilding`과 같은 순서. 안내일 뿐 서버가 다시 검사한다) **또는** 찍을 수 있는 노드가 있다(`CanLearnAnyTrait`) → 이름판 귀퉁이 빨간 점.
- 포인트만 남고 찍을 노드가 없으면 켜지 않는다 — 눌러도 쓸 곳이 없는 재촉이 된다. 남은 포인트 수는 메뉴 [특성 ● n]에만 적는다.

## 트리 없는 건물

1차 트리는 작업장뿐이다(T-183). 나머지 4채는 업그레이드는 열어 두고, [특성] 탭을 감추고 "특성은 준비 중 — 포인트는 쌓입니다"를 적는다. 메뉴의 [특성]을 눌러도 업그레이드 탭으로 간다.

## 트리
