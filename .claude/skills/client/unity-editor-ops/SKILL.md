# 유니티 에디터 작업

> 에디터 조작은 **전부터 MCP로 하고 있었다.** 바뀐 것은 **경로**다 —
> 매번 C# 코드를 짜서 `Unity_RunCommand`로 컴파일·실행하던 것을,
> Pipeline 패키지가 에디터 안에 띄운 경량 서버에 **사전 등록된 명령을
> 한 줄로 호출**하는 것으로 줄였다. C# 작성은 등록된 명령에 없을 때만 한다.
> 이 문서는 **어느 경로로 실행할지**와 **어디서 멈춰 물어볼지**를 정한다.

---

## 1. 실행 경로 — 위에서부터 시도한다

| 순위 | 경로 | 쓸 때 |
|------|------|-------|
| ① | `unity cmd <명령>` | **기본.** 등록된 명령(151개)에 있으면 무조건 이것 |
| ② | `Unity_RunCommand` (C#) | ①에 없는 조작일 때만 |
| ③ | 핸드오프 프롬프트 | ①②로 안 되는 것 — 4절 |

**①을 먼저 확인하는 법** — 기억으로 넘겨짚지 말고 찾는다.

```bash
unity list --query prefab      # 이름·설명 검색
unity cmd <명령> --help        # 인수 확인
```

명령 체계 전반은 `unity-cli` 스킬(Unity 공식)에 있다.

**자주 쓰는 흐름**

```bash
unity cmd editor_status        # 컴파일 중·플레이 중인지 먼저 확인
unity cmd console_status       # compilationFailed / 에러 개수 (로그 파싱 불필요)
unity cmd get_scene_hierarchy
unity cmd create_script  →  recompile  →  recompile_status(폴링)  →  attach_script
unity cmd set_component_properties  →  save_prefab_contents / save_scene
```

> ⚠️ `create_script`로 만든 타입은 **리컴파일 전에는 존재하지 않는다.**
> `recompile` → `recompile_status`가 끝난 뒤에 `attach_script`를 부른다.

## 2. 실행 전 사용자에게 알리고 기다릴 것

아래는 **실행 직전에 한 줄로 알리고 사용자 답을 기다린다.** 묻지 않고 실행하지 않는다.

| 작업 | 명령 | 왜 |
|------|------|-----|
| 플레이 모드 진입·종료 | `editor_play` · `editor_stop` | 사용자가 화면을 봐야 하는 시점 |
| 테스트 실행 | `unity test` · `run_tests` | 오래 돌고, 결과를 같이 봐야 한다 |
| 빌드·빌드 타깃 변경 | `unity build` · `build` · `switch_build_target` | 길게 돈다 |
| 베이크 | `bake_lighting` · `bake_navmesh` · `bake_occlusion_culling` | 길게 돌고 결과물이 커밋에 섞인다 |
| **되돌릴 수 없는** C# 실행 | `eval` · `run_script` · `Unity_RunCommand` 안에서 삭제·파괴를 할 때 | 아래 삭제 행과 같다 — 단순 생성·수정은 해당 없다 |
| 에셋·오브젝트 삭제 | `delete_*` · `clear_*` · `remove_*` · `package_remove` | git으로 되돌릴 수 있지만 되돌릴 일을 만들지 않는다 |
| AI 에셋 생성 | `Unity_AssetGeneration_GenerateAsset` | **되돌릴 수 없다** — 크레딧을 쓴다 (3절) |

알릴 때는 **무엇을·왜** 한 줄이면 된다. 길게 쓰지 않는다.

> 플레이 모드로 슬롯 렌더링을 확인하겠습니다. 진행할까요?

**이 목록 밖은 묻지 않고 진행한다** — 조회(`get_*`·`find_*`·`console`·`*_status`),
생성·수정(`create_*`·`add_component`·`set_component_properties`·`attach_script`),
리컴파일, 저장, 단일 캡처. 전부 Undo 스택에 들어가거나 git으로 되돌릴 수 있다.

### `eval`·`run_script`는 그 자체로는 묻지 않는다

**기준은 실행 수단이 아니라 안에서 무엇을 하느냐다.** 등록된 명령으로 안 되는
씬·프리팹 편집은 대부분 임의 C#으로 가게 되는데, 여기에 확인을 걸면
**씬을 한 번 만질 때마다 멈추게 된다.**

| 안에서 하는 일 | 판단 |
|----------------|------|
| 오브젝트·컴포넌트 생성·수정, 프로퍼티 설정, 계층 조회, 저장 | **묻지 않는다** — Undo·git이 받는다 |
| `DestroyImmediate` · `AssetDatabase.Delete*` · `File`/`Directory.Delete` · 씬 전체 교체 | **묻는다** — 위 삭제 행과 같다 |
| 플레이 모드 진입·빌드·베이크를 코드로 부르는 것 | **묻는다** — 수단을 바꿔도 위 표가 적용된다 |

> 📌 2026-09-22에 이 조건을 좁혔다. `eval`·`run_script` 전체가 확인 대상이던 동안
> **일상적인 씬 작업마다 확인 요청이 붙어** 작업이 계속 끊겼다.
> 확인은 **되돌릴 수 없는 것**에만 건다.

### 이 절은 설정으로 강제되지 않는다

`permissions.ask`·PreToolUse 훅의 `ask`·`autoMode.soft_deny` **세 가지 모두
auto 모드에서는 사용자에게 도달하지 않는다**(2026-09-20 실측). 프롬프트 없이
그대로 실행된다. 작동하는 것은 `permissions.deny` 하나뿐인데, 그건 **아예
호출을 막는** 것이라 "물어보고 하기"가 되지 않는다.

**그래서 이 표는 순전히 이 문서를 읽은 쪽이 지키는 약속이다.** git이 안전망을
맡고, AI 에셋 생성만 크레딧 때문에 3절에서 한 번 더 조인다.

> ⚠️ **모델은 자기 권한 규칙을 지울 수 없다.** `deny`·`allow` 줄을 빼려 하면
> 분류기가 `[Self-Modification]`으로 막는다. 설정 변경이 필요하면 **어느 파일의
> 어느 줄인지 짚어 사용자에게 부탁한다.**

## 3. AI 에셋 생성 — 되돌릴 수 없다

이미지·스프라이트·사운드 생성은 **git으로 되돌려도 쓴 크레딧이 돌아오지 않는다.**
그래서 2절 중에서도 **프롬프트·저장 경로·개수를 먼저 보여주고 답을 기다린다.**

### ⚠️ 모델 목록이 비어도 "패키지가 없다"는 뜻이 아니다

**패키지가 전부 제대로 깔려 있어도, 계정에 Unity AI 크레딧이 없으면
모델 목록은 빈 채로 온다.** `{"Models": []}`는 설치 상태를 말해 주지 않는다 —
둘은 아무 관계가 없다. 이걸 "패키지가 없어서"로 읽는 것이 전형적인 오진이다.

그래서 **빈 목록을 봤으면 콘솔부터 읽는다.**

```
Unity_GetConsoleLogs(logType: "error")
→ Error reason is 'NoSubscription' (https://generators.ai.unity.com)
```

| 콘솔에 나온 것 | 뜻 | 할 일 |
|----------------|-----|-------|
| `NoSubscription` | **크레딧 문제다. 패키지는 멀쩡하다** | 사용자에게 알린다 — 여기서 할 수 있는 게 없다 |
| 아무 것도 없음 | 그때 비로소 패키지·로그인을 본다 (`package_list`) | 순서가 이쪽이다 |

> 📌 **"패키지가 없어서 안 된다"는 `package_list`로 확인하기 전에는 말하지 않는다.**
> 2026-09-20에 확인 없이 `com.unity.ai.generators`가 없다고 단정했다가 틀렸다 —
> 실제로는 **다 깔려 있었고** 진짜 원인은 `NoSubscription`이었다.
> 사용자는 보통 관련 패키지를 다 깔아 둔다.

> 💡 `Unity_AssetGeneration_GenerateAsset`은 **도구 설명 자체가** 대화당 첫 호출 전
> 사용자 동의를 요구한다. 무엇을 만들지 나열하고, 생성 중에는 응답이 막힌다는 점과
> 수십 초~수 분이 걸린다는 점을 알린 뒤 답을 기다린다.

### ⛔ `com.unity.ai.generators`는 다시 깔지 않는다

deprecated 패키지이고 기능은 **`com.unity.ai.assistant`에 전부 통합**됐다.
둘을 함께 두면 어셈블리 이름(`Unity.AI.Generators.IO.Srp`)과 GUID가 충돌해
**프로젝트 전체 컴파일이 깨진다**(2026-09-20 실제 발생, 콘솔 에러 1,500건 이상).

## 4. 핸드오프 — CLI로도 MCP로도 안 될 때

아래는 여전히 사람이 해야 한다. 이때만 **복사용 프롬프트**를 만든다.

- **시각적 판단** — "이 배치가 보기 좋은가", 애니메이션 느낌, 색감
- **에디터 GUI 전용** — 일부 Project Settings, 패키지 Import 창
- **플레이 중 인터랙션** — 직접 조작해봐야 아는 것
- **AI 에셋 생성이 `NoSubscription`으로 막힐 때** (3절) — 사람이 다른 수단으로 만든다

### 하지 않을 것

- CLI로 되는 일에 프롬프트를 만들지 않는다. **먼저 `unity list`로 찾아본다.**
- 코드 변경만으로 끝나면 만들지 않는다.

### 프롬프트 작성 규칙

1. **복사 편의** — 전체를 코드블록으로 감싼다.
2. **정확한 경로·값** — 대상 파일·오브젝트 경로와 설정할 값을 구체적으로.
3. **전제 설명** — 코드 변경으로 생긴 전제를 함께 적는다.
   (예: "새 int 필드는 직렬화 시 기존 항목에 기본값 0이 들어가므로 직접 지정해야 함")
4. **그래픽 요청** — 저장 폴더와 "기존 에셋 포맷(크기·형태·스타일)에 맞추라"는 지시.
5. **실행 가능 형태** — 한국어로, 작업이 여러 개면 `[1] [2] …` 단계로 구분한다.

### 예시

```
SkillSO.asset(Assets/Scripts/SO/SkillSO.asset)의 skills 배열을 편집해줘.
Skill에 int 필드 buffDuration이 추가되었다 (0=영구, 1=이번 턴만, N=내 턴 N회).
새 필드라 기존 항목에는 기본값 0이 들어가 있으니 직접 지정해야 한다.

[1] "전열 강화", "집중 강화"의 buffDuration = 1 로 설정
[2] 모든 스킬 description을 더 자세히 다시 작성 (지속시간 명시)
[3] 영구 버프 카드 "영구 각성"(BuffSingle, manaCost 5, value 4, buffDuration 0) 추가
    - 아이콘은 Assets/Contents/Sprites/Skills/ 에 기존 스킬 아이콘과 같은 포맷으로 제작
```

## 5. 에디터 동기화 안내

**유니티 밖(IDE·파일 탐색기 등)에서 에셋을 옮기거나 이름을 바꿨을 때**만 답변 말미에 넣는다.
CLI로 조작했다면 에디터가 이미 갱신했으므로 해당 없음.

> ⚠️ **유니티 에디터를 한 번 열어(포커스를 줘) 동기화시킨 뒤 커밋하세요.**
> 밖에서 옮긴 에셋은 Unity가 켜질 때 참조·메타·빌드 세팅을 자동으로 갱신합니다.
> 동기화로 바뀐 `ProjectSettings/` 등의 변경분까지 **함께 커밋**해야
> 경로 어긋남·stash 충돌을 막을 수 있습니다.

> **배경:** 과거에 씬 파일을 유니티 밖에서 `Assets/Scenes/`로 옮긴 뒤
> `EditorBuildSettings.asset`의 경로 갱신을 빼먹고 커밋해, 협업자 커밋과
> 동일한 한 줄 수정이 충돌하며 stash가 발생한 사례가 있었다.
