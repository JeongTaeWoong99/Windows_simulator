> 최종 업데이트: 2026-11-07 (신설 — AI 원본 4096px 시트로 그림 저장소가 228MB 늘어난 일)

# 에셋 용량 — 저장소 · 빌드 · 메모리

**"용량"은 세 가지이고, 서로 다른 것이 정한다.** 하나를 줄인다고 다른 것이 줄지 않는다.

| 무엇 | 정하는 것 | 줄이는 방법 |
|------|-----------|-------------|
| **저장소** (clone·pull 크기) | 커밋한 **파일 자체**의 크기 — 모든 버전이 영원히 쌓인다 | 넣기 **전에** 줄인다 (1절) |
| **빌드** (게임 다운로드 크기) | Unity **임포트 설정** — 원본이 PNG든 PSD든 같은 텍스처로 바뀐다 | 임포트 설정 · 안 쓰는 에셋을 참조하지 않기 (2절) |
| **메모리** (실행 중) | 화면에 올린 텍스처의 **가로 × 세로 × 4바이트**(무압축 RGBA) | 큰 그림을 안 띄우기 · 아틀라스 (3절) |

> 예 (2026-11-06): AI 아이콘 시트 20장이 4096px PNG라 **저장소에 228MB**가 들어갔다. 그런데 **게임에 쓰는 결과물은 32px 아이콘 178개 약 2.5MB**이고,
> 시트는 아무 화면도 참조하지 않아 **빌드에도 메모리에도 0**이다. 줄여야 했던 것은 저장소뿐이었다.

---

## 1. 저장소 — 넣기 전에 줄인다

**git은 지운 파일도 기록에 남긴다.** 나중에 줄여 다시 커밋해도 큰 옛 버전은 그대로 받아진다.
**푸시한 뒤에는** 기록을 다시 쓰고 강제 푸시해야만 빠진다 — 함께 받은 사람이 모두 다시 받아야 하니 사실상 못 뺀다고 본다.

### 원본은 쓰는 해상도까지만

| 원본 | 넣는 크기 | 방법 |
|------|-----------|------|
| AI 생성 그림 (Seedream 4096 등) | **긴 변 1536** | `python Assets/Art/_source/shrink_raw.py <raw 폴더>` — 커밋 전에 |
| AI 1024px 그림 | 그대로 | 이미 작다 |
| 구매·무료 팩 | 받은 그대로 | 필요한 것만 추려 넣는다 (`Art 규칙.md` "원본 정리") |
| 실패한 시험 생성 | **넣지 않는다** | 결과·판단만 일감·로그에 글로 남긴다 |

- AI 그림은 **가짜 픽셀**(큰 덩어리)이라 1536에서도 정보가 남는다. 칸 자르기(`grid_to_icons.py`)도 1536으로 줄여 쓰므로 **다시 잘라도 결과가 1픽셀도 같다**(2026-11-07 아이콘 178개 비교).
- 줄일 때는 **NEAREST**(가까운 픽셀)로 한다 — 부드럽게 줄이면 픽셀 경계가 번진다.

### 파일 형식

| 형식 | 손실 | Unity가 바로 읽나 | 쓰임 |
|------|------|-------------------|------|
| **PNG** | 없음 | ✅ | **그림 원본·결과물 기본값** |
| WebP (무손실) | 없음 | ❌ 임포트 안 됨 | PNG보다 약 25% 작지만 Unity·스크립트가 못 연다 — 쓰지 않는다 |
| JPG | 있음 · 투명 없음 | ✅ | 픽셀 그림엔 쓰지 않는다 (경계에 얼룩) |
| PSD | 없음 | ✅ | 레이어가 필요한 손그림 원본만 |
| WAV | 없음 | ✅ | 소리 원본 기본값 — 빌드 압축은 임포트가 한다 (2절) |

- **PNG 손실 압축(pngquant 등 색 수 줄이기)은 원본에 쓰지 않는다** — 다시 가공할 때 색이 틀어진다. 무손실 재압축(`optimize=True` · oxipng)은 써도 된다.
- 같은 파일을 두 곳에 넣어도 git은 **한 번만 저장한다**(`_source/audio`와 `audio/`의 같은 WAV).

### 지금 크기 보기

```bash
git -C Assets/Art count-objects -vH        # size-pack + size = 저장소가 쥔 크기
du -sh Assets/Art/_source/*/*/raw          # 원본 폴더별
```

- **Git LFS** — 지금은 쓰지 않는다. 그림 저장소가 **1GB에 가까워지면** 다시 본다(`Art 규칙.md`). 2026-11-07 약 340MB(그중 228MB는 이미 푸시된 4096 시트).

## 2. 빌드 — 임포트 설정이 정한다

**빌드에는 장면·`Resources/`·카탈로그가 참조하는 에셋만 들어간다.** `_source/`의 원본은 아무도 참조하지 않으니 빠진다.

- ⚠️ **`Resources/` 폴더 안의 것은 참조가 없어도 전부 들어간다.** 원본·큰 그림을 넣지 않는다 — 지금은 카탈로그 SO만 있다.
- 결과물 임포트 설정은 `ArtImportPostprocessor`가 강제한다 (`Assets/Scripts_Client/Editor/art-import/`). 인스펙터에서 바꿔도 되돌아온다.

| 종류 | 지금 설정 | 이유 |
|------|-----------|------|
| 픽셀 그림 (캐릭터·아이콘·대상·배경) | 점 필터 · **무압축** · 밉맵 없음 · 최대 8192 | 블록 압축(DXT·ASTC)은 4×4 칸 단위로 색을 뭉개 픽셀 경계가 번진다. 그림이 작아 무압축이어도 작다 |
| 이펙트 (`fx/`) | 선형 필터 · 무압축 | 부드러운 흰 도형을 늘려 쓴다 |
| 배경음 (`audio/bgm`) | Streaming · Vorbis 품질 0.6 | 길어서 통째로 메모리에 올리지 않는다 |

- 큰 그림이 늘어 빌드가 커지면 **압축을 켜기 전에** 크기부터 본다 — 화면에 실제로 보이는 크기보다 큰 텍스처는 최대 크기(`maxTextureSize`)로 줄인다.
- 빌드에 무엇이 얼마나 들어갔는지는 빌드 뒤 `Editor.log`의 **Build Report**(에셋별 크기 목록)로 본다.

---

## 3. 메모리 — 화면에 띄운 것만

- 무압축 텍스처 메모리 = **가로 × 세로 × 4바이트.** 32px 아이콘 = 4KB · 1536 시트 = 9MB · 4096 시트 = 64MB.
- 그래서 **원본을 런타임에 불러 쓰지 않는다** — 화면은 굽기로 규격을 맞춘 결과물만 쓴다(`Art 규칙.md`).
- 같은 화면의 작은 그림이 많아 그리기 호출이 늘면 Sprite Atlas를 본다 — 성능 문제가 **실제로 관측됐을 때만**([`optimization`](../optimization/SKILL.md)).

---

## 4. 새 에셋을 넣을 때 확인

1. 원본이 쓰는 해상도보다 큰가 → `shrink_raw.py` (AI 원본은 항상)
2. 실패·시험 생성이 섞였나 → 빼고 글로 남긴다
3. `Resources/` 안에 넣지 않았나
4. 결과물이 규격 폴더(`characters/`·`icons/`…)에 들어가 임포트 설정이 자동으로 붙었나
5. 커밋 전 `git -C Assets/Art diff --cached --stat`으로 큰 파일이 없는지 본다 — **푸시 전이 마지막 기회다**
