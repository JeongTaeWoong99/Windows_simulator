# 전파 상세 — 게임 기획 참조의 부록

> 최종 업데이트: 2026-09-13 ([`SKILL.md`](SKILL.md)에서 분리 — 이슈 #18 · T-051)
>
> `SKILL.md`의 "재귀 전파" 규칙으로 판단이 서면 열지 않아도 된다.
> 여기는 **알고리즘 · 사고 사례 · 검사 스크립트 옵션 · 새 시스템/산업 추가 절차**다.

---

## 1. 전파 알고리즘

문서를 고쳤으면 **그 문서 헤더의 `바뀌면 갱신` 블록**(또는
[`문서관계도.md`](../../../../GameDesign/design/문서관계도.md) 2.1)에 적힌 문서를
**전부 열어 본다.** 고친 문서가 생기면 **그 문서에서 또 퍼진다.**

```
큐 = [고친 문서]
방문 = {}
while 큐:
    문서 = 큐.pop()
    if 문서 in 방문: continue      ← 순환(캐릭터 ↔ 작업슬롯)은 여기서 멈춘다
    방문.add(문서)
    for 대상 in 그 문서의 "바뀌면 갱신" 목록:
        대상을 연다
        if 이번 변경으로 대상의 서술이 낡았나?
            대상을 고치고, 대상의 "최종 업데이트"를 오늘로 바꾸고, 큐에 넣는다
        else:
            넘어간다                ← 열어 보고 안 고치는 것이 정상이다
```

## 2. 무엇이 "낡게 만드는" 변경인가

아래에 해당할 때만 대상을 손댄다. 표현만 다듬은 것은 전파하지 않는다.

| 유형 | 예 |
| --- | --- |
| 이름이 바뀜 | `ItemRarity` → `GlobalRarity` |
| 수치·개수가 바뀜 | 아이템 30종 → 150종 |
| 확정 상태가 바뀜 | ❌ 미정 → ✅ 확정 |
| 폐지 | 요일 로테이션 폐지 |
| 구조가 바뀜 | 판정 비용이 상수 → 테이블 |

## 3. 실제로 반복된 사고

- **하위 문서만 고치고 상위·형제를 안 고침** — `Hunting` enum · 아이템 30종 → 150종 ·
  `ItemRarity` → `GlobalRarity` (2026-08-02 확인). 재귀 전파 규칙이 생긴 이유다.
- **엑셀만 앞서 나감** — 2026-08-01에 드롭 시트가 레벨별로 갈라졌는데 `DropTableCatalog`가
  `IndustryLevel`을 읽지 않아 **Lv1 슬롯에서 Lv5 아이템이 나오는 상태**가 됐다.
  "미구현"이 아니라 "오동작"이었다. 엑셀 구조를 바꿀 때는 그 시트를 읽는 서버 코드를 같은 작업 단위로 본다.

## 4. 검사 스크립트

```powershell
powershell -File GameDesign/check-doc-graph.ps1 -Changed   # 이번에 고친 문서 기준 (커밋 전)
powershell -File GameDesign/check-doc-graph.ps1            # 전수 점검
powershell -File GameDesign/check-doc-graph.ps1 -Fix       # 헤더 블록을 실제 그래프에 맞춤
powershell -File GameDesign/check-doc-graph.ps1 -Graph     # 문서관계도 2장 표 갱신용 출력
```

| 결과 | 뜻 |
| --- | --- |
| **오류** (깨진 링크 · 블록 불일치) | 반드시 고친다. 링크를 추가·삭제했으면 `-Fix` |
| **경고** (갱신일 역전) | **전파를 빠뜨렸을 수 있다.** 확인하고, 정말 영향이 없었다면 그대로 둔다 |

> 링크를 새로 걸거나 지웠으면 `-Fix`로 헤더 블록을 맞추고
> `문서관계도.md` 2장 표도 `-Graph` 출력으로 갱신한다.

## 5. 새 시스템·산업을 추가할 때

1. `GameDesign/design/<시스템>/README.md` 를 만든다.
   **폴더는 영문 소문자 kebab-case, 문서(`.md`)명은 한글이다.** (`gathering/자원채취.md`)
   1차 산업이면 `GameDesign/design/gathering/<산업>/README.md`.
2. 기존 문서와 같은 구성을 따른다:
   `확정 사항` → `설계(제안)` → `데이터 설계` → `서버/클라 책임` → `결정 필요`
   헤더에는 `> 상위 문서:` · `> 최종 업데이트:` 두 줄을 반드시 둔다
   (검사 스크립트가 이 형식을 읽는다).
3. `게임기획코어.md` **3장 시스템 지도**(산업이면 **4장 콘텐츠 지도**)에 행을 추가한다.
4. **[`문서관계도.md`](../../../../GameDesign/design/문서관계도.md) 1·2장에 행을 추가**하고,
   `check-doc-graph.ps1 -Fix`로 헤더의 `바뀌면 갱신` 블록을 생성한다.
5. [`SKILL.md`](SKILL.md)의 **문서 지도** 표에도 행을 추가한다.

> 이름 규칙의 전체 내용(예외 목록 포함)은 [`GameDesign/CLAUDE.md`](../../../../GameDesign/CLAUDE.md)의 **"이름 규칙 (문서·폴더)"** 참조.
> `GameDesign/Excel`·`GameDesign/DataLog`는 코드가 경로를 직접 참조하므로 **영문을 유지한다.**
