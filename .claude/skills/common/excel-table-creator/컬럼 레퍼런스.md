# 컬럼 레퍼런스 — 엑셀 시트 작성의 부록

> 최종 업데이트: 2026-09-19 (`//` 행은 사람용 — 생성물에 들어가지 않는다 · T-065)
>
> `SKILL.md`의 "시트 구조 요약" 표로 판단이 서면 열지 않아도 된다.
> 여기는 **셀 배치 예시 · 시트 병합 동작 · `Ref` 세부 · `Description` · Enum 시트 레이아웃**이다.

---

## 시트 구조 (마커 행)

**A열이 마커**, 나머지 열이 컬럼 정의다. 마커 행 다음 **A열이 빈 행이 컬럼명 행**이고,
그 아래부터 데이터다.

```
     A                 B              C          D
1  (비움)
2  //              아이템 TID      이름        메모
3  C&S             a              a           a
4  Type            int            string      string
5  Min
6  Max
7  Default(Null)                              ""
8  Ref
9  (비움)          ItemTID        Name        Description      ← 컬럼명 행
10 (비움)          1              붕어         메모
```

| 마커 | 의미 |
| --- | --- |
| `//` | 한글 설명. 사람용이다 — 생성물에 들어가지 않는다. 짧게 쓴다 |
| `C&S` | 이 컬럼을 누가 쓰는가 (`a` = 양쪽) |
| `Type` | `int`·`long`·`float`·`string`·`bool`·`ID`·`eEnum` (+ `[]` 배열은 `,` 구분) |
| `Min`·`Max` | 값 범위. 벗어나면 파이프라인 실패 |
| `Default(Null)` | 빈 셀일 때 쓸 값. **비우면 "빈 셀 = 오류"** |
| `Ref` | `대상시트.대상컬럼` — 값이 실재하는지 검사 |

마커 행의 순서는 자유이고, 필요 없는 마커 행은 생략해도 된다.

---

## 시트 병합 — `<테이블명>.<접미사>` (2026-08-08)

시트 이름에 `.`을 넣으면 **`.` 앞부분이 테이블명**이고 뒷부분은 사람용 라벨이다.
베이스 이름이 같은 시트들은 **한 테이블로 병합**된다 — 행이 많아질 테이블을
레벨·산업 단위 시트로 갈라 두는 용도다. `.` 없는 시트는 지금처럼 시트 = 테이블.

```
DropFishing.xlsx
├─ FishingBasicTable.Lv1  ─┐
├─ FishingBasicTable.Lv2   ├─→ FishingBasicTable 한 테이블로 병합
└─ FishingBasicTable.Lv3  ─┘
Industry.xlsx
├─ IndustryLevelTable.농사 ─┐
└─ IndustryLevelTable.낚시 ─┴─→ IndustryLevelTable
```

- **모든 시트가 마커 행 전체를 갖는다.** 새 시트는 기존 시트를 복사해서 만든다.
  스키마가 한 시트라도 어긋나면 파이프라인이 **파일·시트·컬럼을 짚어 실패**한다.
- 행 순서 = 파일 열거 순 → 워크북 탭 순. 키(TID) 중복은 로드 시점에 예외.
- 병합은 파일 경계를 넘어도 동작하지만, **한 테이블은 한 파일 안에** 두는 것을 관례로 한다.
- 워크북의 시트가 전부 사라져야 테이블이 삭제된 것으로 간주된다(생성물 자동 정리는 동일).

## `Ref` — 무결성 검사

`대상시트.대상컬럼` 형태로 적으면 **그 값이 대상 시트에 실재하는지** 검사한다.
코드 생성 **전에** 돌고, 위반을 전부 모아 한 번에 던진다. 다른 워크북의 시트도 참조할 수 있다.

```
Ref    (비움)    WorkSpeedTable.WorkSpeedTID
```

- **`Min`/`Max`보다 낫다.** 범위는 "0~10 안인가"만 보지만, `Ref`는 "그 행이 있는가"를 본다.
  대상 시트가 늘어나면 자동으로 유효 범위가 넓어진다.
- **`?`를 붙이면 빈 셀과 `0`을 허용한다.** "참조가 없을 수도 있는" 컬럼에만 쓴다.
  **`0`이 유효한 값이면 `?`를 붙이지 않는다** — 0번 행과 대조돼야 하기 때문이다.

## 예약 컬럼 — `Description`

**게임 로직에 아무 영향을 주지 않는다.** 기획자가 시트에 남기는 메모다.

- `Default(Null)`에 **`""`** 를 지정해 빈 셀을 정상으로 둔다.
- **배열 컬럼(`int[]` 등)에 `""`를 적으면 빈 배열이 기본값이다** (2026-09-14) — `RequiredUnlockTIDs`처럼 "없음"이 정상인 목록에 쓴다.
- 생성된 Row 클래스에 `[기획 메모 — 로직에서 읽지 않는다]` 주석이 자동으로 붙는다.

> ⚠️ **로직에 쓰는 수치를 `Description`에 적지 않는다.** 확률·배수를 메모로 적어 두면
> 실제 컬럼과 따로 놀다가 조용히 어긋난다. 계산에 쓸 값은 반드시 자기 컬럼을 갖는다.

## Enum 시트 (`Enum.xlsx`)

구조가 다르다. **시트명이 곧 enum 이름**이다.

```
     A        B        C
1  EID      Name     Desc
2  EnumID   Value    Description
3  int      enum     string
4  1        Gold     골드            ← 4행부터 데이터
```

- `None = 0`과 `Max`는 **생성기가 자동으로 붙인다.** 시트에 적지 않는다.
- 생성 타입은 `byte` 기반이다.
- **값은 뒤에만 추가한다** (규칙 2 참조).
