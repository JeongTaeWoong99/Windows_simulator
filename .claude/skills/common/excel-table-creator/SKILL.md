# 게임 데이터 엑셀 시트 작성

`GameDesign/Excel/*.xlsx`가 게임 데이터의 **유일한 원본**이다.
여기서 시트를 만들면 파이프라인이 `.cs` · `.bytes` · `.json`을 생성하고 Unity까지 미러링한다.
생성물(`Server/GameData`, `Server/Shared/Data`, `GameDesign/DataLog`, Unity 미러)은 **직접 수정하지 않는다.**

---

## ⚠️ 착수 전 — 이름은 임의로 정하지 않는다

**파일명 · 시트명 · 컬럼명을 마음대로 짓지 않는다.** 후보를 제시하고 사용자에게 확인받는다.

시트명은 곧 생성되는 클래스명(`<시트명>Row`)이고 `.bytes` 파일명이며 Unity 미러 경로다.
한 번 박히면 되돌리는 비용이 크다.

**엑셀 파일명은 영문 PascalCase다** (2026-08-09 확정 — `Drop낚시.xlsx` 등 한글 5개를
`DropFishing.xlsx` 등으로 개명). 새 엑셀 파일을 만들 때 한글 이름을 쓰지 않는다.
시트의 사람용 라벨(`IndustryLevelTable.농사` 같은 `.` 뒷부분)은 한글이어도 된다.

## 하드 규칙

| # | 규칙 | 왜 |
| --- | --- | --- |
| 1 | **Enum 시트를 제외한 모든 시트의 첫 데이터 컬럼은 `<시트명 접두>TID`다** (`ItemTID` · `CharacterTID` · `DropTID` · `WorkSpeedTID`). **값은 유일해야 한다** | 생성기(`TableCodeGenerator.PickKey()`)가 `Type = ID` 컬럼 또는 **첫 비배열 컬럼**을 키로 잡는다. 중복은 `TableSet.From()`이 로드 시점에 예외 |
| 2 | **TID 번호는 재사용하지 않는다.** 중간에 새 번호를 끼우는 것은 된다. **Enum은 반드시 뒤에만 추가한다** | DB에 적힌 정수는 의미를 바꿀 수 없다. 재사용하면 **옛 DB 행이 조용히 다른 것으로 둔갑한다.** Enum은 중간 삽입 시 뒤 값이 전부 밀린다 |
| 3 | **밸런스 수치 컬럼에는 `Default(Null)`을 두지 않는다.** 두는 것은 비어 있는 게 정상인 컬럼(`Description`)뿐 | 비워 두면 **빈 셀 = 오류**(fail-fast). 실수로 빈 셀이 조용히 0이 되면 그 행이 말없이 죽는다 |

- 의미 있는 값이 곧 정체성이면 **그 값을 TID로 쓴다** (`WorkSpeedTable`은 적성 등급 0~10이 곧 `WorkSpeedTID`).
  별도 TID를 두면 항상 1:1인 컬럼이 둘이 되어 어긋날 여지만 생긴다.
- ⚠️ `Ref` 검사는 **엑셀 안에서 엑셀만** 본다. DB에 살아 있는 TID를 시트에서 지워도 검증은 통과하고
  DB에만 고아가 남는다. **삭제는 항상 수동으로 확인한다.**
- 식별자 규칙 상세: [`게임기획코어.md`](../../../../GameDesign/design/게임기획코어.md) 4장.

## 시트 구조 요약

**A열이 마커**, 나머지 열이 컬럼 정의다. 마커 행 다음 **A열이 빈 행이 컬럼명 행**이고 그 아래부터 데이터다.
마커 행 순서는 자유이고 필요 없는 마커 행은 생략해도 된다. **새 시트는 기존 시트를 복사해서 만든다.**

| 마커 | 의미 |
| --- | --- |
| `//` | 한글 설명. 코드에 주석으로 들어간다 |
| `C&S` | 이 컬럼을 누가 쓰는가 (`a` = 양쪽) |
| `Type` | `int`·`long`·`float`·`string`·`bool`·`ID`·`eEnum` (+ `[]` 배열은 `,` 구분) |
| `Min`·`Max` | 값 범위. 벗어나면 파이프라인 실패 |
| `Default(Null)` | 빈 셀일 때 쓸 값. **비우면 "빈 셀 = 오류"** |
| `Ref` | `대상시트.대상컬럼` — 값이 실재하는지 검사 |

| 장치 | 요지 |
| --- | --- |
| **시트 병합** | 시트명 `<테이블명>.<라벨>` — `.` 앞이 테이블명, 뒤는 사람용 라벨. 베이스 이름이 같은 시트는 **한 테이블로 병합**된다(레벨·산업 단위로 가르는 용도). 모든 시트가 마커 행 전체를 가져야 하고, 한 테이블은 한 파일 안에 둔다 |
| **`Ref`** | `Min/Max`보다 낫다 — 범위가 아니라 "그 행이 있는가"를 본다. **`?`를 붙이면 빈 셀과 `0`을 허용.** `0`이 유효한 값이면 `?`를 붙이지 않는다 |
| **`Description`** | 예약 컬럼. 로직 미사용 메모. `Default(Null)`에 `""`를 지정한다. **로직에 쓰는 수치를 여기 적지 않는다** — 실제 컬럼과 따로 놀다 어긋난다 |
| **`Enum.xlsx`** | 구조가 다르다 — `EID` / `Name` / `Desc`, **시트명이 곧 enum 이름.** `None = 0`·`Max`는 생성기가 붙인다. 값은 뒤에만 추가 |

> 📖 셀 배치 예시 · 병합의 동작 규칙 · `Ref` 세부 · Enum 시트 레이아웃은 **[`컬럼 레퍼런스.md`](<컬럼 레퍼런스.md>)** 에 있다 —
> 기존 시트를 복사해 만들고 위 표로 판단이 서면 열지 않아도 된다.
> **워크북을 처음부터 만들거나, 병합 시트·Enum 시트를 만들 때는 연다.**

## 실행 절차

```powershell
GameDesign/generate-tables.ps1
```

1. 엑셀을 **Excel에서 닫는다.** 열려 있으면 파일 잠금으로 즉시 실패한다.
2. 스크립트를 돌린다. `Ref` 검사 → 코드 생성 → `.bytes` 생성 → C# 9 검사 → Unity 미러.
3. **엑셀과 생성물을 같은 커밋에 담는다.** `GameDesign/DataLog/*.json`의 diff가
   데이터 변경 리뷰 수단이므로 함께 커밋한다.

> **시트를 지우면 그 테이블의 `.cs`·`.bytes`·`.json`이 Unity 미러까지 자동 삭제된다.**
> 손으로 지울 필요가 없다.

> ⚠️ **`DataLog`의 JSON은 enum을 이름으로 덤프한다.** enum 번호를 바꿔도 diff에 아무것도
> 나오지 않으므로, 이 종류의 변경은 리뷰로 잡히지 않는다.

## 체크리스트

- [ ] 파일명·시트명·컬럼명을 **사용자에게 확인**했다
- [ ] 첫 컬럼이 `<시트명 접두>TID`이고 값이 유일하다 (Enum 시트 제외)
- [ ] 폐기된 TID 번호를 재사용하지 않았다
- [ ] 다른 시트를 가리키는 컬럼에 `Ref`를 걸었다 (`0`이 유효하면 `?` 없이)
- [ ] 로직이 읽는 수치 컬럼에 `Default(Null)`을 두지 않았다 (빈 셀 = 오류)
- [ ] `Description`에 `Default(Null) = ""` 를 지정했다
- [ ] 엑셀을 닫고 `generate-tables.ps1`을 돌렸다
- [ ] 엑셀 + 생성물 + `DataLog` diff를 같은 커밋에 담았다
