# 창고 가득 참 문구 · enum 개수 파생 · 창고 프레임 수 대조

## 목적 / 배경

- 창고가 가득 찬 계정에서 뽑으면 "알 수 없는 오류 (코드 103)"이 떴다 → tasks/T-064
- T-085 클라 파트: 서버·기획 결정을 기다리지 않고 할 수 있는 것부터 처리했다 → tasks/T-085 7장

## 주요 결정 / 근거

- **`StorageFull` 문구는 뽑기와 상자에 함께 쓴다.** 상자는 넘치면 우편으로 보관되므로 이 코드가 온다는 건
  우편함까지 찼다는 뜻이다. 그래도 사용자가 할 일은 같아서("정리") 문구를 나누지 않았다.
- **`const` → `static readonly`.** `Enum.GetValues`는 컴파일 타임 상수가 아니다. `SlotView.AptitudeCount`도
  `AptitudeLabel.Count`를 받으므로 같이 바꿨다. 지금 `switch case`·특성 인자·기본 인자 자리에서 쓰는 곳은 없다.
- **`DefaultIndustryLevel = 1`은 파생하지 않았다.** T-085 5-3 목록에 있지만 enum이 아니라 서버 상수라
  파생할 원본이 없다. 시트/패킷 이관 쪽 문제다.
- **프레임 수 대조는 클라 사본(`ServerStorageCapacity = 200`)과 한다.** 서버가 한도를 내려 주지 않는다.
  사본 하나가 늘었지만 T-085가 값의 거처를 정할 때까지의 안전장치다. 그때 조회로 바꾼다.

## 후속 작업 / 주의사항

- T-064: 사용자 실플레이 확인으로 완료·보관(2026-09-25). `보유 N / 200` 표시(선택)는 하지 않았다.
- 🔴 **치트 지급(캐릭터·아이템·장비)은 한도를 넘겨 지급된다** — 서버 `User.Cheat.cs`가 `HasStorageFor`를 안 거친다. 서버 [이슈 #40](https://github.com/JeongTaeWoong99/Windows_simulator/issues/40). 그 전까지 치트로 200칸을 넘기면 201번째부터 격자에 안 보인다(클라가 고칠 것은 없다)
- **`EIndustryType`에 1차 산업이 아닌 원소(2차 산업 등)가 들어오면** 적성 칸·장비 필터 수가 함께 늘어난다.
  그때는 None 제외 전체가 아니라 "1차 산업만"으로 거르는 기준이 필요하다.
- 확인은 `dotnet build Assembly-CSharp.csproj`(오류 0)로만 했다. 에디터 실행은 하지 않았다.
