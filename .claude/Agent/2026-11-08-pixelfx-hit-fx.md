# pixelfx 타격 이펙트 · 캐릭터 시트 점검 · 영상 모델 비용 실험

## 목적 / 배경
- 사용자 요청: Unity AI 크레딧 대신 Claude 요금제 사용량으로 이펙트를 만드는 길([patch-gg/pixelfx](https://github.com/patch-gg/pixelfx))을 파악해 이식하고, 우리 스타일 타격 이펙트를 몇 개 만든다.
- 11-07 규칙("캐릭터 시트에는 캐릭터·무기·궤적만")을 기존 캐릭터에 점검한다.
- 싼 길 두 개를 실제로 잰다: 달리기를 이미지 모델로 그리기, Seedance 저해상도.

  - 우리 효과 `src/fx/slot/`(`_lib.js` + `hit-logging·mining·excavation·farming·hunting.js`)와 `tools/export-unity.mjs`.
  - 결과 `fx/hit/hit_<산업>_N.png` 5종 43장(64×56 · 0.3초).
  - `unity-ai-digger`·`unity-ai-miner`의 `sprites/attack_*`에서 흙더미·날아가는 흙·돌 부스러기를 지우고 다시 구웠다.
  - 견습 나무꾼 달리기 영상 시트 `raw/lumberjack_run_seedance.png`.
  - 견습 나무꾼(1010) 굽기: `unity-ai-lumberjack/sprites/`(공격 5 · 달리기 6 · 대기 4 · 배율 3.2) → `characters/apprentice-lumberjack/` · 목록 등록.
  - `_source/__pycache__` 삭제 — `pick_frames.py`·`grid_to_icons.py`가 `ai_to_pixel`을 불러올 때 생기던 파이썬 캐시. `sys.dont_write_bytecode`로 다시 생기지 않게 했다(이름은 파이썬이 정해 바꿀 수 없다).

  - `ArtImportPostprocessor`: `hit_` 접두에 점 필터를 건다.
- 문서
  - 새 스킬 `client/pixel-fx`와 CLAUDE.md 표 줄.
  - `Art 규칙.md`: 타격 이펙트 절, 원본 목록, 비용, 점검 결과.
  - `unity-ai-assets`: 영상 모델 값 표 · **0절 길 고르기**(Unity AI 크레딧 · Claude 사용량으로 코드 그리기 · 구매). 마스터에도 반영.
  - T-174.

## 주요 결정 / 근거
- **타격은 대상(산업) 쪽에 붙였다.** 맞는 반응은 무엇을 치느냐가 정한다. 그래서 같은 산업이면 어느 캐릭터든 같은 타격이 나온다. 팩에 타격 그림이 있으면 그쪽이 먼저다(지금은 29종 모두 비어 있다).
- **fx 폴더를 쓰되 `hit_`만 점 필터로 했다.** 다른 fx는 늘려 쓰는 흰 도형이라 선형 필터를 유지해야 한다.
- 기존 캐릭터 점검 결과 어긋난 것은 AI로 만든 1008·1031뿐이었다. 팩의 베기 궤적과 몬스터 자체 기술(골렘 충격파, 가시 슬라임 가시)은 맞는 대상이 아니므로 남겼다. 삽에 실린 흙도 도구의 일부로 보고 남겼다.
- **마스터에는 `pixel-fx`가 아니라 "길 고르기"만 올렸다.** 모든 프로젝트가 도트가 아니어서 pixelfx 절차는 프로젝트 몫이고, 범용으로 남길 것은 "크레딧 말고 Claude 사용량으로 만드는 길도 있다"는 선택지다(사용자 판단).
- 1010 공격은 도끼질 4·5·7·9·11칸. 9·11칸의 장작·나무 조각은 몸과 떨어진 덩어리를 지우고, 도끼날에 붙은 조각은 색으로 골라 지웠다.
- 비용 실측(502 → 299):
  - 이미지 격자 달리기: 7크레딧, 실패. 발차기·쪼그려 앉기 자세가 나오고 줄이 복사됐다.
  - Seedance 4초: 196크레딧. 480 요청은 무시되고 1024로 나왔지만 품질은 좋다.
  - 결론: 영상은 Kling 3초(107)가 가장 싸다.

## 함정
- `Bits`(굴러떨어지는 조각)의 `life`가 짧으면 알파가 1 아래로 내려가 디더가 걸리고, 덩어리가 점으로 흩어진다. 해결: `life: 2`로 두고 `draw`에서 시간으로 끊는다.
- `unity cmd eval`은 메인 스레드 5초 제한으로 "timed out"을 돌려줘도 작업 자체는 끝까지 돈다. 결과는 다시 조회해서 확인한다.
- `ArtBaker`가 internal이라 eval에서 부를 때는 리플렉션을 쓴다.
- Unity가 플레이 중이 아님을 확인한 뒤 고치고 재컴파일했다.

## 후속 작업 / 주의사항
- 실제 게임 화면에서 타격 이펙트를 아직 보지 않았다. 이번에는 대상 그림 위에 합성한 미리보기로만 확인했다.
- 타격이 대상 가운데에 나오므로 벌목의 큰 나무에서는 잎 쪽에 뜬다. 거슬리면 높이를 조정하는 칸이 필요하다.
- 1010 실측(게임 화면)은 아직이다. 크롭(상반신·머리)은 자동값이라 SO에서 조정할 수 있다.
- 1014는 기준 그림을 고쳐 생김새를 다르게 한 뒤 시트를 받는다(T-174).
