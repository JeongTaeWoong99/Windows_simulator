# 산업 레벨 정보 펼침 패널 + 세팅 화면 진행도 슬라이더

일감: [`tasks/archive/T-078-산업레벨정보표시.md`](../../tasks/archive/T-078-산업레벨정보표시.md)
같은 날 같은 화면을 만진 앞 작업: [`2026-09-24-equip-attach-ui.md`](2026-09-24-equip-attach-ui.md) (T-074)

## 목적 / 배경

- 레벨 탭이 **이름만** 말하고(`Lv2 밭`) 그 레벨이 무엇을 바꾸는지 화면에 없었다 → T-078.
- 세팅 화면에 들어가면 **진행도가 사라졌다** — 목록 칸에만 슬라이더가 있어서, 설정하는 동안
  판정이 어디까지 갔는지 볼 수 없었다(사용자 요청).

## 주요 결정 / 근거

### 🔴 높이가 없다 — 그래서 "펼침"이다

일감이 남겨 둔 물음("높이를 고정할지 접을 수 있게 할지")의 답. **화면이 750으로 고정**이고
`Industry Level Info Panel`은 **1·2단계 공통 영역**이라 켜 두면 아래가 그만큼 눌린다. 실측:

| | 효율 계산 영역 |
|---|---|
| 접힘 | **207** |
| 펼침 (`pref 110`) | **92** (4줄 = `4×28 + 3×5 + 10` = 137이라 스크롤된다) |

- **늘 열어 둘 자리가 없다.** `pref 110` 고정 + **평소 접힘**으로 갔다.
- **여는 조작을 따로 만들지 않았다** — 레벨 탭 자체가 토글이다(같은 탭 재클릭 = 접기).
  레벨을 고르는 순간이 곧 "이 레벨은 무엇이 나오나"를 묻는 순간이라 조작이 하나로 합쳐진다.
  정보 버튼(`?`)을 따로 두면 `Industry Level Panel`의 균등 5칸 배치가 깨진다.
- ⚠️ **`OnDisable`에서 접는다.** 안 접으면 다음에 슬롯에 들어왔을 때 자리를 뺏긴 채로 열린다
  (장비 목록을 `OnDisable`에서 닫는 것과 같은 이유).
- ⚠️ 3단계에서 **같은 레벨을 다시 누르면 요청이 안 나간다**(`RequestIndustryLevelChange`의 조기 반환).
  그래서 `SelectIndustryLevel`이 요청과 **무관하게** `RefreshIndustryLevelButtons()`를 한 번 돌린다 —
  안 그러면 접기가 화면에 반영되지 않는다.

### 산업별 분기는 `GameDataLoader` 한 곳에만

`FarmingBasicTable`…`HuntingBasicTable` 다섯이 **모양은 같고 타입만 다르다.** 화면이 분기하면
그 `switch`가 화면마다 복제된다 → `GetIndustryDrops(산업, 레벨)` + `IndustryDrop` struct로 묶고,
(산업, 레벨) 키로 캐시한다(테이블은 적재 후 불변).

### `EfficiencyRowView`를 재사용하되 풀은 따로

같은 "항목 / 값" 줄이라 프리팹을 새로 만들 이유가 없다. 다만 **둘이 동시에 보이므로**
풀(`_industryLevelInfoRows`)은 효율 계산과 분리했다.

- 자원 줄에 등급 색을 칠하려고 `SetRarity`/`backgroundImage`를 이 프리팹에 **새로 넣었다**(필수 참조).
  ⚠️ `Clear()`가 **씬 기본색으로 되돌린다** — 안 되돌리면 풀에서 재사용될 때
  효율 계산 줄이 이전 자원의 등급 색을 뒤집어쓴다.

### 진행도 슬라이더는 목록 칸의 것을 떼어 왔다

`WorkStationSlotView.prefab`을 씬에 풀어 `Progress Slider`만 꺼내 옮겼다 — **같은 값을 그리므로
규격도 같아야** 목록과 세팅이 다른 물건처럼 보이지 않는다. `interactable`·`transition`은 껐다(표시 전용).
시간 진행은 **화면의 `Update` 하나**가 맡는다(목록 화면과 같은 규칙 — 종속 View에 `Update`를 두지 않는다).

## 후속 작업 / 주의사항

- **플레이 모드 실측이 남았다** — 확인 목록은 일감 파일에.
- 🔴 **기준 주기(`RequiredScore / 1000`초)와 효율 계산의 `실효 주기`는 다른 값이다.**
  전자는 보정 **전** 표값, 후자는 적성·특성·장비가 다 들어간 값 — 나란히 보이므로
  "왜 다르냐"는 질문이 나올 자리다. 문구를 바꿀 거면 둘을 같이 본다.
- 펼침 상태에서 장비 목록을 열면 목록 영역도 92로 줄어든다(같은 자리를 나눠 쓴다). 실측에서 볼 것.

## 업데이트 (2026-09-24) — 자리 문제를 스크롤로 풀었다

사용자 확인 후 **위 "🔴 높이가 없다 — 그래서 펼침이다"의 결론이 뒤집혔다.**

### 접힘 기본 → **펼침 기본**

자리를 아끼려고 접어 두면 **있는 줄도 모른다.** 들어오면 펼쳐져 있고, 고른 탭을 한 번 더
누르면 접힌다. `OnDisable`도 `false`가 아니라 **`true`로** 되돌린다 — 접은 것은 그 화면에서의
선택이라 들고 나가지 않는다.

- 펼침 표시는 **고른 레벨의 버튼 라벨**에 붙인다 — `Lv2 밭 ▲` / `Lv2 밭 ▼`.
  다른 버튼에 붙이면 "누르면 접힌다"는 뜻이 된다.
- ⚠️ **레벨 버튼에 `LayoutElement`(`prefW 0 · flexW 1`)를 넣어야 했다.** HLG가 `ctrl(T,T) exp(T,T)`인데
  LE가 없으면 preferred width = **글자 폭**이라 `▲`가 붙은 버튼만 넓어진다 —
  장비 칸이 `▼`에 밀려 깨졌던 것과 **같은 함정**을 같은 날 두 번 밟았다(T-074 로그 참조).

### 🔴 자리 문제의 진짜 답 — 세팅 단계를 통째로 한 스크롤로

정보 패널을 220(2배)으로 키우라는 요구가 겹치면서, "누가 자리를 가져갈 것인가"를
**나눠 갖지 않는 쪽으로** 풀었다. `2 Character Setting Panel`을 **ScrollRect**로 만들고
캐릭터 카드 · 장비 4칸 · 효율 계산을 `Content` 하나에 얹었다.

| | 세팅 뷰포트 | 내용(효율 4줄) |
|---|---|---|
| 레벨 정보 펼침 | 338 | 493 → 스크롤 |
| 레벨 정보 접힘 | 563 | 493 → 다 보인다 |

- **효율 계산은 제 스크롤을 잃었다** — `Efficiency Scroll View Panel`(ScrollRect)을 없애고
  그 `Content`를 꺼내 `Efficiency Rows Panel`(VLG)로 남겼다. 스크롤 중첩을 만들지 않으려는 것이다.
- ⚠️ **`ContentSizeFitter`는 떼야 한다** — 부모가 레이아웃 그룹이면 둘이 싸운다. 높이는 제 VLG가 말한다.
- ⚠️ **`flexibleHeight`가 스크롤 안에서 뜻을 잃는다**(늘어날 상한이 없다).
  `Equip Picker Panel`은 `flexH 1` → **`pref 300` 고정**으로 바꿔야 했다.
  `flexH 1`인 채로 두면 **높이 0으로 열려 아무것도 안 보인다.**
- ⚠️ **다시 재는 대상이 바뀌었다** — `efficiencyRowParent`가 아니라 `settingScroll.content`를
  `ForceRebuildLayoutImmediate`한다. 줄만 재면 스크롤 길이가 한 프레임 늦어 끝이 잘린다.
- 장비 목록을 열면 **스크롤을 맨 아래로 내린다**(`verticalNormalizedPosition = 0`).
  화면 밖에서 열리면 누른 보람이 없다. **다시 잰 뒤에** 내려야 한다.

### 🪤 함정 — `ScrollRect` 안은 별도 레이아웃 루트다

`ForceRebuildLayoutImmediate(#Main Canvas)`로 재면 스크롤 `Content`가 **패딩값(10)만** 나온다.
안 도는 게 아니라 **거기까지 내려가지 않는 것**이다. `Content`를 직접 대상으로 재야 실제 값(366)이 나온다.
T-074에서 밟은 "부모가 낡은 rect를 읽는다"와 **다른 함정**이니 둘을 섞지 말 것.

### 🪤 함정 — 코드를 고치고 컴파일하기 전에 씬 스크립트를 돌리면

새로 추가한 `[SerializeField]`가 아직 없어 `SerializedObject.FindProperty`가 `null`을 주고
**NRE로 스크립트가 중간에 죽는다**(씬이 반쯤 바뀐 채 남는다). `unity cmd recompile` →
`recompile_status` 확인 **다음에** 씬 스크립트를 돌린다. 중간에 죽었으면 `OpenScene`으로 다시 열어 버린다.

### 그 밖

- 정보 줄을 `■ 작업지 정보` / `■ 나오는 자원` 두 묶음으로 갈랐다.
- 자원 줄에 **판매가**를 비율 옆에 붙였다(`ItemTable.BasePrice`) — "자주 나오지만 싼 것"과
  "드물지만 비싼 것"이 한 줄에서 갈려야 레벨을 올릴지 정할 수 있다.
- ⚠️ 줄을 켤 때 **`Clear()`를 먼저 부른다** — 묶음 제목이 앞서 자원 줄로 쓰이던 오브젝트의
  등급 색을 뒤집어쓰지 않게.

## 업데이트 2 (2026-09-24) — 스크롤을 하나로 합쳤다

### 🔴 스크롤이 3중이었다

레벨 정보 · 세팅 · 그 안의 장비 목록이 저마다 `ScrollRect`였다. 사용자가 먼저 이상하다고 지적했고,
따져 보니 근거가 셋이었다 — **① 휠이 어디로 갈지 모른다**(uGUI는 안쪽이 먼저 먹고 끝에 닿아도
바깥으로 넘겨주지 않는다) **② `Permanent` 스크롤바 3개 = 60px** **③ 영역마다 높이를 나눠 주느라
220/338로 쪼개져 "조금씩만 보이는" 답답함이 생긴다.**

**머리(제목 · 산업 · 산업 레벨)만 고정, 그 아래 전부를 `Body Scroll Panel` 하나에** 담았다.
머리를 남긴 이유는 산업·레벨이 "지금 무엇을 보고 있나"의 표시이고 **레벨 정보를 접는 조작도
그 버튼에 있기 때문**이다 — 함께 굴러가면 접으려고 위로 되돌려야 한다.

- 스크롤을 벗기는 수법은 하나다: **`Viewport > Content`를 패널 자리로 승격시키고 껍데기를 버린다.**
  이름은 참조가 걸려 있어 그대로 물려준다(`1 Character Assign Panel` · `Efficiency Rows Panel` · `Equip Rows Panel`).
- ⚠️ **`flexibleHeight`가 스크롤 안에서 뜻을 잃는다.** `flexH 1`로 두면 **높이 0으로 열린다** —
  속 패널은 전부 `flexH 0` + 내용만큼이다. `Equip Picker Panel`을 `pref 300`으로 고정했다가
  이번에 그것도 풀었다(내용만큼).
- ⚠️ `ContentSizeFitter`는 **스크롤의 `Content` 한 곳에만.** 속 패널에 달면 부모 레이아웃 그룹과 싸운다.
- ⚠️ 줄을 그린 뒤 다시 재는 대상은 **언제나 `bodyScroll.content`**다(효율 줄·레벨 정보 줄 모두).
- 실측: 뷰포트 563 · 펼침 962(스크롤) · 접힘 532(다 보임). 레벨 정보는 12줄이 **425로 전부** 나온다.

### 🪤 함정 — 껍데기를 버릴 때 `Viewport`의 형제도 같이 죽는다

캐릭터 목록의 `Empty Text`는 목록 **위에 겹쳐** 있어서 `Viewport`의 **형제**였다.
껍데기를 지우면서 **같이 지워졌고**, 하필 `find`가 장비 목록의 동명 오브젝트를 집어
그쪽 문구가 캐릭터 목록으로 끌려갔다. 둘 다 복구했다(문구는 `git show HEAD:<씬>`에서 되찾았다 —
"해당 적성을 가진 캐릭터가 없습니다."). 지금은 **목록의 첫 줄**로 내려와 장비 목록과 같은 방식이다.

> 교훈: `Viewport`만 보고 껍데기를 지우지 말고 **패널의 직계 자식을 먼저 세어 본다.**
> 그리고 `Empty Text (TMP)` 같은 **흔한 이름은 `find`로 집지 않는다** — 부모를 지정해 집는다.

### 자원 줄은 프리팹을 따로 만들었다 (`IndustryDropRowView`)

`19.51%  ·  2,025 골드`를 `EfficiencyRowView`의 값 한 칸(120px)에 넣었더니 **잘렸다**(사용자 스크린샷).
칸을 나눠 **이름 / 확률 80 / 판매가 130** 고정폭으로 주면 잘리지 않고, 덤으로 **세로 열이 맞는다** —
`0.1%`와 `64.29%`가 한 칸에 있으면 자릿수 때문에 어긋난다. 최악값(`999,999 골드` = 101px) 실측 확인.

- ⚠️ 스펙 줄(`EfficiencyRowView`)과 **부모를 나눠 쓴다.** 자원 줄은 켤 때마다 `SetAsLastSibling()`으로
  뒤로 보낸다 — 생성 순서에만 기대면 순서가 뒤집힐 수 있다.

## 업데이트 3 (2026-09-24) — 장비를 고르는 동안에는 장비 칸만 남긴다

**장비는 앞으로 계속 늘어난다** — 목록이 길어질수록 자리가 모자라진다. 그래서 고르는 동안에는
위아래를 전부 접어 **장비 칸 넷을 고정 머리 바로 아래로 올린다**(사용자 요청).

| 접는 것 | |
|---|---|
| 위 | 산업 레벨 정보 · `Character Label` · 캐릭터 카드 |
| 아래 | `Efficiency Label` · `Progress Panel` · `Efficiency Rows Panel` |

- 접고 나서 **스크롤을 맨 위로 되돌린다**(`ScrollToTop`). 접힌 만큼 내용이 짧아지는데
  보던 자리에 그대로 서 있으면 엉뚱한 곳이 보인다. ⚠️ **다시 재고 나서 옮긴다** —
  켜고 끈 패널 크기가 반영되기 전이면 옮길 길이 자체가 정해지지 않았다.
  (앞서는 `verticalNormalizedPosition = 0f`로 **맨 아래**로 내렸는데, 위를 접게 되면서 뜻이 없어졌다.)
- ⚠️ **닫을 때 레벨 정보는 되살리지 않는다.** 고르려고 접은 것을 되돌리면
  **사용자가 스스로 접어 둔 것까지 덮어쓴다.** 캐릭터 칸만 되돌린다.
- 캐릭터 카드는 `assignedCard.gameObject`로 끄고, 라벨만 참조가 없어 `characterLabel`을 새로 받았다.
- 실측: 장비 12줄일 때 목록이 489 — 뷰포트 563에서 장비 칸·라벨 144를 뺀 자리를 다 쓴다.
