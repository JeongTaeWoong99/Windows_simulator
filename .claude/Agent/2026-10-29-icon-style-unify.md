# 아이콘 화풍 통일

## 목적 / 배경
- AI 생성(Unity AI) 시험 전에, 지금 넣어 둔 무료 팩 아이콘부터 한 규격으로 맞추자는 요청.
  이 규격이 있어야 구매 에셋·AI 그림도 같은 굽기로 맞춰진다.
- 실측: 자원 8~19px · 장비 16px · 아티팩트/산업 ~30px(칠한 그림). 칸이 `preserveAspect`로 꽉 채우니 아이콘마다 픽셀 굵기가 달랐다.

## 변경 내용
- `ArtImage` — `FitPixelGrid`(긴 변 N 이하로 칸 평균 축소 · 알파 0/255) · `Outline`(1px) · `CenterOn`(정사각 캔버스)
- `ArtSpec` — `IconGridSize 16` · `IconCanvasSize 18` · `IconOutline #19141E`
- `ArtBaker.BakeIcons` — 위 세 단계 적용 · **TID 0도 굽는다**(대체 아이콘)
- 그림 저장소: 아이콘 277장 다시 구움 · `item_0`/`equip_0` 원본을 `_source/icons/fallback/`로 옮겨 레시피 TID 0에 등록
- 규칙: `Art 규칙.md` "아이콘 넣기" · `art-import 규칙.md`

## 주요 결정 / 근거
- ~~캔버스 고정(18×18)~~ (아래 업데이트에서 되돌림) — 줄이기·외곽선만으로는 칸이 그림 크기에 맞춰 늘려서 픽셀 굵기가 다시 어긋난다. 클라 코드는 안 고쳤다.
- 작은 그림은 키우지 않는다 — 키우면 픽셀이 굵어져 같은 문제. 작은 아이콘은 작게 보이는 대신 픽셀이 맞는다.
- 외곽선은 어두운 색 — 흰색은 밝은 배경에서 묻힌다(미리보기 비교). 원래 외곽선 있는 팩에도 똑같이 두른다(조건부로 두르면 두께가 갈린다).
- 색 수 줄이기(공용 팔레트)는 그림이 상할 위험이 있어 보류.

## 후속 작업 / 주의사항
- 캐릭터는 손대지 않았다 — `characterScale` 0.75~2.65·`pixelScaleOverride` 1.2/1.4는 사람이 다듬은 SO 값이라 픽셀 밀도 통일과 충돌한다. 외곽선만 미리보기로 보고 결정 대기.
- 그림 저장소(`Assets/Art/`) 변경은 커밋 전.

## 업데이트 (2026-10-29) — 16px 고정 캔버스 되돌림 · 32px 기준 · 해상도 검사
- 사용자 실측: 흐려지고(22~32px 원본을 16으로 줄임) 하트 등이 칸 속에 작게 떴다(9~19px를 18 캔버스에 그대로).
  원래 아이콘은 **9~32px — 64는 없었다.** → 기준 32 · 넘을 때만 줄임 · 캔버스는 그림에 딱 맞춤(칸이 꽉 채움) · 외곽선 유지. `CenterOn` 삭제.
- 픽셀 굵기 차이는 굽기로 못 없앤다(작은 원본은 칸이 크게 늘린다) — **검사(`CheckResolution`)가 기준 미달을 알린다**: 아이콘 24px 미만 180개 · 캐릭터 `characterScale` ×1.5 초과 10명.
- ⚠️ 발견: `evil-wizard`·`evil-wizard-2`·`medieval-warrior` 레시피 `downscale: 2`가 **디테일 있는 원본을 반으로 버리고** SO가 다시 ×2로 키우고 있었다(원본이 2×2 블록이 아님 — 확인함).
  `downscale 1`이면 디테일이 두 배 — 대신 SO `characterScale` 절반 · 상반신/머리 크롭 다시 잡기가 필요(사람 몫 값이라 확인 대기).
- 검사에 배경 ❌(층 높이 ≠ 무대 높이) 24줄이 난다 — 배경 검사·굽기는 이번에 손대지 않았다. 원인 미확인.

## 업데이트 (2026-10-29) — 캐릭터 3명 원본 해상도로 다시 굽기
- `evil-wizard`·`evil-wizard-2`·`medieval-warrior`: 레시피 `downscale 2→1` · 레시피 `bodyRect`/`portraitRect`/`headRect`를 발(112, 0) 기준 2배 · SO `characterScale` 절반(1.95→0.975 · 2→1 · 1.5→0.75). SO 나머지 값은 그대로(diff 확인).
- `stopGapOffset`은 안 바꿨다 — 사거리(2배)×배율(절반)이라 무대 거리는 같다.
- ⚠️ **칸 높이 96이 원본 해상도를 못 담는다** — `evil-wizard-2` 지팡이 연기(대기·공격 2)가 위로 잘리고, `medieval-warrior` 공격 1의 칼끝이 위로 3프레임 잘린다. 화염 마법사는 가장자리에 닿지 않는다(잘림 경고는 나지만 위·왼·오 가장자리 닿은 픽셀 0).
  → 사용자 결정: **화염 마법사만 원본 해상도로 두고 두 명은 되돌렸다**(git checkout · 그림 저장소에서 두 폴더는 변경 없음). 칸 높이(96)를 키우면 둘도 올릴 수 있다 — 전체 다시 굽기·슬롯 점검이 따르는 큰 작업.

## 업데이트 (2026-10-29) — Unity AI 생성 시험 (아이콘 5 · 캐릭터 1 · 동전 · 패널 · 효과음 2)
- 방법·비용·원본 목록은 `Art 규칙.md` "AI로 만든 그림 넣기" · 원본 목록. 크레딧 1000 → 실측 잔액은 보고 참조.
- **AI 출력은 1024px 가짜 픽셀** — `_source/ai_to_pixel.py`가 칸마다 최빈색으로 줄인다(평균은 번진다). 원본은 `<팩>/raw/`.
- 영상 모델 스프라이트시트(Kling): 4×4 · 256칸 · **배경이 투명이 아니라 회색 + 발밑 그림자** — 가장자리 flood fill + 채도 없는 밝은 회색 지우기 + 납작한 조각(높이 ≤2) 지우기. 흰 옷 캐릭터는 밝은 회색 지우기가 하이라이트도 지우니 손본다.
- **시트는 모든 프레임을 같은 배율로 줄인다** — `to_pixel`은 그림 부분만 잘라 맞추므로, 프레임 모서리에 임시 불투명 점을 찍어 칸 전체를 고정한 뒤 지운다(키 출렁임 방지).
- 시트 앞 3~4프레임은 기준 그림 그대로(서 있음), 잔상 프레임이 섞인다 → run 4~15 중 잔상 1장 뺌 · attack 3~9.
- 효과음·UI 패널은 넣기만 했다 — 클라에 사운드 재생 코드가 없고 패널은 연결할 화면이 없다.
