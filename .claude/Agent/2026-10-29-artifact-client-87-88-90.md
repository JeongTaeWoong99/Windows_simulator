# 아티팩트 클라 묶음 (#90 · #88 · #87 — T-151)

## 목적 / 배경
- 서버 PR #97 · #98 · #100이 머지돼 막혀 있던 T-151의 클라 몫 셋을 한 번에 붙였다. 세 이슈가 같은 화면(장비 탭 아티팩트 칸 · 도감 · 감정 결과)을 건드려 묶었다.

## 변경 내용
- #90 — `PlayerDataModel._artifactCodex`를 `HashSet<int>`로(켜짐 값 없음). 상세 패널 버튼·대기·요청 삭제 · 도감 칸 '꺼짐' 딤 삭제 · 상태 문구는 `UI.Artifact.FilterEquipped`('장착') 재사용. 씬의 `Detail Root/Text Column/Action Row` 삭제(MCP)
- #88 — `InventoryGridPresenter`: `ItemType.Relic`이면 수량 없는 확인 팝업(`AskConfirm` · `UI.Inventory.AskAppraiseOne`) 뒤 `OpenBox(itemId, 1)` — 처음엔 바로 감정했다가 사용자 피드백으로 확인을 넣었다(귀해서). `GachaResultPresenter.AppraiseAsync`: 무대가 끝나면(스킵이면 `RelicAppraiseFx.ShowEnd`) 보상을 띄운 채 머물고(`_isAppraiseHeld`) 바탕 클릭으로 닫힌다. 결과 칸 목록 없음 · 골드 보상이면 보상 자리에서 동전
- #87 — `EquipSlotSource.FillArtifacts`가 `ArtifactStacks[].Slot`에 그대로 앉힌다 · 끌기·놓기 거절 삭제 · Ctrl+좌클릭 잠금(`ELockTarget.Artifact`, Id = 번호) · `LockedArtifactTids`/잠금 응답으로 `_lockedArtifactTids` · 판매(우클릭·일괄·판매 목록 정리)·경매(우클릭 바로가기·등록 창 흐린 줄)에서 잠긴 번호 차단(`EntityBlockText.ForArtifact`) · 아티팩트 ↔ 창고 끌기는 클라가 먼저 막는다
- Loc_UI — 추가 `UI.Artifact.NoWarehouse` · `UI.Result.StorageSlotArtifact` · `UI.Inventory.AskAppraiseOne` / 삭제 HelpToggle · Off · StateOn/Off · TurnOn/Off · WaitToggle · NoLock · NoMove

## 주요 결정 / 근거
- `S_ArtifactActiveResponse` 핸들러는 로그만 남기고 둔다 — 패킷이 미러에 남아 있는 한 핸들러가 없으면 MIKA001. 서버가 패킷 90·91을 지우면 이 핸들러도 함께 지운다
- 아티팩트 칸 Key는 번호(음수)라 같은 번호가 여러 칸이면 Key가 겹친다 — 자원 칸(`ItemId` Key)과 같은 모양이라 그대로 뒀다
- 잠금 응답은 칸 스냅샷을 다시 보내지 않는다(서버) → `OnEntityLockResponded`에서 캐시를 고치고 `ArtifactsChanged`
- 스킵한 감정 무대의 끝 모습은 한 프레임 쉰 뒤 `ShowEnd`로 놓는다 — 같은 프레임에 `DOTween.Kill(this)`를 부르면 죽는 중인 트윈을 또 Kill한다(기존 주석과 같은 함정)
