# Drop 엑셀 산업별 파일 분리 + 시트 병합 규약

## 목적 / 배경

- 산업 레벨이 5 → 30~40으로 늘어날 수 있어, 한 시트에 레벨이 행으로 쌓이는 구조(산업당 38행 → 예상 300행+)를
  미리 갈랐다. 사용자 확정: **파일=산업, 시트=레벨, 제너레이터가 병합.**
- 서버(DropTableCatalog)의 레벨 무시 오동작 수정은 **범위 밖** — 그대로 T-017.

## 변경 내용

- `Server/ExcelGenerator/ExcelGenerator.cs` — **시트 병합 규약** 신설.
  시트 이름 `<테이블명>.<접미사>`의 `.` 앞부분으로 그룹핑해 한 테이블로 이어 붙인다.
  스키마(ColumnInfo 시퀀스) 불일치는 파일·시트·컬럼을 짚어 fail-fast. 규약 상세 → `excel-table-creator` 스킬.
- `GameDesign/Excel/` — `Drop.xlsx` 삭제 → `Drop농사`·`Drop낚시`·`Drop채굴`·`Drop벌목`·`Drop사냥.xlsx`
  (각 `<산업>BasicTable.Lv1`~`.Lv5` 시트). `Industry.xlsx`는 파일 유지, `IndustryLevelTable.농사`~`.사냥` 시트로 분리.
- **DropTID 재채번**: `산업×1000+레벨×100+순번` → **`산업×100000+레벨×100+순번`** (구식은 레벨 10부터 산업 대역 침범).
- 문서: `산업레벨.md` 6.1·6.2, `gathering/README.md` 3장, `fishing/README.md` 5장, `문서관계도.md` 대응표,
  `excel-table-creator` 스킬, CLAUDE.md 파이프라인 절, T-005·T-008·T-017.

## 주요 결정 / 근거

- **병합 그룹핑을 파일 경계 없이 전역으로** 했다 — Industry.xlsx(파일 유지)와 Drop(파일 분리)이 같은 메커니즘을 쓴다.
  관례는 "한 테이블은 한 파일 안"으로만 잡았다.
- **모든 시트가 마커 행 전체를 갖는다** (첫 시트만 스키마를 갖는 안 기각) — 시트 복사로 새 레벨을 만드는 흐름과 맞고,
  탭 순서에 의미가 생기는 것을 피했다. 드리프트는 병합 검증이 잡는다(훼손 테스트로 확인).
- **DropTID 산업 자리 = `ItemType` enum 값**(농사1·낚시2·채굴3·벌목4·사냥5)으로 통일 — `IndustryLevelTID`와 같은 기준.
  ⚠️ **`ItemTID` 대역(낚시1·농사2·벌목3·채굴4·사냥5)과는 이제 어긋난다** — ItemTID는 DB 저장 정수라 이설하지 않았다.
  산업 역산은 어차피 금지(T-005 경고)라 실해는 없다. 대역 통일이 필요해지면 확장–수축으로 별도 일감.
- `IndustryLevelTID`(산업×100+레벨)는 레벨 99까지 버텨 **재채번하지 않았다.**
- 마이그레이션은 ClosedXML `CopyTo`로 시트째 복사 후 타 레벨 행 삭제 — 마커 행·서식이 그대로 보존된다.
  (일회용 도구는 스크래치패드에만 있고 커밋하지 않는다)

## 후속 작업 / 주의사항

- 검증 완료: 파이프라인 통과(테이블 6종·행 수 보존), DataLog diff = **DropTID 190행 변경뿐**, 서버 테스트 119개 통과,
  스키마 훼손 시 fail-fast 확인.
- 🔴 **작업 도중 사용자가 저장소 폴더를 영문 개명 중이었다** (`일감`→`tasks`, `기획`→`design`, `자원채취`→`gathering` …).
  이 로그의 경로는 개명 후 기준. **`check-doc-graph.ps1`이 `GameDesign/기획` 하드코딩으로 즉시 실패한다** —
  개명 작업 쪽에서 스크립트 경로·문서 상대 링크 전수 수정이 필요하다. 이번 변경분의 그래프 검사는 그래서 못 돌렸다.
- 레벨 6+ 추가 절차: 산업 파일에 `.Lv6` 시트 복사 → `IndustryLevelTable.<산업>` 시트에 행 추가.
  Drop 시트 `IndustryLevel` 컬럼의 `Max` 마커(현재 5)를 함께 올려야 한다.
- `RequiredScore` ×3 등비는 레벨 10부터 서버 밀리초 환산이 `int`/`long` 한계를 위협한다 — 곡선 재설계 시점에 처리(수치는 테스트값).
