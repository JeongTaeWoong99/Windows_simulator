# 창고 칸의 적성 표시를 5칸 스트립으로 (T-048)

→ 범위·결정 항목은 `tasks/archive/T-048-창고칸적성표시.md`, 구조 설명은
`Assets/Scripts_Client/UI/Storage/Storage 규칙.md`의 "하단 밴드는 하나고, 두 표시가 나눠 쓴다".

## 목적 / 배경

- T-046이 칸의 보조 문구를 적성 요약(`농사7·낚시2`)으로 바꿨는데, **5종을 다 가진 캐릭터에서
  글자가 뭉개졌다.** 실측하면 `농사1·낚시1·채굴1·벌목1·사냥1` = 19자가 폭 100 · 높이 20의
  자리에 들어가 **약 5px**이 된다(autosize `min 1`이라 경고도 없이 줄어든다).
- **전 산업 적성 1인 기본 지급 캐릭터(TID 1)가 그 최악의 경우**라 흔한 화면이다.

## 주요 결정 / 근거

| 갈림길 | 결정 | 근거 |
|--------|------|------|
| 형태 | **하단 밴드를 20×20 다섯 칸으로.** 위치가 곧 산업, 내용은 숫자만 | 텍스트로는 어떤 방식으로도 안 들어간다(2줄로 펴도 10자/줄 → 9px). **아이콘이 들어올 자리와 같아서** 에셋이 오면 배경 스프라이트만 갈아끼운다 — 두 번 만들지 않는다 |
| 적성 0 | **`X`(회색)로 채운다** (처음엔 빈 칸이었다 → 아래 업데이트) | 칸을 지우면 위치가 밀려 남은 값이 다른 산업으로 읽히고, 비우면 배선 누락처럼 보인다 |
| 대안 (기각) | 최고 적성 1개 + `+N` | 코드 몇 줄로 끝나지만 *"낚시 적성이 있나"* 를 답하지 못한다 — 배치 목록이 적성 0을 걸러 내므로 **그 답이 창고밖에 없다**(T-046의 근거) |
| 대안 (기각) | 칸에서 빼고 상세 패널로 | 정석이지만 상세 패널 자리를 판매 카트가 쓰고 있다(`StorageInformationPresenter` 이름 어긋남) |
| 값의 전달 | `StorageSlotData`는 **안 건드린다.** 격자가 읽어 칸에 넘긴다 | 캐릭터 전용 필드를 공용 struct에 넣으면 자원·가챠 칸까지 따라 두꺼워진다. `Assign Mark`가 `FindSlotIndexOf`로 처리되는 것과 같은 방식 |
| 문구/스트립 전환 | **칸이 쥔다**(`SetAptitudes(null)`이면 되돌린다) | 자리가 하나라는 것은 프리팹의 사실이다. 부르는 쪽이 둘을 각각 켜면 한쪽만 고쳐졌을 때 **두 표시가 겹친다** |

## 지뢰 / 주의사항

- 🔴 **`aptitudeValueTexts`의 순서가 곧 산업이다** (농사·낚시·채굴·벌목·사냥).
  인스펙터에서 섞으면 **값이 조용히 다른 산업 칸에 들어간다** — 컴파일도 경고도 통과한다.
  그래서 배열에 `[NonReorderable]`을 달고 `Awake`가 개수만이라도 확인한다.
- ⚠️ **`SetSubVisible`과 `SetAptitudes`는 같은 위젯의 가시성을 건드린다.** 그래서 칸이
  `_isSubAllowed`를 기억한다 — 없으면 스트립을 끌 때 **가챠 결과 팝업이 꺼 둔 문구가 되살아난다.**
- `CharacterSlotSource.BuildAptitudeText`(+`StringBuilder`·`NoAptitudeText`)를 걷어냈다.
  남겨 두면 표시 경로가 둘이 되어 다음 사람이 어느 쪽이 진짜인지 알 수 없다.
- 200칸 × 5개를 매번 그리므로 **숫자 문자열(0~10)과 `byte[5]` 버퍼를 재사용한다.**
  `ReadAptitudes`가 돌려주는 배열은 **공유된 하나**다 — 보관해 두는 쪽이 생기면 복사해야 한다.
- 프리팹 편집은 Unity MCP로 처리했다(`PrefabUtility.LoadPrefabContents` → `SaveAsPrefabAsset`).
  `Aptitude Strip`은 **프리팹에서 켜진 상태**로 두었다 — 편집할 때 보이도록. 런타임에는 `Awake`가 끈다.
- 칸 배치에 LayoutGroup을 쓰지 않고 **앵커를 0.2씩 나눴다** — 폭이 바뀌어도 5등분이고
  레이아웃 리빌드가 칸 수만큼 돌지 않는다.

## 실측 (에디터, 2026-09-12)

임시 캔버스에 프리팹을 찍어 `{1, 10, 0, 4, 7}`을 넘겨 확인했다.

- 칸 20×20 · **실제 글자 크기 14** (autosize 상한에 그대로 붙었다 = 줄어들지 않았다).
  두 자리(`10`)도 14를 유지한다 — **기존 5px에서 약 3배**다.
- `null`을 넘기면 스트립이 꺼지고 수량 문구가 돌아온다. (적성 0의 표시는 아래 업데이트에서 바뀌었다)

## 후속 작업 / 주의사항

- ⏳ **플레이 확인이 남았다** — 등급색 배경 위에서의 가독성(칸 배경을 검정 55%로 깔았다),
  초상화가 들어온 뒤의 겹침, 탭을 오갈 때 문구↔스트립 전환. (칸 배경 알파는 아래 업데이트에서 0.78로 올렸다)
- 🎨 산업 아이콘이 오면 각 칸의 `Image`에 스프라이트만 넣는다. **그때 약칭(농·낚·광·목·렵)을
  넣을지 판단**한다 — 지금 넣으면 아이콘이 오는 순간 걷어낸다(→ T-048의 D).
- `IndustryLabel.cs`는 스트립이 쓰지 않는다(이름을 안 쓴다). 걷어내는 것은 여전히 T-047의 몫이고
  작업슬롯 화면이 아직 쓴다.

## 업데이트 (2026-09-12) — 1차 실물 확인 뒤 표시 셋을 손봤다

- **적성 0을 `X`(회색)로 채운다.** 빈 칸으로 두니 **배선이 빠진 칸처럼 보였다** — 실물에서
  드러난 것이라 적어 둔다. "못 다루는 산업"은 알려 줄 값이 없는 게 아니라 알려 줄 것이 있는 상태다.
  숫자는 흰색, `X`는 회색이라 눈이 먼저 숫자를 읽는다.
- **칸 경계를 틈으로 냈다.** 숫자 다섯이 한 줄처럼 붙어 보였다 — 각 칸이 1px 물러서
  이웃 사이에 2px가 비고 그 틈으로 등급색이 비친다(칸 18×18 · 배경 검정 78%).
  ⚠️ **테두리 스프라이트가 들어오면 이 틈은 걷어낸다** — 사용자가 이미지를 넣기로 한 자리다.
- **자원 수량에 단위를 붙였다** (`12` → `12 개`, `ResourceSlotSource`). 숫자만 두면
  칸만 보고 수량인지 등급인지 레벨인지 알 수 없다.
