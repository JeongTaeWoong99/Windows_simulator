# PR CI 수리

## 목적 / 배경
- 서버 작업을 PR로 올리기 시작한 뒤(2026-10-25) 모든 PR에서 `서버 CI`와 `일감 정합성 검사`가 실패했다.

## 변경 내용
- `.github/workflows/server-ci.yml` — `permissions: contents: read · pull-requests: write`. 원인: 기본 토큰 읽기 전용 → `marocchino/sticky-pull-request-comment`가 `Resource not accessible by integration`
- `GameDesign/web/scripts/check-tasks.mjs` — `--pr` 플래그: 루트 INDEX의 목록 누락·상태 불일치(2번)와 보관 건수(3번)를 건너뛴다
- `.github/workflows/tasks-check.yml` — `pull_request` 이벤트면 `--pr`
- 사례조사 4개 문서의 `tasks/T-145-…` 링크 → `tasks/later/T-145-…` (main에서도 실패하던 것)
- `docs/CI.md`

## 주요 결정 / 근거
- INDEX는 "머지 뒤 main에서 갱신" 규칙이라 PR에서 INDEX 불일치는 정상이다 — 검사를 규칙에 맞췄다. main push에서는 그대로 전부 검사한다
- 1번(목록 → 파일)은 PR에서도 유지한다 — 목록이 없는 파일을 가리키는 것은 PR에서도 잘못이다

## 후속
- 이 PR CI에서 커버리지 코멘트가 실제로 붙는지 확인 (server-ci.yml을 고쳐서 이 PR에서도 돈다)
- 같은 시각 다른 세션이 `T-186`을 아티팩트 칸 합치기·잠금에 쓰고 있다 — 유물 1개씩 감정(PR #97)과 번호가 겹친다
