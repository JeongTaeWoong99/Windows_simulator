# 서버 답이 돌아온 이슈 #30·#31 정리 · #32 접수

## 목적 / 배경

서버가 이슈 둘(#30 가챠 1번 풀 · #31 치트 `Unlock`)에 답을 달고 "확인되면 닫아 달라"고 넘겼다.
둘 다 **클라 코드 변경은 없고** 문서·실측만 남은 상태였다. 새로 온 #32(우편 패킷)는 접수만 했다.

- `GameDesign/design/item/README.md` 4장 — 가챠 1번 풀 문구
- `tasks/T-031` · `tasks/archive/T-068` — 이슈 대기 표시 해제 + 결론 기록
- 커밋 `3e61d98`

## 주요 결정 / 근거

- **가챠 1번 풀은 테이블에 남긴다.** 클라에서 버튼을 지웠다고 서버 행까지 지우면
  `GachaServiceTest`가 `GachaInfoTable` 1번의 **비용 메타를 읽고 있어 테스트가 깨진다.**
  "화면에서 빼는 것"과 "데이터를 지우는 것"이 다른 결정이라는 게 이 건의 요지다.
- **치트창 해금 목록은 손대지 않는다.** 서버가 속도 재정산을 `TryLearnTrait`에서
  해금 공통 후속(`ApplyUnlock`)으로 옮겨, 치트·찍기·퀘스트 보상 어느 경로든 같은 시점에 속도가 붙는다.
  **포인트는 치트 정의대로 차감하지 않는다** — 그래서 치트창에 특성 전용 버튼을 따로 붙이려던 안은 폐기했다.

## 후속 작업 / 주의사항

- ⚠️ **특성 포인트까지 보는 검증은 치트 「해금」으로 하면 안 된다** — 포인트가 안 빠져 검증이 성립하지 않는다.
  트리에서 직접 찍어야 한다.
- #32(우편)는 **열려 있다.** 클라 `S_Mail*` 4종 핸들러가 없어 MIKA001 경고 4건이 떠 있는 상태 →
  `tasks/T-083` · `tasks/T-064`. 패킷 미러는 이미 들어와 있다.
