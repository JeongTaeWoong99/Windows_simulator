# 서버 콘솔 창 프레임 드랍 — 로그 표시를 가상 스크롤로 교체

## 목적 / 배경
- 서버를 켜고 서버 콘솔 창이 보이는 동안 EditorLoop 스파이크가 나서 프레임이 30까지 떨어졌다. 창이 가려지면 렉이 없었다(사용자 확인).
- 원인: 로그 전체를 문자열 하나로 `CalcHeight` + `SelectableLabel`에 넘겼다. 한 줄만 늘어도 새 문자열이라 IMGUI 텍스트 캐시가 빗나가 전체를 다시 레이아웃했다. 서버가 약 1.8초마다 로그를 찍어 그 주기로 멈칫했다.

## 변경 내용
- `Assets/Scripts_Client/Editor/server-console/ServerConsoleWindow.cs` — 전체 문자열 경로를 제거했다.
  - 스크롤 높이를 `줄 수 × 줄 높이`로 잡고 화면에 걸친 줄만 `GUIStyle.Draw`로 그린다.
  - 줄 단위 선택(클릭·Shift·드래그)과 Ctrl+C·Ctrl+A·우클릭 복사를 넣었다.
  - `AppendChunk`의 O(n²)을 제거했다. `OnEnable`은 파일 끝 2MB만 읽는다. `MaxLines`를 10000으로 늘렸다.
- `ServerRunner.cs` — `IsRunning`의 `Process`를 `using`으로 닫는다.
- `server-console 규칙.md` — "로그 표시" 항목(실측 수치·설계 이유)을 추가했다.

## 주요 결정 / 근거
- 실측(neodgm 16px, `CalcHeight` 캐시 미스)
  - 전체 문자열 방식: 100줄 58ms, 493줄 377ms, 5000줄 6.2초. 기본 폰트도 5000줄 1.15초라 폰트 교체로는 해결되지 않는다.
  - 줄 단위 방식: 처음 보는 40줄 38ms(한 화면 넘길 때 1회), 캐시 적중 40줄 0.65ms.
- "일정 양만 보여 주고 나머지는 파일 열기"는 기각했다. 쌓는 게 문제가 아니라 안 보이는 줄까지 그리는 게 문제라, 가상 스크롤이면 전체 스크롤을 유지할 수 있다.
- 가로 스크롤 폭은 **그린 줄만** `CalcSize`로 재서 넓힌다. 전체 줄을 미리 재면 5000줄에 4.9초가 걸린다. 고정폭 셀 계산(ASCII 1, 한글 2)은 neodgm 실제 폭과 안 맞았다(460 vs 640).
- UI Toolkit `ListView`도 가상화가 되지만, 가로 스크롤·고정폭 폰트 제어가 번거롭다. 기존 IMGUI 창을 유지했다.
- 대가: 여러 줄에 걸친 드래그 **텍스트** 선택이 사라졌다(줄 단위 선택으로 대체).

## 후속 작업 / 주의사항
- `DrawLog`는 `GetControlID`를 Layout 분기보다 **앞에서** 받아야 한다. Layout에서 일찍 return하므로, 순서가 바뀌면 드래그·키보드 포커스 ID가 이벤트마다 어긋난다. `DrawLog` 뒤에 IMGUI 컨트롤을 추가하면 같은 이유로 깨진다.
- 줄 높이 고정이 전제다. `wordWrap`을 켜면 가상 스크롤이 성립하지 않는다.
- 미검증: 10000줄 이상 부하 상태의 Profiler 확인. 작업 당시 서버가 실행 중이라 로그 파일을 교체하지 못했다. 컴파일 오류·경고가 없는 것까지만 확인했다.
