# 슬롯 연출 — 공격은 모션 전체 · 남는 시간은 달리기로

## 목적 / 배경
- 최소 주기 2.1초(×10 치트)에서 공격이 1번이 아니라 2번 나갔다(사용자 실측).
- 원인: 2.1초 = 여운 0.3 + … + 공격 0.6으로 셌는데, 판정은 공격의 **타격 프레임**(약 1/3 지점)이고 타격 뒤가 다음 주기 여운으로 재생됐다 —
  타격 뒤 시간을 두 번 센 셈. 남은 공격 구간 0.6초를 옛 `Fit`이 "공격 길이 0.6에 가장 가까운 횟수"로 채워 2번(각 0.54초)을 골랐다.

## 변경 내용
- `SlotStageTimeline.Evaluate` — 공격은 늘 `AttackSeconds` 그대로 끝까지. 처치 타의 타격 뒤는 다음 주기 맨 앞(Recover)에서 마저 하고,
  바로 달린다. 공격 횟수 = 달리기를 다가오기 이상으로 두고 온전히 들어가는 수, 나머지(<0.6초)는 달리기로. `Fit` 삭제
- `SlotStageSettings` 여운(`recoverSeconds`)·숨(`idleSeconds`) 삭제 · `EPhase.Idle` 삭제 · `RequiredCycleSeconds` 1.6초
- 기획 문서: 게임UI 2.5(연속 공격 · 남는 시간 · 끊김 없이 · 최소 주기 · 짧은 주기) · 게임기획코어 확정 표

## 주요 결정 / 근거
- 사용자 결정 — "공격 애니메이션은 타격 위치와 상관없이 0.6초를 다 재생, 0.6초 미만으로 남는 시간은 달리기로".
- 최소 주기는 연출 한 바퀴에 맞춰 **1.6초로 내린다**(사용자 결정, 2026-10-13) — 엑셀·서버 테스트·서버 문서가 걸려 서버에 넘겼다 → T-149 · 이슈 #70. 반영 전까지는 2.1초라 달리기가 1.5초다.
- **공격과 달리기만 남겼다 — 대기 자세(여운·숨) 전부 삭제.** 사용자 지적 세 번(같은 날)의 결론:
  공격 끝 프레임 유지 → 굳어 보임 / 대기 0.3+0.1 → 늘어져 보임 / 대기 0.1 → 자세가 한 번 더 바뀌어 뚝딱거림.
  흐름: 처치 타 나머지(타격 뒤 프레임) → 달리기 → 공격. 2.1초면 달리기 1.5초, 달리기가 1.6초가 되는 2.2초부터 공격 2번.
- 한 바퀴 합 = 달리기 + 공격 m번 — 처치 타의 머리(타격까지)와 꼬리(다음 주기)가 같은 공격이라 주기가 일정하면 정확히 맞는다.
  주기가 바뀌는 순간엔 꼬리 길이가 한 번 어긋날 수 있다(눈에 띄지 않는 수준).
- 달리기가 1초보다 길면 대상이 화면 밖에서 시작해 같은 속도로 다가온다(`SlotStageView` 속도는 `ApproachSeconds` 기준 그대로).

## 후속 작업 / 주의사항
