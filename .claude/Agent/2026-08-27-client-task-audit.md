# 클라 일감 4건 점검 — 완료·대기 구분과 T-034 등록

## 목적 / 배경

클라 일감(T-015·T-031·T-032·T-033)의 미체크 항목에 **"아직 안 한 것"과
"서버·기획이 안 와서 못 하는 것"이 섞여 있었다.** 목록만 봐서는 무엇부터 손댈지 알 수 없다.
코드·씬·패킷 미러와 대조해 셋으로 갈랐다.

판정 근거와 항목별 결과는 **`tasks/`의 각 일감에 적었다** — 여기 다시 쓰지 않는다.
→ `tasks/README.md` 순서 메모 첫 항목이 요약 표다.

## 변경 내용

- `tasks/T-015`·`T-031` — 완료 항목 체크(4 + 1), 부분 완료는 `◐`로 구분
- `tasks/T-031`·`T-032`·`T-033` — 대기 항목에 `⏸ <기다리는 일감>` 표기
- `tasks/T-034-슬롯산업교체.md` (신규)
- `tasks/README.md` — T-034 행, 클라 현황 표, T-025 경고 정정
- `WorkStationSelectPresenter.cs:23` — 주석이 가리키던 일감 이름을 `T-034`로 (코드 변경은 이것뿐)

## 주요 결정 / 근거

- **`⏸`를 체크박스 앞에 쓰기로 했다.** 별도 절로 빼지 않은 이유는, 대기 항목을 목록 밖으로
  옮기면 **일감의 전체 크기가 작아 보여서** 착수 판단이 틀어지기 때문이다.
  `⏸`는 이미 `WidgetPresenter.cs`·`Widget 규칙.md`에서 "아직 손대지 않는 것"으로 쓰던 기호라
  새 약속을 만들지 않았다.
- **archive로 내린 일감은 없다.** 4건 다 미완이다.
  ⚠️ 최근 커밋의 클라 작업(위젯 스트립·서버 대기 로딩·창 제어 개편·메모리 미터·Common 재편)은
  **애초에 일감으로 등록된 적이 없다.** "많이 했는데 목록이 안 줄어든다"의 정체가 이것이다 —
  `tasks/`는 등록된 것만 추적한다.
- **T-034에 서버 작업을 넣지 않았다.** `User.AssignWorkStation`
  (`Server/WSGameServer/User/User.WorkStation.cs:149`)이 **배치된 슬롯을 그대로 덮어쓴다** —
  정산 → `slot.Assign` → 속도 재계산. 그래서 **해제 → 배치 2연발이 아니라 배치 요청 한 번**이면 교체가 끝난다.
  ⚠️ 2연발로 짜면 정산이 두 번 돌고 **빈 슬롯 상태가 클라에 한 번 반영된다**(칸이 깜빡인다).
- **T-025(서버 담당)는 건드리지 않고 README의 경고 줄만 고쳤다.**
  "main 컴파일이 깨져 있다"가 낡은 정보인데(`7271bd0`에서 미러가 들어왔다)
  **그 줄이 클라 착수를 막는 방향으로 틀려 있어서** 담당 경계보다 오독 비용이 크다고 봤다.
  일감 자체의 상태 정리는 서버 몫으로 남겨 두었다.

## 후속 작업 / 주의사항

- ⚠️ **`WorkStationSelectPresenter`의 주석이 없는 일감을 3주간 가리키고 있었다.**
  "→ 일감 X"라고 적을 때 **그 일감이 실재하는지 확인한다.** 없으면 주석이 조용히 거짓이 된다.
- **T-034를 착수할 때 적성 0 사전 차단을 어디서 할지 먼저 정한다** —
  `tasks/archive/T-006`의 "남은 것"에 같은 항목이 있어 두 곳에서 따로 만들 위험이 있다.
- Unity 콘솔 에러 0 · 경고 0 (주석 한 줄 외 코드 변경 없음).

## 업데이트 (2026-08-27) — ⏸와 🎨를 가른다

### 무엇이 틀렸나

첫 정리에서 **미체크 항목을 "완료 / 대기(⏸)" 둘로만 갈랐다.** 그래서
연출·리소스 항목이 **"선행이 없으니 지금 할 수 있다"** 로 적혔다 —
`tasks/T-031`의 순차 연출을 "먼저 만들어 두면 이득"이라고까지 써 두었다.

**사실은 클라가 의도적으로 미루고 있는 것이다.** 지금 우선순위는 메인 시스템이고,
**연출·리소스를 뒤로 돌린다는 방침은 서버·기획 담당자와 이미 공유돼 있다.**
"할 수 있는데 안 했다"로 읽히면 **미룬 것이 지연으로 오해된다.**

### 결정 — 표기를 셋으로

`tasks/README.md`의 "할 일 항목의 표기" 절에 못박았다.

| 표기 | 뜻 |
|---|---|
| `⏸` | 기획 결정·서버 패킷이 먼저 와야 한다 — **상대에게 요청할 것** |
| `🎨` | 연출·리소스, 의도적 후순위 — **내가 나중에 할 것** |
| `◐` | 일부만 됐다 |

⚠️ **둘을 섞지 않는 것이 핵심이다.** 화면에는 똑같이 미체크로 보이지만
**요청할 것과 미룬 것은 성격이 반대다.** 섞이면 목록을 열 때마다 다시 가려내야 하고,
협업 상대에게는 후순위가 지연으로 보인다.

### 순서 메모를 "요청 목록"으로 다시 썼다

기존 메모는 **클라가 무엇을 할 수 있나**의 관점이었다. 이걸
**서버·기획이 무엇을 먼저 줘야 하나**로 뒤집었다 — 우선순위대로 6줄, 각 줄에
"그것이 오면 클라가 바로 시작하는 일"을 달았다. → `tasks/README.md` 순서 메모 2번째 항목

- **T-028(판매 패킷)을 1순위로 올렸다.** 다른 일감은 일부라도 굴러가는데
  **T-032만 패킷이 없어 한 줄도 못 쓴다.** 게다가 연출이 아니라 **골드 획득 경로**라
  후순위로 미룰 성격도 아니다.
- **클라 → 서버 요청은 지금 없다**는 것도 함께 적었다. T-034가 패킷 추가 없이 되기 때문이다.

연출처럼 보이지만 **하나씩 재생하면 화면이 몇 분간 잠기는 것을 막는 장치**라 P1 항목이다.

## 업데이트 (2026-08-27) — 요청 메모 대조, 공백 3개

클라가 요청한 내용(2026-08-17 메모)이 일감·기획에 실제로 들어갔는지 대조했다.
**14개 중 11개는 반영돼 있고 셋이 빠졌다.**

### 빠진 셋

| 빠진 것 | 확인한 사실 |
| --- | --- |
| **장비 획득 경로** | `T-002`는 장착·해제만. **[아이템] 문서에 "장비"가 0건**(전수 검색) |
| **업그레이드** | `T-002` 할 일에 "강화 수치" **필드 자리만**. 대상·재료·실패 여부 없음 |
| **과금 모델(BM)** | `게임기획코어` 5장에 `❌ 미정` **기록만** |

⚠️ **장비 획득 경로가 T-029(상자 개봉)의 풀 설계와 맞닿는다.**
상자 풀이 **자원 아이템 전제**로 설계돼 있고, T-029의 "결정이 필요한 것"에
*상자가 캐릭터를 줄 수 있는가*는 있는데 **장비는 없다.** 나중에 붙이면 풀을 다시 건드린다.

### 어디에 적었나 — 담당 경계

- **서버·기획 몫은 `tasks/README.md` 순서 메모에만 적었다.** 🕳 "일감조차 없는 공백" 항목 신설.
  **T-002·T-029 같은 서버 일감 파일은 열지 않았다** — 남의 담당 파일을 고치는 대신
  **공용 문서에 요청으로 남기는 쪽**을 골랐다.
- 📌(일감은 있고 산출물 대기)와 🕳(일감 자체가 없음)을 **다른 항목으로 나눴다.**
  섞으면 "언제 오나"와 "누가 정하나"가 같은 줄에 놓여 행동이 안 나온다.
- **클라 몫은 `Storage 규칙.md`에 적었다** — 창고 4탭 중 셋이 비어 있는데
  **왜 비었는지가 없었다.** 캐릭터(T-026 대기) · 장비(**시스템 자체가 없음**) · 특성(서버 미구현)을
  표로 넣었다. "UI만 만들면 된다"고 착수했다가 데이터가 없다는 걸 중간에 발견하는 걸 막는다.

### 기록되지 않은 방향 — 태스크바 히어로

**"태스크바 히어로를 따라가자"가 문서에 없다.** 남은 언급은 T-029의 한 줄과
게임 UI의 **화면 배치 레퍼런스 이미지**뿐이다.
**UI 배치를 참고한다는 것까지만 남아 있고 루프·과금 구조는 기록이 없다** —
장비·업그레이드가 그 게임의 핵심 루프라는 점에서 위 공백 셋과 같은 자리다.

> ⚠️ 대조 결과를 **저장소 밖(바탕화면) 전달용 문서로 만들다가 되돌렸다.**
> 요청한 당사자가 클라이언트 담당이므로 **`tasks/`에 직접 반영하는 편이 맞다** —
> 별도 문서로 빼면 일감과 원본이 둘이 되어 한쪽만 갱신된다.
