# Scripts_Client 문서 구조 재편 — 폴더별 규칙 md 신설과 주석 걷기

## 목적 / 배경

**구조를 설명하는 글이 두 군데로 새고 있었다.**

1. 루트 `CLAUDE.md`(서버·클라 공용)에 클라 전용 nullable 규칙이 들어갔다
2. 스크립트 주석이 구조 문서 역할까지 했다 — 클라 5,329줄 중 **1,912줄(36%)이 주석**이고
   `UIManager.cs` 171줄 · `Win32Native.cs` 107줄처럼 헤더가 설계 근거·흐름도로 채워져 있었다.
   **코드를 읽으러 갔다가 문서를 읽게 된다.**

`UI/`가 이미 `UI 규칙.md`로 정리돼 잘 돌아가고 있어, **그 방식을 나머지 폴더로 확대**했다.

## 주요 결정 / 근거

### 🔒 `Common/`만 주석을 걷지 않는다

Arca Unity Toolkit의 **사본**이라 다른 프로젝트로 복사될 때 **md는 따라가지 않는다.**
`MonoService.cs`(주석 68%)의 설계 근거를 md로 옮기면 새 프로젝트에서 통째로 사라진다.
그래서 `Common 규칙.md`는 **지도 역할만** 하고, 그 이유를 문서 4장에 명시했다.

### README.MD는 "앞으로 참고할 것"과 "어떻게 도달했는가"로 갈랐다

283줄이 프로젝트 착수 전 실험 기록이었다. 기준은 **"다음에 이걸 몰라서 사고가 나는가"** —

- **규칙 문서로**: URP 제약(파이프라인 바꾸면 투명이 죽는다) · 함정 4종 · 호출 매핑 · 필수 세팅
- **로그로**: 이전 과정 · 디버깅 타임라인 · TBH 조사 · 낡은 구성(`WindowPanelUI`는 이제 없다)

### XML 서식 태그(`<c>`·`<b>`)를 버렸다 — 툴팁보다 상시 가독성

이 태그들은 **IDE 툴팁에서만** 서식으로 변환되고, 코드를 읽을 때는 태그가 그대로 보여 문장을 가린다.
사용자가 "오히려 보기가 더 불편하다"고 지적했고 타당하다 — 얻는 것보다 잃는 것이 크다.
게다가 `<b>`·`<br/>`는 XML 문서 주석 **표준 태그도 아니다**(HTML이라 IDE마다 다르게 그려진다).

대체 규칙: **클래스·파일·오브젝트 이름은 작은따옴표**(`'UIManager'`), 강조는 문장을 다시 쓰거나 ⚠️·★ 기호.

> ⚠️ 제거 시 확인할 것 — 제네릭(`MonoService<T>`)이 `<c>` 안에 있다가 노출되면
> XML 파서가 태그로 읽어 **CS1570**이 난다. 이번엔 잔존 `<` 0건으로 확인했다.

### 문서명은 `<폴더명> 규칙.md`, 루트 지도만 예외

`UI 스크립트 규칙.md`만 패턴에서 벗어나 있어 맞췄다. 루트의 `폴더 구조.md`·`서버 동작 이해.md`는
폴더 규칙이 아니라 지도·메모라 이름을 그대로 뒀다.

## 후속 작업 / 주의사항

- ⚠️ **과거 기록의 옛 파일명은 일부러 고치지 않았다** —
  `.claude/Agent/2026-08-10-ui-mvp-rename.md`, `2026-08-10-client-aptitude-lock.md`,
  `tasks/archive/T-024`에 `UI 스크립트 규칙.md`·`서버동작이해.md`가 남아 있다.
  **그 시점의 사실이므로 고치면 기록이 아니게 된다.** 일괄 치환 시 제외할 것
- **주석 걷기는 전부 끝났다.** 기준은 `폴더 구조.md` 3-3·3-4장에 표로 있다
- ⚠️ **문서 규칙의 예외는 두 곳뿐이다** — `Common/`(툴킷 사본이라 md가 안 따라간다)과
  `ServerPacketHandler.cs`(클라 담당이지만 서버 폴더에 있어 `<폴더명> 규칙.md`를 둘 자리가 없다).
  **둘 다 표기 규칙(3-4)은 지킨다** — 예외는 "무엇을 적는가"이지 "어떻게 적는가"가 아니다
- 🔧 **툴킷 미커밋** — `~/.claude/skills`에 6개 파일이 수정 상태로 있다
  (nullable 5개 + `HierarchyStyler.cs` 표기 통일). 사용자가 이전 커밋을 언두했고,
  **최종 판단 후 직접 커밋 요청 예정**
- ⚠️ **같은 사실이 세 군데 적혀 있던 사례** — "캔버스를 켜지 않는다(로그인 전에 게임 화면이 비친다)"가
  `UI 규칙.md`·`UIManager` 클래스 헤더·`ResetMainScreen` 메서드 주석에 각각 있었다.
  **한 파일 안에서도 중복이 생긴다** — 헤더와 메서드 주석을 함께 봐야 한다
- ⚠️ **파일마다 걷을 수 있는 양이 다르다** — `Win32Native`는 주석 107줄 중 90줄이
  상수·함수 정의라 **헤더 16줄만** 걷었다. `GWL_STYLE = -16` 같은 매직 넘버는 주석이 곧 정의이고,
  md로 옮기면 상수 90개를 문서에 옮겨 적는 꼴이 되어 코드와 문서가 따로 논다.
  **비율만 보고 목표를 잡지 말 것**
- ⚠️ **이관은 반드시 "md에 먼저 넣고 코드에서 지운다"** — 순서가 바뀌면 설명이 증발한다.
  `WindowScale`의 절대 픽셀 근거와 `Awake` 예외가 이 경로로 `Managers 규칙.md`에 들어갔다
- 🔴 **낡은 서술 1건 정정** — `Win32Native.cs`가 창 크기를 "화면 세로의 1/3·1/2 모니터 비례"로
  설명하고 있었다(6월 데모 시절). 현재는 **16:9 절대 픽셀 프리셋**이다.
  주석을 걷다 보면 이런 게 더 나올 수 있다
- 개명 시 **`.meta`를 함께 `git mv`** 해야 한다. 파일만 옮기면 Unity가 GUID를 새로 발급해 참조가 끊긴다
  (이번엔 GUID `5a8857e2…`·`26c32bdb…` 보존 확인)
- 링크 검사 스크립트를 짤 때 **`%28`·`%29`(괄호)도 복원**해야 한다. `%20`만 복원하면
  `GameDesign/design/ui/README.md`의 목업 링크가 오탐으로 잡힌다
