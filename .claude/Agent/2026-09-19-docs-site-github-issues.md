# 문서 사이트 홈에 열린 GitHub 이슈 표시

## 목적 / 배경
- 일감 미러 사이트(`GameDesign/web`) 홈에서 GitHub 이슈도 함께 보고 싶다는 요청. 열린 이슈 전부, 라벨 필터 없음.

## 변경 내용
- `src/pages/index.astro` — 상단 카드 아래 "GitHub 이슈" 섹션 + 클라이언트 `<script>`로 `api.github.com` 조회
- `src/lib/paths.ts` — `GITHUB_REPO` 상수 추출, `GITHUB_BLOB`이 이를 쓰도록
- `사이트.md` — 홈 설명 갱신

## 주요 결정 / 근거
- **빌드 때가 아니라 브라우저에서 불러온다.** `docs-deploy.yml`은 문서·tasks 변경에만 빌드되므로 빌드 때 박으면 이슈가 늦게 반영된다. 빌드 방식으로 바꾸려면 워크플로에 `issues:` 트리거를 추가해야 한다.
- 공개 저장소라 토큰 없음. 비인증 한도 IP당 시간당 60회.
- `/issues` API는 PR도 돌려주므로 `pull_request` 필드로 거른다.
- 제목·라벨은 `textContent`로만 넣는다(XSS 방지).

## 후속 작업 / 주의사항
- `astro check`의 오류 8건(`node:fs` 타입 없음 등)은 이 작업 전부터 있던 것 — `@types/node` 미설치.
- 저장소를 비공개로 돌리면 이슈 섹션이 404 문구를 띄운다(토큰 없이 못 읽음).

## 업데이트 (2026-09-19) — 홈 담당 복수 필터

- `index.astro`에 "남은 일감" 목록 + 담당 토글 버튼(클라·서버·기획) 추가. 여러 개를 켤 수 있고 기본은 전부 켜짐.
- **"기획" = 담당 `공용`.** 사용자 확인 받음. 담당 값에 기획을 새로 만들지 않기로 했다 — 만들면 기존 공용 일감을 나누고 task-writer 규칙까지 바꿔야 한다.
- `/tasks`의 단일 선택 필터는 그대로 뒀다.

## 업데이트 (2026-09-19) — 홈 일감 검색

- 담당 필터 옆 검색창. `data-search`(ID+제목 소문자)에 대해 공백으로 나눈 낱말 전부 포함 여부로 거른다. 담당 필터와 AND.
- 본문은 검색하지 않는다 — 본문까지 넣으면 HTML에 일감 전문이 실린다. 필요하면 Pagefind 같은 정적 검색을 검토.
- 남은 일감만 대상. 보관된 일감은 홈에 없다.

## 업데이트 (2026-09-19) — v0.2.0

- `APP_VERSION`·`package.json`·`package-lock.json` 0.1.0 → 0.2.0. 세 곳을 함께 맞춘다(`사이트.md` "버전"에 명시).
- `사이트.md`에 "배포"·"버전(변경 이력)" 절 신설. "아직 안 한 것"의 배포 항목은 이미 Cloudflare Pages로 배포 중이라 삭제.
- 0.1.0 기준점은 `ca4d8cd`(APP_VERSION 도입), 이후 `b598930`(/tasks 2열·/status)과 오늘 작업을 0.2.0으로 묶었다.
