# 경매장 화면 전체 목업 (T-147 1차)

## 목적 / 배경
- 경매장을 거래 열 탭 하나(폭 603)에서 3열 전체(1920 × 950)로 넓힌다. 진우가 목업을 만들어 태웅에게 넘긴다 → `tasks/T-147`
- 사용자 지시: 왼쪽 위 검색창 → 그 아래 검색·시세·판매·완료 탭 · 왼쪽 메이플식 옵션 · 오른쪽 결과가 쭉 이어지고 정렬된다 · "지금 UI의 3배, 메이플·로스트아크와 거의 같은 느낌, 크기는 우리 게임"

## 주요 결정 / 근거
- **매물은 실제 테이블 이름으로 만든 가짜 데이터**다 — `GameDesign/DataLog/{Item,Equip,Character}Table.json`을 압축해 HTML 안 `<script type="application/json" id="catalog">`에 넣었다. 고정 씨앗 난수라 새로고침해도 같다. 테이블이 바뀌어도 목업은 자동으로 안 따라간다(필요하면 다시 뽑는다)
- **색은 지금 게임 팔레트**(`UIThemePalette.cs` 기본값) — 레퍼런스 그림(테스크바 히어로)의 갈색 프레임이 아니다. T-053 때 "목업의 테마를 따르지 않는다"와 같은 이유
- **조회 빈도 제한을 목업에서도 흉내 낸다** — 분류 클릭은 바로 조회, 옵션은 [검색]을 눌러야 조회. 서버의 순간 5회·2초 회복을 그대로 넣었다
- 수수료·기간·상한은 `ConstantsTable` 값(등록비 1% · 수수료 5% · 48시간 · 판매 중 20 · 단가 1조 · 수량 9,999)
- **서버가 바뀌어야 하는 것은 목업 페이지 아래 메모가 단일 진실**이다 — 전체 정렬 · 결과 건수 · 상세 옵션 필터 · 자원을 매물 줄로 · 시세 그래프 · 거래 기록 조회. 일감으로 옮기지 않았다(목업 확정 뒤)

## 후속 작업 / 주의사항
- 사용자 확인 → 고칠 점 반영 → 태웅에게 이슈로 넘기기(`tasks/T-147`)
- 워크트리 `.claude/worktrees/T-147-auction-mockup`을 남겨 뒀다 — 목업을 고칠 때 다시 쓴다
- ⚠️ 헤드리스 Edge 캡처: **한글 파일명 + `#해시`** 주소는 `ERR_FILE_NOT_FOUND`가 난다. ASCII 이름 사본에 해시를 심어(`history.replaceState`) 찍었다. 목업은 `#tab=market|sell|done` · `#node=equip` 해시로 탭을 바로 연다
- 문서 그래프 검사기(`check-doc-graph.ps1 -Changed`)의 블록 누락 3건(아이템·진행 및 성장·게임UI↔작업슬롯)은 **이번 변경 전부터** 있던 것이다

## 업데이트 (2026-10-11) — 2차
- 사용자 피드백 반영: 탭 줄 화면 전체(아이콘 + 글자 가운데) · 등급 드롭다운 · **왼쪽 패널은 검색 탭에만** · 판매 = 판매 중 목록 + [+ 판매 등록] 창 · 완료 거르기도 드롭다운
