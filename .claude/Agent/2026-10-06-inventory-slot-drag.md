# 인벤토리 칸 서버 위치 연동 · 서버 정렬 · 끌어 놓기 이동 (T-044)

## 목적 / 배경
- 서버 T-058이 칸 번호·정렬·이동 패킷을 준비해 둠 → 클라의 세션 한정 자리 기억을 걷고, 드래그로 칸을 옮기게 했다.
- 할 일·완료 조건 → `tasks/T-044` · 규칙 → `Assets/Scripts_Client/UI/Inventory/Inventory 규칙.md` "칸 번호의 주인은 서버다" 절.

## 주요 결정 / 근거
- **클라 정렬 규칙(`CompareForSort`·`CompareByRule`)을 지웠다.** 정렬 결과를 서버가 칸 번호로 돌려주므로 클라 규칙은 쓸 곳이 없다. 두 벌로 두면 한쪽만 고쳐진다.
- **장비 탭도 함께 옮겼다** — 일감 제목은 자원·캐릭터였지만 서버가 세 탭을 같은 규칙으로 맞췄고, 장비만 남기면 자리 규칙이 다시 갈라진다.
- **칸 번호를 `SlotData`에 넣지 않고 `PlacedSlot`으로 감쌌다** — `SlotData`는 가챠 결과 칸도 쓴다.
- **끌기 입력은 별도 컴포넌트(`InventorySlotDrag`)를 격자가 코드로 붙인다** — `SlotView`에 드래그 인터페이스를 달면 가챠 팝업의 스크롤 드래그까지 칸이 삼킨다. 툴팁(`TooltipTrigger`)과 같은 방식.
- **놓은 칸은 좌표로 찾는다(`FindFrameAt`)** — 빈 프레임에는 `SlotView`가 꺼져 있어 레이캐스트로 맞을 것이 없다. 뷰포트 밖이면 버린다(가려진 프레임도 좌표는 살아 있다).
- 정렬·이동 요청은 **하나씩만** — `_slotWaitHandle`이 있으면 다음 요청을 보내지 않는다. 앞 응답 전의 칸 번호로 보내면 엇갈린다.

## 겪은 함정
- `PlayerDataModel.ApplyItemChanges`가 **수량만 복사**하고 있었다 — 서버가 `ItemChangeInfo.Slot`을 실어도 새 자원이 0번 칸으로 읽혀 겹쳤을 것이다. 칸 번호·보관함까지 복사하게 고쳤다.
- Git Bash heredoc에 한글·따옴표가 섞인 긴 Python을 넣으면 "unexpected EOF"로 실패했다 — 스크립트를 파일로 쓰고 실행해 우회.

## 후속 작업 / 주의사항
- 실측이 남았다(T-044 할 일 마지막 칸). 확인되면 T-044 · T-058 함께 완료.
- 칸 위를 끌어 스크롤하지 못한다(칸이 끌기를 받는다). 자동 스크롤은 🎨로 남김.
- 창고 끌어 넣기 → `tasks/T-126` — `C_WarehouseTransferRequest`에 도착 칸이 없어 "놓은 칸 vs 첫 빈 칸"을 서버와 맞춰야 한다.
- `PlayerDataModel.GetItemCount`는 보관함을 구분하지 않는다 — 창고(T-107)가 서면 같은 TID가 두 줄이 되므로 그때 고칠 것.

## 업데이트 (2026-10-06) — 끌리는 그림이 안 보이던 문제 · 놓을 칸 덮개
- 그림이 루트 캔버스에 붙어 열 캔버스(`overrideSorting` 0) 뒤에 깔려 있었다 — 따라다니긴 했는데 안 보였다. 그림에 자기 캔버스(순서 10)를 달아 해결.
- 놓을 칸 덮개는 `Content` 자식 + `ignoreLayout` — 같은 스크롤·마스크를 타고, 격자 배치에는 안 낀다.
