# 레이드 목업 — 메인 UI → 보스 선택 → 프리셋 편성 → 전투 화면

## 목적 / 배경
- 레이드 서버 1차(PR #131)는 있고 클라 화면·전투 재생이 없다. 화면 모양을 먼저 보려고 목업을 만들었다.
- 사용자 방향(2차): 메인 UI 기반 · [길드] 버튼을 [레이드]로 · 보스 목록 → 누르면 상세 → 프리셋 골라 도전 · 프리셋 편성은 따로 뜨는 창 · 도전하면 창이 통째로 전투 화면 · 전투 기록·건너뛰기 없음 · 배속 ×1·×2·×3 · 앞뒤가 있는 2.5D.

## 변경 내용
- `GameDesign/design/ui/레이드목업.html` — 창 넷(메인 UI · 보스 선택 · 프리셋 편성 창 · 전투 화면) + 결과 창. 마지막 응답(JSON)을 페이지 아래에 찍는다
- `GameDesign/design/ui/README.md` 목업 표 · `tasks/T-114-레이드기획.md` 참고에 링크

## 주요 결정 / 근거
- **메인 UI는 실제 플레이 화면 캡처다**(Unity CLI로 플레이 → 계정 `1234` 로그인 → `capture_game_view --source screen`). 문서 사이트가 목업을 한 폴더로 펴서 복사하므로 상대 경로 그림이 깨진다 → PNG를 base64로 파일 안에 넣었다(파일 약 280KB). 색·제목 줄·글꼴(Galmuri11)도 캡처에서 맞췄다
- **목업 안의 가짜 서버는 `RaidBattleSimulator.Simulate`와 같은 식이다.** 스킬 체크를 끄면 로그가 서버와 같다. 재생 쪽은 로그의 `Damage`·`TargetHealth`만 쓴다
- **2.5D는 연출이다.** 세계 좌표 (x, z)를 화면으로 옮기며 뒤(z 작음)일수록 작게·가운데로 모은다. 서버 전투에는 위치가 없어 편성 순서로 자리를 정했다
- 타격 시각을 로그에 맞추려고, 움직임은 그보다 일찍(아군 300ms · 보스 460ms) 시작한다
- 재생이 끝나기 전에는 도전권 숫자를 바꾸지 않는다

## 후속 작업 / 주의사항
- [길드]가 [레이드]가 되면 길드 열(상점·뽑기·창고) 입구가 없어진다 — 미정
- 프리셋 여러 개는 서버에 없다(편성 하나만 저장) · 스킬은 `RaidHitInfo`에 식별자가 필요하다 — T-197에서 정한 뒤
- 캡처용 로그인으로 `Server/Shared/game.sqlite3`가 바뀌었다. 커밋하지 않았다
