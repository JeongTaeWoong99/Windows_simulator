# 메모리 미터 툴팁 조판 정리 + 커밋/워킹셋 설명 정정

## 목적 / 배경

- 툴팁의 `Mono 힙 2.58GB`와 버튼 라벨 `0.81GB`가 모순처럼 보인다는 혼란.
  기존 툴팁이 "예약분 중 물리에 안 올라간 것"만 언급해 **사용량도 워킹셋에서 빠진다**는
  핵심을 빠뜨린 게 원인이었다.
- 툴팁 22줄 산문이 유니티 내장 툴팁 폭 상한에 걸려 문장 중간에서 줄이 꺾였다.

## 변경 내용

- `Editor/memory-meter/EditorMemoryToolbarButton.cs` — `BuildTooltip()` 전면 재작성
- `Editor/memory-meter/EditorMemoryMeter.cs` — `Snapshot` XML 주석에 커밋 기준임을 명시
- `Editor/Editor 규칙.md` — 커밋/워킹셋 설명 보강 + `작업 관리자와 견주는 법` 절 신설

## 주요 결정 / 근거

- **툴팁 폭 확대는 불가능하다** — 내장 툴팁은 네이티브가 그리고 폭 상한이 고정이다.
  `--unity-tooltip`은 UIElements의 색 계열 USS 커스텀 프로퍼티일 뿐 폭 지정이 아니고,
  `UnityEditor.dll`에도 툴팁 폭 관련 관리 코드가 없다(DLL 문자열 스캔으로 확인).
  **내부 툴팁 요소를 리플렉션으로 손대는 길은 택하지 않았다** — 툴바 리플렉션 주입이
  Unity 6.3에서 숨겨진 전례와 같은 부류다.
- 그래서 **줄을 직접 끊는다.** 한 줄 한글 24자 이내가 기준.
  `EditorStyles.label.CalcSize`로 실측: 새 툴팁 최장 줄 **203.9px**,
  기존에 줄바꿈이 일어났던 줄 **387.6px**, 관측된 툴팁 텍스트 영역 약 **324px**.
- 수치는 가변폭 폰트라 공백 패딩으로 열이 안 맞는다 → **`이름 줄` / `값 줄`** 로 나눠 세로 정렬.
- 툴팁에서 뺀 긴 설명은 버리지 않고 `Editor 규칙.md`로 이관했다(툴팁은 슬림, 문서는 상세).
- 그래픽 드라이버 꼬리표를 `(텍스처 · 메시)` → `(VRAM)`으로. 작업 관리자 메모리 열에
  안 잡히는 이유가 VRAM이라는 점이 사용자가 실제로 막힌 지점이었다.

## 후속 작업 / 주의사항

- **툴팁 문구를 고칠 때는 반드시 줄 길이를 다시 잰다.** 한 줄이라도 ~300px을 넘기면
  그 줄만 문장 중간에서 꺾여 조판이 다시 무너진다.
- 툴팁 문구는 `EditorUtility.FormatBytes` 결과("0.81 GB", "183.5 MB")를 그대로 쓰므로
  자릿수에 따라 값 줄 폭이 변한다. 값 줄은 여유가 충분해(최대 124px) 문제 없다.
- 실측 근거 수치(워킹셋 2.1GB / 프라이빗 커밋 9.2GB)는 `Editor 규칙.md`에 날짜와 함께 박아 뒀다.
- 유니티 콘솔 에러 0으로 컴파일 확인. 툴팁 육안 확인은 사용자 몫으로 남았다.

## 업데이트 (2026-08-22) — 용어 정정

첫 판의 툴팁 용어가 **틀렸다.** 다음 사람이 되돌리지 않도록 근거를 남긴다.

- ⚠️ **유니티 프로파일러의 `Reserved`를 '예약'으로 옮기면 안 된다.**
  Win32의 예약(Reserve — 가상 주소만 찜해 접근하면 access violation)이 아니라
  **이미 커밋된 풀**이다. → 툴팁 표기를 **`확보`**로 바꿨다.
- ⚠️ **`Allocated`를 '실제 사용량'이라 쓰면 안 된다.** "물리 RAM에 올라와 있다"로 읽히는데
  실제로는 RAM 적재 여부와 무관하다. → **`할당`**으로 바꿨다.
- ⚠️ **"전체 / 몫"이라는 단어를 버렸다.** 사용자가 이 단어 때문에 워킹셋과 프로파일러 수치를
  **배타적 분할**로 읽었다(실제로는 같은 메모리를 다른 잣대로 잰 것이라 서로 겹친다).
  → `버튼 값 = 워킹셋` · `유니티 할당자`로 바꿨다.
- 포함 관계를 못 박아 뒀다: `할당 ≤ 확보 ≤ 프로세스 커밋`, `워킹셋 ⊂ 프로세스 커밋`,
  **`워킹셋` vs `할당·확보`는 포함 관계가 없다**(겹치되 크기 비교 불가).
- ⚠️ **작업 관리자 탭 이름을 '세부 정보'라고 쓴 게 오역이었다.** 한국어 Windows 11에서는
  **`자세히`**(영문 Details)다. `프로세스`는 사이드바 맨 위 기본 화면.
- OS 3단계(예약·커밋·워킹셋) + 프로파일러 2단계(확보·할당) 표를
  `Editor 규칙.md`의 **`### 용어 — 예약 · 커밋 · 워킹셋 · 할당 · 확보`** 절에 넣었다.
  용어를 다시 손대려면 여기부터 읽는다.
- 재측정: 24줄, 최장 203.9px(여유 120px). 콘솔 에러 0.

## 업데이트 (2026-08-22) — 작업 관리자 열 이름 실검증

앞선 두 판 모두 **작업 관리자 열 이름을 확인 없이 적어** 사용자가 화면에서 못 찾았다.
`C:\Windows\System32\ko-KR\Taskmgr.exe.mui`의 문자열을 직접 뽑아 검증했다.
**앞으로 이 문서의 OS UI 명칭을 고칠 때도 같은 방법으로 확인한다.**

```powershell
$b=[IO.File]::ReadAllBytes("C:\Windows\System32\ko-KR\Taskmgr.exe.mui")
[Text.Encoding]::Unicode.GetString($b)   # 여기서 정규식으로 한글 문자열 추출
```

- ✅ **`커밋 크기`는 실재한다** — 다만 **기본으로 꺼져 있어** 사용자 화면에 없었다.
  `자세히` 탭 → 열 머리글 우클릭 → **`열 선택(S)`**(리소스에 실재하는 메뉴 문자열) → 체크.
  툴팁·문서 둘 다 "켜야 보인다"를 명시하도록 고쳤다.
- ⚠️ **'프라이빗 작업 집합'은 한국어 UI 명칭이 아니다.** 실제 문자열은
  **`메모리(활성 개인 작업 집합)`** · `메모리(개인 작업 집합)` · `메모리(공유된 작업 집합)`.
  '프라이빗'으로 쓴 곳을 **`개인`**으로 고쳤다.
- 확인된 다른 열: `작업 집합(메모리)` · `최고 작업 집합(메모리)` · `작업 집합 델타(메모리)` ·
  `커밋 크기` · `커밋됨` · `페이징 풀` · `NP 풀` · `전용 GPU 메모리` · `공유 GPU 메모리`.
- 문서 가독성 개편: `📖 용어` · `🔍 작업 관리자` 절 표제, `①②③` 단계 번호,
  인용문(`>`)으로 경고 분리, 열 켜는 절차를 트리 코드블록으로. 이모지는 절 구분용으로만 쓴다.
