# 유니티 이펙트 · 해킹 연출 가능성 시험

## 목적 / 배경
- 사용자 요청으로 "유니티 기능만으로 어디까지 되나"를 시험했다. 이펙트는 이미지로 만든다는 원칙과 별개로, 사용자가 기능 시험이라 명시해 코드·셰이더로 만들었다.
- 결과는 사용자가 확인했고("가능성 잘 확인했어"), 작업 폴더 `Assets/temp-vfx-test/`는 **통째로 지웠다. 커밋한 적 없다.**

## 확인한 것
- 파티클 프리팹 4종(불꽃놀이·마법 충격파·도트 불꽃·SF 폭발) — Legacy Particles 셰이더와 코드로 만든 텍스처만으로 만들 수 있었다.
- 사이버펑크2077식 퀵해킹 연출:
  - 시간 정지 → 플레이어 중심 파동 → 대상 그림 영역 감염 → 순차 락온 → 방향키 코드 입력 → 장악
  - Built-in 셰이더 4개(오버레이·대상·레티클·코드 띠)와 MonoBehaviour 3개로 만들었다.

## 주요 결정 / 근거 (실제로 옮길 때 다시 쓸 것)
- 락온이 많아 겹칠 때: 대상 크기의 상자 대신 **고정 크기 레티클**을 쓰고 레티클끼리 서로 밀어낸다. 상세 정보는 화면 구석 LOCK LIST에 모으고, 대상 위에는 번호 칩만 둔다. 상자 방식은 큰 적 위에서 겹쳐 읽히지 않았다.
- 감염 계산은 C#과 셰이더가 **같은 식**을 쓴다. 파동이 그림 영역에 처음 닿은 점부터 번지게 했다. 락온 시각을 C#이 알아야 순번을 매길 수 있기 때문이다.
- 해킹 대상 화살표는 레티클 안쪽 도형 위에 겹치면 읽히지 않는다. 안쪽 도형을 지우고 어두운 원을 깔아야 했다.
- 방향키(↑↓←→)는 이 시험에만 썼다. 게임 키 규칙은 좌·우·Ctrl+좌·Ctrl+우뿐이라, 실제로 넣는다면 키를 다시 정해야 한다.

## 후속 작업 / 주의사항
- Unity MCP `RunCommand`의 제약:
  - `AssetDatabase.DeleteAsset`·`EditorSceneManager.OpenScene`은 "User interactions are not supported"로 막힌다. `NewScene`은 된다.
  - 열린 씬과 같은 경로로 새 씬을 저장할 수 없다. 열린 씬의 루트를 비우고 다시 채워야 한다.
  - `System.Reflection.BindingFlags`는 금지 네임스페이스다. private 필드는 `SerializedObject`로 접근한다.
- 플레이 모드 실입력(시간 정지 유지 포함)은 시험하지 않았다. 에디터 캡처로만 확인했다.
