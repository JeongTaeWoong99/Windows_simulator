# 문서 토큰 효율화 — 이슈 #18 권고의 서버·기획 쪽 적용

## 목적 / 배경
- 클라 담당의 이슈 #18(2026-08-15) 권고가 한 달간 서버·기획 쪽에 하나도 적용되지 않았고, `tasks/README.md`는 그 사이 4배(36.9KB)로 불어 있었다.
- 무엇을 어떻게 했는지의 수치는 → `tasks/T-051-문서토큰효율화.md` · 이슈 #18 마지막 댓글. 여기는 결정·근거·지뢰만.

## 주요 결정 / 근거
- **우선순위를 이슈와 다르게 잡았다** — `tasks/README.md`를 1순위로. T-0XX가 언급될 때마다 `task-reader`가 통째로 여는 파일이라 실제 비용이 제일 컸다.
- **INDEX 압축은 삭제가 아니라 이동** — ✅ 이력 메모 26.8KB를 `tasks/archive/순서 메모 이력.md`로 통째로 내렸다(링크는 한 단계 깊게). 살아 있는 사실 중 일감 파일에 없던 두 건(가챠 시트 개명 → T-029, 장비 획득 경로·`ItemType` 축 → T-002)만 파일로 옮겼다. 표 셋 구조(▶·⏸·🎨)는 의도된 설계라 유지.
- **스킬 분할은 규칙을 남기고 설명만 뺐다** — `description`(발동 조건)은 건드리지 않았다. 감량이 클라 선례(−46%)보다 작은 이유는 두 스킬 모두 이미 규칙 위주였기 때문이다. 더 줄이려면 규칙을 빼야 하는데 그러면 "안 열면 무시되는" 상태가 된다.
- **`기획평가.md`는 완결 기록으로 표시하지 않았다** — 이슈는 "완결된 기록으로 보인다"고 했지만 갱신일이 계속 오르고 `바뀌면 갱신` 그래프에 들어 있는 살아 있는 리뷰다. `research/`·`proposals/`만 표시.
- **`게임기획코어.md` 규범·배경 분리는 보류** — 최상위 진입점을 쪼개면 링크 16곳과 클라 참조가 흔들리고, 테스트 단계라 수치가 자주 바뀐다. 앵커 목차만 넣고 **갱신일은 올리지 않았다** — 올리면 이 문서를 참조하는 15개 문서 전부에 갱신일 역전 경고가 난다(`check-doc-graph.ps1`). 내용이 안 바뀐 구조 변경은 갱신일을 올리지 않는 것이 맞다.

## 후속 작업 / 주의사항
- 🎨 `문서관계도.md` INDEX 압축은 T-051에 남아 있다(🎨 표).
- ⚠️ **같은 작업 트리에서 다른 Claude 세션이 동시에 작업하고 있었다** (T-003 캐릭터 성장). 겪은 지뢰 둘:
  - 파이썬 read-modify-write로 넣은 `게임기획코어.md` 목차가 그쪽 쓰기에 **조용히 덮였다.** 공유 파일은 상대 세션이 유휴(`ListAgents`)일 때 만지고, 넣은 뒤 `grep`으로 남아 있는지 확인한다.
  - **공유 트리에서 `git stash`를 쓰지 않는다.** 검사 스크립트를 깨끗한 트리에서 돌리려고 몇 초 stash/pop 했는데, 그 사이 상대가 그 파일을 쓰면 pop이 실패하거나 상대가 낡은 내용을 읽는다. 이번엔 무사했지만 방법 자체가 틀렸다 — `git stash`는 상대의 미커밋 변경까지 같이 치운다.
  - 상대의 미커밋 hunk가 있는 파일에 내 hunk만 커밋하려면: HEAD 내용에 내 편집을 적용해 쓰고 `git add` → 다시 "그쪽 내용 + 내 편집"으로 작업 트리를 덮어쓴다. `tasks/README.md`·`.claude/Agent/README.md`·`게임기획코어.md`에 이 방법을 썼다.
- `stash@{0}`(2026-07-25 · CLAUDE.md 2줄)는 제 것이 아니라 두었다. `.claude/worktrees/T-028-baseprice-shop/`도 남아 있는데(T-028은 보관됨) 등록된 워크트리인지 확인하지 않았다.
