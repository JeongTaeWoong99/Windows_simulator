# 공용 툴팁 (T-088)

## 목적 / 배경
- 산업 레벨 버튼을 누르면 정보 패널이 펼쳐졌다 접히며 아래 목록을 밀었다(T-078). 사용자가 거슬린다고 했다.
- 부가·세부 정보와 앞으로 이미지로 바뀔 버튼의 이름을 **올리면 뜨는 툴팁**으로 보이기로 했다.
- 사용자 선호: 커서를 따라가지 않고 **대상 오른쪽 옆에 고정**, 창 밖으로 넘치면 왼쪽. 지연 0.3초.

## 변경 내용
- `UI/Shared/TooltipTrigger.cs` · `TooltipContent.cs` — 대상에 붙는 트리거(고정 문구 or `SetProvider`) · 내용(제목 + 줄)
- `UI/System/TooltipPresenter/` — `TooltipPresenter`(호버 감지·그리기·배치) · `TooltipRowView`(라벨/값/보조 값/바탕)
- `Managers/WindowManager.cs` — `UIHitsUnderCursor` 공개. 클릭스루 판정과 툴팁이 **프레임당 한 번** 쏜 레이캐스트를 함께 읽는다
- `WorkStationSelectPresenter` — 펼침 패널·▲▼·줄 풀 제거, `BuildIndustryLevelTooltip`으로 대체. `IndustryLevelButton`에 `tooltip` 필드
- 삭제: `IndustryDropRowView.cs` · `Prefabs/IndustryDropRowView.prefab` · 씬 `Industry Level Info Panel`
- 추가: `Prefabs/TooltipRowView.prefab`(옛 드롭 줄 프리팹을 본떴다) · 씬 `!System Canvas/Tooltip Presenter`(Notice 바로 앞)
- 고정 문구 트리거: 상태 패널 세팅·종료, 뒤로(X) 둘, 창고 정렬(▼)

## 주요 결정 / 근거
- **호버를 `IPointerEnter`로 받지 않는다.** 이 앱은 대개 포커스 없이 떠 있고, 그때 Unity 입력(Input System)이 멈춘다.
  클릭스루와 같은 Win32 커서 폴링 + `RaycastAll` 결과의 **맨 위 하나**를 본다 → 팝업 차단막이 있으면 자연히 안 뜬다.
  ⚠️ 포커스 없는 상태의 `IPointerEnter` 동작은 **실측하지 않았다** — 어느 쪽이든 폴링은 돈다.
- 레이캐스트를 두 번 쏘지 않으려고 `WindowManager`에 프레임 캐시를 뒀다(`_raycastFrame`).
- 툴팁 두 파일(Trigger/Content)은 게임을 몰라 원래 `Common/` 감이지만, 모양이 굳을 때까지 `Shared/`에 뒀다.
- 내용은 **띄우는 순간** 만든다 — 산업·해금이 바뀌어도 다시 넣어 줄 것이 없다.

## 후속 작업 / 주의사항
- 툴팁 안의 그림은 전부 `raycastTarget` 끔. 켜면 깜빡이고 클릭스루가 툴팁을 콘텐츠로 본다.
- T-050(창고 칸 호버)이 이 본체를 쓴다 — 칸에 트리거만 달면 된다.
- 창 크기가 캔버스와 같다는 전제로 `Tooltip Presenter`의 사각형을 창 경계로 쓴다.
- 2026-09-25 사용자 에디터 플레이 실측 완료 → T-088 보관. 빌드에서 포커스 없는 호버는 다음 빌드 확인 때 본다.
