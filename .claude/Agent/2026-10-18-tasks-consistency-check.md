# 일감 정합성 검사 스크립트 + CI (T-129)

## 목적 / 배경

- 공돌리기(→ `github-issue-writer` 3장) 중 기계적으로 판정할 어긋남을 사람 기억 대신 스크립트로 잡는다 → `tasks/T-129`
- 검사 항목·사용법은 `GameDesign/web/scripts/check-tasks.mjs` 머리 주석, CI는 `docs/CI.md`

## 주요 결정 / 근거

- **PowerShell이 아니라 Node** — CI 러너가 리눅스라 `powershell.exe`가 없고, 같은 일감 파일을 다루는 `roll-cycles.mjs`가 이미 Node다. 로컬·CI가 같은 명령
- **배포 워크플로에 넣지 않고 따로(`tasks-check.yml`)** — 같은 job이면 일감 목록이 어긋났다고 문서 사이트 배포가 막힌다
- **`issues: closed` 트리거** — 이슈는 push 없이 닫힌다. push 트리거만 두면 "닫힌 이슈를 기다리는 ⏸"를 다음 push까지 놓친다
- **`막고 있는 것`은 일감·이슈로 시작하는 줄만** 선행 선언으로 본다 — 이 절은 "없음 — T-125는 끝났다" 같은 설명 줄이 많아, 줄 안의 ID를 전부 보면 오탐투성이다. ⏸ 항목은 `- [ ]` 체크박스 줄만(풀린 ⏸ 서술은 제외)
- **목록 ↔ 파일 대조는 ID가 아니라 파일 경로로** — ID 중복이 실제로 있다(아래)
- 옛 경로 링크 검사에서 `tasks/archive/`·`.claude/Agent/`는 뺐다 — 그 시점의 기록이라 고치지 않는다

## 후속 작업 / 주의사항

- ⚠️ **`T-132`가 둘이다** — 루트 데이터 뷰어 · `archive/` 풀링과 UniTask 전환(2026-10-08 동시 등록). 번호를 못 바꿔 스크립트 `KNOWN_DUPLICATES`에 적었다. 새 중복은 검사가 잡는다
- 워크트리에서 돌리면 INDEX 항목(1·2·3)은 어긋난 채가 정상이다 — INDEX는 머지 뒤에 고친다
- gh가 없거나 인증이 안 되면 닫힌 이슈 검사만 경고 후 건너뛴다(실패 아님)
