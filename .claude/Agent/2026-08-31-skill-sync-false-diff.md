# 스킬 동기화 오탐 — CRLF와 의도적 중립화를 차이로 셌다

## 무슨 일

`/unity-skill-sync` 보고에서 **"11개 스킬 · 1,600여 줄 미동기화"**라고 알렸다. **전부 오탐이었다.**
사용자가 "무작정 다르다고 동기화하는 게 아니다"라고 짚어 다시 재고 나서야 드러났다.

| | |
|---|---|
| 보고한 것 | 11개 파일 1,600여 줄 |
| 실제 | **39줄, 그마저 전부 의도된 차이 → 동기화 필요 0건** |

## 원인 둘

### ① CRLF — `diff --strip-trailing-cr` 을 안 걸었다

🔴 **마스터는 LF, 유니티 프로젝트 사본은 CRLF가 정상이다**(git이 체크아웃할 때 바꾼다).
그냥 `diff`를 걸면 **모든 줄이 다르게 나온다.** 옵션 하나로 `1,600 → 39`.

이건 실수가 아니라 **구조적으로 매번 재발하는 함정**이다. 유니티 프로젝트인 한 계속 그렇다.

### ② 줄 수만 세고 내용을 읽지 않았다

39줄의 정체는 전부 **의도적 중립화**였고, 그 이력은 이미
[[2026-08-26-toolkit-common-restructure]] 에 적혀 있었다.

> 작업관리 스킬 4종 마스터 승격 + **중립화** — 엑셀 파이프라인·패킷·DB 컬럼·낚시 TID 같은
> 이 프로젝트 예시를 중립 예시로 바꾸고, "1인 개발이면 `담당` 필드를 두지 않는다" 분기를 넣었다.

| 성격 | 예 |
|---|---|
| 중립화 | `GameDesign/design/` → 일반 경로 · `산업레벨.md` → `전투설계.md` · `엑셀→DB→패킷` → `테이블→서버→화면` |
| 전역 전용 분기 | "1인 개발이면 `담당` 필드를 두지 않는다" (마스터에만) |
| 태그 축 확장 | 프로젝트가 `#design`·`#data` 추가 — 스킬이 "축이 더 있으면 늘린다"고 명시 |

🔴 **사본이 더 구체적인 것은 "마스터가 뒤처졌다"가 아니다.** 이미 처리된 것이다.

## 되짚을 패턴 — 이 세션에서 두 번째다

창 크기 때도 `1324x745 + 프레임 = 1342x792`가 저장값과 **정확히 일치**한다는 이유로 원인을
확정했다가 틀렸다. 이번엔 **줄 수가 크다**는 이유로 미동기화를 단정했다.

> 🔴 **수치는 가설을 지지할 뿐 확정하지 않는다. 세었으면 읽어야 한다.**

## 스킬에 넣은 안전장치 (`unity-skill-sync`)

1. **1단계** — `diff --strip-trailing-cr` 필수. 실측치(1,600→39)를 근거로 함께 적었다.
2. **2단계** — 분류를 3 → **4갈래**로. 🔵 **의도적 일반화**(마스터가 일부러 중립화한 것)를 추가,
   push도 pull도 하지 않는다. "프로젝트 특화의 거울상"이라는 점과, 판정이 안 서면
   `.claude/Agent/`에서 승격 로그를 찾으라는 지침을 함께 넣었다.
3. **4단계** — **줄 수를 근거로 보고 금지.** 분류한 것만 보고하고, 못 했으면 "미분류"라고 적는다.

## 함께 정리한 것

- 프로젝트 사본 `feature-design`·`commit-convention`의 **파일 끝 개행 누락**을 채웠다(내용 차이 아님).
- 마스터 커밋 규칙을 "사용자가 직접" → **"요청받았을 때만"**으로 맞췄다
  (스킬 4단계 · 전역 `CLAUDE.md`). `/unity-skill-sync` 자체도 이날 모델 실행이 허용됐다.

## 현재 상태

동기화 필요 **0건**. 남은 35줄은 전부 🔵 의도적 일반화라 **그대로 두는 것이 맞다.**
