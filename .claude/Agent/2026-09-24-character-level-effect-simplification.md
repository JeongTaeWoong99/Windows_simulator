# 캐릭터 레벨 효과 간소화 요청 — 적성 포인트 → 레벨 자동 가산

## 목적 / 배경

T-003의 남은 클라 작업("포인트 찍기 화면")에 착수하려고 상태를 확인했다.
출발점은 **"레벨이 올라도 캐릭터가 강해지지 않는다"** 는 인상이었는데, 조사 결과
**원인이 미구현이 아니라 클라 화면 부재**였다 → 아래 "가장 먼저 틀리기 쉬운 것".

확인 뒤 기획 방향 자체를 바꾸자는 판단이 나와 [이슈 #35](https://github.com/JeongTaeWoong99/Windows_simulator/issues/35)로 요청했다.
규칙·구현 현황은 [캐릭터 5.4](../../GameDesign/design/character/README.md) · [T-003](../../tasks/T-003-캐릭터성장.md)에 있다 — 여기서는 **결정과 근거만** 남긴다.

## 주요 결정 / 근거

### 왜 적성 포인트를 접자고 했나

간소화의 실제 동인은 "수동 조작이 귀찮다"가 아니라 **상한 데이터의 미완성**이다.

- 5.4가 상한을 **캐릭터·산업마다** 둔 이유는 *"전설 낚시꾼은 낚시 9까지 가지만 농사는 2에서 멈춘다"* —
  자라도 개성이 남게 하려는 것이었다.
- 그런데 `CharacterTable`의 실제 값은 **등급별 한 값을 전 산업에 깔아둔 초안**이다
  (Legendary = 전 산업 9). **지금 데이터대로면 만렙 Legendary는 전 산업 9에 수렴**해,
  5.4가 막으려던 배치 퍼즐 붕괴가 그대로 일어난다.
- 의도를 살리려면 **30종 × 5산업 = 150칸을 손으로 조율**해야 한다. 방치형의 레벨 효과 하나에
  치르는 비용으로 과하다고 봤다.

### 왜 대안이 "가산"인가 (승산이 아니라)

처음 사용자가 제안한 모양은 레벨 배율(승산, `×1.0 → ×1.99`)이었으나 **가산으로 적어 올렸다.**

- 서버 속도식이 이미 `기본값 × (1 + Σ가산) × Π승산`이고 장비·특성이 가산 항에 있다.
  `.Add(레벨가산)` 한 줄이면 **기존 구조에 그대로 얹힌다.**
- 클라 효율 계산도 "속도 가산" 줄에 `레벨 +20% · 특성 … · 장비 …`로 자연스럽게 붙는다.
- **가산이어도 캐릭터 격차는 벌어진다** — `기본값 × (1+합)` 구조라 적성이 높은 쪽이 더 많이 얻는다.
  반대로 지금의 포인트 방식은 적성을 **정수로 평평하게** 올려 격차를 좁히고,
  그래서 상한 150칸이라는 장치로 다시 막아야 했다. 이 뒤집힘이 제안의 핵심 논거다.

### 이슈 제목 형식을 바꿨다

`[서버 요청 · 기획 확인]`처럼 영역마다 종류를 따로 달던 것을 **`[기획·서버 확인]`** 한 칸으로 묶었다.
꼬리표는 목록 왼쪽 끝에서 한눈에 걸러지라고 있는 자리인데, 칸이 길어지면 그 구실을 잃는다.
- 프로젝트 사본 `github-issue-writer` 갱신(`1e45046`) · 툴킷 마스터에도 범용판으로 올렸다
  (`~/.claude/skills` `da39ca4` — 고유명사·계정·이슈 번호는 걷어냈다).

## 후속 작업 / 주의사항

### ⚠️ 가장 먼저 틀리기 쉬운 것 — "레벨 효과가 없다"는 인상

적성 포인트는 **서버가 100% 완성돼 있다** (패킷 32/33 핸들러 · `TryRaiseAptitude` ·
저장 · 기동 검증 · 테스트 19건). 없는 것은 **클라의 UI · 요청 송신 · 모델 보관** 셋뿐이다.
`ServerPacketHandler.AptitudeUpResponded`(받기)는 이미 있어서 **"패킷 배선이 없다"고 읽으면 틀린다.**
`PlayerDataModel`은 적성 `Value`만 들고 `Cap`·`AptitudePoints`는 받아서 버린다.

### ⚠️ 코드를 지우지 않고 데이터로 끌 수 있다

`CharacterLevelTable.AptitudePoint`를 전부 0으로 두면 남은 포인트가 항상 0이라
요청이 `NoAptitudePoint`로 거절된다. **코드·DB·패킷을 하나도 건드리지 않고 기능이 꺼진다.**
결정이 뒤집힐 여지가 있는 동안에는 철거보다 이쪽이 싸다.

### ⚠️ 레벨 가산을 넣으면 클라 역산이 또 틀린다

`WorkStationSelectPresenter.RefreshEfficiency`는 서버가 준 `CurrentWorkSpeed`에서
**전역 배수를 역산**한다. 레벨 기여가 속도식에 들어가면 그 몫이 "개발용 전역 배수"로 잘못 읽힌다
(2026-09-20 속도 특성이 열렸을 때 같은 일이 이미 났다 → [T-055](../../tasks/T-055-속도보정내역전달.md)).
**서버가 레벨 가산을 명시 필드로 내려주는 것이 사실상 선행**이고, 그래야 클라가 "표시 한 줄"로 끝난다.

### 남은 것

- 이슈 #35 답변 대기. **답이 오기 전에 클라 화면을 만들지 않는다** — 동의되면 화면 자체가 사라진다.
- 어느 쪽으로 결론 나든 경험치·레벨 자체(2026-09-13 서버 · [T-052](../../tasks/T-052-클라캐릭터성장반영.md) 클라 배지·게이지)는 그대로 둔다.
- 열린 이슈 #33·#34의 assignee에 기획(규빈)이 빠져 있던 것을 함께 채웠다 —
  **제목이 `[기획 …]`인데 알림은 서버에만 가고 있었다.**
