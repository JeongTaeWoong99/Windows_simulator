# Editor·UI 규칙 문서를 하위 폴더별로 분할

## 목적 / 배경

- `<폴더명> 규칙.md` 구조는 유지되고 있었으나 두 문서가 **한 하위 주제에 잠식됐다.**
  `Editor 규칙.md` 359줄 중 62%가 memory-meter 설명, `UI 규칙.md`는 761줄(48KB).
- 실제 비용 두 가지 — ① 툴바 버튼 하나 붙이려는 사람이 메모리 용어 사전 220줄을 지나쳐야 했다
  ② **절 번호 참조가 이미 조용히 깨져 있었다** (코드 주석 5곳이 존재하지 않는 `'UI 규칙.md' 8장`을 가리킴).

## 변경 내용

- `Editor/` — `shared` · `scene-copy` · `server-console` · `memory-meter` 4개 문서 신설, 상위는 45줄로 축소
- `UI/` — 캔버스 폴더 8개(`Login`·`Main`·`Market`·`State`·`Storage`·`System`·`Widget`·`Layout`) 문서 신설,
  상위는 474줄(26KB)로 축소
- 코드 주석 21곳 · md 링크 8곳을 새 목적지로 재조준
- `폴더 구조.md`에 **3-5절 "규칙 md는 자기 폴더의 규칙만 담는다"** 신설 (분할 기준·참조 방식·파일명 예외)
- 루트 `CLAUDE.md` 이름 규칙에 파일명 예외 한 줄

## 주요 결정 / 근거

- **캔버스 폴더 전부에 규칙.md를 둔다** (사용자 선택). `Login`·`Market`·`Widget`은 26~36줄로 짧지만
  **착지점**으로서의 자리를 먼저 만든 것이다 — 채우려고 내용을 지어내지 않는다.
- **파일명은 `<폴더명> 규칙.md` 공식을 지킨다** → 영문 폴더는 `memory-meter 규칙.md`.
  루트 CLAUDE.md의 "문서명은 한글"보다 **폴더-문서 이름 일치**를 우선했다.
  목록에서 어느 폴더의 규칙인지 못 알아보는 쪽이 더 나쁘다.
- **문서 밖에서는 절 번호를 쓰지 않는다.** 번호는 재편할 때마다 어긋나는데 컴파일도 grep도 안 잡는다.
  문서 **안**에서는 `§3`을 그대로 쓴다(같이 움직인다).
- `memory-meter 규칙.md`는 237줄로 가장 크지만 **쪼개지 않았다.** 용어 표와 작업 관리자 대조는
  따로 읽으면 쓸모가 없다 — 이게 "400줄 넘어도 그대로 두는" 사례다.

## 후속 작업 / 주의사항

- **`UI 규칙.md`가 474줄로 3-5절이 정한 400줄 검토선을 넘는다.** 남은 §0~§6이 전부 UI 전역 규칙이라
  내릴 하위 주제가 없어 그대로 뒀다. 더 커지면 §6 공통 작성 규약이 첫 후보다.
- **XML 서식 태그(`<b>`·`<c>`) 위반이 아직 7개 파일에 약 50곳 남아 있다** —
  `WidgetPositionLayout.cs`(24) · `WindowManager.cs`(7) · `FlexibleGridLayoutGroup.cs`(6) ·
  `ServerWaitManager.cs`(5) · `WindowSettings.cs`(3) · `LoadingPresenter.cs`(2) · `PingManager.cs`(2).
  이번엔 `MainCanvasView.cs`만 걷었다. 나머지는 별도 정리 커밋으로 한 번에 훑는 게 낫다 —
  `<b>`를 지우기만 하면 강조가 사라지므로 **문장을 다시 써야 한다**(`폴더 구조.md` 3-4절).
- `.claude/Agent/` 과거 로그의 옛 절 번호 언급은 **그 시점의 기록이라 고치지 않았다.**
- 신규 `.md` 12개의 `.meta`는 Unity 새로고침으로 생성 완료. 원본과 함께 커밋해야 한다.

## 업데이트 (2026-08-23) — XML 서식 태그 전량 제거

- 남아 있던 7개 파일 50곳(`<b>`·`<c>`)을 전부 걷었다. `Assets/Scripts_Client`에 0건.
- **`<c>이름</c>` → `'이름'`** 은 기계적 치환으로 끝났다(`s|<c>\([^<]*\)</c>|'\1'|g`).
- **`<b>`는 거의 전부 태그만 걷어도 문장이 성립했다.** 이미 `⚠️`·`★`·`■`나 `—` 구조가
  강조를 지고 있었기 때문이다. 문장을 다시 쓴 건 `PingManager`("연결 시점부터" →
  "연결되는 순간부터") 한 곳뿐이다.
- **재발 방지** — `폴더 구조.md` 3-4절에 "남아 있는지 확인하는 법"(grep 한 줄)을 넣었다.
  컴파일도 IDE도 이걸 잡아 주지 않아 한 번 새면 계속 쌓인다. 실제로 규칙이 있는데도
  50곳이 남아 있었다.

> `Assets/Scripts_Server/Protocol`·`Network`에도 같은 위반이 있으나 **자동 미러이고 담당이
> 서버**라 손대지 않았다. 원본은 `Server/MikaProtocol`이다.
