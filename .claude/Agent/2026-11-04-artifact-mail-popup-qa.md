# 아티팩트 거래·칸 실측 · 우편 결과 팝업 수정

## 목적 / 배경
- T-152 · T-188에서 기록이 없던 4항목을 플레이 모드 MCP로 확인했다. 그 과정에서 우편 팝업 버그와 로컬 DB 어긋남이 나와 함께 고쳤다.

## 변경 내용
- `GachaResultPresenter.SummarizeMails` — `MailInfo.Artifacts`를 합쳐 칸으로 그린다. 아티팩트만 든 우편은 "보상이 비어 있다" 경고만 남기고 창이 안 떴다.
- `tasks/T-152` · `tasks/T-188` — 실측 기록.

## 실측 결과
- A 등록 → B 구매 → B 우편 수령 · A 판매금 950(1,000 − 수수료 5%)
- 등록 취소 → 우편 → 아티팩트 칸 복귀 · 수정 뒤 '우편 수령 결과' 창에 아티팩트가 뜬다(캡처 확인)
- 잠근 번호 — 등록 창 흐림·선택 불가 · 서버 `EntityLocked`
- 창고 장비 → 아티팩트 칸 — 드래그 핸들러로 토스트 · 패킷 안 나감 · 직접 보내면 `StorageSlotArtifact`

## 주요 결정 / 근거
- 로컬 경매장 DB — 메인 DB의 다음 `trade_id`가 옛 매물과 겹쳐 등록이 거부됐다. 메인에 진행 중 거래가 없어 옛 DB를 `auction.sqlite3.old-20261104*`로 보관하고 새로 시작하게 했다(gitignore · 이 PC에만 해당).
- 테스트 계정이 남지 않게 끝난 뒤 `game.sqlite3`를 테스트 전 상태로 되돌렸다.

## 후속 작업 / 주의사항
- 옛 DB의 더미 매물 17,300건은 빠졌다. 필요하면 치트 `SeedAuctionListings`로 다시 만든다.
- 등록·구매·취소·수령은 버튼이 아니라 모델·패킷 호출로 돌렸다. 버튼 클릭 경로는 확인하지 않았다.
- 유물 감정 아티팩트는 풀 25·26에만 있다 — 그 위 등급 유물에서는 안 나온다(T-150의 남은 결정).
