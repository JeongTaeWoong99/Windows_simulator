# 배치 해제에 장비 해제를 딸려 보낸다

## 목적 / 배경

슬롯에서 캐릭터를 빼도 **장비가 그대로 끼워진 채 남았다.**
서버의 배치 해제(`User.AssignWorkStation`)는 슬롯만 비우고 `_worn` 매핑을 건드리지 않는다 —
착용은 (캐릭터, 칸) 축이라 슬롯과 무관하기 때문이다.
그 결과 일하지도 않는 캐릭터가 장비를 붙들고, 창고 장비 탭에는 '배' 마크만 남는다.

## 변경 내용

- `UI/Main/WorkStationSelectPresenter/WorkStationSelectPresenter.cs`
  — `UnequipAllWorn()` 신설, `OnAssignedCardClicked`이 배치 해제를 보내기 **직전에** 호출

## 주요 결정 / 근거

- **서버에 "배치 해제하면 장비도 빼 줘"를 요청하지 않고 클라가 보냈다.**
  해제 패킷(`C_UnequipRequest`)이 이미 있고 칸 4개를 도는 것이 전부다.
  서버가 하면 "배치 해제"라는 한 요청이 착용까지 바꾸게 되어, 지금 화면이 기대는
  "요청 하나 = 응답 하나" 대응이 깨진다.
- **대기(`BeginWaiting`)는 배치 해제 하나만 연다.** 장비 응답은 먼저 도착하지만
  `OnEquipCompleted`가 `_pending`(=`Unassign`)을 보고 흘려 보내고,
  표시는 `EquipsChanged`가 따로 갱신한다. 칸마다 대기를 열면 로딩이 5번 깜빡이고
  `_pending`이 한 칸짜리라 단계 판정이 엉킨다.
- **해제를 먼저, 배치 해제를 나중에 보낸다.** 한 세션의 패킷은 보낸 순서대로 처리되므로
  캐릭터가 슬롯에서 빠지기 전에 장비가 창고로 돌아간다.
- **빈 칸은 보내지 않는다** — 서버가 `EquipSlotEmpty`로 거절하고 경고 로그만 쌓인다.

## 후속 작업 / 주의사항

- ⚠️ **클래스 주석의 "클라가 해제를 먼저 보내지 않는다"는 장착에만 해당한다.**
  다른 캐릭터가 낀 장비를 끼울 때는 그대로 보내고 서버가 옮긴다(실패 시 어디에도 안 낀 상태가 된다).
  배치 해제만 예외다 — 주석 두 줄이 나란히 있으니 한쪽만 보고 뒤집지 말 것.
- ⚠️ 중간에 연결이 끊기면 **장비는 빠지고 캐릭터는 슬롯에 남는** 상태가 가능하다.
  둘을 한 요청으로 묶으려면 서버 패킷이 필요하다 — 지금은 다시 해제를 누르면 정리된다.
- 플레이 실측 전이다(코드만 반영).
