# 아트 전 임시 UI 색을 Palworld식 다크 팔레트로 통일

## 목적 / 배경
- 아트 없이 Image·TMP에 색만 넣어 둔 상태라 화면마다 제각각(연하늘 패널 200 · 흰 패널 258 · 짙은회/형광노랑/순빨강 글씨 …)이었다.
- 아트 방향은 Palworld — 짙은 남색 반투명 패널 · 흰 글씨 · 하늘 강조 · 주황 선택으로 맞췄다. **게임에서 추출한 값이 아니라 인상 기반 초안**이다.

## 변경 내용
- `UI/Shared/theme/` — `UIThemeRole`(역할 enum) · `UIThemePalette`(SO, `Resources/UIThemePalette.asset`) · `UIThemeColor`(태그) · `Editor/UIThemeBaker`(적용·자동 태그 메뉴)
- 상태 색 Presenter 6곳 + `AptitudeLabel` — `Color` 필드를 `UIThemeRole` 필드로 바꾸고 `UIThemePalette.Of`로 칠한다
- 자동 태그로 원본 씬 + 프리팹 12개에 태그 555개 부착 → 팔레트 색으로 구움
- 사용 규칙 → `Shared 규칙.md`의 "임시 테마" 절

## 주요 결정 / 근거
- **태그는 실행 중 아무것도 안 한다(에디터에서 굽기만).** 실행 중 OnEnable로 칠하면 캔버스를 껐다 켤 때마다 Presenter가 칠한 선택색·등급색을 덮는다.
- **버튼 바탕은 흰색, 색은 ColorBlock.** ColorTint가 `Image.color`에 곱해져서 바탕에 남색을 두고 틴트를 주면 탁해진다.
- 등급색(`RarityPalette`)은 규칙 의미라 팔레트에서 뺐다. `pickingEquipSlotColor`·`normalCellColor`는 등급색 위에 곱하는 배율이라 그대로 뒀다.
- 씬 안 프리팹 인스턴스는 건너뛰고 프리팹 원본에서 칠한다 — 인스턴스 오버라이드가 쌓이지 않게.

## 후속 작업 / 주의사항
- 자동 태그는 색으로 역할을 짐작한 것이라 틀린 칸이 있을 수 있다 → 인스펙터에서 역할만 바꾸면 된다.
- 팔레트 수정 시 프리팹은 `Window/DesktopWindowControl/UI 테마/적용`을 눌러야 반영된다(열린 씬은 자동).
- `Scenes/Test Copy` 씬은 손대지 않았다.
- 아트가 들어오면 태그를 걷고 `theme/`를 지운다.

## 업데이트 (2026-09-26) — 자동 태그 규칙 수정 후 다시 굽기
- 🔴 첫 매핑은 **색상만 보고** 큰 바탕을 긍정/경고/강조로 분류해 초록·빨강 패널이 남았고, 빨강 글씨·금색 버튼 위 짙은 글씨가 안 보였다(사용자 지적).
- 규칙 변경: 글씨는 **흰색 기본 · 노랑(골드) → Highlight · 파랑(다이아) → Accent만 예외**. 큰 바탕(넓이 2만 이상 또는 가로 300×세로 30 이상)은 색과 상관없이 패널. 화면 전체 바탕(로그인·로딩)은 딤(`Overlay`, 투명도 ≤ 0.6). 금색 버튼은 흰 글씨가 읽히게 더 짙게.
- ⚠️ 자동 태그는 **지금 색**을 보고 짐작한다 — 이미 구운 씬에 다시 돌리면 원본 색이 아니라 팔레트 색을 읽는다. 그래서 씬·프리팹을 git으로 원본에 되돌린 뒤 다시 돌렸다(씬 교체 전 빈 씬을 열어 외부 수정 대화상자를 피함).
