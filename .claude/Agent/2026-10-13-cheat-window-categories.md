# 치트 창 — 왼쪽 분류 목록 · 검색 · 칸 하나 = 클래스 하나

## 목적 / 배경
- 칸 10개가 한 줄 스크롤로 쌓여 보기 불편하고, `CheatWindow.cs`가 1,050줄이라 치트가 늘면 계속 커지는 구조였다.
- 사용자가 고른 방향: 구조 분리 → 분류 목록 + 검색 + 서버 전체 배지 + 줄 정리. 즐겨찾기·시나리오 버튼은 칸이 더 늘면 한다.

## 변경 내용
- 칸 → `CheatSection` 상속 클래스 11개(`<이름>CheatSection.cs`). 창은 `TypeCache`로 모은다.
- 공용 부품 `CheatGui.cs`, `TidPicker.cs`로 분리. 전역 배수는 정산 칸에서 떼어 독립 칸(서버 전체 배지).
- 화면·추가 절차 → `Assets/Scripts_Client/Editor/cheat-console/cheat-console 규칙.md` 「화면 구성」·「치트 추가하기」.

## 주요 결정 / 근거
- **접기 대신 분류**: 2026-09-17 "접었다 펴는 게 불편" 요청을 지키면서 스크롤을 줄인다. 상단 탭보다 왼쪽 목록이 분류가 늘어도 버틴다.
- **[SerializeReference] List<CheatSection>**: 칸 입력값이 도메인 리로드에도 남게. 새 클래스는 OnEnable에서 빠진 것만 만들어 넣고, 지운 클래스는 null로 돌아와 걷어 낸다.
- 회색 안내문은 ⓘ 툴팁(`Hint`)으로 — 상태를 말하는 줄만 본문에 남겼다.

## 후속 작업 / 주의사항
- ⚠️ 칸 클래스에 `[Serializable]`이 빠지면 `[SerializeReference]`가 저장하지 못해 리로드마다 입력이 초기화된다.
- 이번 개편으로 예전 창에 저장돼 있던 입력값(골드 금액 등)은 한 번 기본값으로 돌아간다.
- 컴파일·칸 11개 수집·창 열기까지는 MCP로 확인했고, 화면 모습은 사용자 실측이 남았다(캡처가 터미널에 가려 실패).

## 업데이트 (2026-10-13)
- 분류 목록의 노란 세모(서버 전체 아이콘)를 뺐다 — 사용자 요청. 서버 전체 표시는 칸 머리 배지에서만 한다.
