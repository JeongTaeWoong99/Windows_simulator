# 영약 자동 사용 ON/OFF 전환

## 목적 / 배경
- #123의 태웅 결정 적용. 현재 규칙·진행 상황은 `tasks/T-195-소모품효과적용.md`, 클라 후속은 T-194.

## 주요 결정 / 근거
- 영약 소비 콜백이 보유 재고를 실제 차감한 뒤 지속 판정 수를 반환한다. 슬롯마다 재고 사본을 쓰면 여러 슬롯이 같은 영약을 중복 소비한다.
- 기존 수량은 스키마 변경 때 없애지 않고 환급 원장으로 옮긴다. 로그인 스냅샷 전에 인벤토리·우편·원장 삭제를 묶어 재시도에도 보존한다. 원장 조회는 기존 PK로 충분하다.
- 자동 소비한 칸에 같은 정산 보상이 다시 들어올 수 있다. 저장·응답은 마지막 보유 상태를 읽어야 차감 전/보상 전 값으로 되돌리지 않는다. 직접 사용 응답도 같은 규칙을 적용했다.
- 오프라인 진행은 기존 기획대로 없다. 재접속에서 ON을 복원하고 활동 슬롯의 버프만 채운다.

## 검증
- 먼저 구 방식이 영약을 보관 칸으로 옮기는 실패를 확인했다. 직접 사용·자동 사용 동시 응답의 오래된 보유량도 실패로 재현했다.
- 전체 서버 테스트 1,220개 통과. 환급 중복·부분 우편·중간 실패 롤백·사용자 분리·로그인 스냅샷·패킷 직렬화 포함.
- 워크트리 DB를 별도 포트 서버로 기동해 0015를 적용한 후 종료했다. main 실행 서버·DB는 건드리지 않았다.

## 후속 작업 / 주의사항
- Count/Take·SlotAutoUseInfo.Count를 제거한 호환 불가 계약이다. 클라이언트의 SlotAutoUsePresenter·SlotBuffChipsView를 토글·보유 개수 표시로 바꾸어 함께 반영해야 한다. Unity 컴파일·실플레이 확인은 클라 몫이다.
- 서버 작업 규칙에 따라 브랜치 푸시·PR로 인계한다. tasks/README INDEX는 PR 머지 뒤 갱신한다.
