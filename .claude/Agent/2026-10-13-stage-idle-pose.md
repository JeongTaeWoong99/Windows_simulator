# 슬롯 연출 — 달리기 양 끝에 대기 자세 한 장 (T-097)

## 목적 / 배경
- 10-12에 대기 구간을 빼고 공격·달리기만 남긴 뒤, 두 자세 차이가 커서 바뀌는 순간이 확 튄다는 사용자 피드백.
- 조건: 시간을 더 쓰지 않는다 (최소 주기 1.6초 = 달리기 1 + 공격 0.6 유지).

## 변경 내용
- `SlotStageTimeline.Result.IdlePose` — Run 단계 그대로, 달리기 처음·끝 `poseSeconds`만 true.
- `SlotStageView.PickFrame` — `IdlePose`면 `CharacterVisual.IdleFrame`(대기 첫 프레임, 없으면 달리기 첫 프레임).
- `SlotStageSettings.poseSeconds` 0.08 (0이면 끔) · 게임UI 2.5 · Art 규칙.

## 주요 결정 / 근거
- **새 EPhase를 만들지 않고 Run 안의 플래그로** — 땅 흐름(`Phase == Run`일 때만 흐름)·대상 위치 계산을 안 건드린다. 새 단계로 만들면 그 0.08초 동안 땅이 멈춰 10-12의 "뚝뚝"이 돌아온다.
- **화면 프레임이 아니라 초** — 1프레임은 FPS마다 길이가 다르고 그림 한 장(약 0.08~0.1초)보다 짧아 깜빡임이 된다. 그림 한 장 길이가 리듬이 맞는다.
- 달리기가 짧아지는 경우(주기 < 연출 한 바퀴)를 위해 사이 자세는 달리기의 1/4을 넘지 않는다.

## 후속 작업 / 주의사항
- 실측 대기 — 0.06~0.1 사이에서 인스펙터로 바로 조정 가능(`Resources/SlotStageSettings`).

## 업데이트 (2026-10-13) — 초 → 장수
- 0.08초는 그림 한 장 길이와 같아 동작 속에 묻혀 티가 안 났다 → 두 장 길이로.
- 그림 한 장 길이는 `runLoopSeconds ÷ 달리기 장수`라 캐릭터마다 다르다(0.067~0.1초) — 초로 고정하면 장수가 적은 새 캐릭터는 두 장이 안 된다.
- `poseSeconds` → `poseBeats`(기본 2). 지금 값: black-knight 0.13 · hero-knight 0.16 · warrior·bringer 0.2초. 1/4 상한은 그대로.
