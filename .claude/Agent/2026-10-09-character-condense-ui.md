# 캐릭터 응축 화면 (T-130 · 이슈 #59)

## 목적 / 배경
- 서버 응축(`adc44b0`)에 맞춰 클라 화면을 붙였다. 사용자가 HTML 목업(`응축UI목업.html`)을 보고 "이대로" 승인. 목업은 이후 사용자 요청으로 지웠다.
- 규칙·화면 동선 → `Assets/Scripts_Client/UI/Inventory/Inventory 규칙.md` "응축 창" 절 · 씬 트리 → `UI 배치 현황.md`

## 주요 결정 / 근거
- **팰월드처럼 목록·응축 패널 두 칸을 새로 만들지 않았다** — 인벤토리 격자가 이미 목록이다. 열린 동안 격자 좌클릭 = 재료 고르기, 칸 표시는 창이 `GetMark`로 답한다.
- **큐브 창과 같은 자리·같은 여닫기** — 씬 오브젝트도 `Equip Enchant Presenter`를 복제해 고쳤다. 판매 목록은 두 창의 `OpenChanged`를 같은 핸들러로 듣는다.
- **★은 스프라이트**(`Assets/Sprites/ui/star.png`, PIL로 그린 16px · checkmark.png와 같은 임포트) — `neodgm_pro SDF`가 Static 아틀라스라 `★` 글리프가 없다. 글씨 자리는 `n성`·`단계`.
- **응답에 재료 ID가 없다** → `PlayerDataModel.BeginCondense`로 적어 두고 모델이 지운다(개체 판매와 같은 방식). 캐시 반영 → `CharactersChanged` → `CharacterCondenseCompleted` 순.
- 효율 계산 `속도 가산`에 응축 항을 더했다 — 서버 가산 합에 들어가므로 빠지면 전역 배수 역산이 틀린다.
- 진행 바는 ★마다 한 칸(목업 결정). 누적 76 한 줄이면 ★1 구간이 거의 안 보인다.

## 후속 작업 / 주의사항
- ⚠️ **꺼진 채 저장된 Presenter는 처음 켜는 프레임에 `Start`가 안 돈다.** 그 사이 격자가 `GetMark`를 불러 NRE가 났다(플레이 모드 실측) → `EnsureServices`. 같은 구조(자리 빌려 쓰는 창 + 격자가 질의)를 또 만들면 같은 함정이다.
- ⚠️ `UIThemeColor.Setup`은 역할만 적는다 — 색은 `Apply(UIThemePalette.Current)`로 구워야 한다. 복제한 버튼의 `ColorBlock`이 원본(주황) 그대로 남았었다.
- ⚠️ `capture_game_view --save_path`는 프로젝트 안만 받고 `Temp/x.png`를 **`Assets/Temp/`** 에 쓴다 — 캡처 뒤 지웠다.
- 실측 남은 것 → `tasks/T-130` 체크리스트. 서버 테스트 계정 `condense_test`가 로컬 DB에 남아 있다(DB는 커밋 제외).
- **후속 피드백(같은 날)**
  - "넣을 수 있는 캐릭터가 있는데 없다고 뜬다" → 판정은 맞았다(대상 살쾡이 외 같은 종류 없음). **다른 캐릭터가 같은 임시 그림을 써서** 같은 종류로 보였다.
    창 알림 줄이 재료가 없으면 먼저 "재료로 넣을 {이름}이(가) 없습니다 — 같은 캐릭터끼리만 응축됩니다"라고 말하게 했다.
  - 판매 목록은 **담긴 것이 있을 때만 보인다** — 비어 있으면 꺼지고 격자가 넓어진다. 합계 줄 왼쪽에 [비우기]. 카트 구독은 `Start`/`OnDestroy`(꺼진 채 켜질 신호를 받아야 한다). 플레이 모드 실측: 처음 꺼짐 · 담으면 격자 720→357.5 · 비우면 다시 꺼짐.
- 이슈 #59 공돌리기는 커밋 뒤에 한다(아직 미커밋).
