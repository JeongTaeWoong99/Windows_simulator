# 위젯 알림 줄 · 큐브 자동 [내리기] · 레드닷 4곳 · 위젯 화살표 (T-145 · T-176)

## 목적 / 배경
- 열을 다 접고 위젯만 띄워 둔 상태에서 "놔두면 손해 / 걸어 둔 결과"를 알린다 — 목업 B안(위젯 위 상태 줄) 사용자 확정.
- 큐브 자동은 가운데 팝업(DIM)이 떠 있어야 돌아서 위젯만 남길 수 없었다.
- 위젯 [창 열기/닫기] 화살표가 상태를 따라가게(열림 ↑ · 닫힘 ↓).

## 주요 결정 / 근거
- **팝업 DIM은 빼지 않았다.** 자동 중 뒤를 만지면 그 장비를 팔거나 벗길 수 있다. [내리기] = "3열 전체 접기"로 풀어 팝업 규칙에 예외를 두지 않았다.
- **큐브 창은 끄지 않고 `CanvasGroup`(alpha 0 · 클릭 통과)으로 숨긴다.** 끄면 공개 연출이 멈춰 루프가 `afterFx.IsPlaying`에서 서고 응답 구독도 풀린다. 숨은 동안 굴림 소리는 끈다.
- 복원은 `UIManager.Reopened`(OpenWorkStation이 쏜다) — 위젯 [창 열기]와 띠 클릭이 같은 길로 큐브 창을 되살린다. UIManager가 큐브 창을 모르게 했다.
- 가득 참은 `PlayerDataModel.IsInventoryFull`로 올렸다 — 띠와 하단 [인벤토리] 점이 같이 본다. 슬롯마다 마지막 수확의 `InventoryFull`을 남기고, 판매 성공이면 내린다(아직 가득이면 다음 수확이 다시 올린다).
- 열림 감지는 이벤트가 아니라 Update에서 `UIManager.IsOpen` bool 비교 — 캔버스 여닫기 경로가 여럿이라 이벤트로 모으면 새는 곳이 생긴다.
- 넣지 않은 레드닷: 상자 쌓임 · 응축 가능(재촉이 된다).

## 함정
- 위젯 버튼 이름이 `Open/Close Button`이라 `Transform.Find` 경로로 못 찾는다(`/`가 구분자). 처음 배선이 비어 다시 연결했다.
- 에디터 eval에서 `GetComponent<T>() ?? AddComponent<T>()`는 Unity 가짜 null 때문에 AddComponent가 안 돈다 — `== null`로 검사할 것.
- `python -I`로는 사용자 site-packages(openpyxl)를 못 읽는다 — 엑셀 작업은 `-I` 없이.
- 씬 저장 시 레이아웃이 계산한 RectTransform 값이 대량으로 다시 써진다(diff +3천 줄 · 대부분 앵커·크기 값).

## 후속 작업 / 주의사항
- 가득 참 띠는 실제로 인벤토리를 채워 확인하지 못했다 — 사용자 실측 대기.
- 빈 작업슬롯 점은 열린 빈 칸 전부에 뜬다(쉬는 캐릭터가 있으면). 칸이 많은 계정에서 시끄러우면 "첫 빈 칸만"으로 줄일 것.
- 알림 종류별 끄기 설정은 넣지 않았다.
- 문구 키: `UI.Widget.Alert*` 4개 · `UI.Enchant.Minimize` (Loc_UI.xlsx).

## 업데이트 (2026-11-27)
- **위젯 화살표를 뒤집었다** — 상태가 아니라 누르면 일어날 일을 가리킨다(열림 ↓ · 닫힘 ↑). 사용자 지적.
- **띠는 열어도 남는다** — 열리면 위젯과 같은 줄의 옆 열 빈 자리(옆 열은 가운데 950만 써서 위젯 높이만큼 빈다). 오른쪽 칸 위젯이면 왼쪽.
- **"빈 슬롯인데 띠가 늦게 뜬다" 신고는 구독 문제가 아니었다** — Editor.log로 따라가 보니 칸을 열 때는 캐릭터가 1마리(배치 중)라 쉬는 캐릭터가 없었고, 뒤에 치트로 캐릭터를 받자 바로 떴다. 같은 순서(칸 해금 → 캐릭터 지급)를 재현해 이벤트로 즉시 뜨는 것을 확인. "쉬는 캐릭터가 없으면 안 띄운다"를 바꿀지는 사용자 결정 대기.

# T-212 나침반 자동 사용 (같은 날 이어서)
- `ItemUseLabel.IsAutoUsable` = 서버 `ItemUseCatalog.IsSlotBuff`와 같은 4효과. 보물 지도(즉시 판정)는 빠진다.
- 인벤토리에서 자동 사용 소모품(영약 포함)을 누르면 사용 창 대신 토스트 `UI.ItemUse.TurnOnInSlot`. 서버는 옛 클라의 직접 사용도 받는다(#162).
- 자동 사용 칸 최소 폭이 122px이라 한 줄 5칸(634)은 설정 열(540)을 넘는다 → 영약 / 나침반 두 줄(`SlotAutoUsePresenter.AddLine` — 앞 줄을 복제하고 딸려 온 칸을 지운다). 순서는 효과 → 등급(SlotCount). TID 순은 등급 순이 아니다(은빛 100011이 낡은 100036보다 앞).
- 나침반 칸은 폭이 좁아 이름이 "낡은 ···"처럼 줄어든다 — 아이콘으로 구분된다.
- 로컬 서버는 #162 전이라 나침반 켜기는 거절된다 — `git pull` 뒤 실측.

## 업데이트 (2026-11-27 · 2)
- **열렸을 때 알림은 접는다** — 빈 자리가 위젯 높이뿐이라 띠가 쌓이면 넘친다. `[알림 n건 — 눌러서 보기]` 한 줄(견본을 복제한 `Alert Badge`)만 두고 누르면 펼친다. 여닫거나 띠를 누르면 접힌다.
- **함정:** 열리는 프레임엔 `#Widget Canvas` 폭이 0이라, 그때 한 번 읽은 폭으로 띠를 만들면 폭 0 → 글씨가 자동 축소 최소(1)까지 줄어 점이 된다. 열린 동안 매 프레임 폭을 맞춘다(`FitOpenWidth`).
- **TMP 자동 축소 최소 = 1 일괄 적용** (사용자 "다 1로") — 프리팹 17개 81곳 · 씬 489곳(씬 열린 상태 집계 1,228은 런타임 복제 포함). 자동 축소가 꺼진 글자(118)는 그대로 — 일부러 끈 것이고 레이아웃과 얽혀 있을 수 있다. 수량 팝업 [1개·절반·최대]는 [취소] 버튼을 실행 중 복제하므로 따라온다.
- 자동 사용 칸은 한 줄 2칸(`CellsPerLine`) — 3칸이면 이름이 "낡은 ···"처럼 줄었다.
- 나침반 1개 = 판정 1번 · 2종(상자·유물 50%/100%) · 은빛 삭제는 진우에게 #168로 요청.

## 업데이트 (2026-11-27 · 3)
- **열렸을 때 알림은 경고 점으로** — 옆 열 빈 자리 · 접힌 줄 · 펼침은 띠가 많아지면 옆 열을 덮어 버렸다(사용자). 알림 줄은 닫혔을 때만, 열리면 사유 자리에 `WarningDotView`(느낌표 그림 `Sprites/ui/warning_dot.png` · DOTween 숨 쉬기 · 레이캐스트 켜서 툴팁). 가득 참 → 하단 [인벤토리](빨간 점 대신) · 빈 칸+쉬는 캐릭터 → 그 작업슬롯 칸(잠긴 칸의 "열 수 있다"는 빨간 점 그대로).
- 경고 점은 씬에 꺼진 채 둔다 → Awake가 늦으니 `TooltipTrigger`는 처음 쓸 때 찾는다. 숨 쉬기는 OnEnable에서 건다(열 캔버스가 접혔다 펴지면 KillOnDisable로 죽기 때문).
- **FPS가 위젯을 피한다** — 위·아래는 위젯을 따라가고(설정의 위·아래 무시), 좌·우가 위젯 열이면 반대 구석. `WidgetPositionLayout`에 위치 변경 이벤트가 없어 FPS · 알림 줄 둘 다 Update에서 위치를 비교한다.
- `UI.Widget.AlertBadge*` 문구 2줄은 지웠다(접힌 줄 폐기). 새 키 `UI.Widget.WarningTitle` · `UI.Widget.WarningIdleSlot`.
- **FPS 설정을 보이기 · 숨기기 토글로** (사용자) — 위치는 이제 저절로라 드롭다운의 구석 고르기가 안 먹었다. 자리 규칙은 "위젯이 오른쪽 열이면 왼쪽, 그 밖은 오른쪽"으로 단순화. 저장 키 `Display.FpsTextPosition`은 그대로 두고 0 = 숨김 · 그 밖 = 보이기로 읽어 옛 저장값이 이어진다. 씬의 설정 줄은 `Topmost Row` 토글을 복제해 드롭다운을 대신했다(`Fps Text Row`). 문구 `UI.Setting.FpsHidden` 삭제 · `FpsTextPosition` KR "FPS 표시".

## 업데이트 (2026-11-27 · 4) — FPS 되돌림
- 열렸을 때는 경고 점이 각 자리에 뜨므로 위젯 · 알림 줄 · FPS를 한 가장자리에 모을 이유가 없어졌다(사용자). **FPS 자리 피하기와 보이기 토글을 모두 되돌려** 원래의 숨김 · 네 구석 드롭다운으로 복구(코드 4파일은 2c001415 판, 씬 줄은 [최대 FPS] 드롭다운을 복제해 다시 만듦 · `UI.Setting.FpsHidden` 복구).
