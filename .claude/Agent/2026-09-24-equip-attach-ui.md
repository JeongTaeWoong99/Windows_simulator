# 장비 장착 · 해제 UI — 효율 계산 자리를 갈아 끼운다 (T-074)

## 목적 / 배경

장비를 **얻는 길**(뽑기·상자·치트)과 **보는 곳**(창고 장비 탭)은 다 섰는데 **끼우는 곳이 없었다.**
`C_EquipRequest`·`C_UnequipRequest`는 T-002(`e860066`)에서 들어왔고 **클라 구독자가 0건**이었다.
배경·완료 조건은 → `tasks/archive/T-074-장비장착UI.md`.

서버 쪽은 손대지 않았다 — 2026-09-24 코드로 확인한 것:

| | 확인한 것 |
|---|---|
| 효과 범위 | `Equip.AppliesTo` — `Industry == None`이면 **전 산업**, 아니면 **그 산업만** |
| 합성 | `ResolveSlotSpeed` = 적성 기본값 → `.Add(장비 가산)` → `.Add(특성 가산)` → `.Multiply(전역배수)` |
| 순서 | `정산 → 매핑 변경 → 속도 재확정` — 새 속도가 **이전 구간에 소급되지 않는다** |
| 되돌아오는 것 | `S_EquipSyncResponse`(교체로 밀려난 개체 포함) · `S_WorkStationSlotSyncResponse`(속도가 실제로 바뀐 슬롯만) |

## 주요 결정 / 근거

- **팝업이 아니라 자리 교체다**(사용자 선택). 칸을 누르면 `Efficiency Label`·`Efficiency Scroll View Panel`이
  꺼지고 같은 자리에 `Equip Picker Panel`이 뜬다 — `#Main Canvas`가 이미 쓰는 수법을 패널 안에서 되풀이한 것이다.
  팝업은 **캐릭터·칸 맥락이 화면에서 사라져** 무엇에 끼우는 중인지 잃는다.
- **등급색은 칸 바탕(버튼의 Target Graphic)에 칠한다** — 다른 칸들과 같은 축이다.
  중간에 위쪽 `Rarity Bar`(6px)로 한 번 갔다가 **사용자 지시로 되돌렸다**(2026-09-24).
  띠로 갔던 근거는 *흰 바탕 + 진회색 글자* 위에 등급색을 칠하면 글자가 묻히고,
  `Button`의 색 전이가 `targetGraphic`과 곱해져 **누름·잠김에서 같은 등급이 달라 보인다**는 것이었다.
  되돌린 근거가 더 무겁다 — **색은 임시 표기이고 🎨 스프라이트가 오면 통째로 빠진다.**
  그때 바꿀 곳이 네 군데(창고 칸·캐릭터 카드·작업슬롯 칸·장비 칸)로 **같은 모양이어야** 한 번에 끝난다.
  가시성은 그때까지 감수한다.
- **남이 끼고 있는 장비도 목록에 남긴다.** → **4차에서 뒤집었다**(아래) — 창고에 있는 것만 낸다.
- **거르기는 표시용이다** — `EquipLabel.CanEquip`은 서버 `EquipCatalog.CanEquip`의 사본이고,
  진짜 거절은 `EquipKindMismatch`다.
- **장착 실패는 화면에 남는다** — 산업 교체 실패와 같은 판단이다(그 칸에서 할 일이 남아 있다).
  배치 실패만 슬롯 목록으로 물러난다.
- **씬 작업은 Unity CLI(`eval_file`)로 만들었다.** 프리팹 YAML을 손으로 쓰지 않고 에디터에
  짓게 한 뒤 `SerializedObject`로 배선했다 — GUID·fileID를 손으로 만들지 않는다.
  ⚠️ `eval_file`은 **`using` 지시문을 못 받는다**(메서드 본문으로 감싼다). 전부 정규화 이름으로 쓴다.

## 사용자 피드백 뒤 추가 (2026-09-24)

- 🔴 **칸 넷의 폭이 `▼` 때문에 깨졌다.** 고르는 중인 칸에 `▼`를 붙이자 그 칸만 넓어졌다.
  원인은 `▼`가 아니라 **칸에 `LayoutElement`가 없던 것** — `HorizontalLayoutGroup`의 `childControlWidth`는
  선호 폭을 자식에게 묻는데, 없으면 그 답이 **TMP의 글자 폭**이 된다. 목업 시절엔 네 칸의 글자 길이가
  비슷해서 **우연히 균등해 보였을 뿐**이다. 각 칸에 `preferredWidth 0 · flexibleWidth 1`을 박아
  `1:1:1:1`로 고정했다(`▼` + 긴 이름을 넣어도 넷 다 100.00px 실측).
- **칸에 효과 한 줄을 더했다**(`Effect Text (TMP)`) — 창고 장비 탭과 같은 `EquipLabel.GetEffectText`다.
- **효율 계산에 `속도 가산` 줄**(줄 수 3 → 4). 값은 총합, 주석 줄은 `특성 +20% · 장비 +5%`.
  ⚠️ 서버가 내역을 안 주므로 **클라가 같은 표를 다시 읽는다** — `GetTraitSpeedAdd`·`GetEquipSpeedAdd`는
  서버 `User.GetTraitSpeedAdd`·`User.GetEquipSpeedAdd`의 **사본**이다. `T-055`가 끝나면 지운다.
- ✅ **그 덕에 "개발용 전역 배수" 역산을 고쳤다.** `현재 ÷ 기본값` → `현재 ÷ (기본값 × (1 + Σ가산))`.
  계획 단계에서 *"고칠 곳은 서버다"* 라고 범위 밖에 뒀던 항목인데, **가산을 알게 되자 클라에서 맞출 수 있게 됐다.**
  다만 T-055의 근거(서버가 내역을 명시)는 사라지지 않는다 — 지금 것은 사본이라 표가 갈리면 조용히 틀린다.

## 2차 피드백 — 아이콘 자리 · 선택 표시 · 산업 필터 (2026-09-24)

- **빈 칸의 `비어있음` 글자를 빼고 정사각형 빈 네모를 넣었다**(`Icon Row > Icon (임시)`).
  🎨 아이템 아이콘이 오면 이 Image에 넣는다 — 코드는 손대지 않는다(산업 버튼의 `Icon (임시)`와 같은 수법).
  ⚠️ **세로 줄 안에서 정사각형을 만들려면 한 겹이 더 든다.** `SquareLayoutElement`는 *부모 높이만큼 넓게*라
  가로 줄 전용이다. 그래서 높이를 못박은 `Icon Row`(HLG · `forceExpandHeight`)를 두고 그 안에 넣었다 —
  칸의 세로 줄에 바로 붙이면 `forceExpandWidth` 때문에 칸 폭만큼 늘어나 네모가 아니게 된다.
- **`▼`를 떼고 `Selected Bar`(칸 위 4px 노랑)로 바꿨다.** → **3차에서 다시 뺐다**(아래).
- **산업 필터**(`Filter Panel`). 색 규칙은 산업 버튼과 같다(고른 것만 노랑).
  처음엔 `모두` + 5산업 6개였는데 **5차에서 `모두`를 뺐다**(아래).
  전 산업 장비는 어느 필터에서도 남는다.
- 🔴 **목록에는 정렬이 없었다.** 사용자는 *"자동으로 등급 높은 순서대로 보인다"* 고 읽었지만
  실제로는 `_data.Equips`(서버가 준 순서) 그대로였다 — **우연히 그렇게 보였을 뿐**이라 필터를 켜면 깨졌을 것이다.
  일단 **등급 → TID → 개체 번호**로 못 박았고, 3차에서 **수치 기준**으로 다시 바꿨다(아래).

  했더니 칸 높이가 `114 / 114 / 120 / 114`로 나와 버그처럼 보였는데, 부모가 아직 새 높이(120)를 안 준
  **낡은 rect를 읽은 것**이었다. `#Main Canvas`부터 두 번 돌리니 넷 다 `149.6 × 120`이었다.

## 3차 피드백 — 수치 정렬 · 선택 표시를 버튼 색으로 (2026-09-24)

- **정렬 기준을 등급 → 효과 수치로 바꿨다**(`효과 수치 ↓ → 전 산업 먼저 → TID → 개체 번호`).
  ⚠️ **등급과 수치는 같은 축이 아니다** — 산업 한정 장비가 같은 등급의 전 산업 장비보다 수치가 크다.
  그래서 등급으로 세우면 **더 느린 것이 위로 올라온다.** 필터가 이미 `그 산업 + 전 산업`만 남기므로
  남은 줄은 전부 이 산업에 실제로 붙는 값이고, 한 축으로 비교된다.
  **수치가 같으면 전 산업이 앞이다** — 슬롯의 산업을 바꿔도 그대로 남기 때문이다(사용자 지정).
- **선택 표시를 `Selected Bar`(노란 띠)에서 버튼의 색 전이로 옮겼다**(사용자: "띠는 없애줘").
  고르는 중인 칸에 `pickingEquipSlotColor`(0.5 회색)를 네 상태 모두에 넣어 **눌러 둔 것처럼 어둡게** 만든다.
  칸 바탕이 등급색이라 그 위에 곱해진다. 🎨 나중에 ON/OFF 스프라이트로 갈아 끼울 자리도 여기다.
  ※ `selected`까지 덮는 이유는 산업 버튼과 같다 — EventSystem이 마지막으로 누른 버튼을 잡고 있어
  **표시가 엉뚱한 칸에 남는다.**

> **표시 채널을 세 번 옮겼다** — 글자(`▼`) → 새 위젯(띠) → 버튼이 이미 가진 색.
> 글자는 폭을 흔들었고, 새 위젯은 보기 나빴다. **이미 있는 채널이 남아 있으면 그걸 먼저 쓴다.**

## 4차 피드백 — 목록에는 창고에 있는 것만 (2026-09-24)

- **착용자 주석(`Worn By Text`)을 없애고, 끼워져 있는 개체는 목록에서 뺐다**(사용자: "배치된건 필터에서 보이지 않도록 해줘. 그냥").
  `EquipPickRowView`에서 필드·프리팹 오브젝트를 지우고 `Bind`를 3인자로 줄였다.
  `BuildWornByText`도 지웠다 — 유일한 호출부가 사라졌다.
- **무엇을 잃었는지는 분명히 해 둔다.** 서버는 여전히 남이 낀 장비를 옮겨 주지만
  (`User.TryEquip`이 이전 칸을 비운다) **클라에 그 동선이 없다** — 다른 캐릭터에게서 가져오려면
  그쪽에서 먼저 해제해야 하고, 같은 캐릭터의 장신구 1↔2 맞바꾸기도 해제가 한 번 든다.
  바꾸려면 서버가 아니라 이 목록의 거르기 한 줄만 되돌리면 된다.
- 얻은 것: 줄에 착용자 칸이 없어지고, **같은 장비가 칸에도 목록에도 있는 상태가 사라진다** —
  목록이 곧 "창고에 남은 것"이라 읽기가 한 겹 단순해진다.

## 5차 피드백 — 필터에서 '모두'를 뺐다 (2026-09-24)

- 버튼 6개 → **5개**(산업만). 사용자: "없는게 더 괜찮은 것 같아".
- **기본값이 필요해졌다** — `모두`가 사라졌으니 열 때 무언가는 골라져 있어야 한다.
  **그 슬롯의 산업**(`SelectedIndustry`)으로 맞춘다. 이 캐릭터가 지금 하는 일이 곧 보고 싶은 것이라,
  대부분 **한 번도 안 눌러도 되는** 상태로 열린다. 고정값(농사 등)으로 두면 매번 한 번씩 눌러야 한다.
- 인덱스 매핑이 `i - 1` → `i`로 돌아왔다(0번이 `모두`가 아니게 됐다).
- ⚠️ **`_equipFilter`의 `None`은 남겨 뒀다.** 이제 화면에서 고를 수 없는 값이지만,
  산업을 아직 모르는 때(배치 전 등)에 잠깐 들 수 있어 *거르지 않는다*는 뜻으로 살려 뒀다.
  **장비의 `None`(전 산업)과 뜻이 다르므로** 주석으로 못 박았다.

## 후속 작업 / 주의사항

- **"개발용 전역 배수" 역산은 가산 줄을 만들면서 함께 고쳤다**(위 항목). `tasks/T-055-속도보정내역전달.md`는
  **서버가 내역을 명시 필드로 내리는 일**로 남는다 — 지금 값은 클라가 베낀 사본이다.
- **창고 장비 탭에서 장비를 눌러 캐릭터를 고르는 역방향 동선은 만들지 않았다** — 캐릭터 맥락이
  세팅 화면에만 있다.
- 칸 이미지의 `Raycast Target`이 **꺼짐 → 켜짐**으로 바뀌었다. 목업 시절엔 누를 일이 없어 꺼져 있었다 —
  안 켜면 `Button`이 붙어도 눌리지 않는다.
- **플레이 모드 실측은 사용자 확인 대기 중**(항목은 일감 파일의 "남은 것"). 특히 **'배' 마크가 꺼지는 쪽**은
  T-043에서 여기로 넘어온 미확인 항목이라 이번에 봐야 한다.
