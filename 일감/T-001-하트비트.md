# T-001 하트비트로 끊김 감지

## 배경

오프라인 진행을 폐지하면서 **접속 판정이 곧 재화 생성 조건**이 됐다.
지금은 TCP가 끊겨야 세션이 정리되는데, 그 사이(랜선을 뽑거나 PC가 절전에 들어간 구간)는
서버가 여전히 "접속 중"으로 보고 채취를 계속 굴린다. **그만큼이 공짜로 얻는 진행**이다.

TCP는 끊김을 즉시 알려주지 않는다. RST가 오지 않는 종류의 단절(전원 차단·네트워크 소실)에서는
OS 기본 keepalive가 돌 때까지 수 시간이 걸릴 수도 있다.

## 할 일

- [ ] 하트비트 주기 결정 (기획 — 게임기획코어 5장 `❌ 미작성`)
- [ ] 무응답 판정 시간 결정 — **이 값이 곧 "공짜로 얻는 최대 오프라인 시간"이다**
- [ ] 재접속 유예를 둘지 결정 — 현재는 유예 없이 즉시 리셋
- [ ] `C_HeartbeatRequest` / `S_HeartbeatResponse` 패킷 추가 (`packet-creator` 스킬)
- [ ] 무응답 세션 정리 로직 — `GatheringScheduler`처럼 타이머에서 로직 스레드로 넘긴다
- [ ] 정리 시 마지막 정산이 도는지 확인 (`User.OnDestroy` 경로)

## 완료 조건

랜선을 뽑은 뒤 **정해진 무응답 시간 안에** 세션이 정리되고, 그 이후 구간의 채취가
정산되지 않는다. 순단(짧은 끊김) 후 재접속했을 때의 동작이 결정한 대로 나온다.

## 막고 있는 것 / 선행 일감

- 주기·판정 시간·유예 세 값이 기획 미정이다. **값이 정해져야 구현이 의미를 갖는다.**
