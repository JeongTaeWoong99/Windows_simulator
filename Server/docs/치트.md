# 치트 (Cheat) — 개발·운영 명령

> 최종 업데이트: 2026-09-19 · 상태: **기획·서버 구현 완료(장비 지급 `GiveEquip = 8` 포함) · 클라 입력 UI 미착수**

테스트와 운영이 유저 상태를 바로 바꾸는 통로다. 게임 규칙이 아니라 **개발 인프라**라 `GameDesign/design`이 아니라 여기 둔다.
게임 규칙(경험치·해금·재화)은 건드리지 않고 **기존 지급 함수를 그대로 부른다** — 치트가 통하는 경로와 게임이 통하는 경로가 같아야 치트로 검증한 것이 실제와 같다.

---

## 1. 확정 사항

| # | 항목 | 확정 내용 |
| --- | --- | --- |
| 1 | **권한** | `t_user.admin_level ≥ CheatAdminLevel`. 아니면 `NoPermission`으로 거절하고 아무것도 바꾸지 않는다. ⚠️ **개발 기간엔 `CheatAdminLevel = 0`** — 모든 계정이 통과한다(권한 테스트는 Skip). 배포 전 1로 되돌린다 |
| 2 | **한 패킷** | `C_CheatRequest { ECheatCommand Command, long Arg1, long Arg2 }` / `S_CheatResponse { Result, Command, Message }` |
| 3 | **명령은 enum** | `ECheatCommand`. 문자열 파싱을 두지 않는다 — 오타가 컴파일에서 잡힌다. **뒤에만 추가** |
| 4 | **기존 경로 재사용** | `GainGold` · `TrySpendGold` · `GainItem` · `GrantGachaCharacters` · `GrantCharacterExp` · `SettleWorkStation` · `GrantUnlock`. 치트 전용 지급 코드를 만들지 않는다 |
| 5 | **결과는 기존 푸시로** | 재화·인벤토리·캐릭터·슬롯이 바뀌면 각자의 동기화 패킷이 나간다. 응답의 `Message`는 로그용 한 줄이다 |
| 6 | **전부 기록** | 성공·실패 모두 `ServerLog.Warn("치트", …)`. 운영에서 누가 무엇을 했는지가 남아야 한다 |
| 7 | **실행 시각은 호출자가 넘긴다** | `ExecuteCheat(req, now)`. 테스트가 시각을 고정한다 (저장소 규약) |

## 2. 명령

| `ECheatCommand` | `Arg1` | `Arg2` | 동작 | 거절 |
| --- | --- | --- | --- | --- |
| `GiveGold = 1` | 금액 | — | 양수면 `GainGold`, 음수면 `TrySpendGold(-Arg1)` | 0 → `InvalidCheatArgs` · 잔액 부족 → `NotEnoughCurrency` |
| `GiveDia = 2` | 금액 | — | 위와 같음, 다이아 | 위와 같음 |
| `GiveItem = 3` | `ItemTID` | 개수 (1~) | `AddItem` — 저장 + `S_UpdateItemResponse` 푸시 | 테이블에 없는 TID · 개수 ≤ 0 → `InvalidCheatArgs` |
| `GiveCharacter = 4` | `CharacterTID` | 장수 (1~10) | `GrantGachaCharacters` — 지급 후 목록 재전송까지 같다 | 테이블에 없는 TID · 범위 밖 → `InvalidCheatArgs` |
| `GiveCharacterExp = 5` | `CharacterId`(개체) | 경험치 (1~) | `GrantCharacterExp` — 레벨업·저장·푸시까지 같다 | 미보유 → `CharacterNotOwned` · 0 이하 → `InvalidCheatArgs` |
| `Settle = 6` | 판정 횟수 (1~100, 0이면 1) | — | 가동 중인 슬롯마다 판정 N회분 작업량을 얹고 `SettleWorkStation(now)` — 쌓인 진행도만 정산하면 스케줄러(0.1초)가 먼저 가져가 늘 0개라서 | 100 초과 → `InvalidCheatArgs` |
| `Unlock = 7` | `UnlockTID` | — | `GrantUnlock` — 조건·차감 없이 열고, 기록·`S_UnlockResponse`·슬롯 스냅샷까지 유저 해금과 같다 | 테이블에 없는 TID → `InvalidCheatArgs` · 이미 열림 → `AlreadyUnlocked` |
| `GiveEquip = 8` | `EquipTID` | — | `GrantEquip` — 개체 1개 INSERT 후 창고 첫 빈 칸 · `S_EquipSyncResponse`까지 같다 | 테이블에 없는 TID → `InvalidCheatArgs` |

- 값 대역: `EResultCode` **400~ 치트** — `NoPermission = 400` · `InvalidCheatCommand = 401` · `InvalidCheatArgs = 402`.
- `Arg`는 `long`이다. 골드가 `long`이고, 개체 PK도 `long`이라 하나의 타입으로 전부 나른다.

## 4. 두지 않는 것

- **명령줄 파서** — `"gold 100"` 같은 문자열을 서버가 해석하지 않는다. 클라 입력창이 문자열을 받더라도 enum·숫자로 바꿔 보내는 것은 클라 몫이다.
- **치트 전용 저장 경로** — 지급 함수가 각자 저장한다. 치트가 DB에 직접 쓰는 일은 없다.
- **운영 빌드에서의 차단 스위치** — `admin_level`이 곧 스위치다. 별도 설정을 두지 않는다.
