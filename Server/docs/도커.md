# 도커 — 원격 서버 띄우기

> 최종 업데이트: 2026-10-11 (개발 10050·10060 / 원격 30329·30330 분리 · 에디터는 무조건 개발 서버) · 2026-10-11 (처음 작성 — T-109)

친구들이 붙는 **원격 서버**는 이 PC의 Docker에서 돈다 — 게임 서버 + 경매장, 컨테이너 2개.
코드·이미지는 개발과 같고, 다른 것은 **설정값과 DB 위치**뿐이다. 일감 → [`T-109`](../../tasks/T-109-서버도커외부접속.md)

---

## 1. 개발과 원격

| | 개발 | 원격 (Docker) |
|---|---|---|
| 띄우기 | IDE · 클라 서버 콘솔 | `Server/`에서 `docker compose up -d --build` |
| 설정 | 각 서버의 `appsettings.json` | `docker-compose.yml`의 `environment`가 덮는다 |
| 게임 포트 | **`10050`** | **`30329`** — 공유기가 바깥 `30329`를 이 PC로 넘긴다 |
| 경매장 | `127.0.0.1:10060` | **이 PC에서만** `127.0.0.1:30330` · 게임 컨테이너는 `http://auction:30330` |
| 게임 DB | `Server/Shared/game.sqlite3` (git) | 볼륨 `wsgame_game-data` → `/data/game.sqlite3` (git 밖) |
| 치트 | 모든 계정 (`CheatAdminLevel` 0) | `admin_level` 1 이상만 |
| 클라 | **에디터는 무조건** `127.0.0.1:10050` | **빌드만** `ServerSettings.json` → `14.36.6.179:30329` |

- 설정은 `appsettings.json` → 환경 변수 → 명령줄 순으로 덮는다. 환경 변수는 `Game__ListenPort`처럼 `__`가 절 구분이다 (`GameSettings`).
- **포트가 서로 달라 같은 PC에서 개발 서버와 Docker가 함께 떠도 겹치지 않는다** (2026-10-11 사용자 결정 — 개발은 예전 포트 그대로).
- 원격 DB는 **빈 파일에서 시작한다** — 서버가 없는 DB를 만들고 마이그레이션이 스키마를 채운다. 계정은 로그인할 때 생긴다.

## 2. 띄우기 · 끄기 · 회차 갱신

```powershell
cd Server
docker compose up -d --build   # 처음 · 회차 갱신 — 지금 커밋으로 이미지를 다시 굽고 갈아 끼운다
docker compose ps              # 상태 · 포트
docker compose logs -f game    # 게임 서버 로그 (auction도 같은 식)
docker compose stop            # 끈다 — 재부팅해도 안 뜬다. 다시 켜려면 start
docker compose down            # 컨테이너만 지운다 — 볼륨(DB)은 남는다
```

- 두 서비스 모두 `restart: unless-stopped` — PC를 켜면 Docker Desktop(로그인 시 자동 실행)과 같이 뜬다.
  Docker Desktop은 **Windows 로그인 뒤에** 켜지므로 서버 PC는 자동 로그인을 켜 둔다.
- 갱신하면 게임 서버가 기동하며 DB를 백업(`/data/game.sqlite3.v<판>-<시각>.bak`)하고 남은 마이그레이션을 적용한다 → [T-146](../../tasks/T-146-DB마이그레이션자동적용.md).
  경매장 DB는 판이 바뀌면 기동이 멈춘다 — 경매장 스키마를 바꿀 땐 `AuctionStore`에 단계 변환을 넣는다.
- ⚠️ **`docker compose down -v`는 볼륨까지 지운다** — 친구 데이터가 사라진다.

## 3. 외부 접속 — 공유기 · 방화벽 (사람이 한 번)

1. 공유기 관리 페이지 → 포트포워딩: **외부 TCP `30329` → 이 PC 내부 IP의 `30329`**. 내부 IP는 `ipconfig`의 IPv4 주소.
2. Windows 방화벽 인바운드 허용 — **관리자** PowerShell:
   ```powershell
   New-NetFirewallRule -DisplayName "WSGameServer 30329" -Direction Inbound -Protocol TCP -LocalPort 30329 -Action Allow
   ```
3. 공인 IP는 **`14.36.6.179`** (2026-10-11). 바뀌면 `ServerSettings.json`만 고쳐 빌드 폴더에 넣는다(4장).

- 확인은 **바깥에서** 한다(휴대폰 테더링 등). 같은 공유기 안에서 공인 IP로 붙으면 공유기가 되돌려 주지 않아 실패할 수 있다(NAT 루프백).
- 경매장 `30330`은 공유기에 열지 않는다 — 바깥 공개는 [T-110](../../tasks/later/T-110-공유경매장다중게임서버.md).

## 4. 클라가 붙을 주소

| 어디서 | 어떻게 |
|---|---|
| 에디터(개발) | **무조건 개발 서버 `127.0.0.1:10050`** — 고르는 메뉴가 없다 (2026-10-11 사용자 결정) |

## 5. 같은 PC에서 개발 서버와 함께

개발(`10050`·`10060`)과 원격(`30329`·`30330`)의 포트가 달라 **Docker를 켜 둔 채 평소대로 개발한다.**
클라 서버 콘솔이 orphan 정리로 끄는 포트(`10050`·`10060`)에는 Docker가 없다.

- 개발 서버를 하나 더 띄우려면 명령줄로 덮는다 — `WSGameServer.exe --Game:ListenPort=10051`.
- 개발 게임 서버를 Docker 경매장에 붙이지 않는다(`--Game:Auction:Address=http://127.0.0.1:30330`) —
  원격 게임 서버와 경매 이벤트(판매 정산)를 나눠 받아 정산이 엉뚱한 서버로 간다. 경매장은 게임 서버 하나를 전제로 짜여 있다([T-110](../../tasks/later/T-110-공유경매장다중게임서버.md)).

## 6. 운영 — DB 들여다보기 · 내 계정 관리자

게임 이미지에 `sqlite3`가 들어 있다. PowerShell에서(Git Bash는 `/data` 경로를 바꾸므로 앞에 `MSYS_NO_PATHCONV=1`):

```powershell
docker compose exec game sqlite3 /data/game.sqlite3 "SELECT user_id, provider_id, nickname, admin_level FROM t_user;"
docker compose exec game sqlite3 /data/game.sqlite3 "UPDATE t_user SET admin_level = 1 WHERE provider_id = '<내 로그인 Id>';"
```

- `admin_level`은 로그인할 때 읽는다 — 바꾼 뒤 다시 로그인한다. 볼륨에 남으니 **처음 한 번만** 한다.
