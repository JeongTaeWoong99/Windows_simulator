## 2. 측정 방법

```powershell
# ① 측정용 서버 — DB는 git의 game.sqlite3가 아닌 임시 파일로, 경매장은 없어도 된다
dotnet build -c Release Server/WSGameServer
cd Server/WSGameServer/bin/Release/net10.0
sleep 7200 | ./WSGameServer.exe --Game:ListenPort=10075 --Game:DbPath=<임시>/load.sqlite3 --Game:CheatAdminLevel=0

# ② 부하 봇 — 동접 수만 바꿔 100 · 300 · 500 · 1000
dotnet run -c Release --project Server/MikaLoadTest -- --bots 100 --minutes 5 --heavy --port 10075 --warmup 60 --prefix <회차>-100
```

- 봇(`Server/MikaLoadTest`)은 로그인 → 치트로 슬롯 7칸 해금 · 캐릭터 6장 → 7칸 전부 배치 → 5초마다 핑을 보낸다.
  **가장 무거운 유저**(슬롯 전부 가동)를 가정한다. 접속은 초당 20명씩, 접속·배치가 끝난 뒤(`--warmup`)부터 5분을 잰다.
- 서버 CPU·메모리는 봇이 서버 프로세스(`WSGameServer`)를 직접 읽는다. 송신량은 봇이 받은 바이트를 합친 값이다.
- 측정 PC: **AMD Ryzen 7 7800X3D · 32GB**. AWS Graviton(t4g) vCPU는 이 코어의 절반쯤으로 보고 CPU를 2배로 환산한다.
- ⚠️ **지금 판정은 Lv1(30초 주기)이다.** 속도 특성·장비로 판정이 빨라지면 패킷과 DB 쓰기가 그만큼 는다 — 최소 주기 1.6초까지 당기면 최대 약 19배.

| 동접 | DB 모드 | 로그인 · 끊김 | CPU 평균 / 최대 (1코어 = 100%) | 메모리 평균 / 최대 | 송신 | 채취 결과 |

| 500 | 기본 | 500 · **22** | 30.5% / 68.5% | 284 / 305 MB | 20.98 KB/s | 114.5/s |
| 1000 | 기본 | **124 · 10** | 26.8% / 31.4% | 286 / 288 MB | — | — |
| 500 | WAL | 500 · 0 | 9.7% / 14.8% | 244 / 251 MB | 21.47 KB/s | 117.1/s |
| 1000 | WAL | 1000 · **11** | 17.4% / 20.6% | 404 / 500 MB | 42.71 KB/s | 233.0/s |

- 기본 모드의 끊김은 전부 **`database is locked`** — 유저별 DB 쓰기가 병렬로 몰려 `busy_timeout` 5초를 넘기면 그 세션을 끊는다(`DBManager`). 1000명에서는 로그인 쓰기까지 막혀 124명만 들어왔다.
- 같은 DB를 WAL로만 바꾸면 CPU가 1/4로 줄고 500명이 깨끗하다. CPU를 먹던 것은 계산이 아니라 저널 쓰기·잠금 대기였다.
- 측정 서버는 패킷마다 Debug 로그를 찍는다(5분에 70MB). 운영에서 로그 수준을 낮추면 CPU는 더 준다.
