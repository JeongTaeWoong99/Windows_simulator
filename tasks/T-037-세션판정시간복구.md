# T-037 세션 무응답 판정 시간을 15초로 복구

## 배경

**"가끔씩 이유 없이 서버와의 연결이 끊긴다"의 원인이다** (2026-08-28 규명).

```csharp
// Server/WSGameServer/Common/Global.cs:42
public static readonly TimeSpan SessionIdleTimeout = TimeSpan.FromSeconds(5);
```

이 값이 **클라 핑 주기와 똑같아 여유가 0**이었다. 서버는
`MikaServer.DisconnectIdle`에서 `now - LastReceivedAt >= 판정시간`이면 즉시 끊는데,
클라의 실제 송신 간격은 정확히 5.000초가 아니다 — 프레임 오버슈트가 매번 누적돼 5.008초쯤 된다.
그래서 **매 핑 직전 수 ms 동안 판정선을 넘긴 상태**가 되고, 5초 주기의 감시자 스윕이
하필 그 창을 밟으면 멀쩡한 세션이 끊긴다. 확률상 **수십 분에 한 번 무작위로** 터진다.

값이 15초 → 5초로 내려간 것은 커밋 `d2c52c6`이고, 같은 커밋의
`GatherSpeedMultiplier = 6.0`(채취 주기 30초 → 5초)에 맞춰 "판정은 채취 주기보다 짧게"
규칙을 따라 내린 **확인용 값**이다. **둘 다 배포 전 원복 대상**이다.

> ⚠️ **주석과 값이 어긋나 있다.** `Global.cs:32`는 아직
> *"클라이언트는 5초마다 보낸다 — 세 번 연속 놓쳐야 끊기는 값이다"* 라고 적혀 있는데,
> 그건 15초 시절 문구다. 지금 값에서는 **한 번만 늦어도 끊긴다.**

> 📌 **클라는 이미 완화를 넣었다 (2026-08-28).** 핑 주기를 5초 → **2초**로 내리고
> 송신을 백그라운드 타이머로 옮겨, 판정이 5초인 상태에서도 증상이 나지 않게 했다.
> **이 일감은 그 임시 방어를 걷어내기 위한 것이 아니라, 근본값을 제자리로 돌리는 것이다** —
> 15초로 복구한 뒤에도 클라의 2초 주기는 그대로 유효하다.

## 할 일

- [ ] `Global.SessionIdleTimeout`을 **5초 → 15초**로 되돌린다
- [ ] `Global.cs`의 판정 시간 주석을 실제 값·실제 클라 주기(2초)와 맞춘다
- [ ] `SessionIdleSweepTest`의 `판정_시간은_채취_한_주기보다_짧다`를 다시 본다.
      `BaseCycleSeconds`(30초)와 비교하므로 15초로도 **통과는 하지만**,
      `GatherSpeedMultiplier = 6.0`인 동안 실효 주기는 5초라 **불변식이 사실상 깨져 있다.**
      → [T-004](T-004-전역배수복귀.md)와 함께 처리하거나, 테스트가
      실효 주기(`BaseCycleSeconds ÷ GatherSpeedMultiplier`)를 보도록 바꾼다
- [ ] 서버를 띄우고 시작 로그의 `무응답 판정 N초`가 15초로 나오는지 확인
- [ ] 30분 이상 접속을 유지해 `무응답으로 N개 세션을 끊었다` 경고가 안 나오는지 확인

## 완료 조건

`SessionWatchdog` 시작 로그가 `감시자 시작 — 검사 5초, 무응답 판정 15초`로 나오고,
정상 접속 상태를 장시간 유지해도 유휴 세션 정리 경고가 찍히지 않는다.

## 막고 있는 것 / 선행 일감

- 없음. `Global.cs` 상수 하나와 주석이다.
- 다만 **판정 시간과 채취 실효 주기의 관계**는 [T-004](T-004-전역배수복귀.md)와 얽혀 있다 —
  배수가 6.0인 동안에는 15초 판정이 채취 3주기를 덮는다(개발 서버 한정).
