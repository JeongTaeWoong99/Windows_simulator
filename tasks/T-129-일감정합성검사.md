# T-129 일감 정합성 검사 스크립트 — INDEX ↔ 일감 파일 · 보관 건수 · 끝난 선행을 기다리는 ⏸

## 배경

[T-066](archive/T-066-연계일감갱신스킬.md)에서 연계 갱신을 스킬로 만들지 않고 **공돌리기 규칙**(`github-issue-writer` 3장)에 합쳤다.
그중 **기계적으로 판정할 수 있는 어긋남**은 기억에 맡기면 또 빠진다 — 스크립트가 잡는다.
`GameDesign/check-doc-graph.ps1`처럼 돌리면 목록이 나오는 형태.

## 할 일

스크립트: `node GameDesign/web/scripts/check-tasks.mjs` (어긋남이 있으면 exit 1 · `--no-issues`로 이슈 조회 생략).
`roll-cycles.mjs` 옆에 Node로 두었다 — CI 러너(리눅스)와 로컬에서 같은 명령으로 돈다.

- [x] INDEX 링크가 가리키는 파일이 루트 `tasks/`에 있는지 (보관된 일감이 INDEX에 남았는지) — `art/`·`later/`·`archive/` 목록도 같은 방식으로 본다
- [x] 루트 일감 파일이 INDEX에 다 있는지 · 프론트매터 `상태`와 INDEX `상태` 칸이 같은지 · `Closed`인데 보관되지 않았는지
- [x] 보관 건수(`끝난 일감 N건`)와 `archive/` 파일 수가 같은지
- [x] `⏸`·`막고 있는 것`이 **보관된 일감**이나 **닫힌 이슈**를 가리키는지 — `gh issue list --state closed` 한 번으로 조회. `막고 있는 것`은 일감·이슈로 **시작하는** 줄만 선행 선언으로 본다(`없음 — …`·`✅ …`·설명 줄은 넘긴다)
- [x] `tasks/` 밖 문서의 `tasks/T-0XX-…` 링크가 옮겨 간 파일을 가리키는지 — 기록인 `tasks/archive/`·`.claude/Agent/`는 뺀다
- [x] 돌릴 시점을 공돌리기 절차(`github-issue-writer` 3장)에 한 줄 추가 — 4번
- [x] CI — `.github/workflows/tasks-check.yml` · `.md` push·PR · **이슈가 닫힐 때** · 실패하면 Discord 알림. 배포 job과 나눠 배포는 막지 않는다
- [x] 덤: **일감 ID 중복** 검사 — `T-132`가 루트(데이터 뷰어)와 `archive/`(풀링과 UniTask 전환)에 둘이다(2026-10-08 두 세션이 동시 등록). 커밋·로그가 이미 그 번호로 불러 번호를 바꾸지 않고 스크립트의 `KNOWN_DUPLICATES`에 적었다
- [ ] 첫 실측 — push 뒤 Actions `일감 정합성 검사`가 초록으로 도는지

첫 실행에서 나온 17건 중 일감 파일·링크로 고칠 수 있는 것은 같은 커밋에서 고쳤다(T-150·T-009 끝난 선행 · `Server/docs/인벤토리-창고.md`·`gyub/`·T-085 옛 경로 링크).
