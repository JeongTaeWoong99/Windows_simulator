# T-003 캐릭터 레벨·경험치를 성장에 반영

> 2026-09-13 — 경험치 획득식·레벨 곡선이 확정되어 **데이터는 들어갔다.**
> 남은 사람의 결정은 **"레벨이 무엇을 올리는가"** 하나다. 경험치 누적·레벨업 판정은 그 결정 없이 착수할 수 있다.

## 배경

`t_character`에 `level`·`exp` 컬럼을 만들어 두고 `Character` 객체까지 싣고 있지만
**아무 데서도 읽지 않는다.** 지금 캐릭터 속도는 `CharacterTable`의 고정 적성값으로만 정해져서,
레벨이 올라도 아무 일도 일어나지 않는다.

컬럼만 있고 쓰지 않는 상태가 길어지면, 나중에 성장식을 붙일 때
"기존 유저의 exp를 어떻게 해석할 것인가"라는 마이그레이션 문제가 따라온다.

## 2026-09-13 확정 — 경험치 획득식 · 레벨 곡선

→ [캐릭터 5.2](../GameDesign/design/character/README.md)

| 항목 | 값 |
| --- | --- |
| 획득 시점 | **판정 1회 성립마다** (`WorkStation.Settle`이 돌려주는 `JudgeCount` 단위) |
| 획득량 | `IndustryLevelTable.ExpPerJudge` — Lv1 1 → Lv5 81 (레벨당 ×3, `RequiredScore`와 같은 등비) |
| 레벨 곡선 | `CharacterLevelTable.RequiredExp` — 그 레벨에 도달하는 데 직전 레벨에서 필요한 양. Lv2 10 → 레벨당 ×1.2 (내림) |
| 만렙 | **100** (테이블 마지막 행). 만렙에서는 더 쌓지 않는다 |
| 레벨업 | 필요치를 채우면 +1, 남은 경험치는 이월. 한 정산에서 여러 레벨 가능 |
| 저장 | `t_character.exp` = **현재 레벨에서 쌓은 양** (누적이 아니다) |
