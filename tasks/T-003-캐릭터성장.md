# T-003 캐릭터 레벨·경험치를 성장에 반영

> 2026-09-17 — **레벨 효과가 적성 포인트로 확정됐고 서버 구현까지 끝났다** → [캐릭터 5.4](../GameDesign/design/character/README.md). 남은 것은 클라 화면뿐이다.
> 2026-09-13 — 경험치 획득식·레벨 곡선을 확정하고 **서버 누적·레벨업·저장·푸시까지 구현했다.**

## 배경

`t_character`에 `level`·`exp` 컬럼을 만들어 두고 `Character` 객체까지 싣고 있었지만
**아무 데서도 읽지 않았다.** 캐릭터 속도는 `CharacterTable`의 고정 적성값으로만 정해져서,
레벨이 올라도 아무 일도 일어나지 않는다 — 이 부분은 여전히 그렇다(레벨 효과 미정).

## 2026-09-13 확정 — 경험치 획득식 · 레벨 곡선

→ [캐릭터 5.2](../GameDesign/design/character/README.md)

| 항목 | 값 |
| --- | --- |
| 획득 시점 | **판정 1회 성립마다** (`WorkStation.Settle`이 돌려주는 `JudgeCount` 단위) |
| 획득량 | `IndustryLevelTable.ExpPerJudge` — Lv1 1 → Lv5 81 (레벨당 ×3, `RequiredScore`와 같은 등비) |
| 레벨 곡선 | `CharacterLevelTable.RequiredExp` — 그 레벨에 도달하는 데 직전 레벨에서 필요한 양. Lv2 10 → 레벨당 ×1.2 (내림) |
| 만렙 | **100** (테이블 마지막 행). 만렙에서는 더 쌓지 않는다 |
| 레벨업 | 필요치를 채우면 +1, 남은 경험치는 이월. 한 정산에서 여러 레벨 가능 |
| 저장 | `t_character.exp` = **현재 레벨에서 쌓은 양** (누적이 아니다) |

## 2026-09-17 확정 — 레벨 효과 = 적성 포인트

→ [캐릭터 5.4](../GameDesign/design/character/README.md)

| 항목 | 값 |
| --- | --- |
| 포인트 | **10레벨마다 1** (`CharacterLevelTable.AptitudePoint`) · 만렙까지 10 |
| 사용 | 원할 때 산업 하나 **+1** · 안 쓴 건 남는다 · **되돌리기 없음** |
| 상한 | **캐릭터·산업별** `CharacterTable` `FarmingCap`…`HuntingCap` · 0인 산업도 1로 |
| 저장 | `t_character` `farming_bonus`…`hunting_bonus` — 찍은 양만. 남은 포인트 = 번 총합 − 찍은 합 |
| 패킷 | `AptitudeInfo.Cap` · `CharacterInfo.AptitudePoints` · `C_AptitudeUpRequest`/`S_AptitudeUpResponse` · 결과 코드 `NoAptitudePoint`·`AptitudeAtCap` |
| 반영 | 찍으면 **정산 → 속도 재계산** → 슬롯 싱크 |

## 완료 조건

레벨이 오르면 슬롯 속도가 실제로 달라지고, 그 값이 재접속 후에도 유지된다.
(서버 ✅ — 포인트를 찍으면 슬롯 속도가 바뀌고 보너스가 DB에 남는다. 클라 화면이 남았다.)
(경험치·레벨 자체는 이미 재접속 후 유지된다 — `LoginRepository`가 `level`·`exp`를 읽는다.)
