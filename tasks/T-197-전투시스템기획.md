# T-197 기획 — 전투 시스템

## 배경

2026-11-07(토) 회의에서 보스를 **레이드 시스템**으로 가기로 했고, 그러려면 **전투가 먼저 있어야 한다.**
지금 게임에는 채집(채취 산업)만 있고 전투가 없다 — 사냥도 "달리기 → 공격 → 처치" 연출일 뿐 승패·스탯이 없다.

- 허수아비형 딜량 누적안([이슈 #116](https://github.com/JeongTaeWoong99/Windows_simulator/issues/116))은 **보류**했다. 나중에 다시 꺼낼 수 있다.
- 지금 캐릭터 성장 축(레벨·★·장비·인챈트)은 **전부 작업속도 하나**로 모여 있다. 전투 스탯을 넣으면
  `CharacterTable`·`WorkSpeedTable`·장비·인챈트·★·레벨이 2축이 될 수 있다 — 이 영향 범위를 함께 정한다.

## 결정 (2026-11-09)

- **형태 = 서버 즉시 계산 + 로그 재생.** 도전 요청을 받으면 서버가 전투를 끝까지 계산하고 보상을 DB에 확정한 뒤,
  사건 로그(누가 · 누구에게 · 무엇을 · 얼마)와 보상을 한 번에 내려 준다. 클라는 로그를 연출로 재생만 한다
  (Pokémon Showdown 방식). 클라에 전투 로직을 두지 않으므로 서버·클라 결정론을 맞출 필요가 없다.
  원정 시간을 두고 결과 공개를 늦추는 안(B)은 쓰지 않는다.
- **편성 = 프리셋.** 레이드 프리셋에는 **작업슬롯에 배치되지 않은 캐릭터만** 넣을 수 있다.
  슬롯에 있는 캐릭터로 가려면 먼저 슬롯에서 뺀다 — 이것이 채집과의 비용이다.
  상시 토벌대(#116)·교체 제한은 두지 않는다. 비용이 가볍다고 판단되면 그때 제한을 더한다.
- **스탯 = 공격력 · 체력 두 개만.** 기존 성장(레벨·★·장비·인챈트)이 두 스탯에도 영향을 준다.
  **산업 적성을 전투 역할로 쓰지 않는다.**
- **성장 연결 = 테이블에 컬럼 추가.** 레벨·★·장비·인챈트 테이블마다 공격력·체력 값을 직접 둔다.
  작업속도에서 환산하지 않는다 — 무엇에 투자했느냐로 공격형·체력형이 갈려야 편성에 고를 거리가 생긴다.
- **성장별 담당 (일단안)** — 수치는 정하지 않았다.

  | 성장 | 테이블 | 주는 스탯 |
  |---|---|---|
  | 레벨 | `CharacterLevelTable` | 공격력 · 체력 |
  | ★ | `CharacterStarTable` | 공격력 · 체력 |
  | 무기 | `EquipTable` | 공격력 |
  | 장신구 | `EquipTable` | 체력 |
  | 보석 | `EquipTable` | 행마다 둘 중 하나 |
  | 인챈트 | `EnchantOptionTable` | `EnchantOptionType`에 공격력·체력 추가 — 작업속도·경험치 옵션과 경쟁 |
