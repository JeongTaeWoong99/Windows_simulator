# T-207 기획·서버·클라 — 스팀 로그인

## 배경

**지금 로그인에는 인증이 없다.**

```csharp
// Server/WSGameServer/Network/ClientPacketHandler.cs:75
public static void Handle_C_LoginRequest(ISession session, C_LoginRequest req)
{
    UserManager.Instance.CreateUser(session, req.Id, req.Id);
}
```

`C_LoginRequest`는 **문자열 `Id` 하나**이고, 서버는 그 값을 그대로 `provider_id`·`nickname`으로 써서
**없으면 자동 가입**한다. 즉 **남의 `provider_id`를 보내면 그 계정으로 들어간다.**

개발 빌드로 테스트하는 지금은 문제가 없지만, **거래소가 있는 게임**이라 출시 전에는 반드시 막아야 한다
([거래](../GameDesign/design/trade/README.md) · P4 "모든 재화는 흐른다" → 계정 탈취가 곧 재화 탈취다).

**스키마는 이미 열려 있다** — `t_user.provider_id TEXT NOT NULL UNIQUE`에 주석이
`-- 외부 제공자 ID`로 달려 있다(`0001-baseline.sql`). 스팀 ID를 넣을 자리가 처음부터 있었다.

플랫폼도 이미 스팀을 전제한다 — BM이 **DLC + 스팀 마켓 수수료**(TBH 모델)로
[게임기획코어](../GameDesign/design/게임기획코어.md) 5장에 적혀 있다.

## 결정 필요 (회의 안건 — 261121)

| # | 결정할 것 | 왜 갈리나 |
| --- | --- | --- |
| 1 | **언제 넣나** — 지금인가 배포 전 게이트인가 | 지금 넣으면 테스트마다 스팀이 떠 있어야 한다. 미루면 그동안 계정 신뢰가 0인 채로 거래소를 테스트한다 |
| 2 | **검증을 어디까지 하나** | ① SteamID만 받는다 → **지금과 똑같이 위조된다**(의미 없음) ② **세션 티켓을 서버가 Steam Web API로 검증** → 제대로지만 서버가 외부 HTTP를 치게 된다 |
| 3 | **개발용 로그인을 남기나** | 남기면 그 경로로 그대로 위조된다. 빌드 분리(`#if`)·관리자 키·허용 IP 중 무엇으로 막을지 |
| 4 | **기존 테스트 계정 처리** | `provider_id`가 임의 문자열인 행들이 있다. 마이그레이션으로 옮길지 전부 지울지 |
| 5 | **스팀 없이 실행하는 경로** | Unity 에디터·CI·더미 클라는 스팀이 없다. 2번과 3번이 여기서 만난다 |
| 6 | **닉네임의 출처** | 지금은 `provider_id`를 그대로 닉네임으로 쓴다. 스팀 표시명을 쓸지, 게임 안에서 따로 정할지 |

> 2번이 1·3·5를 다 끌고 간다 — **"검증을 제대로 한다"로 정하면** 서버에 Steam Web API 호출과
> 개발용 우회 경로가 동시에 필요해지고, **"SteamID만 받는다"면 지금과 보안 수준이 같아서** 넣는 의미가 거의 없다.
