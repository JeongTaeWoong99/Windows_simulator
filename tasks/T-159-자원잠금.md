# T-159 서버·클라 — 자원 잠금

## 배경

- [T-137](archive/T-137-잠금기능.md)은 캐릭터·장비만 잠갔다(2026-10-13 — 자원은 TID 하나 = 칸 하나라 개체 잠금이 맞지 않는다).
- 자원에 큐브·상자·기타가 계속 늘어난다 — 일괄 담기의 [상자 제외]·[큐브 제외] 토글로는 종류마다 막을 수 없다.
  **자원도 잠글 수 있어야 한다** (2026-10-15 태웅).
- 칸 하나 = 종류 하나라 **종류(TID) 단위로 잠근다.** 잠긴 종류는 수량 전부가 판매·경매에서 빠진다.
- → [이슈 #72](https://github.com/JeongTaeWoong99/Windows_simulator/issues/72)

## 할 일

> 2026-10-16 서버 몫 끝 — 담당을 태웅으로 넘긴다(클라 몫만 남음).

- [x] 서버(진우) — `ELockTarget.Resource`(3) 추가 · `Id` = 아이템 TID · 아이템 테이블에 없는 TID는 `InvalidLockTarget`
- [x] 서버(진우) — 유저별 잠긴 TID 저장(마이그레이션 `0008-item-lock.sql` · `t_user_item_lock`) · 로그인 때 `S_InventoryResponse.LockedItemTids`로 내려 준다
- [x] 서버(진우) — 즉시 판매 · 경매 등록에서 잠긴 TID를 `EntityLocked`로 거절(판매는 하나라도 섞이면 전부 거절)
- [x] 치트: 해당 없음 — 잠금 요청 자체가 바로 시험된다
- [ ] 클라(태웅) — 자원 칸 Ctrl+좌클릭 토글(`ELockTarget.Resource`, `Id` = TID) · 자물쇠 · 일괄 담기 제외 · 툴팁 (캐릭터·장비와 같은 방식) · `S_EntityLockResponse`의 `Resource` 처리 · 로그인 `LockedItemTids` 반영

## 주의

- 잠가도 **사용은 된다** — 상자 열기 · 큐브 쓰기 · 응축 같은 소비는 막지 않는다. 잠금은 "팔아서 없애는 것"만 막는다.
- 보유 0개가 돼도 잠금은 남긴다 — 다시 얻으면 그대로 잠겨 있어야 한다.
