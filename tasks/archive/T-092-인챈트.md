# T-092 — 장비 인챈트

> **번호 변경 (2026-09-25)** — 처음엔 **T-085** 였다. 원격에 같은 번호의 다른 일감이 먼저 올라가 T-092로 옮겼다.
> 이미 만든 커밋 메시지의 `(T-085)`는 이 일감을 가리킨다.

장비 개체에 **추가옵션(인챈트)** 을 붙인다. 등급(Rare·Epic·Legendary)이 옵션 풀의 질을,
줄 수(2~3)가 옵션 개수를 정하며 **둘은 독립된 축**이다. 아이템으로 부여·재롤·줄 확장을 한다.

## 메모

**착용 중인 장비는 인챈트를 거부한다**(`EnchantEquipped`). 벗기는 것이 선행 조건이다 —
그 덕에 창고 장비만 바뀌어 정산·속도 재확정을 부르지 않고, 소급 버그의 여지가 없다.

희귀도는 옵션에 두지 않았다. 그래서 [`자원채취`](../../GameDesign/design/gathering/README.md) 2.1의
2026-09-20 확정("판정 1회의 양과 질에 보정을 두지 않는다")을 건드리지 않는다.

수치 중 **등급 상승 확률만 확정**(Rare→Epic 5% · Epic→Legendary 0.5%)이고,
옵션 값·`Weight`·아이템 확률은 테스트값으로 시작한다.

## 실서버 확인 (2026-09-23)

`MikaDummyClient`(메뉴 `EquipEnchant`)로 실서버에 붙여 확인했다. 개발 서버는 `GatherSpeedMultiplier = 6.0`이라 속도가 ×6으로 보인다.

| 확인 | 결과 |
| --- | --- |
| `GiveItem`으로 100013~100017 지급 | 각 `Ok` +10 |
| 목검(1001)에 100014 | `Ok Success=True 등급 0→3(Rare) 옵션=[101,103]` · 100014 10→9 |
| 인챈트 있는 장비에 100014 | `EnchantAlreadyRolled` · 소모 없음 |
| 100015 6회 | 매번 줄이 바뀜(`[101,102]`→`[104,104]`→…) · 등급 Rare 유지 |
| 100017 | `Success=True 옵션=[104,101,101]`(3줄) · 한 번 더 → `EnchantLineMax` |
| 3줄에 100015 | 3줄 그대로 재롤 `[106,101,102]` |
| 낚시 슬롯 캐릭터에 장착 | `Speed` 6000(맨손) → 6300(인챈트 전 목검) → **6420**(인챈트 후: 목검 50 + 101 전 산업 20, 106 사냥·102 농사는 0) |
| 착용 상태로 100015 | `EnchantEquipped` · 재접속 인벤 100015=3 그대로(소모 없음) |
| 재접속 | 장비 목록에 `인챈트 3[106,101,102]` — DB 저장 확인 |
