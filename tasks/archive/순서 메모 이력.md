## 순서 메모

- 💰 **판매 → 골드 → 뽑기가 화면까지 이어졌다 (2026-09-04). 남은 것은 실측이다.**

  ```
  자원 칸 우클릭 → (수량 팝업) → 카트 → [판매] → 골드 → 가챠 4버튼 → 결과
   T-032 ✅코드·배선                          T-031 ✅코드·배선
  ```

  - **판매는 자원 탭만이다.** `C_ItemSellRequest`가 아이템 TID 축이라 캐릭터·장비를 담을 수 없다 —
    담고 싶으면 **서버 패킷이 먼저**다. 격자가 자원 탭이 아니면 우클릭을 무시한다.
  - **가챠 버튼이 4개가 됐다** — 풀 2종(1=구슬 상자 · 2=캐릭터 소환) × 단차·10연차.
    이름·비용은 `GachaInfoTable`에서 읽는다. ⚠️ **10연차는 단차 × 10이 아니다**(컬럼이 따로다).
  - 🔴 **잠복 결함 하나를 함께 닫았다** — `GachaResultPresenter`가 `reward.ItemId`를 무조건 읽어
    **캐릭터 보상이 빈 칸으로 그려졌다.** 자원 풀만 뽑던 동안엔 드러나지 않았고
    **컴파일도 경고도 통과했다**(필드가 추가만 된 형태라서). 캐릭터 버튼을 붙이는 순간 터질 자리였다.
  - ⚠️ **담아 둔 사이 인벤토리가 줄면 카트가 따라 깎여야 한다.** 서버 판매는 **전부 되거나 전혀
    안 되므로**(`NotEnoughItem`) 한 종류만 모자라도 통째로 거절된다. `SellCartModel`이 그걸 맡는다.
  - ⏳ **남은 것은 씬·프리팹 배선과 에디터 실측뿐이다** — 각 일감의 "남은 것" 절 참조.
- ✅ **하트비트 끊김 — 끝났다 (2026-09-08 · [보관](T-040-하트비트해결방향.md)).**

  ```
  원인 규명 → 시험 적용 → 철회 → 결정(A-1·B-1) → 적용 ─┬─ A-1 서버 값 ✅ (정정 완료)
                                                       ├─ B-1 서버 몫 ✅ add9b9f
                                                       └─ B 클라 몫  ✅ T-041
                                                            ↓
                                                   실측 A·B 둘 다 통과 ✅
  ```

  **원인은 두 겹이었다.** ① **A** — 서버 무응답 판정(5초)과 클라 핑 주기(5초)의 **여유가 0**.
  ② **B** — 세션 소켓 루프가 **Unity 메인 스레드에 묶여** 창을 끄는 동안 핑이 멈춘다.

  - 🔒 **남긴 것은 값이 아니라 규칙이다 — "핑 주기 ≤ 판정 시간 ÷ 3".**
    이 사고는 값이 틀려서가 아니라 **두 값의 짝이 안 맞아서** 났다. 부등식 셋이
    [작업슬롯 3.3](../../GameDesign/design/workslot/README.md)에 표로 있고, 그중 서버가 아는 둘은
    **테스트가 지킨다**(`SessionIdleSweepTest`). 핑 주기는 클라 상수라 문서·주석으로 묶었다.
  - 🔑 **B는 "넣는 쪽과 비우는 쪽"이 한 쌍이었다.** B-1(서버 몫)이 큐를 비우게 해도
    `PingManager`가 `Update()`에서 핑을 만들면 드래그 중 **넣을 핑 자체가 없다.**
    함께 들어간 **오탐 가드**가 나머지 절반이다 — 없으면 서버가 안 끊어도
    밀린 Pong을 오판해 **클라가 스스로 앱을 내린다.**

  > ⚠️ **드래그를 없애는 선택지는 없다.** 데스크톱 상주형이라 **OS 타이틀바를 지웠고**,
  > 그 대가로 **UI 패널이 타이틀바 역할**을 한다 — 창 이동은 빼도 되는 기능이 아니다
  > ([`DesktopWindow 규칙.md`](../../Assets/Scripts_Client/DesktopWindow/DesktopWindow%20규칙.md) §5-7).

  > 📌 **[T-004](../T-004-전역배수복귀.md)(채취 배수 6.0)가 배포 전 게이트로 남는다.**
  > 판정 15초는 채취 기준 주기 30초 기준으로 안전한데, 배수 6.0이면 실효 주기가 5초라
  > 좀비가 3주기를 부당 적립한다. **개발 중엔 무해하지만 배포 전에 배수를 되돌려야 한다.**

- 🔓 **슬롯 해금이 세 층으로 갈라졌다 (2026-08-28 등록).**

  ```
  T-012 곡선 결정(기획) → T-038 서버 하달·해금 패킷 → T-039 클라 해금 안내·구매
  ```

  지금 클라는 **잠긴 칸과 열린 빈 칸을 구분하지 못한다** — 1~7번이 전부 "비어있음."이고

  담아 상한·잠김 여부·해금 조건이 아예 전달되지 않는 것이다.
  **T-038의 패킷 골격은 곡선을 안 기다리고 착수할 수 있게 갈라 두었다** — 값이 아니라 형식이 먼저다.
