# T-032 클라 — 인벤토리 판매 UI

## 배경

**방치형은 인벤토리가 자동으로 찬다.** 낮은 등급을 하나씩 골라 파는 UI면
플레이어가 매일 수십 번 클릭하게 되고, 이는 P1(주의를 뺏지 않는다)을 정면으로 어긴다.

**일괄 판매가 기본 동선이어야 한다.** 서버(T-028)가 목록 단위 요청을 받도록 설계된 이유다.

### 이번 범위에서 뺀 것

- **희귀도/산업 단위 일괄 선택** — 우클릭 낱개 담기부터 세웠다. 필요해지면 **새 번호로 등록**한다
- **캐릭터·장비 판매** — ⏸ **서버 패킷이 없다.** `C_ItemSellRequest`가 아이템 TID 축
  (`ItemInfo { ItemId, Count }`)이라 개체 PK로 식별되는 캐릭터를 담을 수 없다.
  그래서 격자가 **자원 탭이 아니면 우클릭을 무시한다**
- **좌클릭 상세 표시** — 판매 목록이 `Information Presenter` 자리를 차지했다.
  상세를 되살릴지는 따로 정한다

## 서버가 내려 준 것 (2026-09-02)

```csharp
// 요청 — 종류 목록을 한 번에 보낸다. Count는 "파는 개수"(델타)다
C_ItemSellRequest { List<ItemInfo> Items }          // ItemInfo { int ItemId; int Count; }

// 응답 — 잔액이 아니라 이번에 번 금액이다. 갱신된 잔액은 S_CurrencyResponse가 따로 온다
S_ItemSellResponse {
    EResultCode          Result;
    long                 GainedGold;
    List<ItemChangeInfo> ItemChangeInfos;  // 갱신 후 누적 총량. 0개는 Kind=Remove
}
```

| 결과 코드 | 언제 |
| --- | --- |
| `Ok = 0` | 판매 성공 |
| `NotLoggedIn = 1` | 로그인 전 요청 |
| `InvalidSellRequest = 300` | 빈 목록 · 수량 0 이하 · 존재하지 않는 `ItemTID` |
| `NotEnoughItem = 301` | 보유량 부족 |

**⚠️ 판매는 전부 되거나 전혀 안 된다.** 목록 중 한 종류라도 보유량이 모자라면
`NotEnoughItem`으로 거절되고 **아무것도 팔리지 않는다.** 부분 성공 응답은 오지 않는다.

- `ItemChangeInfos`의 `Count`는 **델타가 아니라 갱신 후 총량**이다 — 덮어쓰기로 반영한다.
- 다 팔아 0개가 된 아이템은 `Kind = Remove`로 온다. 목록에서 칸을 지우면 된다.
- 판매 성공 시 `S_ItemSellResponse` 뒤에 **`S_CurrencyResponse`가 따라온다**(확정 잔액).
- 같은 `ItemId`를 목록에 여러 번 넣어도 서버가 합산한다.
- **판매 불가 아이템은 아직 없다.** 156종 전부 팔린다(상자가 생기는 T-029에서 갈린다).

## 배선 결과 (2026-09-04)

전부 들어갔다. **빠진 참조 0건**으로 검증했고 씬은 저장됐다.
화면 위치는 [`UI 배치 현황.md`](../../Assets/Scripts_Client/UI/UI%20배치%20현황.md)에 있다 — 여기 다시 쓰지 않는다.

| 무엇 | 어디 |
| --- | --- |
| 담김 마크 (임시 — 주황 네모 + "판") | `InventorySlotView.prefab > Sell Mark` (평소 꺼짐 · raycast 끔) |
| 판매 줄 | `Assets/Prefabs/SellCartRowView.prefab` (이름·개수·가격·빼기) |
| 수량 팝업 | `!System Canvas > AmountInput Presenter (↓ SUB VIEW)` — **창고가 아니다** |
| 판매 목록 | `Information Presenter` 안 (스크롤 · 빈 안내 · 합계 · 경고 · [판매]) |
| 카트 | 씬 루트 `SellCart (MODEL)` (`PlayerData (MODEL)` 옆) |

- ⚠️ **`Rarity Image`의 raycast target을 켜 둔 채로 두어야 우클릭이 잡힌다.**
  `Sell Mark` 쪽은 반대로 **꺼 두었다** — 마크가 클릭을 먹으면 담긴 칸을 다시 못 뺀다.
- 🔴 **수량 팝업은 창고 캔버스에 두면 안 된다 (2026-09-05 이동).** 열 캔버스는 넷 다
  Sorting Order가 **0인 형제**라 창고 안의 차단막이 다른 열에 닿지 않는다 — 확인 전인데
  상태바·메인·거래가 눌린다. `!System Canvas`(order 2)로 옮기고 `CanvasGroup`으로 여닫는다.
  창고는 `UIManager.AskAmount(...)`로 부르기만 하므로 팝업 참조를 들지 않는다.
- 새 스크립트·프리팹의 `.meta`는 원본과 함께 커밋한다.
