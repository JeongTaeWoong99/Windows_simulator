# T-083 클라 — 우편함 화면

## 배경

서버 우편([T-081](T-081-서버우편.md))을 보고 받는 화면이다 → [우편](../../GameDesign/design/mail/README.md) 4장.

## 할 일

- [x] **우편함 버튼 위치를 정한다** — 클라 결정 → **상태바**(재화 줄 뒤 · 세팅 앞), 누르면 `#Main Canvas` 가운데가 우편함으로 바뀐다(설정과 같은 흐름 · 2026-09-26)
- [x] 목록 — 제목·발신자·첨부·도착 시각 · 받은 우편은 "받음" 표시(7일 뒤 사라짐)
- [x] 수령 · 모두 받기 — **인벤토리 부족** 거절 안내 · 모두 받기는 받은 수·남은 수 안내
- [x] 받은 우편 삭제 — 안 받은 우편에는 삭제 버튼이 없다
- [x] 새 우편 표시 — **우편함 버튼의 점 하나만.** 숫자·기한·토스트·소리 없음(P1) → [게임 UI](../../GameDesign/design/ui/README.md) 2.4의 예외
- [x] 치트창 — 우편 발송(템플릿 TID · 대상 UID, 0이면 전체)

- [x] 받은 첨부를 결과 팝업(가챠와 같은 창)으로 보여 준다 — 확인 후 닫기 (2026-09-26 요청)
- [x] 상자 개봉 `StoredInMail = true` → "우편함에 보관했습니다" 알림
- [x] 실서버 왕복 확인 — 치트 발송 → 점 → **점검 보상 받기 · 결과 팝업** ✅(2026-09-26 사용자 확인)

## 완료 조건

치트로 보낸 우편이 점으로 표시되고, 우편함에서 받기·모두 받기·삭제가 된다.

- ⚠️ **재현 불가(2026-09-26)** — 모두 받기가 인벤토리 부족으로 **중간에 멈추는** 경우와 상자 넘침 보관(`StoredInMail`)은
  장비 칸 200을 채워야 나온다. 받기·모두 받기·삭제 경로와 같은 코드라 완료로 내린다. 창고를 채운 테스트가 생기면 그때 본다.
- **우편함 가득 참(100통) 표시는 넣지 않았다** — 상한 값의 주인이 [T-085](../T-085-공용상수소유권.md)에서 정해진 뒤 그쪽에서 다룬다.
- **경매 장비 개체(`MailInfo.Equips`)는 이름만** 첨부 요약·결과 팝업에 나온다. 인챈트 표기는 [T-096](../T-096-클라경매장화면.md).
