# T-044 클라 — 인벤토리 칸 서버 위치 연동 · 드래그 이동 (자원 · 캐릭터)

> [T-036](../T-036-창고탭전환.md)에서 갈라져 나왔다. 격자가 **인덱스 기반**으로 바뀌면서
> 자리는 열렸지만, **서버에 슬롯 위치라는 개념이 없어** 지금은 만들 수 없다.
>
> **2026-09-16 범위 확장** — 자원만이 아니라 **캐릭터 탭도** 옮긴다. 그리고 [T-015](art/T-015-산업아이템클라적용.md)에서
> 넣은 **[정렬] 버튼의 임시 기억을 서버 위치로 바꾸는 일**도 여기서 한다(같은 필드를 쓴다).

## 배경

**칸을 끌어 다른 자리로 옮기는 수단이 없다.** 인벤토리 칸의 순서는 지금 **공급자가 내놓는 순서**이고,
그것은 서버가 보내 준 목록 순서다 — 사람이 정한 자리가 아니다.

[정렬] 버튼(2026-09-16)은 누른 순간의 순서를 **클라가 세션 동안만** 기억한다(`StorageSlotSource._place`).
재접속하면 사라진다. 자리의 주인은 서버여야 한다 → [T-058](T-058-창고칸위치서버.md).

### 2026-09-25 — **빈 칸 유지는 클라가 먼저 넣었다**

장착·배치로 개체가 빠질 때 **뒤의 것이 통째로 앞으로 당겨지던 문제**를 먼저 고쳤다.
이제 `StorageSlotSource`가 `Key → 칸`(`_place`)을 들고 있고, 떠난 자리는 **빈 칸으로 남으며**,
들어오는 것은 **앞에서부터 첫 빈 칸**을 가져간다. 격자는 `Get(i)`가 null이면 그 프레임을 비운다.

**그래서 아래 할 일 중 "빈 칸은 빈 채로 그린다"는 이미 됐다.** 남은 것은 그 자리가
**재접속해도 남게** 하는 것 — 즉 `_place`를 서버 칸 번호로 바꾸는 일이다.

## 무엇이 막고 있나

▶ **풀렸다 (2026-10-01)** — 서버 [T-058](T-058-창고칸위치서버.md)이 끝났다. 클라가 쓸 것:

- `ItemInfo.Slot` · `ItemChangeInfo.Slot` · `CharacterInfo.Slot` · `EquipInfo.SlotPosition` — 지금은 전부 `Container = Inventory`
- 송신 `C_StorageSortRequest { Container, Tab, SortKey(Rarity·Name·Count), Order(Descending·Ascending) }` — 응답에 **탭 전체**
- 송신 `C_StorageMoveSlotRequest { Container, Tab, FromSlot, ToSlot }` — 응답에 **바뀐 칸만**(교환이면 둘)
- 수신 `ServerPacketHandler.StorageSlotsReceived` (`S_StorageSlotsResponse { Result, Container, Tab, Slots[(Key, Slot)] }`)
- 거절: `StorageSlotOutOfRange` · `StorageSlotEmpty` · `InvalidStorageSortKey`(캐릭터·장비 탭의 수량순) · `StorageSlotPending`(뽑기·우편 수령 응답 전 예약된 칸으로 이동 — 잠시 뒤 다시)
