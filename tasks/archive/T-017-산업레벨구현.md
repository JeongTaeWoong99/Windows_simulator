# T-017 산업 레벨 구현 — 엑셀 · DB · 패킷 · 서버

## 배경

[산업 레벨](../../GameDesign/design/gathering/산업레벨.md)을 실제로 굴리려면
**엑셀·DB·패킷·서버 로직이 전부 한 칸씩 늘어난다.**
슬롯 배치가 `(산업, 캐릭터)`에서 `(산업, 레벨, 캐릭터)`가 되고,
드롭 롤의 대상이 시트 전체가 아니라 `(산업, 레벨)`로 걸러진 행 목록이 된다.

~~**해금 조건이 정해지기 전에는 시작할 수 없다**~~ →
✅ **2026-08-01에 조건이 확정됐다** — **적성 N + 계정 레벨 M (AND)**.
컬럼은 **`RequiredAptitude` + `RequiredAccountLevel` 정수 2개**로 끝난다.
범용 조건 시스템(`ConditionType` enum 등)을 만들지 않는다.

✅ **2026-08-01에 레벨 개수(5개)와 판정 비용 구조도 확정됐다.**
**판정 1회 비용이 전역 상수에서 `(산업, 레벨)`의 필요 점수가 된다** —
Lv1 30,000에서 레벨당 ×3. 점수는 작업속도로 쌓인다(적성 1 = 1000점/초).

⚠️ **남은 선행 조건: 요구치 값(`N`·`M`)** — 엑셀에 임시값이 들어가 있다 (T-016).

## 🔴 지금 서버가 잘못 동작하고 있다 (2026-08-02 확인 → **드롭은 2026-08-10 해소**)

**엑셀만 먼저 레벨별로 갈라져서, 레벨을 모르는 옛 코드가 새 데이터를 읽고 있다.**
이건 "아직 안 됨"이 아니라 **"틀리게 됨"** 이다.

| 증상 | 원인 | 상태 |
| --- | --- | --- |
| ~~어떤 레벨을 돌리든 Lv1~Lv5 아이템이 전부 섞여 나온다~~ | `DropTableCatalog.LoadAll`이 38행을 통째로 등록했다 | ✅ **해소 (2026-08-10)** — 키를 `(ItemType, Level)`로 갈라 25개 테이블로 등록 |
| ~~희귀도 분포가 의도와 다르다~~ | 5개 레벨의 가중치가 한 통에 합산돼 총합이 부풀었다 | ✅ **해소** — `DropSheetTest`가 (산업, 레벨)별 분포를 검증한다 |
| ~~판정 주기가 레벨과 무관하게 30초 고정~~ | `WorkStationSlot.JudgeCost`가 상수 `30_000_000` | ✅ **해소 (2026-08-10)** — `IndustryLevelCatalog`가 `RequiredScore × 1000`(초→ms 환산)을 준다 |

- `WorkStationSlot`에 **`IndustryLevel`·`JudgeCostUnits` 필드가 생겼다 (2026-08-10 · 기본 Lv1 · 30초).**
  다만 **DB·패킷이 없어 항상 Lv1로 적재**된다 — 현재 해금이 Lv1뿐이라 기획과는 맞는다.
- **레벨 선택 수단(DB·패킷·해금)이 없어 상위 레벨은 아직 돌 수 없다.**
  T-009(회당 산출)의 레벨별 실측은 그것이 붙어야 가능하다. (Lv1 실측·T-008 분포는 가능해졌다)
