# T-123 경매 단가 상한 — x10 배수 → 절대 상한 1조 · 한 번에 9,999개

> 2026-10-06 — ✅ **완료.** 클라 수량 입력 상한 · "10조" → 1조 정리 후 사용자 실측 확인 — [이슈 #56](https://github.com/JeongTaeWoong99/Windows_simulator/issues/56) 닫음.

## 배경 (태웅, 2026-10-05)

경매 단가 상한이 **즉시 판매가 x10**이라 희귀한 물건의 값을 플레이어가 매기지 못했다(즉시 판매가 18 G 자원은 180 G가 끝).
배수를 없애고 **절대 상한 10조**로 바꿨다 — 단가 x 수량 x 수수료가 `long`을 넘지 않는 선이다.
하한(즉시 판매가)은 그대로 둔다 — 즉시 판매보다 싸게 올리면 되파는 길이 열린다.

클라 작업 중 **서버 폴더(진우 담당)도 함께 고쳤다** → 리뷰 요청 [이슈 #56](https://github.com/JeongTaeWoong99/Windows_simulator/issues/56).

## 리뷰 결과 (진우, 2026-10-06) — 상한 1조 · 한 번에 9,999개

방향(배수 폐지 · 절대 상한)은 그대로 받았다. 다만 **10조는 "long을 넘지 않는 선"이 아니었다** —
한 번에 올리는 수량에 상한이 없어(보유량이 곧 상한이고, 우편·상자 개봉은 `MaxStack`으로 자르지 않는다)
보유량이 약 18,000개를 넘으면 `SaleFee`의 `총액 × 천분율`이 조용히 넘친다. 그래서 두 값을 한 쌍으로 묶었다.

- [x] 엑셀 `Constants.xlsx` — `AuctionMaxUnitPrice` 10조 → **1조** · **`AuctionMaxListingCount` = 9999** 행 추가 · 파이프라인 재생성
- [x] 서버 — `AuctionRules.MaxListingCount` · 등록 수량이 상한을 넘으면 `AuctionInvalidRequest`로 거절(`User.Auction.cs` `DescribeItem`)
- [x] 서버 테스트 — 1조 경계 · 9,999개 허용 / 10,000개 거절 · 최고 단가 × 최대 수량의 수수료 계산 — 전체 752 통과(1 건너뜀)
- [x] 문서 — 기획 [거래](../GameDesign/design/trade/README.md) 4.3 · 수치 표 · 6장 #2 · `Server/docs/경매장.md` 7장
