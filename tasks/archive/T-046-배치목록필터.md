# T-046 클라 — 배치 목록의 산업 필터 · 줄 프리팹화 · 창고 '배' 표시

## 배경

**작업슬롯 배치 목록(2단계)이 "지금 고를 수 있는 것"을 보여 주지 못한다.** 셋이 한 화면에서 만난다.

1. **산업을 눌러도 캐릭터가 걸러지지 않는다.** 지금 산업 버튼은 적성 0인 줄을 **잠그기만** 하고
   (`CharacterStateRowView.SetAssignable`) 목록에는 그대로 남긴다. 16마리를 기르면 낚시를 눌러도
   16줄이 그대로 있고, 그중 누를 수 있는 것만 골라 봐야 한다.
2. **배치된 캐릭터가 목록에 그대로 뜬다.** 눌러서 배치하면 그 캐릭터가 **어느 슬롯에서
   빠져나오는지** 화면에 없다.
3. 🔴 **줄이 1개뿐이라 나머지가 아예 안 보인다.** 지금은 경고로 막고 있다.

   ```
   [UI] 보유 캐릭터가 16인데 깔아 둔 줄은 1개뿐이다. 줄을 늘리거나 프리팹으로 빼서 만들 것.
   WorkStationSelectPresenter:RefreshRows () (…:423)
   ```

   ⚠️ **[`UI 배치 현황.md`](../../Assets/Scripts_Client/UI/UI%20배치%20현황.md)는 "씬에 21줄 깔아 두고
   풀처럼 쓴다"고 적고 있는데 실제 씬은 1줄이다.** 문서가 낡았다 — 프리팹화하면 이 불일치 자체가 사라진다.

### ⚠️ 이 일감은 기존 원칙을 뒤집는다

지금까지 이 화면의 규칙은 **"숨기지 않고 잠근다"** 였다. 근거는 `WorkStationSelectPresenter`
클래스 주석에 있다 — *"목록에서 빼면 '이 캐릭터가 왜 안 보이지'가 되고, 적성이 오르는 수단이
붙었을 때 화면이 조용히 틀린다."* [T-035](../T-035-선택패널남은조각.md)의 (a)도 같은 축이었다.

**이 일감은 "건다"로 바꾼다.** 사용자 결정이며, 성립하는 근거는 **창고 캐릭터 탭이 답을
대신 주기 때문**이다 — 보유 목록의 진실은 창고에 있고, 배치 화면은 *"지금 이 슬롯에 넣을 수
있는 것"* 만 보이면 된다. 그래서 아래 **D(창고 '배' 표시)가 이 일감에서 빠질 수 없다.**

> 🔴 **남는 위험 하나 — 적성으로 걸러진 캐릭터는 창고도 답해 주지 못한다.**
> 창고 캐릭터 칸에는 등급·이름·배치 상태만 있고 **적성이 없다.** "낚시를 눌렀더니 내 캐릭터가
> 없다"의 이유를 어디서도 볼 수 없게 된다. 창고 칸에 적성을 함께 보일지, 배치 목록에
> "적성 없는 N마리는 숨겼다" 한 줄을 남길지를 **B를 만들 때 정한다.**

## 할 일

> **A가 먼저다.** B·C는 목록의 내용을 바꾸는 일이라 줄이 1개인 채로는 확인할 수 없다.

### A. `Character State Row`를 프리팹으로 (선행)

- [x] 씬에 깔아 둔 줄을 **프리팹 + 풀**로 바꾼다
      ⚠️ **창고 격자가 아니라 판매 줄(`StorageInformationPresenter`)을 베꼈다** — 아래 "진행" 참조
      (`GetOrCreateRow` · `HideRowsFrom` · `LayoutRebuilder.ForceRebuildLayoutImmediate`)
- [x] **파괴하지 않고 풀로 되돌린다** — 상주 앱이라 목록을 오갈 때마다 만들고 부수면 GC가 쌓인다
- [x] ⚠️ **창고와 다른 점을 먼저 정한다.** 창고는 *프레임 200개*가 씬에 고정으로 깔려 있고
      코드는 그 안에 칸만 만든다. 캐릭터 목록은 **보유 수가 곧 줄 수**라 프레임을 씬에 깔면
      그 개수가 그대로 상한이 된다 — 지금 겪는 문제가 형태만 바꿔 돌아온다.
      **프레임까지 코드가 만들지, 창고처럼 프레임을 깔고 상한을 둘지 정한다**
- [x] `RefreshRows`의 "줄이 모자라다" 경고를 걷어낸다 (그 상태가 없어진다)
- [x] `UI 배치 현황.md`의 "21줄" 서술 정정

### B. 산업 필터 — 고른 산업을 다루는 캐릭터만 보인다

- [x] 산업 버튼을 누르면 **그 산업 적성이 있는 캐릭터만** 목록에 남긴다 (`_data.GetAptitude` > 0)
- [x] ⚠️ `RefreshRows`가 `_data.Characters`를 **인덱스로 그대로** 줄에 태우고 있다.
      걸러 내면 인덱스가 어긋나므로 **걸러 낸 목록을 먼저 만들고** 그것을 태운다
- [x] `CharacterStateRowView`의 적성 0 잠금(`SetAssignable`의 `_aptitude > 0`)이 죽은 코드가
      되는지 확인한다 — 걸러 냈으면 잠글 대상이 없다. **지우지 말고 판단해서 정한다**
- [x] 위 "남는 위험"의 안내를 어떤 형태로 둘지 정해 넣는다
- [x] 📌 **[T-034](T-034-슬롯산업교체.md)·T-006이 남긴 "적성 0 사전 차단"이 여기서 닫힌다.**
      단 **3단계 세팅의 산업 버튼은 여전히 적성을 보지 않는다**(눌리고 서버가 `NoAptitude`로 거절).
      거기도 막을지 함께 정한다

### C. 배치된 캐릭터는 목록에서 뺀다

- [x] 다른 슬롯에 배치 중인 캐릭터를 목록에서 제외한다
- [x] 판정은 **`PlayerDataModel.FindSlotIndexOf`** 를 쓴다 — 창고 캐릭터 탭이 같은 것을 보므로
      각자 `WorkStationSlots`를 훑으면 두 화면이 다른 말을 한다
- [x] ⚠️ **[T-035](../T-035-선택패널남은조각.md)의 (a)를 대체한다.** 그쪽은 *"숨기지 않고 표시한다"*
      였으므로 이 일감과 공존할 수 없다 — T-035에서 (a)를 걷어낸다

### D. 창고 캐릭터 탭에 '배' 마크

- [x] 배치 중인 캐릭터 칸 **오른쪽 위에 마크**를 띄운다 — 판매 담기의 '판'과 같은 자리·같은 방식
- [x] 구조는 `sellMark`를 그대로 베낀다 — 프리팹에 마크 오브젝트 + `SetXxxMark(bool)` +
      `Clear()`에서 되돌리기 (`InventorySlotView`), 켜는 판단은 격자가 매번 그릴 때
      (`StorageGridPresenter.Redraw`의 `view.SetSellMark(…)` 한 줄 옆)
- [x] ⚠️ **자원 탭에서는 꺼져야 한다.** 판매 표시가 `IsSellableTab`으로 탭을 가르듯,
      배치 표시도 캐릭터 탭에서만 켜지는 축이 필요하다
- [x] ⚠️ **기존 표시와 겹친다 — 어느 쪽을 남길지 정한다.** `CharacterSlotSource`가 이미
      보조 문구로 **`배치 중` / `배치 가능`** 을 내고 있다. 마크만 남길지, 문구를 다른 것으로
      바꿀지(예: 적성), 둘 다 둘지 — **셋 다 두면 한 칸이 같은 말을 두 번 한다**
