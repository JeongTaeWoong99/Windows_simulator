## 배경

**슬롯을 여는 경로가 서버에 아예 없다.** 기획은 시작 2개 · 상한 8개로 확정됐는데 서버는
`User.DefaultSlotCount = 1`이고, 패킷은 열린 슬롯만 담아 잠긴 칸을 표현하지 못한다.
클라는 1~7번 칸을 열린 빈 칸과 구분하지 못하고, 눌러 봐야 `InvalidSlotIndex` 거절뿐이다.

해금은 슬롯만의 문제가 아니라 산업 레벨·특성에도 같은 모양으로 필요해서, **한 표(`UnlockTable`)와
한 행동(`C_UnlockRequest`)** 으로 모으기로 했다. 이 일감이 그 골격을 세우고 슬롯에 처음 적용한다.

## 규칙 (확정 · 상세는 기획 문서)

| 항목 | 값 |
| --- | --- |
| 조건 | `UnlockTable` 행의 `Gold` · `AccountLevel` · `RequiredUnlockTIDs`. 0/빈 값 = 없음. 지불 컬럼끼리 OR, 나머지와 AND |
| 판정 순서 | 없는 TID → 이미 열림 → 선행 미충족 → 레벨 미달 → **골드 차감(`TrySpendGold` 재사용)** → 기록 |
| 영속 | `t_user_unlock (user_id, unlock_tid, unlocked_at)` PK `(user_id, unlock_tid)`. 재검사 없음 |
| 슬롯 | `WorkSlotTable.WorkSlotTID`(=칸 번호 0~7) → `UnlockTID`. `0`은 항상 열림 = 시작 2칸. 행 수 = 상한 8 |
| 계정 레벨 | 아직 서버에 없다. `AccountLevel`은 전부 `0`이라 이번엔 **검사만 자리를 만들고 값은 0 비교**로 통과한다 |

## 완료 조건

신규 계정은 2칸으로 시작하고, 로그인 직후 받은 열린 목록과 테이블만으로 클라가 **8칸 각각이 열렸는지·무엇이 필요한지**를
그릴 수 있으며, 해금 요청을 보내면 서버가 조건을 검증해 골드를 빼고 칸을 열거나 사유를 담아 거절한다. 재로그인해도 유지된다.
