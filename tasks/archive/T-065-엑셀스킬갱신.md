# T-065 excel-table-creator 갱신 — 클라·기획이 쓰는 엑셀 작성 스킬로

## 배경

데이터를 추가하려면 `GameDesign/Excel/*.xlsx`를 고쳐야 한다. 이미 [`excel-table-creator`](../../.claude/skills/common/excel-table-creator/SKILL.md)가
시트·컬럼 규칙(TID · 마커 행 · `Ref` · 파이프라인)을 담고 있지만, **서버가 쓰는 것을 전제로** 쓰여 있다.
앞으로 이 스킬을 쓰는 사람은 클라·기획이다. 별도 스킬을 새로 만들지 않고 **이 스킬을 갱신한다** — 규칙이 거의 같아 둘로 나누면 중복만 생긴다.

## 할 일

- [x] 대상 독자를 클라·기획으로 — 서버 내부 설명(`TableCodeGenerator.PickKey()` 등)은 근거 칸으로 줄이고, "무엇을 하면 되나" 위주로
- [x] **행(데이터) 추가 절차**를 앞에 — 가장 흔한 작업. TID 대역 확인 → 행 추가 → `Ref` → 파이프라인 → `DataLog` diff 확인
- [x] **시트·컬럼 신설은 서버와 합의** 선 긋기 — 생성 클래스·`.bytes`·패킷에 닿기 때문
- [x] **서식 규칙 추가** (파이프라인은 값만 읽으므로 데이터에는 영향 없음)
  - 도구: `openpyxl`(Python, 설치돼 있음). ⚠️ 저장 전 Excel에서 파일을 닫는다 · 차트·이미지가 있는 시트는 저장 시 사라질 수 있다
- [x] **서식 기준 = `Character.xlsx`** — Enum 시트를 뺀 모든 테이블 시트에 적용한다 (2026-09-19 확정)

  | 영역 | 예 (`CharacterTable`) | 정렬 | 글꼴 | 칠·테두리 |
  |---|---|---|---|---|
  | 설명 행 (맨 위, 사람용 한글 이름) | 2행 `캐릭터 TID` · `이름` | 가운데 | **굵게** | 주황 칠(테마 accent6 `F79646`) · 얇은 테두리 |
  | 스키마 행 (`C&S` · `Type` · `Min` · `Max` · `Default(Null)` · `Ref`) | 3~8행 | **가운데** | 보통 | 얇은 테두리 |
  | 컬럼명 행 | 9행 `CharacterTID` · `Name` | **왼쪽** | **굵게** | 주황 칠 · 얇은 테두리 |
  | 데이터 — 숫자(`int` · `long` · `float` …) | `1001` · `3` | **오른쪽** | 보통 | 없음 |
  | 데이터 — `string` · enum(`e…`) | `램볼` · `Common` | **왼쪽** | 보통 | 없음 |
  | 열 너비 | 전 컬럼 | — | — | 그 열의 **가장 긴 글자(설명·스키마·컬럼명·데이터 전부)가 보이는 폭**으로 맞춘다 |

  - 숫자·문자 구분은 그 열의 `Type` 행 값으로 판단한다
  - **한글 설명(설명 행)은 최대한 짧게** 쓴다 — 열 너비가 가장 긴 글자에 맞춰지므로, 설명이 길면 열이 늘어난다. 긴 설명은 설명 행이 아니라 기획 문서나 `Description` 열로 보낸다
- [x] **Enum 시트 서식 기준 = `Enum.xlsx`** (`GlobalRarity` 등) — 머리 세 줄은 항상 고정 (2026-09-19 확정)

  | 행 | 예 | 칠 | 글꼴 | 정렬 |
  |---|---|---|---|---|
  | 1행 | `EID` · `Name` · `Desc` | 검정(테마 dk1) | **흰색 굵게** | 가운데 |
  | 2행 | `EnumID` · `Value` · `Description` | 회색(dk1 tint 0.35) | 흰색 | 가운데 |
  | 3행 | `int` · `enum` · `string` | 옅은 회색(lt2 tint −0.1) | 검정 | 가운데 |
  | 데이터 — `EnumID` 열 | `1` · `2` | 없음 | 보통 | **항상 가운데** |
  | 데이터 — `Value` · `Description` 열 | `Farming` · `농사` | 없음 | 보통 | **왼쪽** |

  - 열 너비는 테이블 시트와 같다 — 가장 긴 글자가 보이는 폭
- [x] **기존 워크북 전체(`GameDesign/Excel/*.xlsx`)를 위 기준으로 맞추기** — 어긋난 칸을 전부 고친다. 값은 건드리지 않고 서식만 바꾼 뒤 파이프라인을 돌려 `DataLog` diff가 없는지 확인
- [x] `description`(발동 조건)을 클라·기획의 데이터 추가 요청 기준으로 다시 쓰기
- [x] 루트 `CLAUDE.md` "Skills 참조" 표의 설명 갱신 · 스킬 문서 `최종 업데이트` 날짜 갱신

## 결과 (2026-09-19)

- `GameDesign/format-excel.py` — 위 서식 기준을 12개 워크북 전 시트에 적용. 값 불변, 파이프라인 재실행 후 `.cs` · `.bytes` · `DataLog` diff 없음
- 설명 행 `//` 긴 한글 90칸을 짧게 (`농사 적성 상한 (적성 포인트로…)` → `농사 상한`). 원문은 셀 메모로 옮겼다
- `//` 행은 생성물에 들어가지 않는다 — 스킬의 "코드에 주석으로 들어간다" 서술이 틀려 고쳤다
- 스킬 `SKILL.md` · `컬럼 레퍼런스.md` · 루트 `CLAUDE.md` 표 · `GameDesign/CLAUDE.md` 폴더 표 갱신
- 스킬 수정은 프로젝트 고유 경로·스크립트를 담아 **Arca 마스터로 올리지 않는다**

## 완료 조건

클라·기획이 "아이템 하나 추가해 줘"처럼 요청하면 이 스킬이 발동해, 정해진 서식을 지켜 행을 추가하고
파이프라인까지 돌려 생성물이 갱신된다. 시트·컬럼 신설이 필요하면 서버 합의로 넘어간다.
