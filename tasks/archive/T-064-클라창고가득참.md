# T-064 클라 — 창고가 가득 차 뽑기가 거절될 때 안내

## 배경

[T-063](T-063-창고한도뽑기거부.md)에서 서버가 창고 칸이 모자란 뽑기를 거절하게 된다.
클라는 그 결과 코드를 받아 **왜 안 됐는지** 보여 줘야 한다 — 안 그러면 버튼이 먹통처럼 보인다.

## 할 일

- [x] `ResultMessages`에 `StorageFull`(103) 문구 추가 (예: "창고가 가득 찼습니다. 정리한 뒤 다시 뽑아 주세요") — **서버가 냈다**(2026-09-22). 상자 개봉 거절도 같은 코드다
- [x] 가챠 화면의 거절 처리 경로에서 문구가 뜨는지 확인 — 코드 대조(2026-09-25): 뽑기 `GachaPresenter.OnGachaFailed` · 상자 `StorageGridPresenter.OnItemUseFailed` 둘 다 `ResultMessages.ToText`를 거친다
- [ ] (선택 · 이번에 안 함) 창고 탭에 `보유 N / 200` 표시 — **서버는 한도 값을 내려주지 않는다**(서버 상수 `User.StorageCapacity` · 2026-09-22 T-063). 클라가 아는 200을 쓰고, 값의 소유는 [T-085](../T-085-공용상수소유권.md)가 정한다
- [x] 칸 프레임 수(200)가 서버 한도와 같은지 확인 — `StorageGridPresenter.CacheFrames`가 시작할 때 대조하고, 어긋나면 에러 로그를 남긴다([T-085](../T-085-공용상수소유권.md) 클라 파트와 같이 처리)
- [x] **실플레이** — 캐릭터 200명 계정에서 뽑기 → 가득 참 안내 확인 (2026-09-25 사용자 확인)
      ※ 치트 `GiveCharacter`로는 한도를 넘겨 지급된다 — 서버 몫이라 [이슈 #40](https://github.com/JeongTaeWoong99/Windows_simulator/issues/40)으로 넘겼다. 이 일감의 완료를 막지 않는다

## 완료 조건

캐릭터 200명 계정에서 캐릭터 뽑기를 누르면 재화가 줄지 않고 가득 참 안내가 뜬다 (실플레이).
