# T-165 서버 — T-164 푸시 검토

> ⏩ 261107 회차에 못 끝내 261121로 자동 이월 (2026-11-08)

> ⏩ 261024 회차에 못 끝내 261107로 자동 이월 (2026-10-25)

## 배경

[T-164](archive/T-164-창고물건사용서버.md)(창고 물건도 인벤토리와 똑같이 쓴다 · [이슈 #74](https://github.com/JeongTaeWoong99/Windows_simulator/issues/74))를 `383657d`로 main에 푸시했다.
조회·삭제·자원 소모·로그인 복원·경매 우편 SQL까지 넓게 건드렸으니, 클라 T-163이 붙기 전에 사람 눈으로 한 번 더 본다.

## 할 일

- [x] `383657d` diff 검토 — `TryGetCharacter`·`TryGetEquip`가 양쪽을 보면서 **창고 것이 끼면 안 되는 곳**이 섞이지 않았는지(지급·칸 배치는 인벤토리만)
- [x] 자원 소모 `Inventory.TryRemoveAcross` — 인벤토리 먼저 · 모자라면 창고 · 부족 시 무변경 · `Changes`에 양쪽 칸
- [x] 싱크 패킷의 `Container`가 개체가 있는 보관함으로 가는지(`ToCharacterInfo`·`ToEquipInfo`)
- [x] 경매 우편 수령 `UnlockEquipAsync`·`UnlockCharacterAsync`의 `container = 0`
- [x] 실서버 확인 — 서버를 띄우지 않고 같은 시나리오를 유닛·SQLite 테스트로 덮었다(아래 표)
- [x] 치트: 새 치트 불필요

## 검토 결과 (2026-11-20 · 지금 main 2c715457 기준)

| 항목 | 결론 |
| --- | --- |
| 조회 호출처 전수 | ✅ `TryGetCharacter` 26곳·`TryGetEquip` 11곳 — 장착·배치·큐브·응축·잠금·판매·경매·분해·비약·레이드 편성·로그인 복원·작업 슬롯 고아 정리·속도. 전부 "가진 것인가"를 묻는 자리라 창고 것이 껴야 맞다 |
| 인벤토리만 보는 곳 | ✅ 캐릭터·장비 지급(`GrantCharacters`·`GrantEquip`)·우편 수령 칸 배정과 칸 수 검사(`CharacterSlotsUsed`·`EquipSlotsUsed`·`NextFreeEquipPosition`)는 `_characters`·`_equips`만 본다. 아티팩트는 창고 탭이 없다(이동 거절) |
| `TryRemoveAcross` | ✅ 인벤토리 먼저 · 모자란 만큼 창고 · 합쳐 모자라면 무변경 · `Changes`에 양쪽 칸. 판매·경매·상자·큐브·건물·해금·비약·자동 사용이 전부 `TryRemoveItems`로 이 길을 지난다 |
| 싱크 `Container` | ✅ `ToCharacterInfo`·`ToEquipInfo`가 개체가 든 묶음에서 읽는다. 캐릭터 쪽 테스트가 없어 추가 |
| 경매 우편 `container = 0` | ✅ SQL·테스트(`AuctionDbTest`·`CharacterAuctionTest`) 둘 다 있다 |
| **분해 재료 지급** | **수정** — `TryDisassemble`이 재료를 `Inventory.AddItem`으로 인벤토리에만 넣었다. 칸 검사(`HasStorageFor`)는 창고의 같은 자원 칸부터 채워 보고 통과시키므로(T-175), 인벤토리 자원 칸이 가득 차고 창고에 같은 재료 칸이 있으면 **검사는 통과·장비는 지워지고·재료는 버려졌다.** 지급을 `Deposit`(창고 같은 자원 칸 → 인벤토리)으로 바꿨다 |
| 설계 문서 | 수정 — `인벤토리-창고.md` 4장의 "채취·판매·배치·장착·경매는 인벤토리 쪽만 본다"가 T-164 전 문장으로 남아 있었다. 양쪽을 보는 것/인벤토리만 보는 것으로 다시 적었다 |
