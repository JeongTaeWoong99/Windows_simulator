# T-063 서버 — 창고 칸 한도 · 칸이 모자라면 뽑기 거부

## 배경

클라 창고는 탭마다 **칸 프레임 200개**를 쓴다. 넘치면 뒤쪽이 잘리고 경고 로그만 남는다
(`StorageGridPresenter` — "칸 프레임이 N개인데 표시할 것이 M개다").

**서버에는 한도가 전혀 없다** (2026-09-17 확인).
- 캐릭터: `GachaService.Draw` → `User.GrantGachaCharacters`가 개수 검사 없이 개체를 늘린다
- 자원: `GainItem`이 TID마다 한 줄씩 늘린다 — 종류 수 검사 없음
- 장비: 시스템은 섰다([T-002](archive/T-002-장비슬롯.md) ✅ 2026-09-17 · 뽑기는 [T-067](archive/T-067-장비뽑기.md) ✅ 2026-09-19) — **한도 검사만 없다**

그래서 200칸이 차도 캐릭터 뽑기가 통과하고, 넘친 캐릭터는 화면에서 **보이지 않는 채로 보유**된다.

## 할 일

- [ ] **칸 계산 규칙 확정** — 자원 = 보유 수량 > 0인 아이템 **종류** 수 / 캐릭터 = 개체 수 / 장비 = 개체 수
- [ ] **한도 값의 위치 결정** — 코드 상수 200인가, 엑셀 상수인가. 나중에 칸 확장(해금·과금)을 할지에 따라 달라진다
- [ ] `EResultCode`에 창고 가득 참 코드 추가 (예: 가챠 대역 `StorageFull = 103`)
- [ ] `GachaService.Draw` 순서 조정 — **추첨(순수) → 칸 검사 → 비용 차감 → 지급.**
      지금은 차감이 추첨보다 앞이라, 검사를 넣으려면 추첨을 앞으로 당긴다. 거절 시 재화·보유는 그대로
- [ ] 칸 검사는 **이번 결과가 새로 차지할 칸**만 센다 — 이미 보유한 자원 TID는 칸을 더 쓰지 않는다
- [ ] 장비 뽑기가 생기면 같은 검사를 쓰도록 검사를 한곳에 둔다 (T-002에 메모) — **장비 뽑기가 생겼다**([T-067](archive/T-067-장비뽑기.md) · 2026-09-19). `GachaService.Draw` 장비 분기도 검사 대상이다
- [ ] **뽑기 외 획득 경로 방침 결정** (막을지·버릴지·넘치게 둘지) — 채집 정산(`User.WorkStation` → `GainItem`), 치트 `GiveItem`·`GiveCharacter`.
      특히 채집은 방치 중 거절할 수 없어서 따로 정해야 한다. 이번 범위에서 정하지 못하면 새 일감으로 등록
- [ ] 테스트 (`server-tdd`) — 199칸 + 10연차 거절 · 이미 보유한 TID만 나오면 통과 · 거절 시 재화 불변
- [ ] 프로토콜 미러 커밋 (`EResultCode` 변경) — 서버 일감 공통 완료 조건

## 완료 조건

캐릭터 200명을 보유한 계정이 캐릭터 뽑기를 보내면 `StorageFull`(가칭)로 거절되고 골드·보유가 변하지 않는다.
자원 뽑기도 새로 차지할 종류 수가 남은 칸보다 많으면 같은 코드로 거절된다. 테스트가 이를 확인하고, 미러가 커밋돼 있다.
