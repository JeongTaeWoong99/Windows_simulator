# 일감

이 폴더가 **할 일의 단일 목록**이다. 일감 1개 = 파일 1개이며, 아래 INDEX(표 셋)가 전체 현황이다.
작성·갱신은 [`task-writer`](../.claude/skills/common/task-writer/SKILL.md), 확인은 [`task-reader`](../.claude/skills/common/task-reader/SKILL.md)를 따른다.

- **일감은 앞으로 할 일**, [`.claude/Agent/`](../.claude/Agent/README.md)는 이미 한 일이다. 섞지 않는다.
- **INDEX는 지금 굴러가는 것만** 담는다. 끝난 것은 [`archive/`](archive/README.md)로 내려간다.
- **INDEX는 표 하나가 아니라 셋이다 (2026-09-05).** ▶ · ⏸ · 🎨를 합쳐야 남은 일 전부다. 첫 표만 보고 "이게 전부"라고 하지 않는다.
- 여기 쌓였던 경위·이력 메모는 [`archive/순서 메모 이력.md`](archive/순서%20메모%20이력.md)로 내렸다 — **평소 열지 않는다.**

## INDEX

가르는 축은 담당도 상태도 아니라 **"왜 지금 못 하나"** 하나다.
일감 안 체크박스의 `⏸`·`🎨`(아래 "할 일 항목의 표기")를 목록 층으로 올린 것이다.

| 표 | 뜻 | 여기 있으면 |
|---|---|---|
| [▶ 지금 손댈 수 있다](#-지금-손댈-수-있다) | 선행이 없다 | 집어서 시작하면 된다 |
| [⏸ 남이 먼저 해야 한다](#-남이-먼저-해야-한다) | 상대의 결정·패킷을 기다린다 | 재촉할 대상이 있다 |
| [🎨 뒤로 미뤘다](#-뒤로-미뤘다) | 연출·리소스. **막힌 게 아니다** | 지금 안 해도 기능은 서 있다 |

> ⚠️ **⏸(상대에게 요청할 것)과 🎨(내가 나중에 할 것)를 섞지 않는다** — 섞으면 협업하는 쪽이 미룬 것을 지연으로 오해한다.
> 둘이 함께 있으면 ⏸이 이긴다. 🎨 표에 넣는 기준은 "🎨가 있다"가 아니라 **"🎨만 남았다"** 이다.

## 순서 메모

"먼저 하면 좋은 것"이다. 진짜 선행은 일감 파일과 ⏸ 표에 있다. 경위는 [이력](archive/순서%20메모%20이력.md)에.

- **코어 루프 한 바퀴가 다 돈다 (2026-09-20).** `채취 → 상자 → 개봉 → 아이템 → 판매 → 골드 → 뽑기 → 배치` — 클라 개봉 화면(T-033)까지 섰다. 남은 것은 🎨 연출뿐이다.
- **슬롯 해금 세 층** `T-012 곡선(기획) → T-038 서버 패킷(✅ 2026-09-16) → T-039 클라 UI(✅ 2026-09-17, 🎨 연출만)`. **남은 것은 T-012 곡선(기획)이다.**
- **경제 수치 세트** T-008 · T-009 · T-018은 함께 정한다 — 5산업이 같은 배율이라 따로 정하면 시간당 수익이 안 맞는다. T-016 · T-014도 같은 시트·같은 결정이다.
- **클라 다음 순서** T-050 호버 (T-052는 칸 게이지로 끝나 독립했다). 연출·리소스는 🎨로 뒤에 — 골격이 선 뒤 한꺼번에 올린다.
- **"고를 수는 있는데 무엇인지 모른다" 묶음 (2026-09-22 QA).** [T-078](T-078-산업레벨정보표시.md)(산업 LV 스펙) · [T-079](T-079-특성정보표시후해금.md)(특성 정보 → [확인]) · [T-080](T-080-슬롯리스트산업레벨표기.md)(목록의 산업 레벨) — 셋 다 **서버·패킷 변경이 없고 값은 이미 클라에 있다.** 화면에 자리를 만드는 일이다. T-080이 가장 작다.
- **창고 칸 위치** `T-058 서버 위치·정렬·이동 → T-044 클라 연동·드래그`. 그때까지 [정렬]은 클라가 세션 동안만 기억한다 — **클라가 서버에 요청할 것은 이것이다.**
- **성장 축 한 바퀴가 돈다 (2026-09-21 실측 완료).** `계정 경험치 → 계정 레벨 → 특성 포인트 → 속도·산업 레벨` — 서버 [T-021](archive/T-021-산업레벨해금판정.md)에 이어 클라 [T-068](archive/T-068-클라계정레벨특성트리.md)·[T-043](archive/T-043-창고장비특성탭.md)까지 끝났다. **창고 네 탭이 모두 돈다.**
  - 🔴 그 대가로 **효율 계산의 전역 배수 역산이 이제 실제로 틀린다**(속도 특성을 찍을 수 있게 됐다) → **[T-055](T-055-속도보정내역전달.md)**(서버). 선행이 더 없다.
- **판매는 자원 탭만이다.** `C_ItemSellRequest`가 아이템 TID 축이라 캐릭터·장비를 담으려면 서버 패킷이 먼저다 → **[T-075](T-075-캐릭터장비판매.md)**. 그 앞에 "중복 개체를 팔 것인가 재료로 쓸 것인가"([T-076](T-076-성장재료소비처.md))가 있다.
- **같은 숫자가 두 곳에 박혀 있다.** 창고 200칸 · 치트 캐릭터 상한 10 · 뽑기 허용 횟수 1·10 — 클라와 서버가 각자 들고 있다 → **[T-077](T-077-공용상수시트.md)**. [T-063](T-063-창고한도뽑기거부.md)의 "한도를 코드에 둘지 엑셀에 둘지"가 이 답을 기다린다.
- **장비 세 층** `T-002 서버(✅) → T-043 창고 장비 탭(✅ 2026-09-19) → T-067 획득 경로(✅ 2026-09-20)`. 장착 UI는 **[T-074](T-074-장비장착UI.md)** 로 등록했다(패킷은 T-002에서 이미 왔다).
- **서버 일감마다 프로토콜 미러 커밋이 완료 조건이다** — T-025 사고(미러 누락 → 클라 컴파일 깨짐)를 반복하지 않기 위해.

### 할 일 항목의 표기

일감 안의 체크박스에는 **왜 아직 안 됐는지**를 아래 기호로 붙인다. `상태`는 일감 전체의 값이고, 이건 항목 하나하나의 사정이다.

| 표기 | 뜻 | 읽는 법 |
|------|-----|---------|
| `⏸` | **기획 결정·서버 패킷이 먼저 와야 한다** | 무엇을 기다리는지 일감 ID로 함께 적는다 |
| `🎨` | **연출·리소스 — 의도적 후순위** | 미룬 것이지 밀린 것이 아니다 |
| `◐` | 일부만 됐다 | 무엇이 서고 무엇이 남았는지 항목 아래에 적는다 |
