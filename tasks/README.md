## 순서 메모

- 🎯 **T-026~T-033이 한 덩어리다 — 코어 루프를 실제로 한 바퀴 돌리는 묶음 (2026-08-17 등록).**
  지금은 루프가 `채취 → 인벤토리`에서 끊겨 있다. 캐릭터가 1종이라 배치가 퍼즐이 아니고,
  골드를 버는 길이 없어 지갑이 항상 0이며, 플레이어가 **직접 여는 순간**이 하나도 없다.
  ```
  채취 → 상자 → 개봉 → 아이템 → 판매 → 골드 → 캐릭터 뽑기 → 배치 → 채취
  T-030  T-029          T-028         T-027 · T-026
  ```
  **순서는 T-026 → T-027 → T-028 → T-029 → T-030.** T-028(즉시 판매)만은 선행이 없어
  언제든 먼저 해도 된다 — 골드가 있어야 T-027을 실제로 검증할 수 있으니 **앞당기는 편이 낫다.**
  - **가챠 비용은 골드 직접으로 확정했다 (2026-08-17).** 기획의 sink ③ *가챠 티켓*을 대체한다 —
    티켓 획득 경로를 만들지 않아도 `판매 → 골드 → 뽑기`가 곧바로 이어진다. **T-027이 문서를 고친다.**
  - **상자는 새 시스템이 아니다.** 기존 `GachaTable` 풀을 상자 아이템이 가리키는 구조라
    `GachaPoolCatalog`·`WeightedPicker`가 그대로 재사용된다.
  - **서버 일감마다 프로토콜 미러 커밋이 완료 조건에 들어 있다** — T-025로 터진 사고
    (미러 누락으로 클라 컴파일 깨짐)를 매번 반복하지 않기 위해서다.
  - ⚠️ **T-026이 기획 공백을 하나 닫는다** — "캐릭터 획득 경로 미정"이 가챠로 확정된다.
    이게 풀리면 **T-010(캐릭터 문서화)·T-019(온보딩)의 막힌 지점도 함께 풀린다.**
- **T-008(희귀도 확률)의 성격이 바뀌었다 (2026-07-31).** 분포 통일이 폐지되어
  **산업마다 정한다.** 작업량은 5배지만 **이 일감이 곧 산업 차별화**가 됐다 —
  수치 축이 회당 산출 하나까지 줄었던 것을 되감는 자리다. T-009와 함께 정하는 게 낫다.
- ✅ **T-006·T-007이 끝났다 (2026-08-03).** 로그인 → 배치 → 카운트다운 → 인벤토리 증가가
  화면에서 돈다. **이제 T-004(전역 배수 복귀)에 착수할 수 있다** — 확인용으로 당겨 뒀던
  5초 주기를 1.0배로 되돌리는 일이다.
  - ⚠️ **UI를 다 만든 뒤에도 배치가 안 됐던 구간이 있었다.** 클라가 캐릭터 **종류(TID)** 를 보내고
    서버는 **개체 번호**를 찾고 있었다. `S_CharacterListResponse`(=`MIKA001` 경고로 떠 있던
    미구현 핸들러)를 붙이고서야 풀렸다. **분석기 경고는 곧 기능 누락이다.**
  - 남은 조각들(적성 0 사전 차단 · 캐릭터 선택 UI · 희귀도 색상)은 각각 선행이 달라
    일감 안에 "남은 것"으로만 적어 두었다. 필요해지는 시점에 별도 일감으로 올린다.
- T-010(캐릭터 문서화)은 구현이 이미 끝나서 **옮겨 적기만 하면 되는데**,
  방치하면 다음에 이 영역을 건드릴 때 "미정"으로 보고 다시 설계하게 된다.
- **T-018(`BasePrice`)이 경제 구현의 첫 블록이다 (2026-08-01).**
  즉시 판매가 확정되면서 이 컬럼이 없으면 **즉시 판매·거래소 하한·상점 가격·랭킹 자산 항이
  전부 막힌다.** 컬럼 추가는 지금 가능하지만, **값은 T-008(희귀도 분포)·T-009(회당 산출)와
  함께** 정해야 산업별 시간당 수익이 맞는다. **셋을 한 세트로 본다.**
- **T-019(온보딩)가 기획에서 가장 크게 남은 공백이다 (2026-08-01).**
  핵심 재미·후반 목표·경제가 채워지면서 "1일차에 무엇을 하는가"만 비었다.
  다만 **시작 캐릭터가 T-010(캐릭터 획득 경로 미정)에 걸려 있어** 완전히는 못 닫는다.
- **T-020은 선행이 없다 (2026-08-07).** 싱글턴 제거로 `ILogicExecutor`가 주입 가능해져
  seam이 이미 열렸다. 다만 **`Login()`·`Destroy()`가 전역 `UserManager.Instance`를 만지므로**
  그 처리 방침(주입 / 직렬화 / 우회)을 먼저 골라야 하고, **일감의 크기가 거기서 갈린다.**
- **캐릭터 종류가 1종인 것이 이제 클라의 마지막 병목이다 (2026-08-10).**
  이슈 #13으로 적성이 패킷에 실려 배치 화면의 잠금 표시까지 붙었지만,
  **시작 지급이 `1001`(전 산업 적성 1) 하나뿐이라 잠금이 화면에 나타나지 않는다.**
  가챠는 아이템 전용이고 **획득 경로가 T-010(기획 미정)**이라 목록·필터를 실검증할 수 없다.
  엑셀엔 1001~1006이 이미 있으므로 **여러 종을 가진 계정을 만들 임시 지급 수단**만 정하면 된다.
  - ✅ **[T-026](T-026-캐릭터가챠.md)이 이 병목을 정면으로 푼다 (2026-08-17 등록).**
    임시 지급 수단이 아니라 **가챠를 획득 경로로 확정**한다 — 클라의 잠금 표시·목록·필터가
    그때 실검증 가능해진다.
- **T-016(산업 레벨)이 T-005·T-014와 같은 시트를 건드린다 (2026-08-01).**
  `<산업>BasicTable` 5종에 `IndustryLevel` 컬럼이 붙고 레벨마다 행이 늘어나므로,
  **T-005의 드롭 시트 작업이 끝난 뒤에** 손대는 편이 충돌이 적다.
  T-014(농사 파종)는 T-016과 **같은 결정**이라 따로 정하면 어긋난다.
