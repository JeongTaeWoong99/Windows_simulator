## 순서 메모

- 🔌 **하트비트 끊김 — 결정은 끝났다(A-1 · B-1). 남은 것은 적용 둘 (2026-09-02 · `add9b9f`).**

  ```
  원인 규명 → 시험 적용 → 철회 → 결정(A-1·B-1) → 적용 ─┬─ B-1 서버 몫 ✅
                                                       ├─ A-1 서버 값 ✅ (정정 완료)
                                                       └─ B 클라 몫 ❌ → T-041로 분리
                                                            ← 지금 여기
  ```

  **독립된 문제 둘에 각각 답이 정해졌다.**
  ① **A** — 서버 무응답 판정(5초)과 클라 핑 주기(5초)의 **여유가 0** → **A-1**(판정을 늘린다) 채택.
  ② **B** — 세션 소켓 루프가 **Unity 메인 스레드에 묶여** 창을 끄는 동안 핑이 멈춘다 → **B-1**(스레드풀) 채택.

  - ✅ **B-1 서버 몫** (`add9b9f`). `MikaClient`가 세션 루프를 `Task.Run`으로 띄우고
    `ConfigureAwait(false)`로 호출자 컨텍스트를 잡지 않는다. 종료 경로까지 막았고 회귀 테스트가 붙었다.
  - ✅ **A-1 정정** (2026-09-02). `add9b9f`가 늘린 것은 판정이 아니라 **검사 주기**였다 —
    `Global.SessionIdleTimeout`을 **15초로** 올리고 `SessionWatchdog.Interval`은 **5초로** 되돌렸다.
    **15초는 새 값이 아니라 [작업슬롯 3.3](../GameDesign/design/workslot/README.md)이 확정해 둔 값**이고,
    코드가 5초로 내려가 있던 것이 회귀였다.
  - ❌ **B 클라 몫은 [T-041](T-041-클라핑타이머.md)로 뗐다** (2026-09-02). 한 번 적용했다가 되돌렸고,
    **빌드에서 드래그 증상은 그대로 재현된다.** 남은 것이 클라 폴더 하나뿐이라 담당을 갈랐다 —
    **선행이 없어 바로 착수할 수 있다.**
  - 🔒 **"핑 주기 ≤ 판정 시간 ÷ 3"을 규칙으로 못 박았다.** 부등식 셋이
    [작업슬롯 3.3](../GameDesign/design/workslot/README.md)에 표로 있고, 그중 서버가 아는 둘은
    **테스트가 지킨다**(`SessionIdleSweepTest`). 이번 사고는 값이 틀려서가 아니라 **짝이 안 맞아서** 났다.
  - ⏳ **A(무작위 끊김)는 빌드 실측이 남았다** — 몇 시간 켜 둬야 나온다.
    B(드래그)는 에디터에서 재현되지 않으므로(`#if !UNITY_EDITOR`) **T-041을 끝낸 뒤 빌드로** 확인한다.

  > ⚠️ **드래그를 없애는 선택지는 없다.** 데스크톱 상주형이라 **OS 타이틀바를 지웠고**,
  > 그 대가로 **UI 패널이 타이틀바 역할**을 한다 — 창 이동은 빼도 되는 기능이 아니다
  > ([`DesktopWindow 규칙.md`](../Assets/Scripts_Client/DesktopWindow/DesktopWindow%20규칙.md) §5-7).

  > 📌 **[T-004](T-004-전역배수복귀.md)(채취 배수 6.0)가 배포 전 게이트가 됐다.**
  > 판정 15초는 채취 기준 주기 30초 기준으로 안전한데, 배수 6.0이면 실효 주기가 5초라
  > 좀비가 3주기를 부당 적립한다. **개발 중엔 무해하지만 배포 전에 배수를 되돌려야 한다.**

### 할 일 항목의 표기

일감 안의 체크박스에는 **왜 아직 안 됐는지**를 아래 기호로 붙인다.
`상태`는 일감 전체의 값이고, 이건 **항목 하나하나의 사정**이다.

| 표기 | 뜻 | 읽는 법 |
|------|-----|---------|
| `⏸` | **기획 결정·서버 패킷이 먼저 와야 한다** | 담당자가 못 하고 있는 것. 무엇을 기다리는지 일감 ID로 함께 적는다 |
| `🎨` | **연출·리소스 — 의도적 후순위** | **미룬 것이지 밀린 것이 아니다.** 메인 시스템이 선 뒤에 한꺼번에 올린다 |
| `◐` | 일부만 됐다 | 무엇이 서고 무엇이 남았는지 항목 아래에 적는다 |

> **`⏸`와 `🎨`를 섞지 않는다.** 둘 다 미체크로 보이지만 **상대에게 요청할 것(⏸)과
> 내가 나중에 할 것(🎨)** 은 완전히 다르다. 섞이면 목록을 볼 때마다 다시 가려내야 하고,
> 협업하는 쪽에서는 **미룬 것을 지연으로 오해한다.**
