## 배경

회차 회의(토 22:00)에서 각자 로컬 서버가 아니라 **한 서버에 함께 붙어** 플레이해야 거래소·경매장 같은
공유 기능을 확인할 수 있다. 지금은 서버를 내 PC에서 직접 실행하고, 클라는 `127.0.0.1`에만 붙는다.

현재 상태 (2026-10-02):

- Docker 파일이 저장소에 없다.
- `WSGameServer` — TCP `10050` 리슨 (`Server/WSGameServer/Network/NetworkManager.cs`)
- `AuctionServer` — gRPC `127.0.0.1:10060` 리슨 (`Server/AuctionServer/appsettings.json`) — 게임 서버가 붙는 서버
- 클라 접속 주소가 `127.0.0.1:10050`으로 박혀 있다 (`Assets/Scripts_Server/Network/MikaNetwork.Unity/NetworkManager.cs`)
- DB는 SQLite 파일 (`Server/Shared/game.sqlite3`) + `.bytes` 데이터

### 범위 — 이번 회차는 "모두 내 Docker 게임 서버에 붙기"

- 이 일감: **게임 서버·경매장 둘 다 내 Docker** · 친구 클라가 내 게임 서버에 붙는다.
- **각자 로컬 게임 서버 + 내 경매장 공유** 조합은 [T-110](T-110-공유경매장다중게임서버.md)으로 뗐다 (2026-10-02) —
  `listing_id`·이벤트·판매 대금 정산이 게임 서버 하나를 전제로 짜여 있어 프로토콜·정산 흐름을 바꿔야 한다.
- 다만 T-110이 바로 이어받을 수 있게 **경매장 주소는 이번에 설정값으로 빼 둔다.**

### 개발 / 원격 분리 (2026-10-11)

**코드·이미지는 하나, 차이는 설정값과 DB 파일 위치만 둔다.**
설정은 `appsettings.json`(개발 기본값, 커밋) + 원격은 compose의 환경변수로 덮어쓴다 — `Game__DbPath`처럼 `__`가 절 구분.
경매장 서버는 이미 이 방식이다(`Auction` 절) — 게임 서버도 같은 모양으로 맞춘다.

| | 개발 | 원격 |
|---|---|---|
| 실행 | IDE에서 `dotnet run` | `docker compose up` |
| 코드 | 작업 트리 그대로 | **회차 커밋**으로 빌드한 이미지 |
| 게임 DB | git의 `game.sqlite3` (본체) | 볼륨 안의 사본 (git 밖) |
| 경매장 주소 | `appsettings.json` 기본값 `http://127.0.0.1:30330` | `Game__Auction__Address=http://auction:30330` |
| 클라 | 에디터 `로컬` 프리셋 | `진우 서버` 프리셋 / 회차 빌드 |
| 치트 | 모든 계정 (`CheatAdminLevel` 0) | **막는다** — `admin_level ≥ 1`만 (`Game__CheatAdminLevel=1`, 2026-10-11 결정) |

- 원격 DB는 **덮어쓰지 않는다** — 새 이미지가 뜰 때 서버가 남은 마이그레이션을 자동 적용한다([T-146](T-146-DB마이그레이션자동적용.md)).
  친구 데이터가 회차를 넘어 남는다.
- `.bytes`(`Shared/Data`)는 코드와 짝이라 **이미지에 굽는다** — 볼륨에 두면 회차 이미지와 어긋난다.

## 완료 조건

`docker compose up` 한 번으로 두 서버가 뜨고, **261024 회차 클라 빌드로 친구 PC에서 내 서버에 접속해**
로그인·채취·경매장 등록/구매가 된다.
컨테이너를 재시작하거나 새 회차 이미지로 갈아 끼워도 계정·매물 데이터가 남아 있다(스키마는 마이그레이션으로 따라간다).
개발 서버와 Docker 게임 서버를 같은 PC에서 동시에 띄울 수 있다(포트 분리).
