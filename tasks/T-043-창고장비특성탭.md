# T-043 클라 — 창고 장비 · 특성 탭

> [T-036](archive/T-036-창고탭전환.md)에서 갈라져 나왔다. 전환 구조·격자는 이미 서 있고
> **여기는 남은 두 탭의 내용물만** 다룬다.
> 2026-09-19 — **장비 탭을 열었다.**
> 2026-09-20 — **특성 탭도 열었다. 네 탭이 모두 눌린다.** 남은 것은 실측뿐이다.

## 배경

창고 탭 4개 중 **자원·캐릭터·장비 셋이 돌고, 특성 하나만 버튼이 잠겨 있다.**
클라가 못 만든 것이 아니라 **데이터가 오지 않는다.**

> 잠금은 `StorageGridPresenter.HasSource`에서 파생된다 — **공급자가 생기면 그 탭은 저절로 열린다.**
> 탭 줄(`StorageTabPresenter`)에 잠금을 따로 적어 두지 않았으므로 그 파일은 열지 않아도 된다.

## 할 일

> **착수 지점은 [`Storage 규칙.md`](../Assets/Scripts_Client/UI/Storage/Storage%20규칙.md)의
> "탭 하나를 채우는 절차" 네 단계다.** 공급자 파일 하나 + 등록 한 줄이면 탭이 열린다.

- [x] **장비 탭** (2026-09-19) — 선행 둘이 다 풀렸다
      - [x] ~~[T-002](archive/T-002-장비슬롯.md) 장비 시스템~~ → 완료. `S_EquipListResponse`·`S_EquipSyncResponse`가 온다
      - [x] ~~⚠️ `ItemType`의 축을 먼저 정해야 한다~~ → **해당 없음.** T-002가 장비를 `ItemTable`이 아니라
            **별도 `EquipTable`·별도 패킷**으로 냈다. 자원 테이블에 얹을 일이 없어진 것이라 축 결정도 사라졌다
      - [x] 장비는 **개체마다 상태가 다르다** → `Key`는 `EquipId`(개체), 이름·등급·효과는 `EquipTid`로 읽는다 — 캐릭터 탭과 같은 모양
      - [x] `PlayerDataModel.Equips`·`EquipsChanged` 신설(구독자가 하나도 없었다) · `EquipSlotSource` · 등록 한 줄
      - [x] 칸 표시 — 이름 + 효과 한 줄(`낚시 +30%`) · 장착 중은 '배' 마크 재사용 · 순서는 서버 `SlotPosition`
      - [ ] ⚠️ **'배' 마크(장착 중)는 미검증이다** — 장착 UI가 없어 장비를 낄 경로가 없다.
            장착 패킷(`C_EquipRequest`·`C_UnequipRequest`)은 **이미 다 있다** — 클라 구독자만 없다.
            → **[T-074](T-074-장비장착UI.md)로 등록했다 (2026-09-20).** 그때까지 이 항목은 확인할 수 없다
- [x] **특성 탭** (2026-09-20) — [T-068](T-068-클라계정레벨특성트리.md)의 트리 화면과 **같은 화면으로 두었다**
      - [x] 격자를 쓰지 않는 유일한 탭이다. 공급자를 하나 더 만드는 대신 `#Storage Canvas`의
            자식 `Trait Presenter`를 두고, **잠금 판정만 `StorageTabPresenter.HasScreen` 한 곳으로 넓혔다**
      - [x] 특성 탭에서 꺼지는 것은 셋(도구 줄 · 격자 · 판매 목록)이고 **각자 스스로 끈다**
      - [ ] ⏳ **실측** — 탭을 누르면 셋이 사라지고 트리가 뜨는지

## 완료 조건

네 탭이 모두 눌리고, 각 탭이 자기 목록만 보여 준다.

> **구현은 2026-09-20에 끝났다.** 남은 것은 실측과, 장착 경로가 없어 확인 못 하는 '배' 마크뿐이다
> (그 항목은 [T-074](T-074-장비장착UI.md)로 넘어가 있다 — 여기서 다시 잡지 않는다).
