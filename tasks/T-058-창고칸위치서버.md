# T-058 서버 — 창고 칸 위치 저장 · 정렬 요청 · 자리 이동 (자원 · 캐릭터)

> [T-015](T-015-산업아이템클라적용.md)에서 갈라져 나왔다 (2026-09-16).
> 클라가 [정렬] 버튼을 먼저 넣었지만 **순서를 세션 동안만 기억한다** — 재접속하면 사라진다.

## 배경

창고 격자는 **i번째 항목을 i번째 칸에 그린다**. 그런데 그 순서가 지금은 **서버가 보내 준 목록 순서**다.
사람이 정한 자리가 아니라서, 정렬해도 다시 접속하면 원래대로 돌아가고 드래그로 옮길 수도 없다.

**칸 위치를 서버가 들고 있어야** 재접속·다른 기기에서도 자리가 유지된다.
클라가 저장하면(PlayerPrefs 등) 계정과 기기가 어긋나는 순간 조용히 틀린다.

지금 패킷에는 위치가 없다 — `ItemInfo { ItemId, Count }`, `CharacterInfo { CharacterId, CharacterTid, … }`.

### 정렬 기준 셋 (2026-09-20 추가)

원래 이 일감의 정렬은 **클라 임시 정렬과 같은 규칙 하나**였다. QA 피드백으로
**'이름순'·'보유 수량순'** 이 더해져 기준이 셋이 됐다 —
자원이 150종을 넘어 등급 하나로는 찾을 수가 없다
([`0920-피드백 및 답변 정리.md`](../gyub/0920-피드백%20및%20답변%20정리%28정태웅%29/0920-피드백%20및%20답변%20정리.md) 2번).

> **기준 자체는 클라가 먼저 넣는다** → [T-073](T-073-창고정렬기준.md). 줄 세우는 것은 받아 둔 목록을
> 다시 정렬하는 것이라 서버가 필요 없다. **이 일감이 맡는 것은 "그 순서가 재접속해도 남는가"** 다 —
> 지금은 로그인할 때 버려서(세션 한정) 껐다 켜면 원래대로 돌아간다.
> 그래서 **여기서 정할 기준 목록은 T-073과 같아야 한다** — 다르면 서버 정렬을 켠 순간 순서가 바뀐다.
> (찾기(검색·필터)도 서버 없이 클라만으로 간다 → [T-069](T-069-창고찾기도구.md).)

## 할 일

- [ ] **칸 번호 필드** — `ItemInfo`·`CharacterInfo`에 창고 칸 번호(`SlotPosition` 등, 0부터)
- [ ] **DB 컬럼** — 인벤토리 행·캐릭터 행에 칸 번호. 기존 데이터는 지금 목록 순서대로 채운다
- [ ] 스냅샷(`S_InventoryResponse`·`S_CharacterListResponse`)과 증분 푸시(`S_UpdateItemResponse`·`S_CharacterSyncResponse`)에 칸 번호를 싣는다
- [ ] **새 항목은 첫 빈 칸에 둔다** (채취·가챠로 처음 들어온 자원·캐릭터). 수량만 늘면 자리는 그대로다
- [ ] 수량이 0이 된 자원의 칸을 비울지 정한다 — 지금 서버는 0개 행도 실어 보낸다
- [ ] **정렬 요청** `C_StorageSortRequest { 탭, 기준, 방향 }` — **서버가 계산해** 새 위치를 푸시한다.
      **기준은 셋이다** (2026-09-20 QA 피드백 — 아래 "정렬 기준 셋"):
      - `등급` — 지금 클라 임시 정렬과 같게. 자원: 등급↓ → 산업 순(`ItemType` 값: 농사·낚시·채광·벌목·사냥·기타·특수) → TID↑ /
        캐릭터: 등급↓ → `CharacterTid`↑ → `CharacterId`↑
      - `이름` — 표시 이름 기준. ⚠️ **정렬 기준이 되는 이름의 출처를 먼저 정한다** → [T-047](T-047-산업이름출처.md)
      - `보유 수량` — **자원 탭만**이다. 캐릭터·장비는 개체라 수량이 늘 1이다
      - 방향(↑↓)은 기준과 무관하게 뒤집을 수 있게 한다 — 클라 화살표가 이미 그렇게 동작한다
- [ ] **자리 이동 요청** — 칸 A → 칸 B. 빈 칸이면 옮기고, 차 있으면 **서로 바꾼다.** 드래그 이동([T-044](T-044-창고칸이동.md))이 쓴다
- [ ] 거절 코드 — 범위 밖 칸 · 없는 항목 · **그 탭에 쓸 수 없는 정렬 기준**(캐릭터 탭의 보유 수량 등)
- [ ] 테스트 — 새 항목 첫 빈 칸 · 정렬 결과 · 교환 · 재로그인 후 유지
- [ ] **프로토콜 미러 커밋** (T-025 사고 재발 방지 — 서버 일감 공통 완료 조건)

## 완료 조건

더미 클라이언트로 정렬·자리 교환을 보낸 뒤 **재로그인해도 스냅샷의 칸 번호가 그대로**이고,
새로 채취한 자원이 첫 빈 칸에 들어간다. Unity 미러가 커밋돼 클라 컴파일이 깨지지 않는다.
