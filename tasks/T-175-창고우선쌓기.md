# T-175 창고 우선 쌓기

## 배경

지금 새로 들어오는 자원은 **언제나 인벤토리로만** 간다(`User.GainItem` → `Inventory.AddItem` · [인벤토리-창고](../Server/docs/인벤토리-창고.md) "새로 들어오는 것은 언제나 인벤토리의 첫 빈 칸").
창고에 같은 자원 칸이 MaxStack 미만으로 남아 있어도 채우지 않는다.

- 창고에 넣어 둔 자원은 **보관하겠다는 뜻**인데, 같은 것이 들어올 때마다 인벤토리에 새 칸이 생긴다 — 매번 손으로 창고에 옮겨야 한다
- 인벤토리 칸이 다 차면 들어온 몫은 **버려진다**(T-160) — 창고에 빈 몫이 있어도 버린다

2026-10-20 태웅 제안 — 창고에 같은 자원 칸이 있으면 거기부터 채우고, 차면 인벤토리로 간다.

## 할 일

- [ ] 기획 — 지급 순서를 정한다 (제안: ① 창고의 같은 자원 칸(칸 번호 앞부터) MaxStack까지 → ② 인벤토리의 같은 자원 칸 → ③ 인벤토리 첫 빈 칸). **창고 빈 칸에 새 묶음은 만들지 않는다** — 창고는 플레이어가 고른 것만 둔다
- [ ] 서버 — `GainItem`이 위 순서로 넣는다. 수확·상자·뽑기·우편·분해 재료 등 지급 경로 전부(전부 `GainItem`을 지난다)
- [ ] 서버 — 칸 수 검사(`HasStorageFor`)가 창고의 남은 몫까지 센다 — 안 그러면 창고에 들어갈 수 있는데 `StorageFull`로 거절된다
- [ ] 클라 확인 — `ItemChangeInfo`에 `Container`가 이미 있어 패킷 변경은 없다. 창고 칸 갱신이 화면에 바로 반영되는지만 본다(태웅)
- [ ] 문서 — [인벤토리-창고](../Server/docs/인벤토리-창고.md) 자원 지급 행 · "새로 들어오는 것" 절
- [ ] **보강 (2026-10-20 · [#82 코멘트](https://github.com/JeongTaeWoong99/Windows_simulator/issues/82#issuecomment-6293823150))** — 이미 나뉜 칸 합치기
  - [ ] 서버 — [합치기] 한 보관함 안 같은 자원을 칸 순서 그대로 앞 칸부터 MaxStack까지 모음(제안 `C_StorageMergeRequest`)
  - [ ] 서버 — [창고에 쌓기] 창고에 **이미 있는** 자원만 인벤토리 → 창고 같은 자원 칸으로(제안 `C_WarehouseStackRequest`)
  - [ ] 클라 — 인벤토리 도구 줄 [합치기] · 창고 화면 [창고에 쌓기] 버튼 (패킷 확정 뒤 · 태웅)
  - 유지: 지급은 덜 찬 칸 앞부터 · 차감은 인벤토리 먼저 + 적은 칸부터(이미 조각을 줄이는 방향)
- [ ] 치트: 기존 아이템 지급 치트로 확인 — 창고에 같은 자원을 일부 넣어 두고 지급

## 완료 조건

창고에 MaxStack 미만인 같은 자원 칸이 있으면 들어온 자원이 거기부터 차고, 넘친 몫만 인벤토리로 간다. 캐릭터·장비(개체)는 지금처럼 인벤토리로 간다.
