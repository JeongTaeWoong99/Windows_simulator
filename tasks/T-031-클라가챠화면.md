# T-031 클라 — 가챠 화면 · 뽑기 결과 연출

## 배경

**"좋은 아이템이 나왔다"를 플레이어가 확인할 수 있어야 뽑기가 재미가 된다.**
서버가 결과를 내려줘도 화면이 없으면 인벤토리 숫자만 조용히 늘 뿐이다.

`S_GachaDrawResponse`는 이미 **연출용 델타(`Rewards`)와 인벤 반영용 누적(`ItemChangeInfos`)을
분리해서** 내려준다 — 뽑힌 순서 그대로 하나씩 열어 보이는 연출이 가능하다.
희귀도(`EGlobalRarity`)도 함께 실려 있고, **등급 색상은 `Enum.xlsx`에 정의돼 있다.**

## 할 일

> ◐ = 일부만 됐다 · ⏸ = **기획·서버가 먼저 와야 한다**(클라가 지금 못 한다)
> 🎨 = **연출·리소스. 의도적 후순위다** — 메인 시스템이 선 뒤에 한다
>

> ⚠️ **아직 main에 병합되지 않았다** — 브랜치 `worktree-T-026-character-gacha`(`f7698d4`).

- [x] 가챠 화면 — 단차/10연차 버튼 (`GachaPresenter`)
- [ ] **가챠 화면 · 풀 목록 · 비용 표시** (버튼 둘만 있고 풀·비용은 아직 없다) — ✅ **착수 가능**
      → `GachaInfoTable`이 생겼다: `GachaInfoTID` · `Name` · `CostCurrency` · `CostSingle` · `CostMulti`.
      ⚠️ **비용을 상수로 박지 않는다** — 10연차가 단차 × 10이라는 보장이 없다(컬럼이 따로다)
- [ ] **보유 골드 표시 · 부족하면 버튼 비활성** — ✅ **착수 가능**
      (**클라 판단은 표시용일 뿐, 거절은 서버가 한다**)
      → 골드 값은 이미 있고(`PlayerDataModel.Gold`) **비교 기준이 생겼다**(`CostSingle`·`CostMulti`)
- [x] 결과 창 — 뽑힌 목록을 5열 × n행으로 한 번에 표시(수량 표시는 끔), 희귀도 **색상** 적용
      (`UI/System/GachaResultPresenter/`, 칸은 `InventorySlotView` 프리팹 재사용)
- [ ] 🎨 결과 **연출** — 한 번에 띄우는 지금 방식 대신 뽑힌 순서대로 하나씩 공개
      → **길은 이미 열려 있다**(`S_GachaDrawResponse.Rewards`가 뽑힌 순서의 델타다).
      **못 해서가 아니라 뒤로 미룬 것이다** — 보상 종류 축(T-026)이 들어오면 연출이 다뤄야 할
      대상이 바뀐다. **한 화면에서 아이템·캐릭터를 함께 처리하는 모양이 정해진 뒤에 만든다**
- [ ] 🎨 희귀도 **스프라이트** — 지금은 `RarityPalette`가 색만 돌려준다
      (코드에 TODO. 표 한 줄과 `InventorySlotView.Bind` 한 줄을 sprite 대입으로 갈아끼우면 끝난다).
      **색으로 이미 구분되므로 기능은 서 있다.** 리소스가 준비되는 시점에 붙인다
- [ ] 🔴 **캐릭터 결과와 아이템 결과를 한 화면에서 처리한다** — ✅ **착수 가능 · 지금은 화면이 틀린다**
      → `GachaRewardInfo.RewardType`(`Item`/`Character`)로 갈라 `ItemId` / `CharacterTid`를 읽는다.
      ⚠️ **`GachaResultPresenter.OnGachaCompleted`가 `reward.ItemId`를 무조건 읽는다** —
      캐릭터 보상은 `ItemId`가 0이라 **빈 칸이 그려진다. 필드가 추가만 되어 컴파일은 통과한다**
- [ ] ◐ 뽑은 뒤 캐릭터 목록·인벤토리·골드 표시가 재로그인 없이 갱신되는지 확인 — ✅ **착수 가능**
      → **인벤토리는 확인됐다** (2026-08-26, 10연차 실행 검증).
      **캐릭터**는 지급 직후 서버가 `S_CharacterListResponse`를 다시 민다 —
      뽑기 응답에는 개체 PK가 없다(DB가 늦게 발급한다). **골드**는 `S_CurrencyResponse`로 온다
- [ ] ◐ 실패 응답 처리 — 연출을 재생하지 않고 사유를 보여준다
      → 흐름은 서 있다: `GachaPresenter.OnGachaFailed`가 `ResultMessages.ToText`로 문구를 만들어
      대기를 `Fail`로 닫고, `GachaResultPresenter`는 `GachaCompleted`만 구독하므로 팝업이 안 뜬다.
      🔴 **남은 것은 문구다** — `ResultMessages.ToText`에 **`NotEnoughCurrency = 102`가 없어**
      *"알 수 없는 오류가 발생했습니다. (코드 102)"* 로 뜬다. **골드 부족은 정상적인 실패 경로다**

## 완료 조건

화면에서 골드로 10연차를 뽑아 **결과가 순서대로 열리고**,
뽑은 캐릭터가 배치 화면 목록에 바로 나타난다.
