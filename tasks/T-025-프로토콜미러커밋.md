# T-025 슬롯 동기화 패킷의 Unity 프로토콜 미러 커밋

## 배경

[T-024](archive/T-024-슬롯동기화패킷.md)(커밋 `4365d83`, 이슈 #12)에서
**`Assets/Scripts_Server/Protocol/MikaPacket.cs`가 빠졌다.**

이 파일은 `Server/MikaProtocol/MikaPacket.cs`를 `sync-protocol-to-unity.ps1`이 단방향 복사한
**서버 생성물**이다. `MikaProtocol.csproj`의 post-build에서 자동 실행되므로,
**빌드를 한 번이라도 돌렸으면 미러가 함께 생성됐을 파일이다.**

그 결과 `main`이 이런 상태로 남아 있다.

| 쪽 | 상태 |
|----|------|
| 서버 (`Server/MikaProtocol`) | `PacketId=18` · `S_WorkStationSlotSyncResponse` 있음 — 정상 빌드 |
| Unity 미러 (`Assets/Scripts_Server/Protocol`) | 둘 다 없음 — 직전 커밋 `d2c52c6` 상태 |

**서버는 멀쩡한데 Unity만 깨진다.** 클라 쪽 `ServerPacketHandler`·`PlayerDataModel`이
그 타입을 참조하므로 `CS0246`이 나고, 증상만 보면 원인이 클라 코드로 보인다.

> 클라가 로컬에서 스크립트를 돌려 컴파일은 뚫어 뒀지만 **커밋하지 않는다.**
> 미러는 서버 담당 폴더이고(`CLAUDE.md` 폴더 표 · 협업 규칙), 생성물을 소유하지 않은 쪽이
> 대신 넣기 시작하면 다음에 또 어긋났을 때 누가 진실인지 알 수 없게 된다.

## 할 일

- [ ] `Server/MikaProtocol` 빌드 → post-build로 미러 자동 생성 확인
      (또는 저장소 루트에서 `powershell -File Server/sync-protocol-to-unity.ps1`)
- [ ] `Assets/Scripts_Server/Protocol/MikaPacket.cs`를 커밋·푸시
- [ ] 앞으로 **패킷을 건드리는 커밋은 미러를 같은 커밋에 담는다** — 절차 확인

## 완료 조건

`main`을 새로 받아 Unity를 열었을 때 `CS0246` 없이 컴파일된다.
(`MIKA001` 핸들러 누락 경고도 없어야 한다 — 소스 제너레이터가 PacketId 18을 잡는다)
