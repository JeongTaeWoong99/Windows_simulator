# T-062 클라 — 설정에서 프레임 제한 고르기

## 배경

지금은 `Application.targetFrameRate`·`QualitySettings.vSyncCount`를 어디서도 정하지 않는다.
바탕화면에 상주하는 앱이라 사용자가 **프레임(= CPU·GPU 사용량)을 직접 고를 수 있어야** 한다.
이 설정은 **에디터 플레이와 빌드 양쪽에서 실제로 적용**돼야 한다.

## 할 일

- [ ] 설정 화면(`SettingPresenter`)에 드롭다운 추가 — 항목: `30` · `60` · `90` · `144` · `모니터 동기화`.
      옵션 라벨은 코드가 채운다(기존 드롭다운 규약)
- [ ] 적용: 숫자 항목 = `vSyncCount = 0` + `targetFrameRate = N` / 모니터 동기화 = `vSyncCount = 1` (`targetFrameRate`는 무시됨)
- [ ] 적용 담당 결정 — `WindowManager`에 붙일지 별도 담당자를 둘지 (`Settings/`는 저장만, 적용은 매니저 — `Settings 규칙.md`)
- [ ] `PlayerPrefs` 저장 — 새 접두사(예: `Display.FrameRate`), 값이 바뀔 때만 즉시 `Save()`
- [ ] **에디터 권위 규칙 결정** — `Settings 규칙.md` 1장은 창 설정을 "에디터=인스펙터가 진실"로 둔다.
      프레임은 창 모양과 달리 에디터에서도 저장값을 따를지 정하고 규칙 문서에 적는다
- [ ] 기본값 결정 (예: 60)
- [ ] ⚠️ 에디터 검증 — 에디터에서는 Game 뷰의 VSync 토글이 `vSyncCount`를 덮는다.
      `모니터 동기화`가 에디터에서 실제로 먹는지 확인하고, 안 먹으면 한계를 규칙 문서에 적는다
- [ ] 빌드(.exe)에서 각 항목 실측 (프로파일러 또는 FPS 표시) — 투명 창 모드에서도
- [ ] `Settings 규칙.md` 키 표 갱신

## 완료 조건

설정에서 5개 항목을 고르면 에디터 플레이와 빌드 모두 해당 프레임으로 돈다(실측).
빌드를 껐다 켜도 고른 값이 유지된다.
