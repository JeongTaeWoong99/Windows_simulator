# T-079 클라 — 특성 정보 표시 후 해금 플로우

## 배경

지금은 **노드를 누르는 즉시 결과가 튀어나온다.**

```
노드 클릭 ─┬─ 이미 배움      → 알림 "이미 배운 특성입니다."
           ├─ 조건 미달      → 알림 "계정 레벨 n이 필요합니다." / "○○을 먼저 배워야 합니다."
           ├─ 포인트 부족    → 알림 "특성 포인트가 부족합니다."
           └─ 전부 통과      → 확인 팝업 → 서버 요청
```

노드 칸 아래 한 줄(`BuildDetail`)이 **조건이거나 효과 중 하나만** 적는다 —
잠기면 조건을, 열리면 효과를. 즉 **열려 있는 특성은 무엇을 얼마나 주는지 한 줄로밖에 못 본다.**
"눌러야 알 수 있는데, 누르면 바로 팝업"이라 **읽고 결정할 자리가 없다.**

## 바꿀 흐름

```
노드 클릭 → 하단 정보 영역에 그 특성을 펼친다 (이름 · 효과 · 조건 · 필요 포인트 · 현재 상태)
                      └─ [확인] 버튼 → 지금의 판정·팝업·알림을 그대로 탄다
```

**판정 순서와 문구는 바꾸지 않는다.** 서버 판정과 같은 순서(선행 → 계정 레벨 → 포인트)를 유지하고,
그것이 불리는 **시점만** 노드 클릭에서 [확인] 클릭으로 옮긴다.

## 조사 결과 — 무엇이 어디 있나

| 확인 팝업 · 알림 | `UIManager.AskConfirm` · `ServerWaitManager.RaiseNotice` |

**서버·패킷 변경 없음.** `C_UserTraitLearnRequest`는 그대로다.

## 영향 범위

- **`Trait Presenter` 안에서 끝난다.** 창고 탭 줄·격자·도구 줄·판매 목록과 무관하다.
- `Trait Presenter`는 `Trait Tab Panel(34)` + `Point Text(22)` + `Scroll View Panel(flexH 1)` 구성이다.
  정보 영역을 붙이면 **트리 스크롤 영역이 그만큼 줄어든다** — 높이를 고정할지 정해야 한다.
- **`Redraw`가 해금·계정 레벨 변경마다 돈다.** 정보 영역도 같이 갱신돼야 한다 —
  찍은 직후 "필요 포인트 n" 이 남아 있으면 안 된다.
- 고른 칸이 **다시 그려지며 사라질 수 있다**(탭 전환 · 트리 재구성). 고른 TID를 들고 있되
  그 TID가 지금 구역에 없으면 정보 영역을 비운다.
