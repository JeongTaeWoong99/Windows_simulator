# T-173 칸 마우스 입력 정식화

## 배경

지금 칸(자원·장비·캐릭터) 입력은 동작마다 클릭 조합 하나씩이다 — 우클릭 판매 담기 · Ctrl+좌클릭 잠금 · Ctrl+우클릭 경매 등록 · 좌클릭 상자/큐브/응축.
타르코프 같은 익스트랙션 슈터의 정식 방식(우클릭 = 메뉴 · 수정키+클릭 = 안전한 지름길 · 파괴 동작은 한 번에 끝나지 않음)을 따르기로 했다 (2026-10-19 사용자 결정 — **정식 게임 방식을 따른다**).

- 우클릭 한 번이 판매로, Ctrl 실수가 경매 등록으로 이어진다
- 조합 네 개를 다 써서 분해([T-131](T-131-장비분해.md))를 넣을 자리가 없다

## 할 일

| 입력 | 지금 | 바꿀 것 |
|---|---|---|
| 좌클릭 | 상자 열기 · 큐브 창 · 응축 창 | **선택·집기만** — 누르기만 해서는 아무 일도 없다 |
| 좌클릭 드래그 | 칸 이동 | 그대로 |
| 더블클릭 | 없음 | **기본 동작** — 상자 열기 · 큐브 창(장비) · 응축 창(캐릭터) |
| 우클릭 | 판매 목록에 담기 | **메뉴 열기** |
| Ctrl+좌클릭 | 잠금 | **빠른 이동** — 지금 열린 반대편으로 |
| Ctrl+우클릭 | 경매 등록 | 없앤다(메뉴로) |

- [ ] 우클릭 메뉴 — 칸 종류마다 할 수 있는 것만 · 지금 못 하는 것은 흐리게 + 이유(잠김 · 착용 중 · 배치 중)
  - 자원: 열기(상자) · 판매 목록에 담기 · 경매 등록 · 창고로/인벤토리로 · 잠금/해제
  - 장비: 큐브 · 판매 목록에 담기 · 경매 등록 · **분해**(서버 ✅ `C_EquipDisassembleRequest` — T-131) · 창고로/인벤토리로 · 잠금/해제
  - 캐릭터: 응축 · 판매 목록에 담기 · 경매 등록 · 창고로/인벤토리로 · 잠금/해제
- [ ] 더블클릭 = 기본 동작 — 좌클릭 한 번에 붙어 있던 것을 옮긴다
- [ ] Ctrl+좌클릭 빠른 이동 — 창고가 열려 있으면 인벤토리↔창고 · 판매 목록이 열려 있으면 담기 · 경매 등록 창이 열려 있으면 등록 칸에 · 아무것도 안 열려 있으면 아무 일 없음
- [ ] 잠금은 **메뉴에만** 둔다 — 따로 단축 입력을 두지 않는다
- [ ] 규칙 문서 갱신 — `KeyInputManager.cs` 머리 주석 · `Managers 규칙.md` 키 표 · `Inventory 규칙.md`(판매·잠금·경매 등록·상자 절)
- [ ] 치트: 해당 없음 — 입력만 바뀐다. 분해 확인은 기존 `GiveEquip`(8)

## 완료 조건

우클릭으로 메뉴가 열리고, 메뉴에서 판매 담기·경매 등록·분해·잠금·창고 이동이 된다. 더블클릭이 상자·큐브·응축을 열고, Ctrl+좌클릭이 열린 반대편으로 보낸다. 우클릭·Ctrl 한 번으로는 아무것도 팔리거나 등록되지 않는다.

## 막고 있는 것 / 선행 일감

- ⏸ 방향 재검토 — 입력을 바꾸지 않고 판매 목록에 [판매 | 분해] 모드를 두는 안 · [이슈 #83](https://github.com/JeongTaeWoong99/Windows_simulator/issues/83) (진우 · 2026-10-20 태웅 제기). 배경의 "우클릭 한 번이 판매로"는 실제로는 담기만 한다
- 2026-10-25 회의 뒤 안 — 판매 목록을 **종류별**(지금 탭만 · 탭을 바꾸면 비움)로 두고 **장비만 [골드로 판매] · [마석으로 분해]** 두 버튼. 목업 [`판매분해목업.html`](../GameDesign/design/ui/판매분해목업.html) — 사용자 검토 대기
- 분해 서버(T-131)는 끝났다
