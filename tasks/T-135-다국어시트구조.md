# T-135 기획·서버 — 다국어 시트 구조 — 화면에 보이는 문구를 언어별로 둘 수 있게 (우선 KR·EN)

## 배경

- 클라 설정 화면에서 **언어(KR·EN)를 고를 수 있게** 하려 한다 (2026-10-09 태웅). 폰트는 [T-100](archive/T-100-폰트교체.md)에서 KR·EN으로 나눠 굽는다.
- 그런데 플레이어에게 보이는 문구 대부분이 **엑셀 데이터**에 한국어 한 벌로만 있다 — `Name` · `Tooltip`(아이템·장비) 등.
  언어를 바꾸려면 이 값이 언어별로 있어야 한다.
- 시트 구조는 `Server/ExcelGenerator`가 읽어 **서버·클라 양쪽 Row 클래스**를 생성하고, `Tooltip`의 `{컬럼}` 보간도 생성기가 한다.
  클라 혼자 바꿀 수 없다 — 서버(생성기)·기획(시트) 몫이다.
- 지금은 KR·EN만 쓰지만 **언어가 늘어도 시트 구조를 다시 갈아엎지 않는** 모양이어야 한다.

## 할 일

- [ ] 구조 결정 — 예: (가) 데이터 시트에 언어별 컬럼(`Name_KR`·`Name_EN`) / (나) 문자열 시트(`Key | KR | EN | …`)를 두고 데이터 시트는 키만 참조. 언어 추가 = 컬럼 하나 추가로 끝나는 쪽
- [ ] 대상 범위 — 어느 테이블·컬럼이 플레이어에게 보이는 문구인가 (`Name`·`Tooltip` 외 · `Description`은 기획 메모라 제외)
- [ ] 생성기 — 언어별 값 생성 · `Tooltip` 보간이 언어마다 돈다 · EN이 비어 있을 때 규칙(KR로 대체 / 파이프라인 멈춤)
- [ ] 서버가 보내는 문구(우편 제목·본문 · 거절 사유 등)가 있으면 언어를 어떻게 다룰지
- [ ] 클라가 언어를 골라 읽는 API 모양 — 예: `row.Name` 대신 `row.GetName(lang)` · 클라 고정 UI 문구도 같은 문자열 시트에 둘지
- [ ] EN 값 채우기 — 최소 한 테이블이 KR·EN 둘 다 도는 것까지
- [ ] 문서 — `GameDesign/CLAUDE.md` 예약 컬럼 절 · 미러 커밋

## 완료 조건

한 테이블 이상이 KR·EN 값을 갖고, 클라가 언어를 지정해 그 값을 읽을 수 있다. 언어를 하나 더 늘리는 방법이 문서에 있다.
