# T-121 그림을 비공개 저장소로 분리

## 배경

[T-120](archive/T-120-아트가공파이프라인.md)에서 그림(원본 팩·가공 결과·레시피)을 `.gitignore`로 뺐다(`4e27f51`).
지금은 **그림이 각자 PC에만 있다** — 다른 사람이 받으면 화면은 대체 그림(빈칸)으로 돈다.
보관 방식을 정해 팀에 전파한다. 세팅·전파는 태웅이 한다.

## 왜 바꾸나

| 이유 | 내용 |
|---|---|
| 저장소가 공개 | 메인 저장소(`Windows_simulator`)는 공개라, 올리면 누구나 받는다 |
| 라이선스 | 원본 팩은 무료·유료 모두 **재배포 금지**가 많다. 가공 결과도 원본의 파생물이라 같다 |
| 메인을 비공개로 돌리면 | 무료 플랜에서 GitHub Pages(문서 사이트)·Actions 무료 시간을 잃는다 |

## 어떻게 관리되나

| 항목 | 내용 |
|---|---|
| 메인 저장소 | `Assets/Art/*`를 무시한다 — `Art 규칙.md`(와 `.meta`)만 올린다 |
| 그림 저장소 | **비공개 저장소를 새로 만들어** `Assets/Art/` 자리에 그대로 클론한다 (원본 `_source/` · 결과물 · 레시피 · `VisualCatalog.asset`, `.meta` 포함) |
| 둘의 관계 | 서로 모른다 — 서브모듈 아님. 메인은 그 폴더를 무시할 뿐이다 |
| 권한 | 그림 저장소에 팀원만 초대한다 |

## 워크플로가 어떻게 바뀌나

| 상황 | 전 | 후 |
|---|---|---|
| 처음 받기 | 메인 클론 1번 | 메인 클론 → `Assets/Art/`에 그림 저장소 클론 (2번) |
| 최신 받기 | pull 1번 | 메인 pull + 그림 pull (2번) |
| 그림만 바꿨다 | — | 그림 저장소에만 커밋·푸시 |
| 코드가 새 그림을 쓴다 | 커밋 1개 | **양쪽 다 푸시** — 그림을 먼저 올리고 메인을 올린다 |
| 그림 저장소를 안 받았다 | — | 화면은 대체 그림·빈칸으로 돈다(깨지지 않는다). CI도 그림 없이 돈다 |
