# T-040 하트비트 끊김 — 해결 방향 결정 (이슈 #19)

## 배경

**하트비트(Ping/Pong)가 두 가지 이유로 끊긴다.**

| | 증상 | 빈도 |
|---|---|---|
| **A** | 아무 조작도 안 했는데 "서버와의 연결이 끊어졌습니다" | 수십 분에 한 번, 무작위 |
| **B** | 창 제목줄을 잡고 **5초 이상** 끌면 끊긴다 | **확정적** |

- **A — 여유가 0이다.** `Global.SessionIdleTimeout`(5초) == 클라 핑 주기(5초).
  서버는 `now - LastReceivedAt >= 판정`이면 즉시 끊는데(`MikaServer.DisconnectIdle`),
  클라의 실제 간격은 프레임 오버슈트 누적으로 5.008초쯤 된다.
- **B — 세션 루프가 Unity 메인 스레드에 묶여 있다.** `NetworkManager.Start()`가 `async void`라
  메인 스레드에서 돌고, `Session.StartAsync()`의 송수신 루프가 첫 `await`에서
  `UnitySynchronizationContext`를 캡처한다. `WindowManager.BeginWindowDrag`가 창 이동을
  **OS 모달 루프에 위임**해 메인 루프를 멈추면 소켓도 함께 멈춘다.

> **에디터에서는 B가 재현되지 않는다** — `BeginWindowDrag`가 `#if !UNITY_EDITOR`다.

## 왜 보류인가

**클라가 시험 적용해 증상이 사라지는 것까지 실측 확인했지만, 되돌렸다.**

효과를 낸 수정(`Task.Run` + `ConfigureAwait(false)`)이 **서버 담당 폴더**
(`Assets/Scripts_Server/Network/MikaNetwork.Client/`)에 있었고, **그 방식이 유일한 답도 아니다.**
후보가 여럿이고 각각 **경제 밸런스**(부당 적립 구간) · **창 제어 설계**(OS 위임을 버릴 것인가) ·
**패킷 추가**와 얽힌다. **클라 단독으로 정할 문제가 아니다.**

- 되돌린 커밋: `45b55c6` → 되돌림 커밋 `2fb9dcb`
- **revert의 revert로 그대로 되살릴 수 있다.**
- **지금 `main`은 수정 전 상태이고 증상이 그대로 재현된다.**

## 완료 조건

빌드에서 창을 10초 이상 끌어도 연결이 유지되고, 몇 시간을 켜 둬도 무작위 끊김이 없다.
서버 콘솔에 정상 세션이 `무응답으로 끊었다`로 잡히지 않는다.
