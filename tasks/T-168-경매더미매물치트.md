# T-168 서버 — 경매 더미 매물 치트

## 배경

경매 검색은 건수를 1,000에서 세다 멈추고, 클라는 그때 "1,000건 이상"을 보인다([이슈 #71](https://github.com/JeongTaeWoong99/Windows_simulator/issues/71) · [T-155](T-155-경매검색확장.md)).
이걸 화면에서 보려면 판매 중 매물이 1,000개 넘게 있어야 하는데, 지금은 만들 길이 없다.

- 클라에서 한 계정이 올리는 방법은 막힌다 — 유저당 판매 중 상한(`AuctionRules.MaxActiveListings`)과 빈도 제한이 있고, 보유 아이템도 1,000개가 필요하다.
- 계정 여러 개로 나눠 올리는 것도 50개 넘게 만들어야 한다.

그래서 **더미 판매자 이름으로 매물을 바로 넣는 서버 치트**를 만든다. 서버 기능·부하 테스트(검색 비용 — T-155 후속)와 클라 확인(건수·쪽 넘기기·정렬)에 함께 쓴다.

## 할 일

- [x] 치트 — `ECheatCommand`에 명령 추가 (예: `SeedAuctionListings` · Arg1 = 개수 · Arg2 = ItemTID, 0이면 섞어서) · [`Server/docs/치트.md`](../Server/docs/치트.md) 2장에 한 줄
- [x] 매물은 유저 상한·빈도 제한·등록비를 거치지 않는다. 판매자는 실제 유저가 아닌 더미(이름 예: `더미상점`) — 팔려도 대금이 실제 유저에게 가지 않게
- [x] 단가·만료를 조금씩 흩어 정렬(단가·마감)이 확인되게
- [x] 더미 매물을 한꺼번에 지우는 방법 (같은 명령에 Arg1 = 0 등)
- [ ] 클라 치트 창([`cheat-console`](../Assets/Scripts_Client/Editor/cheat-console/cheat-console%20규칙.md))에 버튼 — 태웅

### 한 것 (2026-10-17)

- `SeedAuctionListings = 16` — `Arg1` 개수(1~5,000, **0이면 삭제**) · `Arg2` ItemTID(0이면 자원을 돌아가며). 자원 매물만 만든다(장비·캐릭터는 개체 행이 필요해 뺐다)
- 더미 판매자 `AuctionDummy.SellerId`(9×10¹⁸ — 실제 계정과 안 겹친다) · 닉네임 `더미상점`. 원장에 바로 쓰고 경매장에는 릴레이가 보낸다(한 바퀴 100개)
- 삭제: 더미의 거래·등록 outbox·우편·기록을 지운 뒤 경매장에 남은 더미 매물을 판매자 기준으로 취소한다. 구매 중이라 못 지운 것은 "남음 N" — 다시 실행
- 응답이 두 번 온다 — 접수 + 끝났을 때
- 테스트 1035개 통과 (새 `AuctionDummyTest` 9개 · `UserCheatAuctionDummyTest` 8개 · 끝-대-끝 3개 — 1,050개 → 검색 1,000건 · 삭제 · 구매)

## 완료 조건

치트 한 번으로 매물 1,000개 이상이 올라가고, 클라 검색 탭에서 "검색 결과 1,000건 이상"과 `n 쪽` 표시가 보인다.
