# T-086 — 아이템 설명 보간

**엑셀 설명문에 숫자를 직접 적지 않고, 같은 행의 컬럼 값을 생성 시점에 치환한다.**

| 엑셀에 적는 것 | `.bytes`에 들어가는 것 |
|---|---|
| `인챈트 부여 {SuccessPermille:permille}` | `인챈트 부여 50%` |
| `농사 +{Value:permille}` | `농사 +4%` |

## 왜

[`GameDesign/CLAUDE.md`](../GameDesign/CLAUDE.md)가 **"로직에 쓰는 수치를 `Description`에 적지 않는다"** 고
금지해 뒀다 — 확률·배수를 메모로 적으면 실제 컬럼과 따로 놀다가 조용히 어긋나기 때문이다.
보간이 그 금지를 푸는 열쇠다: **숫자는 실제 컬럼 한 곳에만 존재하고**, 값을 고치면 설명이 따라온다.

결과가 `GameDesign/DataLog/*.json`에 찍히므로 **diff 리뷰로 확인된다.**
클라·서버는 이미 문자열을 읽을 뿐이라 **코드를 안 고친다.**

## 할 일

- [ ] 토큰 문법 확정 — `{컬럼명}` · 포맷 지정자 `:permille`(천분율 → %) 등
- [ ] `Server/ExcelGenerator`에 치환기 추가 (같은 행 컬럼만)
- [ ] 플레이어용 설명 컬럼 신설 — `Description`은 기획 메모로 남긴다(로직이 안 읽는다)
- [ ] 미지정 토큰·없는 컬럼은 **fail-fast** (조용히 빈 문자열이 되지 않게)
- [ ] `GameDesign/CLAUDE.md`의 `Description` 절 갱신

## 하지 않는 것

- **엑셀 수식**(`="…"&C2/10&"%"`). `format-excel.py`가 openpyxl로 저장할 때 **수식 캐시값이 날아가고**,
  그러면 ClosedXML 평가에 의존하게 된다 — 서식 정리를 돌릴 때마다 터질 수 있다.
- **다른 시트 값 참조.** "어느 행인지"를 지정하는 문법이 필요해 급격히 복잡해진다.
  `Ref`로 이미 연결된 경우에만 나중에 연다.
- **런타임 보간.** 치환기를 클라·서버 양쪽에 두게 되고 미러가 2곳이다.
  다국어나 레벨별 가변 수치가 생기면 그때 재검토한다.
