# T-012 최대 슬롯 증가 곡선 결정

> 2026-09-14 — 슬롯 해금은 [해금 시스템](../GameDesign/design/unlock/README.md)으로 흡수됐다.
> 골드 곡선은 `UnlockTable`에 테스트값(500 → 60,000)으로 들어갔고, 조건 문구는 클라가 테이블에서 만든다.
> **남은 결정은 칸별 계정 레벨 요구치(`UnlockTable.AccountLevel`) 하나**이고, 이건 계정 레벨 곡선 뒤다.

## 배경

**슬롯 수가 곧 경제 총량의 배수다.** 슬롯이 2개면 재화가 2배로 생긴다.
~~시작 슬롯 수·증가 수단·상한이 전부 미정이라~~ **셋 다 2026-08-01에 확정됐는데**,
서버는 아직 확정 이전의 임시값으로 돌고 있다.

```csharp
// Server/WSGameServer/User/User.WorkStation.cs — 2026-08-02 확인
/// <summary>신규 유저에게 기본으로 열어 주는 작업슬롯 수. 시작 슬롯 수가 미확정이라 1개로 둔다.</summary>
public const int DefaultSlotCount = 1;   // ⚠️ 확정값은 2. 주석도 낡았다
```

> ⚠️ **상한 8을 강제하는 코드도 없다.** 슬롯 해금 경로가 아직 없어서 당장 문제가 되진 않지만,
> 해금을 붙일 때 함께 넣어야 한다.

> ✅ **시작 2 · 상한 8은 곡선과 무관하게 지금 반영할 수 있다.** 아래 곡선(미정)을
> 기다릴 필요가 없는 항목이다 — 상수 두 개와 주석만 고치면 된다.
> **구현은 [T-038](archive/T-038-슬롯해금서버.md)로 옮겼다.**

## 2026-08-01 확정 — 구조는 정해졌다

| 항목 | 값 |
| --- | --- |
| 시작 슬롯 수 | **2개** |
| 상한 | **8개** |
| 증가 수단 | **계정 레벨(상한) × 골드(구매)의 이중 게이트** |

| 한쪽만 쓰면 | 문제 |
| --- | --- |
| 레벨만 | 슬롯 확장이 sink가 아니게 된다 |
| 골드만 | `골드 → 슬롯 → 골드` 자기가속이 폭주한다 |

**남은 것은 곡선이다** — 레벨 N에 상한 몇 개인가, 슬롯 N번째의 가격은 얼마인가.

## ⚠️ 이 결정이 화면 한 칸을 막고 있다 (2026-08-28)

클라는 지금 **잠긴 칸과 열린 빈 칸을 구분하지 못한다.** 1~7번은 전부 "비어있음."으로 그려지고,
눌러 보면 서버가 거절해 *"아직 열리지 않은 작업 슬롯입니다"* 알림만 뜬다.
**"어떻게 여는지"를 표시할 방법이 없다.**

```
T-012 (여기) 곡선 결정  →  T-038 서버가 잠긴 칸·조건을 패킷에 싣는다  →  T-039 클라가 그린다
```

> 곡선 값이 임시여도 클라 화면은 만들 수 있다 — **값이 아니라 형식**이 먼저 필요하다.
> 그래서 T-038의 패킷 골격은 이 일감을 안 기다리고 착수할 수 있게 갈라 두었다.

## 완료 조건

"레벨 N이면 슬롯 M개까지, 각 슬롯의 가격은 얼마"가 데이터로 정해지고,
**잠긴 칸에 무엇을 표시할지**까지 정해져 T-038이 그대로 구현에 들어갈 수 있다.
